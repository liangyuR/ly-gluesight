# 全局提示、SN 显示与示教笔刷决策记录（r2-ui）

范围：展示层——全局提示、50 字符 SN 的显示、硬编码颜色、示教笔刷默认值与提取失败提示。不改业务规则。

### U-1 全局提示放在主区顶部居中

- 问题：qing-steel 与 Material 3 的 snackbar 默认在视口底部；GlueSight 的示教、默认参数、相机配置都有吸底操作栏，底部提示会盖住操作按钮。
- 可选项：底部居中；底部右侧；主区顶部居中；视口右上角。
- 采用：主区顶部居中（距主区上沿 16 px）。原先的成功提示也出现在这一带，操作员的视线不用换位置；浮层不占布局。
- 实现：`src/App.tsx` 用 qing-steel 的 `SnackbarProvider` 包住 `AppLayout`，提示层 `.qs-snackbars` 渲染在 `.app-shell` 之后；组件默认固定在视口底部居中，`SnackbarProvider` 没有位置或容器参数，GlueSight 只能靠 `src/styles.css` 的两条规则把它限定在主区顶部：`.app-shell ~ .qs-snackbars` 取 `top: calc(12px + var(--space-16))`、`left: calc(var(--sidebar-w) + 24px)`、`right: 12px`，`.app-shell:has(> .sidebar.collapsed) ~ .qs-snackbars` 在侧栏收起时把 `left` 换成窄栏宽度。提示在主区内居中，不随页面滚动。页面里用 `useSnackbar()` 取 `{ show, clear }`，没有挂 Provider 时会抛错，所以单元测试要自己挂 `SnackbarProvider`。
- 工作台顶栏左侧只放配方选择与发布版本，候选修订、待生效、保存状态、重试保存放在右侧“配方库”之前：1920×1080 下各状态、各提示都不压顶栏任何元素；1440×900 下较长的提示可能压住文字和徽章，但不遮挡“保存失败”“重试保存”等可点控件。
- 另比较过：顶部右侧会压住系统设置、相机页的操作按钮；底部居中或左下会压住示教页与验证页的操作。仍取顶部居中。
- 提示文字控制在一行内（约 32 字以内，最宽 560 px）：两行的提示会压到步骤条上沿。
- 回退：删除 `src/styles.css` 中 `.app-shell ~ .qs-snackbars` 与 `.app-shell:has(> .sidebar.collapsed) ~ .qs-snackbars` 两条规则，提示回到 qing-steel 默认的视口底部居中；顶栏恢复原顺序只需把 `spacer` 移回“配方库”之前。

### U-2 同一时刻一条，按文字长度自动消失，悬停暂停

- 采用：新提示替换旧提示（旧提示 120 ms 淡出，与新提示叠在同一格，不上下推挤）；时长 `clamp(3000 + 字数 × 70, 4000, 10000)` ms；指针悬停或焦点在提示内时暂停计时，离开后按剩余时间继续；带关闭按钮。提示层 `role="status"`、`aria-live="polite"`。只动 transform 与 opacity；减少动态效果时动画关闭，离开立即移除。
- 实现：以上行为都由 qing-steel 的 `SnackbarProvider` 提供。同一次处理里连续 `show` 两条时，Provider 只保留最后一条。
- 换配方、清空当前选择、工作台操作开始时调用 `useSnackbar()` 的 `clear()` 收起当前提示（`src/features/workspace/context.tsx`），与原页面内提示的清除时机一致，上一配方或上一次操作的结果不会留到新上下文里。
- 理由：瞬时结果多为一句话；连续操作时堆叠多条会遮挡顶栏且没有新信息。
- 回退：`SnackbarProvider` 一次只显示一条，没有堆叠选项。要改为堆叠，需要向 qing-steel 提需求（见 [qing-steel-080.md](qing-steel-080.md) 的缺口清单），或在 GlueSight 自行封装一个提示通道替换 `App.tsx` 中的 Provider。

### U-3 哪些提示进全局提示

- 进全局提示（瞬时的操作成功）：工作台 `act` 的成功消息（保存候选、保存示教、记录标定验证、保存采集轮次与样本、验证完成、提交 / 重试 / 放弃发布等）；PLC 配置已保存；S7 点表已载入草稿（info 色，页面另有“未保存”徽章）；系统设置两个分区保存；工位标定完成（结果另在“当前标定”行持续显示）。
- 留在页面内：所有错误；需要用户处理的提示（候选未保存、参数无效、待生效 / 生效失败 / 状态不确定、需重新采集等）；带后续操作的结果（历史导出 CSV 的“打开所在文件夹”、诊断包导出结果在对话框内）；相机配置保存栏内的“已保存并应用 · 时间”（保存栏里的状态文字，替换原文字，不推动布局）。
- “已记录标定验证：误差超出 ±0.1 mm，未通过”用警告色全局提示，因为它是一次已完成的记录操作，未通过状态在右侧“标定”卡持续显示（徽章“验证未通过”、卡片展开）。
- 回退：对应页面恢复 `notice` 状态与页面内提示条。

### U-4 候选配置自动保存不弹提示

- 问题：原来自动保存候选配置也走“候选配置已保存，生产版本保持不变”，默认参数页每停顿 0.9 s 就插入一次提示。改成全局提示后仍会频繁弹出。
- 采用：自动保存静默，状态看顶栏徽章（等待保存 / 保存中 / 草稿已保存 / 保存失败）；点“保存候选配置”按钮仍提示。
- 回退：`context.tsx` 自动保存分支改回调用 `saveDoc()`。

### U-5 GlueSight 不引入 qs-motion.js

- 问题：qing-steel 的 `QingSteel.snackbar()` 直接操作 DOM；GlueSight 是 React 应用，不引入面向非 React 页面的 qs-motion.js。
- 采用：不引入 qs-motion.js。全局提示使用 qing-steel 提供的 React 组件 `SnackbarProvider` / `useSnackbar`，时序与时长规则与 DOM 版一致。qs-motion 的实现给非 React 页面和演示页使用。侧栏、工作台步骤条的选择轨道仍是 GlueSight 本地的 React 实现。
- 回退：无。

### U-7 SN 显示：列表与详情完整显示，固定高度处单行

- 问题：SN 最多 50 字符（协议 8 `String[50]`），各页原按 24 字符的宽度设计。
- 可选项：处处单行截断加悬停；处处换行；按位置区分。
- 采用：按位置区分。新增 `.sn`（等宽、表格数字、`word-break: break-all`，断行时整行填满，不在连字符处提前断开）。
  - 生产页顶栏 SN 芯片：单行，最宽 480 px，放得下 50 个等宽字符；更窄的屏幕省略并悬停显示全文。判定卡标题在 420 px 右栏放不下“判定结果 · SN + 50 字符”，单行省略、悬停全文（顶栏芯片已有完整 SN）。判定卡固定高度（ui-shell §9）不变。
  - 历史列表：SN 单行完整显示（1920 下约 380 px），来源 / 样本标签换到下一行；1600 px 以下允许 SN 换行，避免原因列被挤到约 100 px。
  - 历史详情、离线最近样本件、验证样本来源、批量重判：完整显示，必要时按字符断行。
  - 运行日志工件列固定 240 px，50 字符 SN 两行显示，内容列保留宽度。
  - 图像查看器标题新增可选 `caption`，标题里的 SN 用等宽；图像的无障碍名称仍用原字符串。
- 未改：诊断导出对话框只列记录号、不显示 SN；离线控制条里的运行消息是后端拼好的文字（离线 SN 固定 18 字符），已有单行省略。
- 回退：删除 `.sn` 相关样式，各处改回 `mono`。

### U-8 资料初始化窗口暂不改用令牌

- 问题：`public/storage-startup.html` 写死 9 处十六进制颜色。
- 可选项：改成 Vite 多页入口并引入 qing-steel `tokens.css`；把令牌值复制成本页 CSS 变量；保持。
- 采用：保持。该页在主界面、WebView 数据目录准备好之前显示，是 `public/` 原样复制的独立静态页，不经 Vite 处理，无法引用依赖包里的令牌；改为多页入口要改 `vite.config.ts` 与打包流程，复制令牌值仍是硬编码。其余前端样式（`src/**/*.css|ts|tsx`）已无 rgba / rgb / hsl / 十六进制字面色。
- 后续：如要统一，改为 Vite 多页入口（`build.rollupOptions.input`）并在打包测试中核对。

### U-9 默认笔刷 120 px（固定值）

- 问题：默认 80 px，实拍胶宽约 34 px；同一组笔划 80 px 有 3/36 提取失败，120 px 只有 1/36（另见 [r2-algorithm.md](r2-algorithm.md) RA-2）。
- 可选项：固定 120 px；按“胶宽上限 ÷ 当量 × 约 3”推算。
- 采用：固定 120 px。理由：示教时当量可能还没有（样本集 `mmPerPx=null`、标定未验证），推算无从下手；胶宽上限是判定容差（默认 10 mm），不是实际胶宽，按它推算会明显偏大（0.115 mm/px 时约 260 px），笔刷过宽会把邻近阴影和边缘纳入候选；固定值行为可预期，现场胶宽不同时操作员可调（6–300 px）。
- 回退：改 `TeachingPage.tsx` 的 `DEFAULT_BRUSH_PX`。

### U-10 提取失败的下一步提示

- 采用：刷选提取返回 `discontinuity`（候选边缘无法连续连接）或 `missing_edges`（未找到完整两侧边缘）时，第一次在后端原因后加一句“可加大笔刷宽度（当前 N px，约为胶宽的 3 倍较稳）后沿胶路重刷”；连续第二次仍失败，提示改用笔划直接生成再手工修正，并把该按钮设为主操作。提取成功、换相机或切换选区工具时计数清零。`ambiguous`（多条候选）与 `reversal`（笔划折返）不建议加大笔刷：前者加大只会纳入更多邻近候选，后者与笔刷宽度无关。
- 依据：后端 `reason` 代码，不解析提示文字；后端原文保持不变。
- 回退：删去 `extractionAdvice` 与 `strokeAdvised`。
