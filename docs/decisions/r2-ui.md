## 走查环境与方法

- 隔离实例：开发模式构建（`cargo build`，覆盖配置标识 `com.xyzrobotics.tujiaovision.r2ui-tests`、隐藏窗口），前端由本工作线专用 vite（端口 14352）提供；CDP 端口 9352，视口用 `Emulation.setDeviceMetricsOverride` 固定 1920×1080（另测 1440×900）。数据目录用短路径 `C:\gs-tmp\r2-ui\com.xyzrobotics.tujiaovision.r2ui-tests`（数据目录末级必须与测试标识一致；路径过长时 WebView2 不建窗口）。WebView2 有时只在 `[::1]`、有时只在 `127.0.0.1` 监听调试端口，脚本两个都试。
- 数据：进程内虚拟 S7 产线 + `2026-10-17-normal-sampleset` 副本（端到端夹具的模拟当量 0.112 mm/px 与人工断胶件 p02），本机 lyFlow 1.1.0。经 IPC 建配方、整圈采集、示教、验证、发布，离线生产 4 件（2 件 OK · 局部超差、2 件 NG · 断胶）。
- 50 字符 SN：虚拟产线的 SN 是 `OFFLINE-` 加 10 位数字（18 字符），PLC 侧 SN 点位由握手状态机管理、不能手动写入。走查时在 WebView 里包装 IPC 的 `fetch` 响应，把 `sn` / `partSn` / `resultSn` / `sampleSn` 字段和 SN 点位的当前值换成 50 字符（含连字符），只影响界面拿到的数据。逐页统计 SN 文本所在元素的宽度、是否被祖先裁切、是否有悬停全文，以及主区是否出现横向滚动。

## 决策

### U-1 全局提示放在主区顶部居中

- 问题：qing-steel 与 Material 3 的 snackbar 默认在视口底部；GlueSight 的单帧示教、默认参数、相机配置都有吸底操作栏，底部提示会盖住“运行试测”“保存本组示教”等按钮。
- 可选项：底部居中；底部右侧；主区顶部居中；视口右上角。
- 采用：主区顶部居中（距主区上沿 16 px）。原先的成功提示也出现在这一带，操作员的视线不用换位置；浮层不占布局。qing-steel 组件默认仍是底部，`.top` 为顶部变体；GlueSight 把定位层放在主区内一个零高度锚点里，随主区居中，不随页面滚动。
- 审查后修订：“工作台顶栏中段是空白”只在 1920 宽且没有待生效徽章时成立。隔离实例实测（提示宽 294–546 px）：原顶栏在 1920×1080 有“待生效”徽章与“保存失败”时，提示盖住“保存失败”徽章和“重试保存”按钮，指针移上去还会暂停计时；1440×900 下平时就盖住候选修订文字与保存状态徽章，最长的提示还压到配方选择框。改为顶栏左侧只放配方选择与发布版本，候选修订、待生效、保存状态、重试保存移到右侧“配方库”之前，提示仍在主区顶部居中。改后：1920×1080 各状态、各提示都不压顶栏任何元素；1440×900 平时 14–17 字的提示不压任何元素，更长的提示压住“已发布”徽章，有待生效 + 保存失败时压住候选修订文字（较长提示还压住部分待生效徽章）；“保存失败”与“重试保存”在两种分辨率下都不被遮挡，被压住的只有文字和徽章，没有可点的控件。
- 另比较过：顶部右侧（压住系统设置“打开资料目录”、相机页“刷新相机配置 / 添加相机”）；底部居中或左下（压住示教页“保存本组示教 / 保存并进入下一组 / 运行试测”和验证页的样本选用）。仍取顶部居中。
- 提示文字控制在一行内（约 32 字以内，最宽 560 px）：两行的提示会压到步骤条上沿。
- 回退：去掉 `SnackbarHost` 的 `top` 类即回到视口底部居中；顶栏恢复原顺序只需把 `spacer` 移回“配方库”之前。

### U-2 同一时刻一条，按文字长度自动消失，悬停暂停

- 采用：新提示替换旧提示（旧提示 120 ms 淡出，与新提示叠在同一格，不上下推挤）；时长 `clamp(3000 + 字数 × 70, 4000, 10000)` ms；指针悬停或焦点在提示内时暂停计时，离开后按剩余时间（至少 1.5 s）继续；带关闭按钮。提示层 `role="status"`、`aria-live="polite"`。只动 transform 与 opacity；减少动态效果时动画关闭，离开立即移除。
- 同一次处理里连续发出两条时也只留最新一条：通道按自己维护的当前列表让旧提示退场，不读上一次渲染的结果。
- 换配方、清空当前选择、工作台操作开始时收起当前提示，与原页面内提示的清除时机一致，上一配方或上一次操作的结果不会留到新上下文里。
- 理由：瞬时结果多为一句话；连续操作时堆叠多条会遮挡顶栏且没有新信息。
- 回退：`src/components/Snackbar.tsx` 中 `show` 不再 `retire` 旧条目即可改为堆叠。

### U-3 哪些提示进全局提示

- 进全局提示（瞬时的操作成功）：工作台 `act` 的成功消息（保存候选、选图、保存示教、记录标定验证、采用 / 保存采集轮次、导入样本组、验证完成、提交 / 重试 / 放弃发布、绑定历史原图、保存总览、写入曝光增益）；PLC 配置已保存；一期 S7 点表已载入草稿（info 色，页面另有“未保存”徽章）；系统设置两个分区保存；工位标定完成（结果另在“当前标定”行持续显示）。
- 留在页面内：所有错误；需要用户处理的提示（候选未保存、参数无效、待生效 / 生效失败 / 状态不确定、需重新采集等）；带后续操作的结果（历史导出 CSV 的“打开所在文件夹”、诊断包导出结果在对话框内）；相机配置保存栏内的“已保存并应用 · 时间”（保存栏里的状态文字，替换原文字，不推动布局）。
- “已记录标定验证：误差超出 ±0.1 mm，未通过”用警告色全局提示，因为它是一次已完成的记录操作，未通过状态在右侧“标定”卡持续显示（徽章“验证未通过”、卡片展开）。
- 勾选复用但没有复用到任何拍照点：警告色全局提示“未复用：没有同相机、同图号、设备与标定一致且未单独设当量的拍照点”，不用成功色。当前图的记录已完成；其他拍照点仍缺验证的状态持续显示在各自的“标定”卡徽章、步骤条“标定待验证”和进度总览的阻塞项里。
- 回退：对应页面恢复 `notice` 状态与页面内提示条。

### U-4 候选配置自动保存不弹提示

- 问题：原来自动保存候选配置也走“候选配置已保存，生产版本保持不变”，默认参数页每停顿 0.9 s 就插入一次提示。改成全局提示后仍会频繁弹出。
- 采用：自动保存静默，状态看顶栏徽章（等待保存 / 保存中 / 草稿已保存 / 保存失败）；点“保存候选配置”按钮仍提示。
- 回退：`context.tsx` 自动保存分支改回调用 `saveDoc()`。

### U-5 GlueSight 不引入 qs-motion.js

- 问题：qing-steel 的 `QingSteel.snackbar()` 直接操作 DOM；GlueSight 其余动效（侧栏、选择轨道）都是 React 自行实现，没有引入 qs-motion.js。
- 采用：GlueSight 用 React 实现同样的时序与时长规则（`snackDuration` 两边一致），只复用 qing-steel 的样式类。qs-motion 的实现给非 React 页面和演示页使用。
- 回退：无。

### U-6 qing-steel 依赖固定到 PR 提交

- 采用：只有 `feat/ui-global-snackbar` 修改 `package.json` / `pnpm-lock.yaml`，固定到 qing-steel PR 提交 `8d5701a`。qing-steel PR 合并并打 `v0.4.0` 标签后，依赖改为 `github:liangyuR/qing-steel#v0.4.0`。其余 GlueSight PR 只用 0.3.0 已有的令牌。
- 回退：依赖改回 `#v0.3.0`（全局提示会失去样式）。

### U-7 SN 显示：列表与详情完整显示，固定高度处单行

- 问题：交互表把 SN 改为最多 50 字符（plc-table §6），各页按 24 字符时代的宽度设计。
- 可选项：处处单行截断加悬停；处处换行；按位置区分。
- 采用：按位置区分。新增 `.sn`（等宽、表格数字、`word-break: break-all`，断行时整行填满，不在连字符处提前断开）。
  - 生产页顶栏 SN 芯片：单行，最宽 480 px，放得下 50 个等宽字符；更窄的屏幕省略并悬停显示全文。判定卡标题在 420 px 右栏放不下“判定结果 · SN + 50 字符”，单行省略、悬停全文（顶栏芯片已有完整 SN）。判定卡固定高度（ui-shell §9）不变。
  - 历史列表：SN 单行完整显示（1920 下约 380 px），来源 / 样本标签换到下一行；1600 px 以下允许 SN 换行，避免原因列被挤到约 100 px。
  - 历史详情、离线最近样本件、验证样本来源、批量重判：完整显示，必要时按字符断行。
  - 运行日志工件列固定 240 px，50 字符 SN 两行显示，内容列保留宽度。
  - 图像查看器标题新增可选 `caption`，标题里的 SN 用等宽；图像的无障碍名称仍用原字符串。
- 未改：诊断导出对话框只列记录号、不显示 SN；离线控制条里的运行消息是后端拼好的文字（离线 SN 固定 18 字符），已有单行省略。
- 回退：删除 `.sn` 相关样式，各处改回 `mono`。

### U-8 资料初始化窗口暂不改用令牌

- 问题：`public/storage-startup.html` 写死 9 处十六进制颜色。
- 可选项：改成 Vite 多页入口并引入 qing-steel `tokens.css`；把令牌值复制成本页 CSS 变量；保持。
- 采用：保持。该页在主界面、WebView 数据目录准备好之前显示，是 `public/` 原样复制的独立静态页，不经 Vite 处理，无法引用依赖包里的令牌；改为多页入口要改 `vite.config.ts` 与打包流程，超出本工作线（展示层）范围，复制令牌值仍是硬编码。其余前端样式（`src/**/*.css|ts|tsx`）已无 rgba / rgb / hsl / 十六进制字面色。
- 后续：如要统一，改为 Vite 多页入口（`build.rollupOptions.input`）并在打包测试中核对。

### U-9 默认笔刷 120 px（固定值）

- 问题：默认 80 px，这批胶宽约 34 px；算法评测（algorithm A-2）同一组笔划 80 px 有 3/36 提取失败，120 px 只有 1/36。
- 可选项：固定 120 px；按“胶宽上限 ÷ 当量 × 约 3”推算。
- 采用：固定 120 px。理由：示教时当量可能还没有（样本集 `mmPerPx=null`、标定未验证），推算无从下手；胶宽上限是判定容差（默认 10 mm），不是实际胶宽，按它推算会明显偏大（0.115 mm/px 时约 260 px），笔刷过宽会把邻近阴影和边缘纳入候选；固定值行为可预期，现场胶宽不同时操作员可调（6–300 px）。
- 回退：改 `TeachingPage.tsx` 的 `DEFAULT_BRUSH_PX`。

### U-10 提取失败的下一步提示

- 采用：刷选提取返回 `discontinuity`（候选边缘无法连续连接）或 `missing_edges`（未找到完整两侧边缘）时，第一次在后端原因后加一句“可加大笔刷宽度（当前 N px，约为胶宽的 3 倍较稳）后沿胶路重刷”；同一组连续第二次仍失败，提示“常见于胶堆、断胶等局部异常，请点「笔划直接生成中线」再手工修正”，并把该按钮设为主操作（“自动提取中线”降为次按钮）。提取成功、换组或切换选区工具时计数清零。`ambiguous`（多条候选）与 `reversal`（笔划折返）不建议加大笔刷：前者加大只会纳入更多邻近候选，后者与笔刷宽度无关。
- 依据：后端 `reason` 代码，不解析提示文字；后端原文保持不变（`centerline.rs` 属于 r2-algorithm）。
- 实测：隔离实例中 S011 组（样本 S032，中段胶堆）按算法夹具笔划刷选，120 px 报“无法连续连接”并给出加大笔刷提示；加到 180 px 仍失败，提示改用笔划生成，按钮变为主操作。
- 回退：删去 `extractionAdvice` 与 `strokeAdvised`。

### U-11 无要检拍照点时胶路示教比例返回 null

- 问题：`workspace.rs` 的 `coverage()` 在没有要检拍照点时返回 100，前端只好按拍照点数自行显示“—”；全部拍照点被设为不检时前端仍显示 100%。
- 可选项：返回 0；返回 null。
- 采用：null。0% 会被读成“一个都没示教”；没有要检拍照点时比例没有意义。只涉及视图计算；发布前检查的“胶路示教”通过时本来恒为 100%，明细去掉百分比，不牵涉业务规则。
- 回退：`coverage()` 改回 `f32` 并在无拍照点时返回 100。
