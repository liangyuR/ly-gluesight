## 一、上线前必须处理

1. **PLC 方提供**（协议 8 第十一节）：
   - 机械臂信号 `partType`、`sn`、`PartArrived`、`CaptureActive`、`PartDone` 的接口形式与地址；
   - “记未检 / 记 NG / 记检测错误”的去向（HMI、输出位或 MES）；
   - Line0 输出点与三台相机的接线；
   - DB4、DB2 在现场工程中的块号；
   - CPU 型号与固件，确认已允许 PUT/GET 访问。

   另外，机械臂从工件到达到拍照信号置 1 之间须留 ≥ 2 s，让 PC 在采集前读到请求并完成接件登记（协议 8 第十节）。
2. **真机验证**：以下都还没有验证，各项验证只基于进程内虚拟 S7、合成图三相机与样本集回放。
   - 协议 8 的现场 PLC 联调，机械臂信号接口，Line0 门控与三台相机接线，现场节拍；
   - 接件登记的实际耗时：专机上用真机 PLC 与相机核对“接件阶段”日志的 `elapsedMs`，确认加上 PC 发现请求的时间后仍小于现场到达到拍照信号的间隔；
   - **3 × 25 Hz 吞吐门槛**：没有达标，也没有被直接验证。门槛口径不改，在现场工控机用真实相机来源做持续生产压测 并重跑 `throughput_probe` 探针后，再决定降帧率还是加测量并发（[segment-burst.md](segment-burst.md) 第七节、第九节第 14 条）；
   - **分段算法**：已实现按各段 N_exp 比例分段和边界过渡区；现场边界误差仍须用量产曝光与速度下、已确认手动分段的三相机序列评估，图像运动细化尚未实现（segment-burst D-SB-40、D-SB-43）；
   - 弯道帧走出走廊的判据（默认做法 4）没有真实弯道图验证。
3. **真机标定**：样本集没有标定，模拟当量只用于打通业务链路。段配方读设备标定 `calib/device/plane_calib_{device}.json`，只存过 `{device}-v1` 的单视角相机要在标定页重新标定一次（D-SB-30）。胶宽限值在真机标定后按正常件统计复核（[r2-algorithm.md](r2-algorithm.md) RA-5）。

## 二、需要用户决定

| 事项 | 现状 | 文档 |
| --- | --- | --- |
| 吞吐门槛复测后的取舍 | 现场工控机真实相机复测后，在 ① 降相机帧率（各段 N_exp 随之变，须按新帧率的示教件重新分段）与 ② 加测量并发（开发机 4 物理核，4 → 6 线程增益有限，需改代码重测）之间选 | segment-burst 第七节、第九节第 14 条 |
| 逐帧定向与工件边胶偏 | 已实现，新建的段默认开启逐帧定向、工件边胶偏默认不用：每帧以出胶点为锚找胶条方向，只测距出胶点 s₀ 到 s₀ + L 的固定窗口；按段开关，沿用现有走廊示教（D-SB-47）。胶偏以工件边为参考、实现 `ToEdge`，参考值取图纸胶边距或测量示教件得出的值（D-SB-48）。生产开启 D-SB-47 前须用实际涂胶、画面里有胶嘴的轮次复测 | segment-burst D-SB-47、D-SB-48 |
| 段配方的待确认取舍 | 提前结束不加标记、不判 ERR，可能出现 PLC 记未检而 PC 记 OK；气泡、拉丝不检 | segment-burst 第三节、D-SB-15、D-SB-34、D-SB-37 |
| lyFlow 与 GlueSight 分工 | 草案：算子只测量、判定归 GlueSight；业务参数存配方，算子与判定门限一律取测量图模板默认、配方不存。P1 不改 lyFlow，先把写死的门限改为参数并显示诊断输出；P2 改为图模板；P3 配合 lyFlow 1.2 拆算子。方向已确认、实施中，不迁移旧配方，流程调试页嵌入 lyFlow 编辑器（锁拓扑、只临时调参数试跑） | lyflow-operators |
| 运行日志容量 | 1 GB 上限在每天数千件时只能保留几天。建议提高到 4–8 GB，或超限时先删旧分段的 debug 行；`plc.db` 没有容量上限 | r2-records R-6 |
| 胶宽上限与帧内累计超差 | 保持默认（上限 5.5 mm、累计允许 5 mm）。实拍正常件在起点、胶堆、拐角处常有 5.3–6 mm 的段落，需现场按产品复核每帧累计超差长度；直线 / 弯道可分别调 | r2-algorithm RA-5、segment-burst D-SB-16 |
| 维护模式一期未做事项 | 找不到配方的件不录图；`plc.earlyEnd` 未写；采集占用空间未统计 | maintenance-mode “一期未做” |
| 历史件导入的限制 | 采集版件识别不了提前结束；硬链接要求同卷；只列最近 200 件 | maintenance-mode “二期未做” |

## 三、已按建议实现的取舍

| 事项 | 采用 | 文档 |
| --- | --- | --- |
| 计划模型 | 段列表 + 三台独立单视角相机；没有段的配方文件读入时报“旧拍照点配方已停用”，代码已删除 | segment-burst D-SB-1、D-SB-11 |
| 多段配方的发布与运行 | 示教件确认手动分段后各段 N_exp 取其帧组数，各段都有 N_exp 才能发布；生产按预测段测量，收尾后按比例分段补测与判定，帧数只核对整件 | segment-burst 第二节、D-SB-40、D-SB-45 |
| 缺帧、帧数、丢帧 | 某台相机缺帧只把该帧组标检测不完整；不核对帧组数、不记帧数告警，提前结束不另加标记；丢帧只告警；都不改 OK/NG。只有三台相机整件一帧都没测成才判 ERR 91 | segment-burst D-SB-2、D-SB-3、D-SB-13、D-SB-34 |
| 接件校验顺序 | 先核型号（95），再看配方能否编出计划（100）；不能检测的件照常运动，工件结束后回 90 与故障码 | core-flow D-CF-4 |
| PC 主动断开 | 3.5 s 后自动重连一次，重连后按 R2P-9 自动复位；仍确认不了置故障就停在断开等人工 | r2-plc R2P-3 |
| 复位 | 待复位或故障时，复位条件满足就自动复位，不论原因、有无在途件；连续 3 次后至少间隔 30 s；人工、PLC 复位信号、PLC 置 99 照常可用 | r2-plc R2P-9 |
| 维护模式 | 按件锁存、结果码 0、不能检测的件也回 0、采集件只录图 | maintenance-mode MM-1–MM-4 |
| 历史件导入 | 硬链接物化、round.json 3 与 `origin`、不要求空闲 | maintenance-mode HI-1–HI-7 |
| 进程中断的在途件 | 重启时补一条 ERR 98 历史记录，按开工时的来源记录 | r2-records R-4 |
| 握手审计保留 | 4 MB 滚动，30 天 / 256 MB 清理，保留未结交付需要的分段 | r2-records R-5 |
| 首启配方库 | 不写入样例配方；新建配方的模板是段配方 | core-flow D-CF-8、segment-burst D-SB-24 |
| 检测默认参数 | 不变（搜索半宽 15 mm、胶宽 1–10 mm），现场按产品收紧 | algorithm A-8 |
| 示教默认笔刷 | 固定 120 px；彩色帧刷选按胶色吸附并连同胶色保存，失败时按原因引导重刷，连续失败改用笔划生成 | r2-ui U-9、U-10 |
| 笔刷提取的胶极性 | 两种都试，明显更多站成立的先试，相近时先按配方极性 | r2-algorithm RA-6 |
| 矩形框选提取 | 「顶帽找胶 → 笔刷提取对中」 | r2-algorithm RA-1 |
| 全局提示 | 主区顶部居中，同时只显示一条；只放瞬时的成功提示，错误留在页面内 | r2-ui U-1–U-3 |
| 局部超差的颜色 | 统一用警告色；未测成和设备故障用故障紫，与 NG 红分开 | ui-shell §4–5 |
| 生产页判定字号 | 80 px，右栏 420 px | ui-shell §6 |
| 历史复测时调整分段 | 历史详情“调整分段”在同一窗口打开候选的分段页并定位到对应示教件帧组；返回时恢复件、相机、帧组、复测配方、对照与滚动位置，不自动复测 | ui-recipe D13 |
| 相机页设计稿的 9 个问题 | 2 项已实现，7 项维持现状 | ui-recipe 相机页一节 |
| 运行日志保留 | 按日滚动，单个分段 16 MB，保留 30 天，总量上限 1 GB | log-replay §3 |
| 资料盘下限 | 剩余空间低于 2 GB 时告警、新件不录原图，照常检测；恢复后自动恢复录制 | soak S-7 |
| 追溯记录 | 尽力而为：存不下只告警、不挡生产、不需重启；结果不等落盘即回 PLC；无法恢复的 spool 文件移到 `.unrecovered/` 待人工核对 | soak S-8 |
