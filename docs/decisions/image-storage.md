# 原图存储与计算决策记录（image-storage）

生产原图的保存方式、占用空间与图像计算共享的取舍。目标是全部件的原图都保存，在线采集与检测不受影响。

## IS-1 录制线程只写未压缩原图

- 问题：一件约 570 帧、每帧 1.3 MB，约 0.7 GB。在录制线程里即时压缩能省空间，但编码与逐帧同步落盘、检测争用 CPU，持续采集下的队列与丢帧没有验收依据。
- 可选项：A 录制时即时压缩；B 录制写未压缩原图，压缩放到件收尾之后。
- 采用：B。录制每帧写带 `# bayer` 注释的原始 PGM 并同步落盘，写后核对；项目导出、复制、发布和冻结示教图也按原字节保存，不压缩，包格式不变。
- 回退：无数据迁移；没有产生过压缩原图。

## IS-2 件收尾后在空闲时无损压缩

- 问题：要保存全部件，占用只能靠无损压缩和磁盘容量解决。
- 可选项：A 超过 30 天再压缩；B 件收尾并校验后，空闲时即可压缩；C 改存 PNG。
- 采用：B。压缩无损、带校验，读取透明解压，近期件的复测与示教不受影响。A 让占用最大的近期数据全部不压缩，而更早的原图多半已被滚动清理。C 的体积与采用的编码接近，但编码更慢，Bayer 相位没有标准位置，普通看图软件打开看到的仍是马赛克灰度图。
- 依据：240 帧 1280 × 1024 彩色录制原图（一轮三相机采集，Python 实测，单线程）。无损压缩只能省三到四成，全部保存的容量主要靠磁盘。

  | 编码 | 体积 | 编码耗时 |
  | --- | --- | --- |
  | Zstandard level 1 直接压缩 | 72.5% | 2.0 ms/帧 |
  | 拆四个同色平面 + Zstandard level 1 | 72.6% | 2.6 ms/帧 |
  | 拆四个同色平面 + 行内差分 + Zstandard level 1 | 63.5% | 4.8 ms/帧 |
  | PNG 灰度 | 65.2% | 8.6 ms/帧 |

  level 3 与 level 1 的体积相差不到 0.5 个百分点。
- 开关：设置页“空闲时压缩历史原图”，本机设置（`config/history.json` 的 `idleCompress`），默认关闭；现场真机持续生产下的表现尚未验证。
- 文件：`X.pgm` 压缩后是同目录、同主名的 `X.gsr`，原文件删除；记录库、`part.json` 与采集轮次里记的文件名仍是 `X.pgm`。`.gsr` 依次是固定头 16 字节（魔数 `GSR\x1a`、版本 1、变换标识、PNM 文件头长度、像素字节数、原文件全部字节的 CRC-32，小端）、原 PNM 文件头的原字节（含 `# bayer` 注释）、一个带内容校验和的 Zstandard level 1 帧，能逐字节还原出原文件（`src-tauri/src/image_file/gsr.rs`）。
- 变换：带 Bayer 注释、宽高都是偶数的 8 位 P5，把马赛克拆成 (0,0)、(0,1)、(1,0)、(1,1) 四个同色平面，每个平面按行对左邻像素取差（模 256）；灰度 P5、P6 与宽或高为奇数的 Bayer 直接按行对左邻同通道像素取差。不是 8 位 P5 / P6、像素之后还有多余字节或压缩后不比原文件小的文件不压缩。
- 读取：统一读图入口（`image_file.rs`）在 `X.pgm` 不在时读 `X.gsr` 并还原，两者都在时用 `X.pgm`；历史查看、复测、选作示教件、示教、诊断包都经它读。压缩文件截断、带多余数据、缺校验和、校验不符、头与像素长度不一致或超过 256 MiB 时按读图失败处理。历史件导出包、项目导出包与项目复制把 `.gsr` 还原成原始 `.pgm` 字节带走，包格式不变。`scripts/gsr_raw.py` 供读录制目录的 Python 脚本使用。
- 对象：记录库里录制完整、原图可用的真机件（本机全部项目，含维护采集件与被示教、标定引用的件），录制目录已收尾（有 `part.json`、不在 `_pending`）、不是导入暂存或未提交的导入件。
- 空闲：没有在途工件与未结 PLC 事务，录制队列为空，没有待入库的录制，没有进行中的任务（复测、示教测量、导入导出、诊断导出、记录清理与删除、项目删除），且最后一次业务活动（含读原图、录制写盘）之后连续满 60 秒。每帧之前重新检查，业务一恢复就不再开始下一帧。压缩线程是后台优先级，不持有锁；清理、导出等任务登记时等它做完手上这一帧。
- 单帧：读 `X.pgm`，编码，写 `X.gsr.tmp` 并同步落盘，读回解码并与原文件逐字节比较，改名为 `X.gsr`，删除 `X.pgm`。任一步失败保留 `X.pgm`、删除临时文件并记告警，下一轮扫描再试；一件里失败 3 帧就停下这一轮。处理一件之前先收拾中断残留：`.gsr.tmp` 删除；`X.pgm` 与 `X.gsr` 并存时，`X.gsr` 能还原出相同字节就删 `X.pgm`，否则删 `X.gsr`。不压缩的帧记在内存里，本次运行不再重试。
- 日志：运行日志的“原图空闲压缩”，状态变化（运行、因业务暂停、已关闭、出错、本轮扫完）各记一条，每件压缩完记一条帧数与前后大小。
- 实测：本机一件 1280 × 1024 彩色录制（三相机，每三帧取一帧共 286 帧，357.5 MB），Rust release 构建单线程。

  | 项目 | 结果 |
  | --- | --- |
  | 体积 | 64.2%（357.5 MB → 229.7 MB） |
  | 编码 | 2.8 ms/帧 |
  | 解码 | 2.4 ms/帧 |
  | 压缩一帧（含同步落盘、读回校验、替换） | 9.6 ms/帧 |

## IS-3 滚动清理先删合格件

- 问题：超出件数或容量上限时按时间从旧到新删除，不区分判定；磁盘不足时较旧的 NG、ERR 件先于较新的合格件被删。
- 可选项：A 按时间一刀切；B 先删合格件；C 不合格件完全不参与滚动清理。
- 采用：B。最新一件总是保留；其余的件先算不合格件、再算合格件（OK 与 OK_WITH_EXCURSION），各自从新到旧累计件数与字节数，超出上限的删除。合格件删完仍超限时才删最旧的不合格件，所以上限仍是硬上限（C 在不合格件多时会写满磁盘）。结论取自录制目录名 `{时间戳}_{结论}_cycle_{cycleId}`，不读 `part.json`、不查库；认不出结论的目录按不合格算。现有保护（最新一件、在用、待入库、维护采集、被示教或标定引用）不变，按天清理不变。
- 回退：回滚该提交即恢复按时间清理，已删除的原图不会恢复。

## IS-4 不做分块存储与冷热两种表示

- 问题：是否把原图合并进定长分块文件，并为同一资产维护未压缩与压缩两种表示。
- 采用：不做。清理按件删除整个录制目录，跨件的分块只能在停产时压实，生产期间空间收不回来；生产帧各不相同，按内容去重没有收益。一件一个目录、一帧一个文件的布局保持不变，录制盘之间搬移沿用按记录目录找盘的规则。

## IS-5 同帧 RGB 结果共享（待实现）

- 问题：彩色模式下 RGB 每帧 3.75 MiB，每台相机 256 MiB 的预算只放得下 68 帧，原始 Bayer 另占同额的独立池；去马赛克在取图路径上完成。
- 采用：相机回调只做校验、复制进有界缓冲与分发；去马赛克移到计算线程，同一帧的 RGB 结果由检测、预览共享，灰度与缩略图按需生成并计入同一内存预算。颜色算法与测量数值口径不变，先验证算法输入逐字节一致。
