# 配方构建流程：示教件与标定件（RB）

状态：RB-1～RB-8 于 2026-10-28 用户确认，已实现（原生端到端未跑）；[RB-9 工件胶路导航图](#rb-9-工件胶路导航图)已实现，现场导航精度未验证。RB-1～RB-8 修订 [segment-burst](segment-burst.md) D-SB-44、D-SB-45、D-SB-49、D-SB-51 与 [maintenance-mode](maintenance-mode.md) HI-5 中涉及采集轮次页的部分；业务行为见 [配方创建流程](../architecture/recipe-creation-workflow.md) 与 [在线投运](../architecture/online-commissioning.md)。

## 问题

- D-SB-49 删除整圈示教采集后，采集轮次页只剩“从历史选用”导入，实际作用是初步筛选历史件；但用户必须先导入成轮次，才能看图、才能决定这一轮拿来做什么。
- “轮次”贯穿全流程，同一概念承担几种需要数量差别很大的用途：分段模板轮（1 轮）、走廊示教帧来源（每段可来自不同轮次，实际 1 轮就够）、多轮标定（≥ `calibrationRounds` 轮）、标准件（x_ref）。
- 同一轮的整理分散在三处：采集页做屏蔽与数字边界，段列表页“其余轮次复核”确认边界，标定页加入、移出。操作员要在页面间来回，才能把一轮变成可用的标定数据。

## RB-1～RB-8 已定（用户确认）

- **RB-1 示教件**：每个候选恰好一件示教件，从历史件中选取。分段边界、全部（段, 检测相机）的走廊示教帧都只来自示教件，不允许某段改用其他件。示教件即原“分段模板轮”，两个概念合并。
- **RB-2 换示教件即清空**：更换示教件时，凡由示教件图像得出的内容全部失效并直接清空，不按图像对齐迁移：示教件边界与其余各件的已确认边界、全部走廊与示教帧、全部标定件及标定派生结果（各段 N_exp、标定统计、`partCalib`、x_ref）。段列表结构（段的数量、顺序、类型、检测相机、检测项与容差）与配方级参数保留，新示教件进入分段步骤时以现有段结构按比例给出初始边界，须重新确认。
- **RB-3 示教件也是标定件**：示教件的边界在分段步骤已确认，自动计入标定件，算入 `calibrationRounds`；加入标定要用已示教的走廊测量每帧，所以在走廊示教完成后、多轮标定页同步标定件时由软件加入；不能单独移出标定（要移出只能换示教件）。示教件不能标为标准件。其余标定件在多轮标定页另选，凑足轮数。两者只差在用途：示教件提供图像（分段与走廊），标定需要多件统计各段帧数的波动，一件得不出 N_exp 的均值与容差。
- **RB-4 轮次对界面隐藏**：界面上不再出现“采集轮次”、轮次编号与轮次列表；用户面对的是历史件（时间、SN、模式），在用到时由软件导入。轮次仍是存储格式（`recipe-capture/` 下的 `round.json` 3 与 `origin`），日志 `op.capture.import` 照记。
- **RB-5 旧候选停用**：现有候选不迁移。候选文件加流程版本，旧版本候选在配方库标“旧流程候选，已停用”，不能打开、编辑或发布，由用户在配方库自行删除，软件不自动删除、不统一弹窗；删除时连同它导入的轮次一并删除。生产配方与发布包不受影响，照常运行；同一配方编号的旧候选删除后，可从生产配方新建新流程候选。
- **RB-6 导入前预览**：历史件在导入前即可按相机、帧组浏览原图（只读，直接读录制目录），看过再决定选用。
- **RB-7 版本辨认**：靠两处标记辨认配方是怎么建的，都不改配方 `schemaVersion`（仍为 8，改了会使现有生产配方加载失败、必须重建）：
  - 候选的流程版本 `flow`：新流程候选为 2，缺省即旧流程；RB-5 按它判定旧候选。
  - 配方的示教件来源：发布时把示教件来源（历史件的时间、SN、`cycleId`）写进配方文档的可选字段，随生产配方与发布包保存。配方库卡片显示“示教件：时间 · SN”，工作台“配方信息”显示当前示教件；没有这个字段的生产配方即旧流程发布，照常运行。
- **RB-8 改版候选也清空**：从生产配方新建的候选（改版）继承段列表结构与配方级参数，但不继承图像派生内容：首次设示教件时同样按 RB-2 清空各段 N_exp、标定统计、`partCalib`、x_ref 与继承的走廊，每次改版都在新示教件上重新示教、重新标定。没有示教件之前候选不能发布（发布前检查“示教件”）。

## 采用

### 步骤与页面

进度步骤为 示教件 → 分段 → 走廊示教 → 多轮标定 → 发布。步骤 ID 与路由沿用（`capture`、`/recipe/capture`），标签改为“示教件”，减少改动面。

| 步骤 | 行为与完成条件 |
| --- | --- |
| 示教件 | 历史件选择器（单选）：本配方最近的真机录制件，列时间、SN、模式、帧组数、各相机帧数、时长 / 实测帧率（设定）、原图是否完整、不可用原因与提示（现“从历史选用”的列）；选中一行在旁边预览原图。“设为示教件”导入并记入候选；已有示教件时先列出 RB-2 将清空的内容，确认后才替换。完成条件：有示教件 |
| 分段 | 现分段标定工作台，模板轮固定为示教件，不再选轮次。保存即确认示教件边界。段参数编辑不变。“其余轮次复核”移到多轮标定 |
| 走廊示教 | 示教帧只在示教件本段的帧组里选，去掉轮次选择与“重新采集”入口；其余不变（D-SB-45、D-SB-47、D-SB-48） |
| 多轮标定 | 历史件选择器（多选，可勾“标准件”）选标定件（`workspace_calibration_pick`，须先有示教件），确认后软件依次：导入 → 同步（`workspace_calibration_sync`）：把示教件边界对齐到该件（D-SB-51 的可信判据；单段配方不对齐，直接确认）→ 全部可信则自动确认，走廊示教已完成时测量并加入标定，否则列入“待复核”并写明原因。待复核的件在本页逐边界确认（原“其余轮次复核”的交互）后再同步加入。改了屏蔽范围后点“同步标定件”重新加入；加入后改了走廊、当量或检测参数（标定件记录的走廊身份与当前不同）时，同步把这些件移出标定、清除派生标定结果并重测加入。帧组屏蔽与恢复、弃用（`workspace_calibration_remove_round`）、逐帧查看都在本页。顶部显示“标定需要 N 件（含示教件，不含标准件），已加入 M 件”。应用标定、确认容差、起涂收尾建议不变 |
| 发布 | 发布前检查加“示教件”一项。独立验证样本不得是已用于走廊示教的示教件或已加入标定的件 |

### 历史件选择器

- 一个组件，两种模式：示教件页单选，标定页多选并带标准件标记。数据沿用 `history_candidates` 的可用条件（HI-1～HI-8）；`HistoryCandidate.usage`（`teaching` / `calibration`）非空的件标“已使用”，不能重复选，不可用原因写“本候选已选用这一件”，不露出轮次编号。
- 预览沿用历史页的只读接口 `workspace_record_frame_image`（按记录、计划相机与帧组读录制原图）；不写候选，不占配置锁。
- 不可用原因在勾选框悬停与原因列都显示。

### 候选与配方数据

- 候选（`workspace.json`）新增：流程版本 `flow: 2`，表示按本决策的步骤建的候选，字段缺省即旧流程。它只标候选的建法，与配方文档的 `schemaVersion`（生产配方与发布包的文件格式，仍为 8）无关；生产加载与发布包都不读它。
- 候选另新增 `teachingPiece`：示教件的轮次 ID 与来源历史件（`roundId`、`cycleId`、`recordId`、SN、时间）。`captureReview.template` 在分段保存时设为示教件，对齐以示教件已确认的边界为准，界面不再读它。`workspace_set_teaching_piece` 设示教件（导入、按 RB-2 清空、删除原示教件与标定件的轮次；验证样本库引用的轮次不删；同一件重复设置报错）。
- `WorkspacePlanView.pieces`：示教件与标定件（角色 `teaching` / `calibration` / `standard`、来源记录、复核状态与确认方式、是否已加入标定、屏蔽数），示教件在前。
- 配方文档新增可选字段 `teachingPiece`（`cycleId`、`recordId`、SN、时间），发布正式版时从候选写入（RB-7）；候选文档里恒为空（新建与保存时都清掉，不从生产配方继承、不接受前端回传）。不进计划身份，不换计划版本，生产加载不需要它；配方 schema 仍为 8。`recipe_list` 的配方摘要同样带 `teachingPiece`。
- 旧流程候选：`workspace_get` 与所有修改命令报“旧流程候选已停用：请在配方库删除后重建”；启动时自动选配方跳过它。删除旧流程候选只删候选与 `recipe-capture/` 下该编号的全部轮次，保留生产配方与发布归档；删除新流程候选照旧连同同编号的生产配方一起删除，也连带其轮次。
- 走廊示教的选帧、保存与试测（`workspace_teach_segment_corridor`、`workspace_teach_preview_*`）都要求帧来自示教件，否则报“示教帧只能取自示教件”；`workspace_capture_review_confirm_cuts` 对示教件报错（示教件边界只在分段确认）。

### 删除的界面与命令

- 采集轮次页（`CapturePage`）：采集结果面板、采集历史下拉、轮次规则说明、实时采集状态文案、“设备实拍 / 离线模拟”标记；由示教件页（`TeachingPiecePage`）取代，“从历史选用”（`HistoryImportPanel`）由 `HistoryPicker` 取代。
- 轮次整理（`CaptureReviewPanel`）的数字边界输入、按比例 / 原帧号套用模板、设为模板；帧组屏蔽移到多轮标定页（`PieceMask`）。D-SB-44 的“回退：采集页轮次整理”一并作废。
- 段列表页的“其余轮次复核”与其轮次列表（迁到多轮标定，逐件复核）。
- 命令：`workspace_history_import`、`workspace_calibration_add_round`、`workspace_capture_review_save`、`_confirm`、`_set_template`、`_apply_template`、`_auto_confirm`（被同步取代）。
- 旧轮次读兼容（D-SB-49：格式 2 带 `teachingRoundId`、失败状态变体）保留：旧流程候选删除前它们仍在磁盘上，项目导入也可能带入。

### 手动配置数据（`capture_fixture`）

`capture_fixture` 改为生成仿历史录制件，不再直接写轮次（`src-tauri/src/history_fixture.rs`）：按录制时生效的生产配方（采集版）用库里的 `Recorder` 写与真机同格式的录制目录（`part.json` 带 `partMode`、`devices`、`plc` 与来源标记 `fixture: {label}`，原图 `{相机}_s{seq:06}.pgm`），并用记录库现有接口写对应的 `parts` 行（模式为维护采集，不进当日统计；SN 前缀 `FIXTURE-`；库版本不变）。这样选择器只有历史件一个来源，端到端与长稳测试走与现场相同的选件、导入路径。`HistoryCandidate.fixture` 带来源标签，选择器标“手动配置”；历史页按 SN 前缀辨认，不另加标记。轮次的 `origin.kind = prepared` 不再产生，已有的照常读取。

记录引用采集版的修订号，所以脚本先建候选、发布采集版，再生成数据：候选的版本号留给之后的正式版，若仿历史件用它写快照，正式版投产时同修订号的真实记录会因快照不同被记录库拒绝。这与现场先发采集版、再维护采集的顺序一致。

## 理由

- 示教只需要一件的图像，标定需要多件的帧数统计，按用途选件比先导入一批再分派更直接；“只来自示教件”让分段、走廊、标定共用一套边界基准，去掉“示教帧来自哪一轮”“模板轮是哪一轮”这类状态，代码与校验都更简单。
- 换示教件直接清空，避免跨件迁移走廊与边界带来的隐性误差；代价是重做示教，换件本应少见。
- 对界面隐藏轮次后，用户只认得历史件，和在线检测页、历史页用同一身份（时间、SN）。

## RB-9 工件胶路导航图

状态：2026-10-28 已实现；首版不做相机偏移，地图在候选里编辑，发布时冻结为独立辅助资料。软件定向回归与浏览器交互验证不替代现场导航精度验收。

### 目的与范围

固定相机每帧只看到胶嘴附近的局部，工件移动和转动后难以从示教帧辨认整件位置。增加一张完整工件图，在图上沿胶路标出段及当前帧组的估计位置，用于选帧、理解段顺序和辅助人工确认边界。

- 首版只接入分段工作台和走廊示教页，共用地图显示与导航组件；不增加必经流程步骤，没有地图仍能示教、标定和发布。
- 图片只作示意资料，建议使用接近正上方拍摄、轮廓清晰的整件图；支持透明背景图片，透明与否不影响映射。
- 不做局部帧到整件图的图像配准、全景拼接、自动描胶路或机器人轨迹接入；不参与测量、分段算法、OK/NG 判定、PLC 通讯或计划身份计算。
- 首版不做相机偏移标定。三台相机共用当前帧组的估计位置，同一帧组切换相机不增加位置偏移；界面称“帧组估计位置”，不称“相机视野中心”或“精确胶嘴位置”。相机在工位中固定，并不保证工件转动后沿胶路的偏移固定；用帧数表示偏移还会受速度影响。

### 地图编辑与空间分段

1. 在候选内导入工件图，复制成项目内受管资源；保存后不依赖导入来源文件。图片更换或裁切会改变标注坐标基准，不能直接沿用已确认的空间对应。
2. 沿胶路画有序折线，明确起点和机器人的涂胶方向，显示方向箭头。闭合胶路也必须指定起点，以有方向的展开弧长区分首尾；同一像素位置可以对应首段或末段。
3. 标记实际采集范围的起止点。当前协议起头、收尾不拍，不能默认第一帧就是起涂点、最后一帧就是胶路终点。首版支持沿涂胶方向的一段连续采集范围，闭合胶路跨起点时按展开弧长表示；采集范围外画灰色，不支持跳帧。
4. 按当前 K 段的顺序，在采集范围内标 K−1 个空间分界点，与段列表逐段对应。空间边界必须严格沿路径递增，不允许零长度段；单段只需采集起止点。段类型沿用段列表，地图不根据折线形状推断直线或弯道。
5. 空间标注与帧边界分别保存、分别确认。拖动地图分界点只修改地图，不能自动移动示教件帧边界；修改帧边界也不能自动移动空间分界点。地图帮助人工对照，不作为边界正确性的验证证据。

地图视图支持缩放、平移、左右旋转 90°、任意角度旋转、水平／垂直翻转和重置。图片与胶路一起变换，文字保持正向，旋转后适配完整图片范围；画点、拖点、分界吸附和跳帧均反算到原图坐标，方向键按屏幕方向微调顶点。

旋转、水平／垂直翻转与透明图片底色以地图 `view` 保存，重新打开候选恢复，并随发布辅助快照冻结、改版继承；旧地图缺省为 0°、不翻转、中灰底色。浏览时调整后点“保存视图”，编辑标注时随地图保存；未保存视图同样按候选草稿保护。仅改变视图不使空间对应失效，不改涂胶方向或检测身份。缩放、平移仍为临时状态；“适合窗口”保留旋转与翻转，“重置视图”恢复原始方向并保留底色。

透明图片默认使用中灰纯色衬底，可选浅色或低对比棋盘格，衬底不写入图片像素，原图 Alpha 保留。

地图编辑按“画胶路 → 采集范围 → 分段”组织，同一画线工具点击空白处追加顶点、拖动已有顶点调整；标采集起点后自动切到终点。只有一段时不显示分段工具，明确提示无需标分界。默认只展开当前步骤，顶点手柄仅画胶路时显示，方向箭头最多显示八处，避免密集顶点遮住胶条。旋转、翻转和底色收在“视图设置”，坐标输入、路径进度、反转方向与保存未完成草稿收在“精确调整与更多操作”；常用保存按钮为“保存地图”，仍执行空间对应确认校验。地图编辑支持折线顶点调整与撤销。相邻顶点重合时不能确认；闭合胶路自动连接首尾，不重复添加起点。空间分界点吸附到折线上，采集范围及分界点始终用同一条有向路径表示。

### 帧组与地图的双向映射

使用示教件的原始帧组序号和当前分段边界。沿用现有 `cuts` 口径：每个值是上一段最后一个原始帧组，各段范围 `[a,b]` 含首尾。走廊示教使用已确认的范围，不用多轮标定得到的 `expectedFrames` 替代示教件实际段长。

折线顶点按原图宽、高分别归一化保存；计算弧长时还原到图片像素坐标，避免宽高比使距离失真。使用累计折线长度插值，不按顶点序号插值。这里的弧长是图片中的路径长度，不是毫米长度，不写入段的 `lengthMm`。

令一段的起止弧长为 `L0`、`L1`，帧组范围为 `[a,b]`：

```text
N = b - a + 1
t = (seq - a + 0.5) / N
L = L0 + t * (L1 - L0)
```

从累计弧长 `L` 找到折线位置。按帧中心定位，单帧段落在空间段中点，分界点位于相邻段帧组之间；空段不生成映射。

点击地图时，先确定目标段，将点击位置投影到该段折线，再反算帧组：

```text
t = clamp((L - L0) / (L1 - L0), 0, 1)
seq = a + min(N - 1, floor(t * N))
```

- 使用原始 `seq`，缺帧、录制缺图与屏蔽都不删除序号、不压缩段长；跳到无图帧组时显示原有缺图状态，不静默改跳附近有图的帧。屏蔽只影响标定取样。
- 点击命中采用屏幕距离阈值，远离胶路的点击不跳帧。完整胶路上的最近投影位于未采集区、且比采集区投影更近时不跳帧，不能将采集端点外的点击吸附成首末帧。相邻胶路、交叉点或闭合首尾存在歧义时优先当前段；需要跳到另一段时通过段标签明确选择，仍有多个等距投影时提示选择，不任意跳转。
- 点击共享空间边界时以已选择的段为准，落到该段首帧或末帧；地图点和帧号采用同一映射函数，避免边界来回跳。
- 在走廊示教页点击只浏览帧，不自动替换已保存的示教帧或走廊。跨段沿用现有任务切换及未保存修改处理；所选相机不检测目标段时，转到该段可用的检测相机任务。

### 确认状态与界面反馈

| 状态 | 显示与导航 |
| --- | --- |
| 只有图片或胶路，空间对应不完整 | 展示已有资料，不显示帧组位置、不支持跳帧 |
| 空间对应有效，正在编辑示教件帧边界 | 分段工作台按有效草稿预览，标“估计位置／边界未确认”；预览不赋予确认状态，走廊示教不使用未确认草稿 |
| 空间对应有效，示教件边界已确认 | 高亮当前段和帧组估计位置，支持双向导航；单段沿用现有全件 `[1, groupCount]` 范围，无需额外确认帧边界 |
| 段对应失效或缺少可用帧范围 | 保留图片和胶路，说明待确认原因，暂停帧定位与跳帧 |

地图需同时显示段号、方向和采集范围，颜色不是唯一识别方式。界面持续注明“示意位置”，不承诺像素级或毫米级准确性。段内插值假设进度近似均匀；速度变化、透视和人工标注都会造成误差。只有每个空间分界点与帧边界对应同一位置时，分段锚点才能阻止段内误差跨段累积，不能预先承诺误差只有几帧。

### 候选保存、继承与失效

地图属于候选的可选辅助资料，按候选修订保存，避免较旧页面覆盖新标注。地图保存格式版本、图片内容摘要与原图尺寸、有序归一化折线、闭合与方向信息、采集范围、空间分界点、段结构版本及空间对应确认状态。`workspace.json` 只持 `navigationId` 和 `navigationStructureRevision`；图片与地图 JSON 以内容摘要命名、不可变写入，候选修订和引用通过原有候选保存一起生效。资源摘要只校验完整性，不充当配方业务身份。首版不保存相机偏移。帧映射由候选当前示教件与边界计算，不维护第二份可编辑的帧边界。

| 操作 | 地图处理 |
| --- | --- |
| 更换示教件 | 保留图片、胶路和仍有效的空间分段；按 RB-2 清空图像派生内容，新件帧范围确认前暂停定位；单段沿用全件范围规则 |
| 从生产配方创建改版候选 | 从对应发布版本的辅助快照复制可编辑副本；按 RB-8 重新示教和标定，不能继承旧件帧映射 |
| 增删、重排段或修改段类型 | 保留图片、胶路和原标注供参考，空间对应标为待确认，重新关联并确认后启用 |
| 更换图片、调整折线、方向、起点或采集范围 | 使空间对应待确认；不得把旧确认状态套在新几何上 |
| 调整空间分界点 | 空间对应重新确认；不修改帧边界、走廊和标定结果 |
| 修改示教件帧边界 | 沿用现有分段保存及派生内容失效规则；地图按新范围映射，不擅自移动空间分界点 |
| 修改限值、走廊、检测相机或帧组屏蔽 | 地图空间对应保持有效，不重新标注；是否使检测标定失效仍按原规则处理 |

当前段编号按顺序连续排列，不是稳定身份。保存段结构时按段编号和类型序列推进结构修订，不能只比较段数；现有界面没有重排入口，将来新增同类型段重排时必须显式推进修订，不能仅比较重排前后的类型序列。候选地图不属于 RB-2 / RB-8 清空的示教件图像派生内容；地图保留也不能豁免重新分段、示教与标定。

### 发布时冻结为独立辅助资料

正式发布时，以同一次发布使用的候选修订为来源，冻结图片、地图标注、段结构以及示教件原始帧组数与已确认边界，记录配方编号、配方修订、发布 ID 和示教件来源。边界副本只供解释该版示教位置，不携带整套示教件原图，不代替原图归档；没有原图时只能看地图，不能声称能回放图像。

- 辅助快照不可原地修改。后续候选编辑不影响已发布快照；改版发布产生新快照，按发布身份查询，不能拿最新候选地图解释旧版本。
- 辅助资料独立于检测发布包。项目内 `workspaces/<配方>/navigation/images/<摘要>.png`、`navigation/maps/<摘要>.json` 保存候选资料，`recipe-support/<配方>/<发布 ID>/` 保存 `image.png`、`snapshot.json`、`manifest.json`。独立清单校验快照和图片的 SHA-256。
- 不向现有 `vision/releases/<配方>/<发布 ID>/` 添加地图文件，也不将其加入检测发布清单。当前发布包会拒绝未声明、未引用或缺失的资源，直接加入会把地图可用性变成生产依赖。
- 地图不进入 `PlanIdentity`，不改变计划版本、PLC 协议、检测参数和标定身份；运行检测无需读取辅助资料。无地图、地图待确认或辅助快照缺失、损坏时，只关闭对应导航并给出提示，不阻止生产配方加载、布防或检测。
- 发布页单独显示辅助资料是否可冻结、是否完整及是否已冻结。未确认的地图不标为可导航；冻结失败必须明确报告“辅助资料未归档”，不能宣称完整归档，也不能回退关联其他版本地图。未发布成功的配方不能留下被标为有效发布的辅助快照。
- 辅助快照在 `.tmp-*` 目录写齐并校验后转入 `.pending-<发布 ID>`；生产配方成功生效后再转为正式发布 ID 目录。辅助失败显示独立状态和发布警告，不回滚已生效配方；临时或待生效快照不导出。独立清单校验资源与身份。辅助资料校验失败不降低现有检测发布包的校验强度，也不成为生产就绪条件。
- 项目复制、导出、导入同时携带候选地图与各发布辅助快照，校验相对路径和身份关联；与项目现有身份改写保持一致。旧项目无此资料照常使用。
- 地图及冻结快照不是缓存，不跟随录制原图的保留天数清理。删除候选不能误删仍由发布版本引用的快照；辅助快照随其所属发布归档或整个项目的显式删除清理。

### 实现与验证范围

- 后端：`workspace/navigation.rs` 实现地图编辑、几何校验、独立读图、发布冻结、生效及改版继承；`project/transfer.rs` 携带辅助资料并报告校验异常。
- IPC：`workspace_navigation_import(id, revision, bytes)`、`workspace_navigation_save(id, revision, map, confirm)`、`workspace_navigation_delete(id, revision)` 返回 `WorkspaceView`；`workspace_navigation_image(id, imageId)` 返回 PNG。视图的 `navigation` 独立返回地图、图片可用性、错误、结构修订及发布辅助状态，地图损坏不使候选读取失败。
- 图片导入支持 PNG、JPEG、BMP、TIFF，源文件与转换后 PNG 均不超过 32 MiB，最多 3200 万像素、单边 16384；统一保存 RGBA PNG，保留透明度。错误在导入处报告，不更改已有图片引用。
- 前端：`navigation/` 实现编辑和弧长映射；`WorkspaceNavigation` 适配候选接口与图片；`SegmentWorkbench`、`TeachingPage` 负责帧联动，发布页显示独立辅助资料状态。地图草稿在工作区内跨页保留，保存仍携带开始编辑时的候选修订；冲突拒绝覆盖。未保存地图时阻止换配方、发布及切换项目；保存或撤销后恢复。浏览器关闭页面使用 `beforeunload` 提示，原生窗口关闭未作端到端验证。
- 地图保存只推进候选修订，不改变检测身份、标定结果；仅与修改前候选修订一致的验证结果随修订保持有效，过期验证不能因保存地图重新生效。图片、地图及归档读取失败只降级对应导航；检测发布记录中的可选导航状态格式损坏时按无导航状态读取，检测字段及检测包仍严格校验。配方结构版本 8、检测发布包版本 5、候选流程版本 2 均保持不变，缺省没有地图。

定向验证保护下列规则：

| 验收场景 | 防止的回归 |
| --- | --- |
| 不均匀折线顶点、非正方形图片、单帧段、首尾帧及反向点击 | 把顶点序号当距离、归一化坐标扭曲弧长、除零或跨段偏一帧；使用参数化用例验证映射结果 |
| 缺图或屏蔽中间帧组后再导航 | 压缩序号导致后续帧全部错位 |
| 闭合首尾、相邻或交叉胶路、采集范围外点击 | 命中歧义导致跳错段，或将未采集区伪装成有帧 |
| 草稿边界预览与走廊页点击浏览 | 未确认边界被当作已确认，或浏览操作覆盖已保存示教帧 |
| 换示教件、改版、同段数结构变化 | 旧帧映射或旧空间对应被静默复用；图片与胶路被无故清空 |
| 发布后继续编辑候选，并复制或导出导入项目 | 冻结快照被覆盖、资源丢失或关联到错误发布版本 |
| 无地图及辅助快照缺失、损坏的配方加载与检测 | 辅助资料意外成为生产依赖；不能只测辅助读取函数的 mock 返回值 |

自动化证据：`tests/navigation.test.ts`、`tests/navigation-map.test.tsx` 保护映射及编辑；`tests/workspace-navigation.test.tsx` 用真实页面与 Provider 验证跨段浏览不写示教、草稿跨页恢复和发布互锁；Rust `workspace::navigation_tests` 验证修订锁、非法空间对应、透明度与检测身份保留、结构失效、换件保留、冻结及损坏降级；`project::transfer::tests` 覆盖资料复制与导出导入。浏览器使用合成工件图验证绘制、缩放拖点、平移、闭合跨起点、点击跳帧及窄屏布局；不把合成图导航当作真实胶路精度证据。

未验证：真实相机、PLC 生产链路及现场导航误差。辅助资料损坏的后端回归直接证明配方库可加载，生产隔离同时依据调用路径审查，未据此声称真机检测已通过。现场验收需选覆盖直线、弯道和首尾的可辨识位置，与示教件实际帧对照，记录导航误差及是否足以辅助选帧；不能用公式测试代替现场精度验证。

### 取舍与后续边界

首版以人工空间标注换取稳定、可解释的段对应，代价是每种工件首次要画图、确认段和采集范围。若现场发现长段或弯道内非匀速误差妨碍选帧，可另行决策增加段内人工对应点，做分段线性插值；相机专属映射或机器人 TCP 轨迹属于后续独立范围。

停用导航功能时，原示教、分段、标定和生产流程继续使用；辅助资料可保留供恢复，不改写生产配方和已冻结检测包。
