# 配方构建流程：示教件与标定件（RB）

状态：2026-10-28 用户确认，已实现（原生端到端未跑）。修订 [segment-burst](segment-burst.md) D-SB-44、D-SB-45、D-SB-49、D-SB-51 与 [maintenance-mode](maintenance-mode.md) HI-5 中涉及采集轮次页的部分；业务行为见 [配方创建流程](../architecture/recipe-creation-workflow.md) 与 [在线投运](../architecture/online-commissioning.md)。

## 问题

- D-SB-49 删除整圈示教采集后，采集轮次页只剩“从历史选用”导入，实际作用是初步筛选历史件；但用户必须先导入成轮次，才能看图、才能决定这一轮拿来做什么。
- “轮次”贯穿全流程，同一概念承担几种需要数量差别很大的用途：分段模板轮（1 轮）、走廊示教帧来源（每段可来自不同轮次，实际 1 轮就够）、多轮标定（≥ `calibrationRounds` 轮）、标准件（x_ref）。
- 同一轮的整理分散在三处：采集页做屏蔽与数字边界，段列表页“其余轮次复核”确认边界，标定页加入、移出。操作员要在页面间来回，才能把一轮变成可用的标定数据。

## 已定（用户确认）

- **RB-1 示教件**：每个候选恰好一件示教件，从历史件中选取。分段边界、全部（段, 检测相机）的走廊示教帧都只来自示教件，不允许某段改用其他件。示教件即原“分段模板轮”，两个概念合并。
- **RB-2 换示教件即清空**：更换示教件时，凡由示教件图像得出的内容全部失效并直接清空，不按图像对齐迁移：示教件边界与其余各件的已确认边界、全部走廊与示教帧、全部标定件及标定派生结果（各段 N_exp、标定统计、`partCalib`、x_ref）。段列表结构（段的数量、顺序、类型、检测相机、检测项与容差）与配方级参数保留，新示教件进入分段步骤时以现有段结构按比例给出初始边界，须重新确认。
- **RB-3 示教件也是标定件**：示教件的边界在分段步骤已确认，自动计入标定件，算入 `calibrationRounds`；加入标定要用已示教的走廊测量每帧，所以在走廊示教完成后、多轮标定页同步标定件时由软件加入；不能单独移出标定（要移出只能换示教件）。示教件不能标为标准件。其余标定件在多轮标定页另选，凑足轮数。两者只差在用途：示教件提供图像（分段与走廊），标定需要多件统计各段帧数的波动，一件得不出 N_exp 的均值与容差。
- **RB-4 轮次对界面隐藏**：界面上不再出现“采集轮次”、轮次编号与轮次列表；用户面对的是历史件（时间、SN、模式），在用到时由软件导入。轮次仍是存储格式（`recipe-capture/` 下的 `round.json` 3 与 `origin`），日志 `op.capture.import` 照记。
- **RB-5 旧候选停用**：现有候选不迁移。候选文件加流程版本，旧版本候选在配方库标“旧流程候选，已停用”，不能打开、编辑或发布，由用户在配方库自行删除，软件不自动删除、不统一弹窗；删除时连同它导入的轮次一并删除。生产配方与发布包不受影响，照常运行；同一配方编号的旧候选删除后，可从生产配方新建新流程候选。
- **RB-6 导入前预览**：历史件在导入前即可按相机、帧组浏览原图（只读，直接读录制目录），看过再决定选用。
- **RB-7 版本辨认**：靠两处标记辨认配方是怎么建的，都不改配方 `schemaVersion`（仍为 8，改了会使现有生产配方加载失败、必须重建）：
  - 候选的流程版本 `flow`：新流程候选为 2，缺省即旧流程；RB-5 按它判定旧候选。
  - 配方的示教件来源：发布时把示教件来源（历史件的时间、SN、`cycleId`）写进配方文档的可选字段，随生产配方与发布包保存。配方库卡片显示“示教件：时间 · SN”，工作台“配方信息”显示当前示教件；没有这个字段的生产配方即旧流程发布，照常运行。
- **RB-8 改版候选也清空**：从生产配方新建的候选（改版）继承段列表结构与配方级参数，但不继承图像派生内容：首次设示教件时同样按 RB-2 清空各段 N_exp、标定统计、`partCalib`、x_ref 与继承的走廊，每次改版都在新示教件上重新示教、重新标定。没有示教件之前候选不能发布（发布前检查“示教件”）。

## 采用

### 步骤与页面

进度步骤为 示教件 → 分段 → 走廊示教 → 多轮标定 → 发布。步骤 ID 与路由沿用（`capture`、`/recipe/capture`），标签改为“示教件”，减少改动面。

| 步骤 | 行为与完成条件 |
| --- | --- |
| 示教件 | 历史件选择器（单选）：本配方最近的真机录制件，列时间、SN、模式、帧组数、各相机帧数、时长 / 实测帧率（设定）、原图是否完整、不可用原因与提示（现“从历史选用”的列）；选中一行在旁边预览原图。“设为示教件”导入并记入候选；已有示教件时先列出 RB-2 将清空的内容，确认后才替换。完成条件：有示教件 |
| 分段 | 现分段标定工作台，模板轮固定为示教件，不再选轮次。保存即确认示教件边界。段参数编辑不变。“其余轮次复核”移到多轮标定 |
| 走廊示教 | 示教帧只在示教件本段的帧组里选，去掉轮次选择与“重新采集”入口；其余不变（D-SB-45、D-SB-47、D-SB-48） |
| 多轮标定 | 历史件选择器（多选，可勾“标准件”）选标定件（`workspace_calibration_pick`，须先有示教件），确认后软件依次：导入 → 同步（`workspace_calibration_sync`）：把示教件边界对齐到该件（D-SB-51 的可信判据；单段配方不对齐，直接确认）→ 全部可信则自动确认，走廊示教已完成时测量并加入标定，否则列入“待复核”并写明原因。待复核的件在本页逐边界确认（原“其余轮次复核”的交互）后再同步加入。改了屏蔽范围后点“同步标定件”重新加入；加入后改了走廊、当量或检测参数（标定件记录的走廊身份与当前不同）时，同步把这些件移出标定、清除派生标定结果并重测加入。帧组屏蔽与恢复、弃用（`workspace_calibration_remove_round`）、逐帧查看都在本页。顶部显示“标定需要 N 件（含示教件，不含标准件），已加入 M 件”。应用标定、确认容差、起涂收尾建议不变 |
| 发布 | 发布前检查加“示教件”一项。独立验证样本不得是已用于走廊示教的示教件或已加入标定的件 |

### 历史件选择器

- 一个组件，两种模式：示教件页单选，标定页多选并带标准件标记。数据沿用 `history_candidates` 的可用条件（HI-1～HI-8）；`HistoryCandidate.usage`（`teaching` / `calibration`）非空的件标“已使用”，不能重复选，不可用原因写“本候选已选用这一件”，不露出轮次编号。
- 预览沿用历史页的只读接口 `workspace_record_frame_image`（按记录、计划相机与帧组读录制原图）；不写候选，不占配置锁。
- 不可用原因在勾选框悬停与原因列都显示。

### 候选与配方数据

- 候选（`workspace.json`）新增：流程版本 `flow: 2`，表示按本决策的步骤建的候选，字段缺省即旧流程。它只标候选的建法，与配方文档的 `schemaVersion`（生产配方与发布包的文件格式，仍为 8）无关；生产加载与发布包都不读它。
- 候选另新增 `teachingPiece`：示教件的轮次 ID 与来源历史件（`roundId`、`cycleId`、`recordId`、SN、时间）。`captureReview.template` 在分段保存时设为示教件，对齐以示教件已确认的边界为准，界面不再读它。`workspace_set_teaching_piece` 设示教件（导入、按 RB-2 清空、删除原示教件与标定件的轮次；验证样本库引用的轮次不删；同一件重复设置报错）。
- `WorkspacePlanView.pieces`：示教件与标定件（角色 `teaching` / `calibration` / `standard`、来源记录、复核状态与确认方式、是否已加入标定、屏蔽数），示教件在前。
- 配方文档新增可选字段 `teachingPiece`（`cycleId`、`recordId`、SN、时间），发布正式版时从候选写入（RB-7）；候选文档里恒为空（新建与保存时都清掉，不从生产配方继承、不接受前端回传）。不进计划身份，不换计划版本，生产加载不需要它；配方 schema 仍为 8。`recipe_list` 的配方摘要同样带 `teachingPiece`。
- 旧流程候选：`workspace_get` 与所有修改命令报“旧流程候选已停用：请在配方库删除后重建”；启动时自动选配方跳过它。删除旧流程候选只删候选与 `recipe-capture/` 下该编号的全部轮次，保留生产配方与发布归档；删除新流程候选照旧连同同编号的生产配方一起删除，也连带其轮次。
- 走廊示教的选帧、保存与试测（`workspace_teach_segment_corridor`、`workspace_teach_preview_*`）都要求帧来自示教件，否则报“示教帧只能取自示教件”；`workspace_capture_review_confirm_cuts` 对示教件报错（示教件边界只在分段确认）。

### 删除的界面与命令

- 采集轮次页（`CapturePage`）：采集结果面板、采集历史下拉、轮次规则说明、实时采集状态文案、“设备实拍 / 离线模拟”标记；由示教件页（`TeachingPiecePage`）取代，“从历史选用”（`HistoryImportPanel`）由 `HistoryPicker` 取代。
- 轮次整理（`CaptureReviewPanel`）的数字边界输入、按比例 / 原帧号套用模板、设为模板；帧组屏蔽移到多轮标定页（`PieceMask`）。D-SB-44 的“回退：采集页轮次整理”一并作废。
- 段列表页的“其余轮次复核”与其轮次列表（迁到多轮标定，逐件复核）。
- 命令：`workspace_history_import`、`workspace_calibration_add_round`、`workspace_capture_review_save`、`_confirm`、`_set_template`、`_apply_template`、`_auto_confirm`（被同步取代）。
- 旧轮次读兼容（D-SB-49：格式 2 带 `teachingRoundId`、失败状态变体）保留：旧流程候选删除前它们仍在磁盘上，项目导入也可能带入。

### 手动配置数据（`capture_fixture`）

`capture_fixture` 改为生成仿历史录制件，不再直接写轮次（`src-tauri/src/history_fixture.rs`）：按录制时生效的生产配方（采集版）用库里的 `Recorder` 写与真机同格式的录制目录（`part.json` 带 `partMode`、`devices`、`plc` 与来源标记 `fixture: {label}`，原图 `{相机}_s{seq:06}.pgm`），并用记录库现有接口写对应的 `parts` 行（模式为维护采集，不进当日统计；SN 前缀 `FIXTURE-`；库版本不变）。这样选择器只有历史件一个来源，端到端与长稳测试走与现场相同的选件、导入路径。`HistoryCandidate.fixture` 带来源标签，选择器标“手动配置”；历史页按 SN 前缀辨认，不另加标记。轮次的 `origin.kind = prepared` 不再产生，已有的照常读取。

记录引用采集版的修订号，所以脚本先建候选、发布采集版，再生成数据：候选的版本号留给之后的正式版，若仿历史件用它写快照，正式版投产时同修订号的真实记录会因快照不同被记录库拒绝。这与现场先发采集版、再维护采集的顺序一致。

## 理由

- 示教只需要一件的图像，标定需要多件的帧数统计，按用途选件比先导入一批再分派更直接；“只来自示教件”让分段、走廊、标定共用一套边界基准，去掉“示教帧来自哪一轮”“模板轮是哪一轮”这类状态，代码与校验都更简单。
- 换示教件直接清空，避免跨件迁移走廊与边界带来的隐性误差；代价是重做示教，换件本应少见。
- 对界面隐藏轮次后，用户只认得历史件，和在线检测页、历史页用同一身份（时间、SN）。
