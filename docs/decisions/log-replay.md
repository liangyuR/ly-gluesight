# 工作线 log-replay：日志调试与回放的决策记录

本工作线交付三个 PR：结构化日志与诊断包（feat/structured-logs）、历史回放比对（feat/history-replay）、使用说明与离线验证脚本（feat/log-replay-docs）。下列每条写明问题、可选项、采用的做法与理由、回退方式。

## 1. 运行日志的文件格式

- 问题：原日志是 `gluesight-YYYY-MM-DD.log` 纯文本（`时间 [级别] 事件：内容`），工件身份只混在内容里，无法按 cycleId、拍照点可靠检索。
- 可选项：A 保留文本，查询时用正则解析；B 每行一条 JSON（JSON Lines）；C 写入 SQLite。
- 采用：B。文件名 `gluesight-YYYY-MM-DD[.N].jsonl`，每行 `{ts, level, ev, msg, cycleId?, sn?, requestSeq?, recipeId?, shotId?, k?, camera?, view?, stage?, data?}`。追加写、崩溃时最多丢最后一行；工具与人都能直接读；查询时按日期文件裁剪范围，再逐行解析。C 需要额外的写入线程与库迁移，收益不明显。
- 回退：`applog::Sink::write` 改回文本格式即可；查询、时间线、诊断包读取 `.jsonl` 的部分随之失效。

## 2. 旧文本日志（D-0）

- 问题：旧 `.log` 文件是否迁移或继续查询。
- 采用：不读取、不转换；旧文件只参与保留期与总量清理，过期自然删除。软件未投产，不保留旧格式读取兼容。
- 回退：无需回退；如需查看旧文件，直接用文本编辑器打开。

## 3. 滚动、保留与磁盘上限

- 问题：原实现按天滚动、保留 30 天、总量 512 MB，但“当天文件始终保留”，单日日志可以无限增长，上限形同虚设。
- 采用：按本地日期滚动，单个文件超过 16 MB 换下一个分段；保留 30 天；总量上限 1 GB。清理从最新往旧累计，超过上限即删除，只保护正在写入的分段（当天较早的分段也会被删）。离线实测每件 78 行（36 个拍照点的帧到达与 12 个检测拍照点的测量明细等），约 31 KB；1 GB 约可容纳 3 万件。
- 回退：修改 `applog::LIMITS`。

## 4. 级别

- 问题：原来的级别混用 `info / ok / ng / warn / err / error / panic`，既表达严重程度又表达界面颜色。
- 采用：文件中统一为 `debug / info / warn / error`。映射：`err / error / panic → error`，`warn / ng → warn`（NG 件需要关注），`ok / info → info`；逐帧“帧到达”、逐拍照点“测量完成（无缺胶）”记为 `debug`（文件保留，供时间线使用；运行日志页默认不显示）。界面事件流（`cycle://log`）仍用原来的 `ok / ng` 着色，不受影响。
- 回退：改 `Level::from_tone` 映射或把 `cycle::trace` 调用改回 `log`。

## 5. 关联字段从哪来

- 问题：日志散落在相机、PLC、测量、录制等模块，逐处传 cycleId 改动面大。
- 可选项：A 每个调用点显式传入；B 在途工件上下文自动附加；C 只按时间窗口关联。
- 采用：A + B。partStart 时 `applog::begin_cycle`（cycleId、SN、requestSeq，选定配方后补 recipeId），S7 事务结束、复位完成或站点模式切换（丢弃当前工件身份）时 `end_cycle`；在途期间写入的记录自动补齐这些字段。帧到达、测量完成、拍照点超时等显式带 shotId、k、相机、视角与耗时数据。显式指明了其他 cycleId 的记录不会被改写。
- 说明：在途期间其他模块的记录（相机断线、PLC 告警）也会挂到本件，这是有意的：回看时需要看到本件期间发生的设备事件。不按内容哈希、不按时间猜测关联运行日志。
- 回退：去掉 `correlate` 中的自动补齐，只保留显式字段。

## 6. 本件时间线的数据源与阶段耗时

- 采用：运行日志按 cycleId 精确取（只读该件日期前后各一天的文件，最多 3000 条）；PLC 信号取 `logs/plc.db` 中本件首末记录前后 1 s 内的值变化，且不越过上一件（或示教采集）的 S7 事务结束、下一件的 partStart（PLC 日志本身没有 cycleId，只能按时间窗口展示；连续生产时相邻两件只隔几百毫秒，不设界会把上一件的结果回写显示到本件）；排除 `plcHeartbeat / pcHeartbeat` 心跳点，最多 400 条。
- 阶段耗时只由关键事件计算，缺任一端点记为未知，不拿别的事件顶替：校验与布防（partStart→armed）、运动与采集（armed→partEnd）、收尾与判定（partEnd→检测结果，含持久化与回写）、等待 PLC 确认（检测结果→S7 事务结束）、整件（partStart→S7 事务结束）。
- 回退：时间线只读日志，不影响生产；删除面板即可。

## 7. 诊断包格式与范围

- 可选项：A 导出目录；B tar；C ZIP（引入 zip crate）；D ZIP（自写最小写入器）。
- 采用：D。Windows 资源管理器直接打开，不新增依赖（复用已锁定的 `flate2` 与 `crc32fast`）。只写普通 ZIP（无 ZIP64），因此限制：时间范围 ≤ 31 天、记录 ≤ 5000 件、附原图 ≤ 200 件且原图总量 ≤ 2 GB、PLC 日志 ≤ 20 万条；超限部分不打包并写入 `manifest.json` 的 notes。
- 哈希规则：ZIP 条目的 CRC32 是格式规定的传输校验，由解压工具使用；软件不用它做任何业务匹配、校验或身份关联，不违反“禁止哈希匹配”。
- 内容：`manifest.json`、`logs/gluesight-*.jsonl`（时间段内）、`logs/plc.jsonl`、`config/`、`state/`（单文件 ≤ 8 MB）、`records/parts.csv` 与 `records/parts.jsonl`（完整明细）、`recipes/<revisionId>.json`（涉及的配方快照）、`records/<记录号>_<cycleId>/`（原图、`part.json`、对照结果）。不含 WebView 资料与样本原件；候选调试件的原图在受管样本中，不重复打包。
- 原图默认只附异常件（NG / ERR / 局部超差），新的优先；从历史详情导出“本件诊断包”时附该件全部原图。
- 回退：删除 `diagnostics_export` 命令与界面入口，不影响其他功能。

## 8. 回放比对在哪里计算

- 问题：逐拍照点比对放后端并随对照结果保存，还是前端计算。
- 采用：前端由已加载的原记录（测量表、分段结论、拍照点记录）与对照结果计算，不改对照结果文件格式。若在文件中新增字段，D-0 下旧对照文件会因缺字段整批读取失败，影响面大于收益。
- 回退：删除 `ReplayDiff` 组件即可回到只看整件结论。

## 9. 比对容差

- 采用：偏移、胶宽差超过 0.01 mm 或测点状态（有胶 / 缺胶 / 未测成）改变、分段结论改变，即记为差异。同一发布包、同一原图的重跑应一致：离线实测 3 件 × 12 个检测拍照点，最大偏移差约 5×10⁻⁸ mm、最大胶宽差约 2×10⁻⁷ mm（f32 存储与 JSON 往返的舍入），0.01 mm 只用于吸收这类舍入；任何真实差异都会远大于它。
- 回退：修改 `REPLAY_TOLERANCE_MM`。

## 10. 原图叠加层中的胶宽与缺陷位置

- 问题：生产记录只保存每站的偏移、胶宽与状态，不保存胶边像素坐标；从偏移和法向反推胶边需要算法内部的法向约定，容易画错。
- 可选项：A 前端按示教中线估算法向反推；B 生产时把胶边坐标写入录制目录；C 胶边取自原包重跑结果。
- 采用：C。原图上始终显示示教中线与按原判定着色的测量站（红色为缺胶或超差的站，即缺陷位置）；运行“按原发布包重现”或候选复测后，再叠加该次测得的胶边与胶宽线，与原结果状态不同的站标为橙色。B 会改动生产热路径和录制格式，不在本工作线范围。
- 回退：去掉 `replayEdges` 叠加。

## 11. 逐件回看的导航

- 采用：从历史列表进入详情时，通过路由 state 带上列表筛选，前一件 / 后一件按同一筛选（如只看 NG）和记录号顺序；直接打开详情时只在本件所属范围（真机 / 离线 / 调试）内导航。快捷键：← / → 切换拍照点，[ / ] 切换工件（Alt+← 在 WebView2 中是后退，不使用）。
- 回退：去掉详情页头部按钮与键盘监听；列表页的 `state` 无副作用。

## 12. 重跑前置条件的提示

- 采用：缺发布包、配方快照缺失、原图不完整（录制关闭、按策略未保存、录制失败、已清理或身份核验失败）时，在按钮下方列出原因；后端仍按原逻辑拒绝，绝不改用当前配方代替。
- 回退：删除提示，不影响后端拒绝。

## 13. 大量记录时的性能

- 历史列表已分页（50 条 / 页）；运行日志页分页（100 条 / 页），只读覆盖查询时间段的文件；时间线条数有上限并在面板内滚动。
- 已保存对照结果每件最多 100 条且通常只有几条，本次未改成摘要列表（需要改动端到端脚本依赖的返回结构）。若现场单件对照很多，再改为“列表只返回摘要、选中时加载全文”。

## 14. 运行日志页的入口

- 采用：在侧栏“生产”分组的“历史记录”之后加“运行日志”（`/logs`），只在 `nav.ts` 增加一项；侧栏布局归 ui-shell，不做其他改动。PLC“通讯日志”页保持原样。

## 15. 离线验证的模拟标定

- 问题：2026-10-17 单圈样本集 `mmPerPx = null`，样本集目录只读。
- 采用：脚本把样本集复制到输出目录，在副本中写全局 `mmPerPx = 0.1`。依据：胶条在 1280×1024 原图中约 30–40 px 宽，按 FIPG 涂胶常见 3–4 mm 胶宽推定约 0.1 mm/px；按此当量离线测得各检测拍照点胶宽 3.2–4.2 mm，与推定一致。此值只用于打通离线回放链路，不代表现场标定或测量精度。
- 每个点位（拍照点组）只能选一台相机的图示教，因此每组各选一个胶条清晰的拍照点（共 12 个，覆盖 3 台相机），其余 24 个设为不检；ROI 与检测参数（搜索半宽 3 mm、胶宽 1.5–5 mm、暗胶）是演示夹具。
- 布防预算：调试构建的隔离实例中，布防实测约 250 ms（发布包核验约 56 ms、审计健康约 28 ms、PLC 布防确认约 160 ms），超过默认 200 ms，首件判 ERR 98（时间线完整记录了各阶段耗时）。验证脚本把布防预算放宽到 1000 ms，只用于验证回放链路；默认值是否需要调整交给负责节拍与 PLC 的工作线判断。
- 回退：换用已标定样本集时删除脚本中的 `mmPerPx` 覆盖；去掉 `armMs` 覆盖即恢复默认预算。

## 16. 使用说明的提交方式

- 采用：使用说明（`guide.json` 新章节、重新生成的 `index.html`、截图）、本决策记录与离线验证脚本单独成一个文档 PR，在两个功能 PR 之后合并，避免两个功能 PR 同时改生成文件 `index.html` 而冲突。PDF 未重新导出：二进制文件与其他工作线必然冲突，建议所有工作线合并后统一执行 `pnpm guide:pdf`。

## 17. 不检拍照点原图缺失时的重跑入口

- 问题：离线验证中删除一幅“不检”拍照点的原图后，后端按原发布包重跑仍能成功（只读取检测拍照点的原图），但历史详情按“全部拍照点原图齐全”判断原图完整性，按钮被禁用。
- 可选项：A 原图完整性只看检测拍照点；B 保持按全部拍照点判断。
- 采用：B。原图完整性同时用于候选原图复测与示教取图，候选可能把原来不检的拍照点改为检测，按全部拍照点判断更稳妥；按钮下方已写明原因（哪一类原图缺失）。检测拍照点原图缺失时，后端明确拒绝重跑（离线验证已覆盖）。
- 回退：如现场需要，可只对“按原发布包重现”单独按检测拍照点判断。
