# 日志调试与回放决策记录（log-replay）

范围：结构化运行日志、诊断包、历史回放比对。每条写明问题、可选项、采用的做法与理由、回退方式。

## 1. 运行日志的文件格式

- 问题：原日志是 `gluesight-YYYY-MM-DD.log` 纯文本（`时间 [级别] 事件：内容`），工件身份只混在内容里，无法按 cycleId、相机与帧可靠检索。
- 可选项：A 保留文本，查询时用正则解析；B 每行一条 JSON（JSON Lines）；C 写入 SQLite。
- 采用：B。文件名 `gluesight-YYYY-MM-DD[.N].jsonl`，每行 `{ts, level, t?, code?, ev, msg, …关联字段, data?}`，关联字段为 cycleId、sn、requestSeq、recipeId、camera、seq、stage 等，可省略。追加写、崩溃时最多丢最后一行；工具与人都能直接读；查询时按日期文件裁剪范围，再逐行解析。C 需要额外的写入线程与库迁移，收益不明显。
- 回退：`applog::Sink::write` 改回文本格式即可；查询、时间线、诊断包读取 `.jsonl` 的部分随之失效。
- 日志 schema 2：`t` 为带 UTC 偏移的本地时间，`code` 为稳定事件编码（见[编码表](../architecture/agent-logging-codes.md)）；`ts`、`level` 是前两个键，没有 `t`、`code` 的行照常读取。设计见[面向 Agent 的日志改造方案](../architecture/agent-logging.md)。

## 2. 旧文本日志（D-0）

- 问题：旧 `.log` 文件是否迁移或继续查询。
- 采用：不读取、不转换；旧文件只参与保留期与总量清理，过期自然删除。软件未投产，不保留旧格式读取兼容。
- 回退：无需回退；如需查看旧文件，直接用文本编辑器打开。

## 3. 滚动、保留与磁盘上限

- 问题：原实现按天滚动、保留 30 天、总量 512 MB，但“当天文件始终保留”，单日日志可以无限增长，上限形同虚设。
- 采用：按本地日期滚动，单个文件超过 16 MB 换下一个分段；保留 30 天；总量上限 1 GB。清理从最新往旧累计，超过上限即删除，只保护正在写入的分段（当天较早的分段也会被删）。1 GB 能保留几天取决于每天件数，见 [r2-records.md](r2-records.md) R-6。
- 回退：修改 `applog::LIMITS`。

## 4. 级别

- 问题：原来的级别混用 `info / ok / ng / warn / err / error / panic`，既表达严重程度又表达界面颜色。
- 采用：文件中统一为 `debug / info / warn / error`。映射：`err / error / panic → error`，`warn / ng → warn`（NG 件需要关注），`ok / info → info`；逐帧“帧到达”、逐帧测量明细记为 `debug`（文件保留，供时间线使用；运行日志页默认不显示）。界面事件流（`cycle://log`）仍用原来的 `ok / ng` 着色，不受影响。
- 回退：改 `Level::from_tone` 映射或把 `cycle::trace` 调用改回 `log`。

## 5. 关联字段从哪来

- 问题：日志散落在相机、PLC、测量、录制等模块，逐处传 cycleId 改动面大。
- 可选项：A 每个调用点显式传入；B 在途工件上下文自动附加；C 只按时间窗口关联。
- 采用：A + B。partStart 时 `applog::begin_cycle`（cycleId、SN、requestSeq，选定配方后补 recipeId），S7 事务结束、复位完成或站点模式切换（丢弃当前工件身份）时 `end_cycle`；在途期间写入的记录自动补齐这些字段。帧到达、测量完成等显式带相机、seq 与耗时数据。显式指明了其他 cycleId 的记录不会被改写。
- 说明：在途期间其他模块的记录（相机断线、PLC 告警）也会挂到本件，这是有意的：回看时需要看到本件期间发生的设备事件。不按内容哈希、不按时间猜测关联运行日志。
- 回退：去掉 `correlate` 中的自动补齐，只保留显式字段。

## 6. 本件时间线的数据源与阶段耗时

- 采用：运行日志按 cycleId 精确取（只读该件日期前后各一天的文件，最多 3000 条）；PLC 信号取 `logs/plc.db` 中本件首末记录前后 1 s 内的值变化，且不越过上一件的 S7 事务结束、下一件的 partStart（PLC 日志本身没有 cycleId，只能按时间窗口展示；连续生产时相邻两件只隔几百毫秒，不设界会把上一件的结果回写显示到本件）；排除 `plcHeartbeat / pcHeartbeat` 心跳点，最多 400 条。
- 阶段耗时只由关键事件计算，缺任一端点记为未知，不拿别的事件顶替：校验与布防（partStart→armed）、运动与采集（armed→partEnd）、收尾与判定（partEnd→检测结果，含持久化与回写）、等待 PLC 确认（检测结果→S7 事务结束）、整件（partStart→S7 事务结束）。partStart、armed、partEnd 是运行日志的事件名，分别对应协议 7 的 plcState=10、pcState=20、plcState=20。
- 回退：时间线只读日志，不影响生产；删除面板即可。

## 7. 诊断包格式与范围

- 可选项：A 导出目录；B tar；C ZIP（引入 zip crate）；D ZIP（自写最小写入器）。
- 采用：D。Windows 资源管理器直接打开，不新增依赖（复用已锁定的 `flate2` 与 `crc32fast`）。只写普通 ZIP（无 ZIP64），因此限制：时间范围 ≤ 31 天、记录 ≤ 5000 件、附原图 ≤ 200 件且原图总量 ≤ 2 GB、PLC 日志 ≤ 20 万条；超限部分不打包并写入 `manifest.json` 的 notes。
- 哈希规则：ZIP 条目的 CRC32 是格式规定的传输校验，由解压工具使用；软件不用它做任何业务匹配、校验或身份关联，不违反“禁止哈希匹配”。
- 内容：`manifest.json`（导出参数、构建信息 `build`、`utcOffset`、`logSchema`、`configSummary`、`notes`，以及除自身外每个文件的 path、bytes、sha256）、`README.md`（包结构、时间口径、事件编码表与推荐分析顺序）、`logs/gluesight-*.jsonl`（时间段内）、`logs/plc.jsonl`（时间段内，时间正序，每行带本地时间 `t`）、`config/`、`state/`（单文件 ≤ 8 MB；握手审计当前文件只写时间段内的行，已滚动分段取与时间段有交集的）、`records/parts.csv` 与 `records/parts.jsonl`（完整明细）、`recipes/<revisionId>.json`（涉及的配方快照）、`records/<记录号>_<cycleId>/`（原图、`part.json`、对照结果）。不含 WebView 资料与样本原件；候选调试件的原图在受管样本中，不重复打包。
- 原图默认只附异常件（NG / ERR / 局部超差），新的优先；从历史详情导出“本件诊断包”时附该件全部原图。
- 回退：删除 `diagnostics_export` 命令与界面入口，不影响其他功能。

## 8. 回放比对在哪里计算

- 问题：逐区域比对放后端并随对照结果保存，还是前端计算。
- 采用：前端由已加载的原记录（区域判定与逐帧指标）与对照结果（`Comparison.burst`）计算，不改对照结果文件格式。若在文件中新增字段，D-0 下旧对照文件会因缺字段整批读取失败，影响面大于收益。
- 回退：删除 `RegionReplayDiff` 即可回到只看整件结论。

## 9. 比对容差

- 采用：偏移、胶宽差超过 0.01 mm 或帧状态改变、区域结论改变，即记为差异。同一发布包、同一原图的重跑应一致：离线实测最大偏移差约 5×10⁻⁸ mm、最大胶宽差约 2×10⁻⁷ mm（f32 存储与 JSON 往返的舍入），0.01 mm 只用于吸收这类舍入；任何真实差异都会远大于它。
- 回退：修改 `REPLAY_TOLERANCE_MM`。

## 11. 逐件回看的导航

- 采用：从历史列表进入详情时，通过路由 state 带上列表筛选，前一件 / 后一件按同一筛选（如只看 NG）和记录号顺序；直接打开详情时只在本件所属范围（真机 / 离线 / 调试）内导航。快捷键：← / → 在本件内切换图像，[ / ] 切换工件（Alt+← 在 WebView2 中是后退，不使用）。
- 回退：去掉详情页头部按钮与键盘监听；列表页的 `state` 无副作用。

## 12. 重跑前置条件的提示

- 采用：缺发布包、配方快照缺失、原图不完整（录制关闭、按策略未保存、录制失败、已清理或身份核验失败）时，在按钮下方列出原因；后端仍按原逻辑拒绝，绝不改用当前配方代替。原包重跑读不到某一帧时，该帧记“测量失败”、所在帧组标检测不完整，OK/NG 不变（[segment-burst.md](segment-burst.md) 第九节第 17 条）。
- 回退：删除提示，不影响后端拒绝。

## 13. 大量记录时的性能

- 历史列表已分页（50 条 / 页）；运行日志页分页（100 条 / 页），只读覆盖查询时间段的文件；时间线条数有上限并在面板内滚动。
- 已保存对照结果每件最多 100 条且通常只有几条，未改成摘要列表。若现场单件对照很多，再改为“列表只返回摘要、选中时加载全文”。
- 运行日志查询每页都完整扫描所选时间范围内的分段来计总数，耗时与范围内条数成正比（7 天 22 万条时深翻页 3–8 s）；是否改为分段索引、缓存总数或缩短默认范围，待现场日志量确定后评估。

## 14. 运行日志页的入口

- 采用：在侧栏“生产”分组的“历史记录”之后加“运行日志”（`/logs`），只在 `nav.ts` 增加一项。PLC“通讯日志”页保持原样。
