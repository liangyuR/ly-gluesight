# 核心业务流程决策记录（core-flow）

范围：配方 → 采集 → 示教 → 标定 → 发布 → 生产 → 记录的业务规则与状态。每条记录问题、可选项、采用的做法及理由、如何回退。

## D-CF-4 接件校验的故障码顺序：型号 → 计划；不能检测的件结束后回 ERR

- 问题：接件时若先做整份计划核对，人工选型号时 PLC 下发了别的型号，报的是 100（计划不一致）而不是 95（配方不可用），现场会按计划版本排查，找不到真正原因。
- 采用：接件登记时先核对 PLC 报的型号与所选配方（不符报 95），再看配方能否编出拍照计划（编不出报 100）（`cycle/admission.rs`）。协议 8 的请求只带型号、序号与 SN，不核对拍照数量与计划版本。
- 校验不通过、发布包核验失败、相机未就绪、测量线程全部超时、工件身份分配失败等不能检测的情况，PC 只记下本件的故障码：PLC 不等 PC，本件照常运动、采图，PC 等到 plcState=20 才以结果码 90 回写该 faultCode（维护模式回 0，见 [maintenance-mode.md](maintenance-mode.md) MM-3）。任何结果都只在 plcState=20 之后发布。
- 回退：调换 `admit` 中两项核对的顺序。

## D-CF-6 故障时只改写仍在等 PLC 确认的工件交付

- 问题：进入故障时，只要上一件结果还在，就把它的 PLC 交付改记为失败。工件已确认、已释放后空闲时再出故障，追溯拒绝回退并记假错误；持久追溯故障期间每拍重新进入故障，每拍向追溯 spool 追加一条交付事件，强制退出时留下 `.tmp`，重启被拒为“审计 spool 含未知或未完成文件”。
- 可选项：① 只在结果已回写、等 PLC 确认（`Phase::Report`）阶段改记失败，故障原因不变时不重复进入故障；② 放宽 spool 启动校验，接受残留 `.tmp`。
- 采用：①（`fault_fails_delivery`、`enter_fault`）。交付状态只应在结果确认前因故障改为失败；② 治标不治本。在途件（接件到判定之间）进入故障时记 ERR 98、交付失败。
- 回退：还原 `enter_fault` 的判断为“不在途且有上一件结果”，并去掉同一原因的重复进入判断。

## D-CF-8 新安装使用空配方库，不写入样例配方

- 采用：首次启动与空配方库重启都不自动写入样例配方，用户通过工作台创建自己的配方；新建配方的模板是段配方（[segment-burst.md](segment-burst.md) D-SB-24）。已有配方继续加载，不按名称自动删除，避免误删用户已编辑的配方。
- 回退：恢复首启写入样例配方。

## D-CF-10 PLC 闸门拆成链路门与配置门

- 问题：`plc_gate` 一把锁同时保护 PLC 链路和“接件 / 配置一致性”，节拍每 20 ms 整个周期都持有。PLC 连接后，相机释放 / 重连 / 取帧、配方删除、标定、曝光下发要么一碰就报“正在处理 PLC 事务”，要么跟每次 S7 读写排队。
- 可选项：① 保持一把锁，各处改为有界等待；② 拆成链路门与配置门；③ 在 ② 基础上，相机长操作不持锁，接件遇到维护中的相机直接按相机未就绪记本件 ERR。
- 采用：②。`link_gate` 保护 S7 握手、PLC 配置 / 连接 / 断开 / 手动写点；`config_gate` 保护接件登记、切换待生效配方、相机重配置、配方 / 设置 / 标定 / 样本修改。节拍每拍持 `link_gate`；只在接件到登记在途期间持 `config_gate`，切换待生效配方用 `try_lock`，配置操作进行中就留到下一拍。离线进入 / 退出 / 候选试运行两把都持。加锁顺序固定为先 `link_gate` 后 `config_gate`，只持 `config_gate` 的操作不再取 `link_gate`。相机重连在整个打开过程中持 `config_gate`，期间到来的工件等相机打开后再登记（PLC 不等 PC，登记前收到的帧不计入本件，按缺帧判定）。
- 影响：空闲时相机与配置操作不再与 S7 读写竞争；相机重配置期间节拍可能读到相机未就绪，按设备未就绪如实上报。
- 回退：把两把门合并回一把，节拍整拍持有。③ 待现场确认“重连期间到来的工件直接记 ERR”可接受后再做。
