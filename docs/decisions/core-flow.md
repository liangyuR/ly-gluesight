# 核心业务流程决策记录（core-flow）

范围：配方 → 采集 → 示教 → 标定 → 发布 → 生产 → 记录的业务规则与状态。每条记录问题、可选项、采用的做法及理由、如何回退。

## D-CF-4 接件校验的故障码顺序：型号 → 计划；不能检测的件结束后回 ERR

- 问题：接件时若先做整份计划核对，人工选型号时 PLC 下发了别的型号，报的是 100（计划不一致）而不是 95（配方不可用），现场会按计划不一致排查，找不到真正原因。
- 采用：接件登记时先核对 PLC 报的型号与所选配方（不符报 95），再看配方能否编出拍照计划（编不出报 100）（`cycle/admission.rs`）。PLC 只报型号、件序号与 SN，不核对拍照数量。
- 找不到配方、正常模式遇到采集版、计划不一致、生产生效版本尚未确认、预热未完成或失败、发布包核验失败或超时、相机未就绪、计数来源不可信、测量线程全部卡住、工件身份分配失败等不能检测的情况，PC 只记下本件的故障码（95 / 98 / 99 / 100）：PLC 不等 PC，本件照常运动、采图，PC 等到工件结束（`inspecting` 回 0）才以结果码 90 回写该 faultCode（维护模式回 0，见 [maintenance-mode.md](maintenance-mode.md) MM-3）。任何结果都只在工件结束之后发布。
- 这些问题只影响本件，下一件重新检查。相机、配方、追溯或磁盘问题不影响通讯就绪；在途件相机掉线只让本件记 ERR 98。只有通讯未就绪（PLC 断开、协议版本不符、心跳失活）才让节拍进故障，恢复后自动就绪（[r2-plc.md](r2-plc.md) R2P-2）。
- 回退：调换 `admit` 中两项核对的顺序。

## D-CF-6 PLC 交付以回写为准

- 问题：PLC 不确认结果，PC 无从知道 PLC 是否取走；交付状态要有一个不依赖 PLC 应答的终态。
- 采用：交付状态为 `pending` → `submitted` 或 `failed`。结果回写 PLC（最后写 `resultSeq`）即记 `submitted`，是成功终态，之后通讯未就绪或下一件到达都不再改它。没有回写的件记 `failed`：通讯未就绪或中途换件而中断的在途件（ERR 98）、等不到工件结束的件（ERR 97）、回写前 PLC 已切到下一件的件、进程中途退出后补记的件。`acknowledged` 只存在于旧记录。
- 理由：见 [r2-plc.md](r2-plc.md) R2P-1；`submitted` 只表示结果已写到 PLC，PLC 是否采用以它自己的记录为准。

## D-CF-8 新安装使用空配方库，不写入样例配方

- 采用：首次启动与空配方库重启都不自动写入样例配方，用户通过工作台创建自己的配方；新建配方的模板是段配方（[segment-burst.md](segment-burst.md) D-SB-24）。已有配方继续加载，不按名称自动删除，避免误删用户已编辑的配方。
- 回退：恢复首启写入样例配方。

## D-CF-10 PLC 闸门拆成链路门与配置门

- 问题：`plc_gate` 一把锁同时保护 PLC 链路和“接件 / 配置一致性”，节拍每 20 ms 整个周期都持有。PLC 连接后，相机释放 / 重连 / 取帧、配方删除、标定、曝光下发要么一碰就报“正在处理 PLC 事务”，要么跟每次 S7 读写排队。
- 可选项：① 保持一把锁，各处改为有界等待；② 拆成链路门与配置门；③ 在 ② 基础上，相机长操作不持锁，接件遇到维护中的相机直接按相机未就绪记本件 ERR。
- 采用：②。`link_gate` 保护 S7 会话读写、PLC 配置 / 连接 / 断开 / 手动写点；`config_gate` 保护接件登记、切换待生效配方、相机重配置、配方 / 设置 / 标定 / 样本修改。节拍每拍持 `link_gate`；只在接件到登记在途期间持 `config_gate`，切换待生效配方用 `try_lock`，配置操作进行中就留到下一拍。加锁顺序固定为先 `link_gate` 后 `config_gate`，只持 `config_gate` 的操作不再取 `link_gate`。相机重连在整个打开过程中持 `config_gate`，期间到来的工件等相机打开后再登记（PLC 不等 PC，登记前收到的帧不计入本件，按缺帧判定）。
- 影响：空闲时相机与配置操作不再与 S7 读写竞争；相机重配置期间节拍可能读到相机未就绪，就绪检查如实显示，不影响通讯就绪。
- 回退：把两把门合并回一把，节拍整拍持有。③ 待现场确认“重连期间到来的工件直接记 ERR”可接受后再做。
