# 核心业务流程（core-flow）决策记录

工作线 1：配方 → 采集 → 示教 → 标定验证 → 发布 → 生产 → 记录的业务规则与状态。每条记录问题、可选项、采用的做法及理由、如何回退。核对结果见 [核心流程上线核对清单](../testing/launch-core-flow-checklist.md)。

## D-CF-1 实拍样本集的模拟标定当量取 0.112 mm/px

- 问题：`2026-10-17-normal-sampleset`（12 点位 × 3 相机，1280×1024）`mmPerPx=null`，没有标定就无法走“样本集声明当量”的标定验证，也无法以毫米判定。
- 可选项：① 用参考件人工标定（无真机，做不到）；② 从图中胶宽反推（循环论证，胶宽本身是被测量）；③ 沿用项目已记录的同分辨率现场相机假设当量。
- 采用：③。`docs/architecture/p0-plan.md` 记录 MX11 现场相机（同为 1280×1024）“像素当量约 0.112 mm/px”，mx11 样本集也按此写入。只写进副本清单的全局 `mmPerPx`，并给副本 id 加后缀，原件保持只读、不被导入覆盖。结果只证明业务链路，不证明毫米精度。
- 回退：现场给出真实标定后，在样本集 `shots[].mmPerPx` 写真实值，或修改离线端到端夹具的 `mmPerPx`。

## D-CF-2 离线端到端按样本集 id 选夹具，改用实拍三相机样本集

- 问题：`tests/native/offline-e2e.mjs` 停在 10-15 前的流程：整圈采集仍传 `cameraId`（现为 `cameraIds`），断言离线相机只有 1 台，示教用 `workspace_set_views` 跳过 3 个点；10-17 起每个拍照点组必须恰好选一张检测图，跳过的组无法通过验证与发布；重启续测用外部样本目录重新进入离线，而样本集现在会导入受管副本，同 id 再导入被拒。main 上这条端到端已无法通过。
- 可选项：① 只修参数名，继续用 mx11-demo；② 按样本集 id 维护夹具，主用实拍三相机样本集。
- 采用：②。mx11-demo 在分组规则下要示教全部 8 个点，S003/S006/S007 没有可靠笔划夹具，暂不保留其夹具；实拍样本集每组按夹具选一台相机、用刷选笔划提取中线（S006 组用框选），4 个组用窄搜索参数。重启续测改用 `site_status().last.sampleSetDir`（受管副本）。CDP 地址改为 `localhost`，避免 WebView2 只监听 `[::1]` 时连接被拒；等主窗口页面出现（最长 120 s）再驱动，跳过启动时的资料准备窗口。对应 PR #99。
- 回退：给 mx11-demo 补齐 8 个点的笔划后加回 `FIXTURES`。

## D-CF-3 实拍样本集只有正常件，副本中人工生成断胶件

- 问题：实拍样本集只有 1 件正常件，覆盖不到 NG 结论、缺陷样本验证、NG 历史复测。
- 可选项：① 只跑正常件；② 用 mx11-demo 的真实断胶件（夹具缺失，见 D-CF-2）；③ 在副本里由 p01 复制出 p02，擦除一段胶路。
- 采用：③。p02 的 S032（S011 组所选 cam2 图）把 (880,140) 起 80×100 px 的胶段换成左移 50 px 处的板面像素，约 11 mm，超过默认最大断口 6 mm；清单里标 `label=ng`、`shotLabels.S032=gap`、`origin` 注明人工擦除。期望投产 NG_GAP 且原因指向 `S011-cam2`。人工断胶只用于业务链路，不代表真实缺陷外观或算法检出率。对应 PR #99。
- 回退：删除夹具的 `defect` 字段即只跑正常件。

## D-CF-4 布防拒收的故障码顺序：产品代码 → 触发数量 → 计划

- 问题：开始请求先做整份计划核对（S7 会话 `validate_plan` 同时比较 planVersion、shotCount、deviceShots），任一不符都报 ERR 100「拍照计划不一致：需 version=…」。人工选型号时 PLC 下发别的产品，报的是 100 而不是 95；产品代码一致但触发数量不符时也报 100，94 的分支永远到不了。现场会按计划版本排查，找不到真正原因。
- 可选项：① 维持现状；② 先产品代码（95），再配方能否编出拍照计划（100），再触发数量 shotCount/deviceShots（94），最后由 S7 会话核对计划版本与内容（100）。
- 采用：②，与协议表语义一致：95 配方不可用，94 拍照计划/数量不匹配，100 计划版本、设备绑定或计划内容不一致。对应 PR #98。对 PLC 可见的变化：
  - 人工选型号、PLC 下发别的产品：100 → 95。
  - 产品代码一致（PLC 按产品代码选配方时必然一致）但 shotCount/deviceShots 与配方计划不符：100 → 94。PLC 来源下这是唯一的变化，不是“行为不变”。
  - 只有 planVersion 不符、计划内容或设备绑定不符、配方编不出拍照计划：仍为 100。
  - deviceShots≠shotCount 属请求 payload 不合法，在此之前已按 visionFault 处理，不回写故障码，不受本条影响。
- 协议文档：[一期 S7 握手契约](../integration/plc-s7-phase1.md) 第 6 节“PLC 侧须同步新的 planVersion 与设备计数，否则拒绝布防（故障 100）”与上述变化不符，应改为“planVersion 不同步报 100，shotCount/deviceShots 不同步报 94”。协议文档归 plc-table 工作线，本工作线不改，已列为跨工作线问题；同步前现场排查以本条为准。
- 回退：还原 `cycle.rs` 中 `start_part` 的核对顺序并删除 `cycle/admission.rs`；数量不符随之恢复为 100，协议文档第 6 节无需改动。

## D-CF-5 重启后不沿用上次进程的可疑设备会话

- 问题：设备会话编号每次启动从 1 分配。启动时把磁盘上异常轮次（含退出时中断的轮次）的会话编号载入可疑集合，会与本次启动同编号的新会话冲突：重启后整圈采集一律报“上一轮采集异常…请重新连接这些相机”。离线期间相机页只读，无法重连，只能退出再进入离线绕过。
- 可选项：① 启动时不载入可疑会话；② 会话编号改为跨进程唯一（如以启动时间作种子）。
- 采用：①。旧进程的帧不可能送进新进程，跨重启封锁没有保护意义；改动只在整圈采集记录内，不动相机会话分配。对应 PR #97。
- 回退：恢复 `RecipeCaptureHost::open` 中的载入；若要跨进程封锁，须同时采用 ②。

## D-CF-6 故障时只改写仍在等 PLC 确认的工件交付

- 问题：进入故障时，只要上一件结果还在，就把它的 PLC 交付改记为失败。工件已确认、已释放后空闲时再出故障，追溯拒绝回退并记假错误；持久追溯故障期间每拍重新进入故障，每拍向追溯 spool 追加一条交付事件。离线实测写到 spool 序号 2565，强制退出时留下 `.tmp`，重启被拒为“审计 spool 含未知或未完成文件”。
- 可选项：① 只在 Report（已回写结果、等确认）阶段改记失败，持久追溯故障原因不变时不重复进入故障；② 放宽 spool 启动校验，接受残留 `.tmp`。
- 采用：①。交付状态只应在结果确认前因故障改为失败；② 是持久追溯的启动规则，属另一工作线，且治标不治本。对应 PR #101。
- 回退：还原 `enter_fault` 的判断为“不在途且有上一件结果”，并去掉持久追溯分支的重复进入判断。

## D-CF-7 整组不检暂不支持

- 问题：配方创建文档写有“标记不检测：保留该点图像和示教”。10-17 起分组示教要求每个 Pose 恰好一张检测图，界面没有整组不检，组内全部标记不检会被验证与发布拦下。
- 可选项：① 保持“每组恰好一张”；② 允许整组 0 张（不检），发布时仍要求至少一组检测。
- 采用：①，以最近一次产品决定为准，不改规则；组内其他相机的图仍只采集不检测。需要整组不检的 Pose 由现场确认是否本就不该触发拍照。
- 回退：如现场确认需要整组不检，按 ② 放开 `doc_group_selection_errors` 的 0 张情况并补界面入口。

## D-CF-8 首次启动写入的样例配方保留，列为上线前清理项

- 问题：全新站点会写入样例配方 MTR-HSG-A/B（产品代码 12/13、计划版本 12/13）。真机和样本集模式下它们没有发布包、不可运行，开工就绪的“可开工配方”项显示的是“MTR-HSG-A：所选生产版本没有不可变发布包”，而不是“配方库为空”；也占用产品代码。
- 可选项：① 不再写入样例配方；② 保留，现场部署后删除。
- 采用：②。离线·合成图演示与 `pnpm test:ui:production` 依赖样例配方，改动面超出本工作线；PLC 下发 12/13 时按无发布包拒收（95），不会误判。
- 回退：不涉及。后续如采用 ①，需同步改合成图演示与生产桌面测试。

## D-CF-9 无可开工配方时 PLC 复位提示不清

- 问题：真机或样本集模式没有可开工配方时，节拍判定设备未就绪，S7 复位报“设备尚未就绪，不能复位并置视觉就绪”，而相机项显示“相机就绪”，操作员看不出是缺配方。整圈采集期间会放宽这一条，不影响示教采集。
- 可选项：① 在 S7 会话复位失败原因里带上具体原因；② 在开工就绪报告里由配方项解释。
- 采用：本轮不改。原因文字在 S7 会话（`plc_session`）内生成，改接口会波及 S7 会话及其线协议测试，属 plc-table；已列为跨工作线问题。
- 回退：不涉及。
