# 分段连拍飞拍决策记录（segment-burst）

段配方（分段连拍飞拍）是唯一的生产模型，本文是它的现行基准：规格与代码冲突时采用的做法（第四节 D-SB-n）、前后端 IPC 契约（第五节）、口径（第六节）、内存与队列（第七节）和实现要点（第九节）。PLC 握手与现场接线以 [生产通讯协议 8](../integration/plc-communication-protocol.md) 为准。

依据：分段连拍飞拍方案第 18 版（2026-10-22，下称“规格”）与实现决策补充（2026-10-22，用户已确认，下称“决策补充”）；两者冲突时以决策补充为准。契约类型在 `src-tauri/src/{plan,frame_group,segmentation,burst_judge,calibration}.rs` 与 `src/features/plan/types.ts`（字段与 Rust serde 输出逐一对应）。

## 人定分段与按段相机、走廊

依据现场 NEW-14 的 16 轮采集（第四节 D-SB-40 列出数据与边界偏差），分段改为“人定结构、软件定位边界”：

- D-SB-40：段结构、检测相机与走廊由人定；生产按各段 N_exp（示教件已确认分段的帧组数）比例与本件总帧组数推算边界，边界两侧各留 `boundary_guard`（默认 2）帧过渡区。
- D-SB-41：每段指定检测相机，修订 D-SB-14 的“三台相机每帧取最差”。
- D-SB-42：直线段示教段走廊，弯道用出胶点短走廊，修订 D-SB-17 的“每台相机一条走廊”；生产怎么选走廊见 D-SB-45。
- D-SB-43：图像运动细化边界列为后续。
- D-SB-45（2026-10-26 用户确认，已实现；现场吞吐复测待做）：走廊只按段、相机只留参数，取消相机走廊（默认走廊）；生产按预测段选走廊，收尾后补测归属变了的帧。修订 D-SB-17、D-SB-21、D-SB-41、D-SB-42。
- D-SB-46（2026-10-26 用户要求，已实现）：发布不再要求独立样本验证；发布时当场核对发布前检查，样本验证改为可选。修订 D-SB-20 与规格 §0/§1 的独立验证门槛。

- D-SB-52（2026-11-02 用户确认，已实现）：工作台保存分段按示教件帧范围逐段对应，没动的段连同走廊与示教帧原样保留。修订 D-SB-42、D-SB-44、D-SB-45 的“类型序列变化即清空全部走廊”。

- D-SB-53（2026-11-02 用户确认，已实现）：段可设为不检测：照常计帧与分段，不测不判，整段连同两侧过渡帧列为未检区域。

- D-SB-54（2026-11-02 用户确认，已实现）：轮询各相机 Line0 电平，看到门控关闭满余量即提前收尾，不再固定等满收尾窗口。

- D-SB-55（2026-11-02 用户确认，已实现）：生产按相机时间戳给帧编号（门控号 + 门控内序号），取代 SDK 帧号与开流基线；相机重开不再判 ERR，丢帧可定位，门控关闭时最后一帧已到即收尾。

- D-SB-61（2026-11-07 用户确认，已实现）：胶宽“偏宽只预警”按段开关、新建的段默认开启：超出胶宽上限和溢胶上限只在软件里预警，PLC 收到合格；偏窄照常判 NG_WIDTH。

- D-SB-62（2026-11-07 用户确认，已实现）：一次门控即一笔。段边界落在两笔之间时按笔对齐、不留过渡区，笔中间的边界在本笔内按比例换算；每笔开头、结尾按配方跳过，整笔太短的不检；本件笔数与示教件不同只记笔数异常并整件按未分段判。

实施顺序：D-SB-40 → D-SB-41 → D-SB-42 → D-SB-45 → D-SB-46 → D-SB-52 → D-SB-53 → D-SB-54 → D-SB-55 → D-SB-61 → D-SB-62 已实现；D-SB-43 未实现。

## 2026-10-27 逐帧定向与工件边胶偏（已实现，按段开关，新建的段默认开启）

现行走廊按帧号选、方向固定，胶偏以胶嘴为参考。针对工件轻微扰动与帧前后偏移，有两项可分别开启的修订：

- D-SB-47：每帧以出胶点（按相机标定，未标定时由走廊起点推算）为锚，用 lyFlow 的扇形扫描与粗跟踪算子在出胶点背离最近画面边的半圈里找胶条方向并拟合胶路（选方向由 GlueSight 判），只测距出胶点 s₀ 到 s₀ + L 的固定窗口（按段设置，新开启的段默认 5–20 mm，试测页按示教件测量核对是否覆盖每帧后移量）；方向序列同时用于细化分段边界。按段开关、新建的段默认开启，沿用现有走廊示教。修订 D-SB-42、D-SB-45 的走廊选择，取代 D-SB-43 的运动估计。
- D-SB-48：胶偏以工件边为参考，用 lyFlow 的 `glue.part_edges` 找零件边、GlueSight 选侧剔野后量胶边距，实现 `ToEdge`；模板匹配只用于工件定位，不用于找胶条。修订 D-SB-15、D-SB-18 与默认做法 2。

两项都已实现（2026-10-27，用户要求不等实际涂胶数据先实现）：开关全部关闭时测量图、发布包与生产行为都不变。NEW-14 离线评估（见各条“离线评估”）：空跑数据的画面里没有胶嘴、胶条贯穿整个画面，D-SB-47 无法在这批数据上验证，生产开启前须用实际涂胶、画面里有胶嘴的轮次复测；D-SB-48 的找边在部分直线段可用，极性须按段设置。

## 一、采集模型

- 三台独立单视角相机（D-SB-11），Line0 高电平期间按软件设定的固定帧率连续采集，默认 10 fps；PLC 按机械臂拍照信号 `CaptureActive` 门控采集使能（一件内可多次开关，段间空走不出帧，各段的帧都计入本件），不产生逐帧脉冲。Software 触发只用于单帧标定与调试。
- 帧按各相机 SDK 帧号（`frame_counter`）配组（D-SB-10、第六节）；帧数告警只比较相机之间，不代表曝光同步。
- PC 读到 plcState=10 即接件登记（核对配方、发布包与相机，定帧计数基线，开始录制），不回写 PLC；登记前收到的帧不计入本件，按缺帧判定。
- PLC 报工件结束（plcState=20）后，PC 等收尾截止（收尾窗口 `drain_ms`，默认 1000 ms；本件相机都看到 Line0 门控已关闭满 `gate_guard_ms`，默认 80 ms，即提前截止，D-SB-54）、已接受的帧都测完（含 D-SB-45 的收尾补测），再判定并回写结果；任何结果都只在 plcState=20 之后回写。下一件须等当前件释放。
- 分段按 D-SB-62 与 D-SB-40：段结构由人定。配方有示教件的笔结构、本件笔数相同时按笔换算边界；没有笔结构时 `Proportional` 按各段 N_exp 比例与本件帧组数推算边界。笔中间的边界两侧各留 `boundary_guard` 帧过渡区，两笔之间的边界不留。单段配方、有段还没有 N_exp、笔数不同或帧组数越界时整条胶路按“未分段”处理，只跑每帧独立检测、不判胶偏。每笔首尾的跳过（D-SB-62）不论分段是否可信都生效。

## 二、多段配方的发布与运行

- **发布门槛**：示教件即基准件（[recipe-build-flow](recipe-build-flow.md) RB-3）：各段 N_exp 都已由示教件分段得出，整件 ΣN_exp（`expected_total`）为各段之和；示教件分段未确认时没有 N_exp，不能发布（D-SB-45）。
- **N_exp 的来源**：各段 N_exp = 示教件在分段步骤已确认的各段帧组数，候选每次改动后由软件写入（`calibrate_from_teaching`），不能手填；`expected_total` = 各段 N_exp 之和（`plan::expected_total(segments, part_calib)`）。`part_calib` 不再写入，候选里恒为空。
- **运行时**：多段配方按笔（D-SB-62）或按比例（D-SB-40）分段判定；单段配方，本件笔数与示教件不同，或没有笔结构时本件总帧组数超出 `expected_total ± tolerance_total`，整条胶路按“未分段”区域判，只跑每帧独立检测、不判胶偏。帧组数越界另记帧数异常、笔数不同另记笔数异常，都不改结论。
- 协议 8 的 PLC 只报型号、序号与 SN，ΣN_exp 只用于 PC 侧的帧数核对，换示教件、改分段不用改 PLC。

## 三、已接受的默认做法

- **默认做法 1**：**溢胶**按“每帧最大胶宽超过溢胶上限（`overflow.max_width_mm`）”判，结论 NG，结果码沿用 NG_WIDTH（14），原因写“溢胶”；本段开了偏宽只预警时只记溢胶预警（D-SB-61）。**气泡、拉丝不检**，结果中标注“未检项”（`BurstJudgement.unchecked`）。
- **默认做法 2**（经 D-SB-48 修订）：胶偏默认按 `AbsoluteX` 判；选 `ToEdge` 并配了找边参数时按胶边距判（D-SB-48），没配找边参数的段结果标“胶偏未判：测量量未实现”（`OffsetUnjudged::MeasureNotImplemented`）。
- **默认做法 3**：**提前结束**（PLC 提前报工件结束）：PC 用已收到的帧照常判 OK/NG；帧组数 < ΣN_exp − Σtol 时加 `short_part`（疑似提前终止）标记，历史中单独显示（`PartSummary.flags`）。
- **默认做法 4**：**每段、它的每台检测相机示教一条走廊**（D-SB-42、D-SB-45）；弯道用从出胶点起画的短走廊，帧走出走廊记“检测不完整”（`FrameState::OutOfCorridor`），不判 NG。弯道走廊没有经过真实弯道图像验证。
- **默认做法 6**：**换示教件或改分段使 N_exp / expected_total 变化时分配新的 `plan_version`**（二者都进入计划身份，见 D-SB-19）；计划版本是 PC 侧发布包与记录的身份，不下发 PLC。
- **默认做法 7**：按本段检测相机取最差，未分段区域按每帧预测段的检测相机取最差（D-SB-45）；帧序号取 SDK **`frame_counter`**；三台相机整件**全无帧判 ERR 91**；采集失败的异常码为 98 / 99（D-SB-33）；**容差默认 2 帧**（直线、弯道相同，D-SB-24）。

## 四、冲突与决策

每条写问题、采用的做法与理由；问题里的文件行号指当时的代码。

### D-SB-1 计划模型：段列表

- 问题：原模型 `RecipeDoc.shots: Vec<ShotSpec>`（id/pose/camera/view）按触发分组编计划；规格 §1 改为段列表。
- 采用：`plan::PathSegment`（Rust、TS 同名，避开 `recipe::Segment`）。`RecipeDoc` schema 8 有 `segments`、`inspect: Vec<CameraInspect>`（有序，计划相机顺序取它）、`segment_defaults: KindDefaults`、`part_calib: Option<PartCalib>`（不再写入，候选里恒为空）。旧文件里的 `calibrationRounds` 读入时忽略。`segments` 非空即段配方，要求 `shots` 为空。`segments` 为空的配方（旧拍照点配方，从未部署）不能开工、不能发布（“旧拍照点配方已停用，请新建段配方”），遗留类型不再维护。
- 回退：不计划。

### D-SB-2 帧数只告警，接件不核对数量

- 问题：规格 §2 帧数在 N_exp ± tol 内正常，超出只告警。
- 采用：接件只核对型号与计划能否编出（[core-flow.md](core-flow.md) D-CF-4），不核对拍照数量。运行时只核对整件帧组数与 `expected_total ± tolerance_total`，越界记“帧数异常”告警，不改结论。记录库按实际帧落库。

### D-SB-3 区域帧数口径：帧数 = 帧组数

- 问题：规格 §2 每段取各轮帧数均值作 N_exp，运行时每段帧数与 N_exp ± tol 比较，但没说三台相机各自的帧数怎么合成一个“帧数”。
- 采用：示教件分段和运行同一口径——帧数 = 帧组数，即区域内 seq 的个数（`last_seq − first_seq + 1`）；整件或整轮的帧组数 = 各相机最大 seq 的最大值。单台相机的帧数只用于丢帧告警（与另外每一台相机都相差 > 1），不参与容差比较。详见第六节。
- 理由：某台相机缺帧时帧组数不变，结论与告警分开；示教件与运行用同一个量，N_exp 才可比。

### D-SB-7 下一件基线：每台相机各取自己见到的最高 frame_counter

- 问题：规格 §3 帧序号取 SDK 帧号；PLC 不报触发计数。
- 采用：每台相机下一件的帧计数下限 = max(该相机原基线, 该相机本件见到的最高 frame_counter)（`Grouper::max_counter` → `Ledgers::set_frame_floor`，记在 `Ledger.frame_floor`，接件时由 `shot_router::arm_frames` 与本会话最高帧计数取大）。故障复位（`Ledgers::clear_floors`）清掉下限，之后只按实际见到的计数定基线。
- 理由：相机偶发丢末帧（已计数、帧没送到）只会让下一件出现两个不完整帧组，且下一件后自动对齐。

### D-SB-8 采集轮次帧数与存储

- 问题：规格 §5 取消示教轮次的帧数上限，示教轮次不核对计数。
- 采用：采集轮次（`CaptureRoundV2`）不设帧数上限、不核对计数；图像为无压缩 PGM，一帧一个文件，帧元数据在 `frames.jsonl`。

### D-SB-9 采集轮次完成判据

- 问题：规格 §5 不再用计数做结束校验，§3 缺帧只告警。
- 采用：轮次只来自导入（D-SB-49），导入时状态直接为 Complete；各相机帧数、不完整组和丢帧告警写进轮次记录（`CaptureRoundV2`）。

### D-SB-10 帧序号来源：frame_counter

- 问题：规格 §3 帧序号取 SDK 帧号；`camera.rs` 的 frame_counter 是“有 Chunk 帧计数用它，否则用 nFrameNum”。
- 采用：`camera.rs` 的 frame_counter 取值符合规格，不改。示教采集轮次以 `Frame.frame_counter − 该相机基线` 作 seq；生产改按相机时间戳编号（D-SB-55），帧号只留作诊断与手动帧判断；生产的 Policy 信任 ChunkFrame、SdkFrame、ChunkTrigger 三种来源的 frame_counter，离线另外信任 Synthetic。trigger_counter 只作诊断。

### D-SB-11 设备模型：三台独立单视角相机

- 问题：原相机配置 `view_count ∈ {1,3}`，三视角靠 `composite_layout` 拆拼接图；规格 §0 一次采集 = 三台独立相机各出 1 帧，§1 Plan.cameras = 3 台设备 id。
- 采用：段配方的计划相机必须是 3 个互不相同、单视角（`view_count = 1`、无 `composite_layout`）的设备；不满足时段配方校验报错，接件时本件记检测错误。相机配置本身仍允许三目拼接，标定页对单视角相机不选视角。
- 回退：若决定彻底停用三目拼接，在相机配置加载处拒绝。

### D-SB-12 所有帧都测

- 问题：原模型同 Pose 组只检所选的一张；规格 §0 所有帧都参与每帧独立检测，不裁帧。
- 采用：检测相机在它负责的段内每帧都测，没有组选图；其余相机标 `NotInspected`（D-SB-45）。

### D-SB-13 缺帧、多帧、未完成的结论

- 问题：原模型缺帧判 ERR 91，多帧 / 超计划判 ERR 96，未完成判 ERR 99；规格 §0/§3 某台缺帧时该组照常判，组和整件标“检测不完整”，不影响 OK/NG，帧数超出容差只告警。
- 采用：缺帧（含回调通道满、内存预算满、测量队列满、测量失败、走出走廊）→ 组标 incomplete，整件 `flags.incomplete`；帧数越界 → `frame_count_anomaly`；都不改 OK/NG。只有三台相机整件一帧都没有时才判 ERR 91；检测中相机重开（会话变化）不再判 ERR（D-SB-55），时间戳回退的相机之后的帧不收，缺的帧组标检测不完整。96 不再使用，常量保留。

### D-SB-14 三台相机结论取最差

- 问题：规格 §0 所有帧都参与独立检测。
- 采用：可信段区域只取本段检测相机的最差，未分段区域按每帧预测段的检测相机取最差（D-SB-45）；任一参与检测的帧 NG，所在区域即 NG，整件取最严重结论。

### D-SB-15 胶偏判定：段级 AbsoluteX 与 ToEdge

- 问题：原模型逐站与示教中线比对，以及特征定位；规格 §4 直线段去首尾各一帧，用 x 均值 − x_ref 判整段偏移、最大偏差判局部跑偏，中线逐点比对停用；§0/§1 有稳定边缘用 ToEdge，否则 AbsoluteX。
- 采用：每帧输出 `x_mm`（帧内胶中心相对走廊的法向偏移均值，即 AbsoluteX）。胶偏只在 Straight 区域按段判（`burst_judge`）。ToEdge 在模型中保留，结果标“胶偏未判：测量量未实现”（默认做法 2）。不做中线逐点比对与特征定位。
- 修订（已实现）：D-SB-48 实现 ToEdge：找边参数配在 `offsetRef.edge`，每帧输出胶边距 `edge_mm`，判定口径同上，参考值取图纸胶边距或测量示教件得出的 x_ref。
- 回退：`offsetRef` 选 `AbsoluteX`。

### D-SB-16 胶宽均匀性

- 问题：规格 §4 直线段胶宽 / 均匀性按段级 min/max/mean 检，弯道用弯道允差，未分段用较宽允差。
- 采用：`WidthCheck` 有 `max_range_mm: Option<f64>`（区域内各帧 `width_mean` 的极差上限，默认 None 即不检），只在 Straight 区域判，超限 NG_WIDTH，原因“胶宽不均”。Corner 和 Unsegmented 不判极差，只判每帧胶宽。每帧胶宽按 `widths × spacing_mm` 算帧内累计超差长度，不超过 `max_excursion_mm` 为 OK_WITH_EXCURSION。逐站宽度以 `f32` 保存，逐站比较时上下限也转换到同一精度，避免恰好合格的边界值因存储舍入被计入超差；溢胶缺少原始最大宽度、从逐站值回退时同样处理。原始 `f64` 极值仍按原精度判定。默认胶宽 4 ± 1.5 mm、帧内允许超差 5 mm（`plan::KindDefaults`）。开了偏宽只预警（D-SB-61）时只累计偏窄的站。

### D-SB-17 检测走廊

- 问题：规格 §4 中线逐点比对停用，保留边缘提取。
- 采用（默认做法 4，经 D-SB-42、D-SB-45 修订）：走廊只决定 ROI 和测站，按“段 × 该段的检测相机”示教，存在 `CameraInspect.segments`；胶条走出走廊时该帧记 `OutOfCorridor`（检测不完整），不判 NG。全流程验收用合成直线 / 弯道三相机；真实样本集是停稳拍数据，只做冒烟。

### D-SB-18 胶偏参考值 x_ref

- 问题：规格 §0/§1 `offset_ref.x_ref` 取标准件多轮测量均值，只用于 Straight 段。现场没有多轮采集，建配方用真实历史件与维护件。
- 采用：示教件兼作标准件（[recipe-build-flow](recipe-build-flow.md) RB-3）。`x_ref` 由“测量示教件”（`workspace_measure_teaching`）自动算出，不能手填：只给单段配方的直线段，用已示教的走廊按示教件分段测量每一帧，参考相机去掉首尾各一帧（再去掉起涂、收尾帧，D-SB-50）后取测成帧的胶中心 x（AbsoluteX）或胶边距（ToEdge 且没填图纸胶边距时，D-SB-48）均值；只有一件，`spread` 记 0。多段配方暂不计算 x_ref（不阻断发布）。`OffsetRef` 有 `camera` 字段（三台相机几何不同，不能共用 x_ref），默认取计划第一台相机。走廊身份（走廊、当量、检测参数、站距、出胶点、定向参数、专家参数、扇区方向）变了，测量即失效、x_ref 自动清空，需重新测量。没测量时 `x_ref`、`spread` 为 null。

### D-SB-19 计划版本身份

- 问题：规格 §1 段序列、类型、相机绑定变化分配新版本，限值、容差、x_ref 变化沿用。
- 采用：段身份 = `product_code` + 各段 `(index, kind, expected_frames)` + 有序 cameras + `expected_total`（`plan::plan_identity`）。限值、容差、x_ref、inspect_range、length_mm 不参与。`same_plan` 按它判断是否沿用 `plan_version`。
- 理由：换示教件或改分段使 N_exp 变化时，帧数核对与比例分段随之改变，计划版本要能区分（默认做法 6）。

### D-SB-20 就绪与发布前置

- 问题：规格 §1 新建时 expected_frames = null 标“待标定”，未标定不能发布，§0 N_exp 不能手填。
- 采用：`Recipe::ready_burst` 要求每段每台检测相机有走廊、相机有当量、各段都有 N_exp（示教件分段已确认，D-SB-45）。`update_doc` 不采用传入的 `expected_frames`、`calib`、`part_calib` 与 x_ref，沿用候选当前的值（界面拿着旧值保存也不报错）；段的序列或 kind 改变时清空全部 N_exp、calib、x_ref，待示教件按新段结构重新确认分段。发布时当场核对发布前检查，独立正常样本验证可选（D-SB-46）。

### D-SB-21 各段 N_exp 取自示教件

- 问题：规格 §2 同一程序连续采集多轮、逐段取帧数均值作 N_exp。现场没有多轮采集，建配方只用真实历史件与维护件。
- 采用：示教件即基准件（[recipe-build-flow](recipe-build-flow.md) RB-3）。分段确认后（候选每次改动后），软件把示教件已确认分段里各段的帧组数写成该段 `expected_frames`，`calib` 记 1 件（min = max = mean = N_exp）；ΣN_exp 取各段之和，`part_calib` 不写。示教件分段未确认或已失效时各段 N_exp 为 null、界面标“待示教件分段”，不能发布（D-SB-45）。帧数波动由容差吸收（D-SB-24 的默认 2 帧，可逐段确认修改）。

### D-SB-22 检测范围与未检区域

- 问题：规格 §0/§1 每段写明 inspect_range [a_mm, b_mm]，结果页标“未检区域”。
- 采用：`PathSegment.inspect_range` 显式配置；`burst_judge` 按配方算出 `[0, a)` 与 `(b, length_mm]` 放进 `BurstJudgement.uninspected`，段长未知时 `to_mm` 为 null，界面按 mm 展示。
- 修订（2026-10-26，用户确认）：毫米区间从未在判定中排除帧（软件不把毫米换算成帧号），结果却写“未检区域”，会误导。改为按帧：`PathSegment.skip_head` / `skip_tail`（段首、段尾跳过的帧组数，0–1000，不进计划身份）。`resolve_regions` 把跳过的帧划为 `RegionKind::Skipped`，优先于过渡区；分段可信时按各段首尾定位，未分段或合并区域里只有贴着整件首尾的第 1 段段首、末段段尾能定位。`burst_judge` 对跳过区域不取任何相机：不判定、不计检测不完整；`BurstJudgement.uninspected` 按帧组号列出（`fromSeq` / `toSeq`），旧记录的 `fromMm` / `toMm` 照旧读取显示。`inspect_range` 保留读取但停用，段列表遇到旧区间提示清除；计划导出另带 `skipHead` / `skipTail`。第 1 段段首、末段段尾的跳过帧数由示教件测量给建议（D-SB-50）。

### D-SB-23 触发方式固定为 Fly

- 问题：配方有 `TriggerMode` Fly | Stop；规格 §0 只有飞拍。
- 采用：段配方固定写 Fly，界面不展示触发方式，离线节拍按帧率，不读 `trigger_mode`。`RecipeSummary.trigger_mode`、`parts.trigger_mode` 列保留。

### D-SB-24 新建模板：三台相机、一个直线段

- 问题：规格 §1 cameras = 3 台，容差默认 ±1，直线与弯道分别设。
- 采用：新建模板取相机组前三台（不足 3 台也建，但无法发布），附一个 Straight 段，`expected_frames = null`。`segment_defaults` 的 serde 默认值即 `KindDefaults::default()`（straight、corner 的 tolerance 都是 2），`new_segment` 从这里取。N_exp 只取一件示教件，没有多件统计，容差按 2 帧覆盖边界与起止相位的波动（D-SB-40 现场最差约 2 帧）；操作员可在试测页逐段确认修改（`workspace_confirm_tolerance`），不另给建议值。

### D-SB-25 计划导出

- 采用：`plan::PlanExport` 与命令 `recipe_plan_export`；工作区视图带 `WorkspaceView.plan.productionExport / candidateExport`，旧字段 `productionPlc / candidatePlc` 为 null。配方总览不设“PLC 对接参数”面板：协议 8 的 PLC 只需型号，已发布配方的型号与 ΣN_exp 看配方库卡片摘要。

### D-SB-29 检测记录结构

- 问题：规格 §3/§4/§6 要记录每台相机每一帧、帧组、段、不完整组、未检 / 未分段区域。
- 采用：`part_frames` 表与 `parts` 的段配方列（ΣN_exp、Σtol、各相机帧数、整件标记、整份区域判定 `burst_judgement`），本机记录库版本 10（[history-scope](history-scope.md)；D-0：版本不符时备份后重建）。
- `part_frames` 主键 (part_id, camera, seq)，入库时帧数不要求等于预期，但 (camera, seq) 唯一、相机属于计划相机、指标身份与帧一致，摘要结论与区域判定相同；原图引用按 (camera, seq) 只增不换。
- 审计 spool FORMAT 4，原图引用 `files[].frame` 有值即段配方帧。录制文件名 `{相机}_s{seq:06}.pgm`，part.json 有 `missingFrames`（相机没出图，只追溯，录制仍可完整）与 `rawDropped`（录制队满没录，证据 Incomplete）。
- 历史重判 `Overrides` 有 `straight` / `corner`（按段类型覆盖胶宽上 / 下允差与帧内允许超差长度，`maxGapLen` 作用于每帧）；用当前候选重判时计划身份或走廊、当量、标定、检测参数变化跳过并记 LayoutChanged，重判结果 `changes[].flags` 带出整件标记。CSV 末尾有段配方的帧数与标记列；时间线 Entry 与运行日志字段有 `seq`。

### D-SB-30 发布包与标定键

- 问题：规格 §0 三台独立设备，没有视角。
- 采用：`release::publish_burst` 按相机组织，写 schema 5（D-SB-45：每台相机一份标定，它检测的每段一张示教帧与一条走廊）；段配方的标定键为设备标定 `device/{device}`（`vision::CalibKey::Device`，文件 `calib/device/plane_calib_{device}.json`）。
- 标定页（`CalibPanel`、飞拍标定页）对任何相机都带图编号，单视角相机为 1。`vision_calibrate` 对单视角相机的图 1 同时写 `{device}-v1` 与设备标定，两份内容相同；三目拼接相机的图 N 只写 `{device}-v{N}`；不带图编号只写设备标定。`vision_calib_info` 带图编号读 `{device}-v{view}`，不带读设备标定。没有回退读取：只存过 `{device}-v1` 的单视角相机，要在标定页重新标定一次才会生成设备标定。
- 设备标定放单独子目录 `calib/device/`，与工位标定的扁平文件名 `plane_calib_{键}.json` 永不同名（相机编号允许 `-`，`cam1-v1` 与 `cam1` 的图 1 会撞名）。发布包 `calibration.json` 的 `reference` 对设备标定记 `device/{device}`，显式标定引用仍记引用本身。

### D-SB-34 本件未检与提前结束

- 问题：规格 §0 PLC 不提交请求（或提前终止）时整件按未检处置。
- 采用（默认做法 3）：PLC 不提交请求时 PC 没有记录，由 PLC 记未检。提前结束由 PLC 提前报工件结束表达，PC 用已收到的帧照常判，帧组数 < ΣN_exp − Σtol 时加 `flags.short_part`（疑似提前终止），历史中单独显示，不改 OK/NG。在途 PLC 进入故障或复位时，本件按中断记 ERR 98（[core-flow.md](core-flow.md) D-CF-6）。

### D-SB-35 采集轮次的一致性校验

### D-SB-40 人定段结构，生产按比例定位边界（2026-10-26 用户确认，已实现）

- 问题：分段算法未开发（D-SB-21），生产整条胶路按未分段处理，胶偏不判，也无法按段选相机和走廊（D-SB-41、D-SB-42）。现场数据 NEW-14（2026-10-24，同一正式程序空跑已涂胶工件，16 轮完整，20 fps）各轮帧组数 35–39；以 R01 为参考按图像逐帧对齐后，同一胶路位置在其余 15 轮的帧号偏差：按原帧号映射最大偏差中位 1 帧、最差 2.5 帧，按总帧组数比例映射中位 1 帧、最差 2 帧。偏差主要来自使能电平与帧时钟的起止相位，比例换算消不掉。
- 采用：
  - 段结构（序列、类型）、每段检测相机（D-SB-41）与走廊（D-SB-42）由人定。各段 N_exp 取示教件已确认手动分段的各段帧组数（D-SB-21）；手动边界只作 N_exp 的来源与分段算法评估的真值，不直接进生产。
  - 生产新增比例分段器：判定在本件收尾后进行，总帧组数 `total` 已知；第 k 个边界 = round(total × C_k / ΣN_exp)，C_k 为前 k 段 N_exp 之和。`total` ∈ ΣN_exp ± Σtol 时各边界置信度 1，否则 0（全部合并为 `Unsegmented(LowConfidence)`）。有任一段 N_exp 为 null 时仍返回 `Unsegmented(AlgorithmPending)`，即现行行为。
  - 边界余量：配方新增 `boundary_guard`（帧，默认 2，可配 0–5，不进计划身份）。每个可信边界两侧各 `boundary_guard` 帧划为过渡区域（`UnsegReason` 新增 `Transition`）：只判每帧胶宽、断胶、溢胶，允差取两侧较宽一档，不判胶偏与胶宽均匀性。取代 `resolve_regions` 现行的“边界两侧各一帧归弯道”。直线段核心区域仍按 D-SB-15 去首尾各一帧判胶偏。
  - 段长：直线段每一头先去掉过渡区与本段跳过帧（D-SB-50）中较多的一截（两者从同一端数起、互相重叠；第 1 段开头、末段结尾没有过渡区），胶偏判定再去掉区域首尾各一帧（D-SB-15）。N_exp 少于“两头去掉的帧数 + 3”时没有帧判胶偏，该段标胶偏未判，发布前检查给出警告（不阻断）；默认过渡 2 帧、不跳过时，中间直线段至少 7 帧，第 1 段与末段至少 5 帧。弯道段不限。警告按 N_exp 核对，本件帧组数少于 ΣN_exp 时各段按比例变短，贴着门槛的段仍可能取不到帧。
  - 比例边界是推算值，不逐段核对帧数；帧数告警仍只核对整件（第二节）。
- 理由：现场数据的边界偏差在默认余量 2 帧以内；判定在整件收尾后进行，比例映射所需的总帧组数在判定时已知；复用示教件已确认的分段与 `resolve_regions`，不需要图像算法即可上线按段判定。
- 现场偏差超过余量时须重新评估段结构、速度与边界余量；图像运动细化属于待开发方向（D-SB-43），没有可用的自动回退实现。多段配方不能以段 N_exp 保持 null 的方式发布。
- 实现（2026-10-26）：`segmentation::Proportional`；`resolve_regions` 增加 `guard` 参数，过渡区为 `Unsegmented { reason: Transition }`，覆盖边界两侧的段，取代“边界两侧各一帧归弯道”。生产节拍、示教件测量的 boundaries.json、独立样本验证、历史复测与重判都改用它。`RecipeDoc` / `Recipe` 新增 `boundaryGuard`（serde 默认 2，校验 0–5，不改配方 schema 8，旧文件读作 2），段列表页可编辑。`burst_judge`：过渡区不判也不标胶偏、不计入 `flags.unsegmented`；直线 / 弯道区域 `count_status` 恒为空（帧数只核对整件与未分段区域）。发布前检查：多段配方直线段 N_exp 不够去掉过渡区、跳过帧与首尾各一帧后留 1 帧时在“段帧数”里提示，x_ref 检查区分“已有各段 N_exp（多段配方暂不计算 x_ref，运行时标胶偏未判）”与“示教件分段未确认”。单段配方仍未分段，行为不变。
- 离线评估：`src-tauri/examples/segment_eval.rs` 对已确认手动分段做留一评估（见 [TESTING](../testing/TESTING.md)）；NEW-14 尚未标手动分段，评估结果待补。
- 修订（D-SB-62）：配方有示教件的笔结构时，边界按笔换算，比例分段只在没有笔结构的配方上使用；两笔之间的边界不留过渡区。

### D-SB-41 每段指定检测相机（修订 D-SB-14，2026-10-26 用户确认，已实现，测成率建议待实现）

- 问题：D-SB-14 三台相机每帧都参与判定、取最差。相机围在胶嘴周围，不同段只有部分相机能看到出胶点附近的胶条；其余相机的帧走出走廊只能记检测不完整（D-SB-13），整件结果被“检测不完整”淹没。规格 §1 已把“相机绑定”列入计划身份（D-SB-19 问题描述），但段模型没有这个字段。
- 采用：
  - `PathSegment` 新增 `cameras`（检测相机，计划相机的非空子集；新建与旧数据默认全部计划相机）。
  - 可信的直线段、弯道段区域只用本段检测相机的帧判定，取最差；未选中相机的帧照常测量、落库、录图供追溯，但不参与判定，也不计检测不完整。过渡区域取两侧检测相机的并集；未分段区域（算法未就绪、置信度不足）退回全部计划相机，即 D-SB-14 现行做法。整件 ERR 91 口径不变。
  - 检测相机由人在分段标定工作台逐段选；测成率只作提示（D-SB-45）。
  - 计划身份：各段 `cameras` 进入 `plan_identity`（按规格 §1），变化时分配新计划版本。
- 理由：只让能看到胶条的相机判这一段，避免检测不完整掩盖真实结果；默认全部相机等于现行行为。
- 限制：NEW-14 数据是已涂胶工件空跑，胶嘴未对准胶条，测成率偏低且不代表生产；正式绑定须用实际涂胶的件核对。
- 回退：各段 `cameras` 设为全部计划相机。
- 实现（2026-10-26，按用户要求提前到分段标定时选相机）：`PathSegment.cameras`（serde 默认空 = 全部计划相机，`plan::segment_cameras` 给出实际相机）；`validate_segments` 校验子集、不重复、胶偏参考相机属于本段相机；`plan_identity` 纳入各段实际相机（列全三台与不指定等价，不换版本）。`burst_judge`：直线 / 弯道区域只取本段相机的帧判定与计算检测不完整，过渡区取两侧并集，未分段区域全部相机；整件 `flags.incomplete` 改为各区域的检测不完整之并；`camera_frames` 仍按全部相机计数供追溯。分段标定工作台在段下方逐段点选相机（至少一台），没选中的相机缩略图变暗；段列表卡片显示检测相机，走廊示教页的胶偏参考相机只能选本段相机。改相机不改段签名，已确认的边界不失效。测成率提示尚未实现。

### D-SB-42 按段示教走廊（修订 D-SB-17，2026-10-26 用户确认，已实现）

- 问题：D-SB-17 每台相机一条走廊、所有帧共用。相机相对胶嘴固定，画面里只有出胶点位置不变；直线段内胶条方向不变，弯道里胶条绕出胶点旋转，一条固定走廊只能对齐示教帧附近的路径，NEW-14 数据上大部分帧走出走廊。
- 采用：
  - 直线段：该段每台检测相机示教一条段走廊，示教帧必须落在该段内（按示教轮次已确认的手动分段判断）；走廊从出胶点一侧起画，沿胶条方向。
  - 弯道段：用一条从出胶点起画的短走廊，示教页提示长度上限（默认 8 mm，超过只警告）；弯道仍只判胶宽、断胶、溢胶（D-SB-15 不变）。胶条走出走廊照旧记 `OutOfCorridor`。
  - 像素当量与检测参数按相机设置，不按段；走廊没有相机级兜底（D-SB-45）。
  - 生产按预测段选走廊、收尾后补测归属变了的帧（D-SB-45）；示教件测量按已确认边界、历史复测按已解析区域选走廊。
- 理由：直线段方向不变，固定走廊可覆盖整段；弯道只能靠贴近出胶点的短走廊减小旋转造成的偏移（约为走廊长度 × 转角正弦）。
- 实现：
  - 数据：`CameraInspect.segments`（`[{segment, corridor}]`，按 `PathSegment.index`）存段走廊；段示教帧记在 `Workspace.cameraTeaching`（`segment` 必填），导出、验证样本独立性、屏蔽保护覆盖全部示教帧。`cameraTeaching[].segments` 给出每段示教帧与是否已保存。
  - 示教：`workspace_teach_segment_corridor` 冻结一帧，要求这台相机是该段检测相机、帧组落在该段内（多段配方要求示教轮次已确认手动分段）；同一相机各段示教帧尺寸相同。走廊随候选整份保存（`workspace_save_doc`），每条段走廊须有对应段示教帧。`workspace_clear_segment_corridor` 去掉一段的走廊与示教帧。工作台保存分段时走廊与段示教帧按示教件帧范围迁到对应的新段（D-SB-52），没有可比的旧边界时段的类型序列变化即一并清空。
  - 示教页：相机行只设相机参数，相机下列出它检测的段；选段后在已确认分段的轮次里只能选本段帧组；弯道走廊超过 8 mm 只提示。

### D-SB-43 图像运动细化边界（2026-10-26 列入后续，未排期）

- 问题：比例边界依赖各轮速度曲线一致；工况变化（减速、暂停）会让偏差超出余量。
- 采用（方向）：逐帧估计工件在画面中的平移与旋转（直线段以平移为主，弯道以绕出胶点的旋转为主），在比例边界附近把边界对准运动转折点，置信度取转折强度。实现时需增加运动特征输入与搜索范围，当前没有相应占位接口。以 NEW-14 16 轮已确认的手动分段为真值离线评估，验收：≥ 95% 的边界误差 ≤ 1 帧；另需实际涂胶轮次复核。
- 理由：工件运动不依赖胶嘴是否对准胶条，空跑数据即可开发；边界之外的段结构、相机与走廊仍由人定，只替换比例分段器的边界定位。
- 与 D-SB-45 的关系：细化只在收尾后移动边界，归属变了的帧走 D-SB-45 的收尾补测（补测原图从本件录制读回，D-SB-60）。

### D-SB-44 分段标定工作台（2026-10-26 用户确认，P1 已实现）

- 问题：段结构在段列表页填表定义、看不到图像；边界在采集页按帧号手填、一次只看一台相机；操作员无法判断怎么分段（NEW-14 调试时卡在这一步）。
- 采用：段列表页顶部是分段标定工作台，模板固定为示教件（[recipe-build-flow](recipe-build-flow.md) RB-1），不选轮次。三台相机的缩略图按帧组排成时间轴：点帧间竖缝插入或删除边界（可拖动），点段名按 直线 → 弯道 → 不检测 循环切换（D-SB-53），点缩略图在下方并排预览三台相机原图（叠加已示教走廊）；← → 切换帧组，B 在当前帧组后插入或删除边界。保存时用组合命令（`workspace_segment_template_save`）在同一候选副本上依次替换段列表（受 `guard_calibration` 约束）、保存并确认示教件边界，任一步失败整体不写入；确认后软件按示教件各段帧组数写 N_exp（D-SB-21）。段参数、走廊与示教帧按示教件帧范围逐段对应（D-SB-52），没动的段原样保留；保存前预演，有走廊清除、段结构改变或示教件测量失效时弹窗逐条列出。段的数量、顺序与类型只在工作台改，段列表页只编辑各段参数；两边都有未保存改动时互相锁定，避免修订冲突。缩略图由 `recipe_capture_round_thumbs` 按相机一次取整轮（8× 箱式平均下采样，前端 canvas 按通道数直接画灰度或彩色）。
- 图像对齐：`frame_align::align_cuts` 把一件的边界按图像对齐到另一件（两件全部帧 32× 箱式平均成 40×32 小图，逐相机平均绝对差除以该相机距离中位数后取平均，首尾固定、带宽 max(3, 0.15·M) 的 DTW；模板帧 c、c + 1 所配目标帧中位数的中点即边界，保持严格递增），可信判据见 D-SB-51。只示教件一件定分段，应用里没有其余件的边界复核，对齐算法只用于离线评估 `segment_eval`。
- 后续（同一决策，待实现）：P3 运动曲线与自动建议。P4 即 D-SB-41，已实现。

### D-SB-45 走廊只按段，相机只留参数（修订 D-SB-17、D-SB-21、D-SB-41、D-SB-42；2026-10-26 用户确认，已实现）

- 问题：
  - 走廊表示一帧里胶条在画面上的位置，这个位置由工件此刻走到胶路的哪一段决定，与相机本身无关。D-SB-42 之后每台相机仍保留一条“默认走廊”，用于兜底：没示教段走廊的段、过渡区、未分段区域，以及相机量它不检测的段（只为追溯）。
  - NEW-14 调试中，三台相机的检测段都画了段走廊后默认走廊已无用处，但示教仍要求它（7169fa9 先放宽了示教与标定）；生产、验证样本、历史复测仍只用默认走廊，段走廊发布了却不生效。
  - 默认走廊的示教帧还承担了“相机像素当量、图像尺寸、设备标签”的来源，把相机参数和某一帧绑在一起。
- 采用：
  - 模型
    - 相机（`CameraInspect`）只留相机参数：像素当量、标定引用、检测参数（极性、搜索半宽、胶宽范围；为空用配方默认）。去掉 `corridor` 和相机级示教帧。像素当量默认取设备标定，可手填。
    - 走廊归“段 × 该段的检测相机”：每一段、它的每一台检测相机各一条走廊和一张示教帧，示教帧必须落在该段内（按示教轮次已确认的手动分段）。没有“默认走廊”，也没有兜底：缺任何一条，走廊示教就没完成。
    - 存放位置沿用 D-SB-42 已实现的 `CameraInspect.segments`（`[{segment, corridor}]`），不移到段上：已示教的段走廊原样保留，段编辑路径不受影响。`segment` 所指的段必须把这台相机列为检测相机。走廊不进计划身份（不影响 PLC），但进示教件测量的走廊身份（x_ref 可比性）。
    - 段相机变化：从某段去掉一台相机，同时去掉它在该段的走廊与示教帧（界面先提示）；加一台相机，该段这台相机变为“待示教”。段的类型序列变化时走廊按 D-SB-52 逐段对应。
    - 同一台相机的全部示教帧尺寸必须相同；测量图按这个尺寸建。示教帧各自记设备标签，发布检查逐帧核对（取代“相机示教帧采集后设备参数改变”）。
  - 生产怎么选走廊（判定仍在收尾后，D-SB-40 不变）
    - 到达时按预测段测：帧到达时总帧组数未知，按累计 N_exp 预测所属段（第 seq 帧属于满足 seq ≤ C_k 的最小 k，超过 ΣN_exp 的帧归最后一段），只用预测段的检测相机、各自在该段的走廊测量。不检测这一段的相机不测这一帧，只录图（不计检测不完整，同 D-SB-41 对未选中相机的口径）。
    - 收尾后补测：drain 完、总帧组数已知后，先按 D-SB-40 得出区域，再找出“判定需要、但到达时没用对应走廊测过”的（帧, 相机）：区域归属与预测段不同的帧；过渡区里需要另一侧检测相机、或需要另一侧走廊的帧。这些帧用解析后所属段（过渡区为该相机检测的那一侧）的走廊补测，补测完再判定。补测期间件仍在收尾中，下一件照常等待当前件释放。
    - 补测原图：内存里不为补测留图，补测时从本件录制目录读回原图（D-SB-60）；没录到原图的帧记检测不完整，不改 OK/NG。
    - 过渡区每台相机取用规则：帧按比例边界落在哪一段，该段检测相机用该段走廊，只检测最近边界另一侧那一段的相机用那一段的走廊；每台相机每帧只用一条走廊，没测成即检测不完整，不再换另一侧补救。短段使相邻过渡区合并（中间的段被取空）时同样逐帧按所在段与最近边界取，不拿首尾两段的走廊量中间段的帧。
  - 未分段的处理
    - 置信度不足（总帧组数超出 ΣN_exp ± Σtol，D-SB-40）：整件合并为未分段区域，不补测；每帧用到达时的预测段结果、预测段的检测相机，允差取较宽一档，不判胶偏与均匀性（D-SB-16），照常标 `frame_count_anomaly` 与 `unsegmented`。修订 D-SB-41“未分段退回全部计划相机”：其余相机看不到胶条，强行测量只产生检测不完整。
    - 有段没有 N_exp（`AlgorithmPending`）：多段配方无法预测所属段，也就无法选走廊，因此须各段都有 N_exp（示教件分段已确认）才能发布、进生产。单段配方所有帧归第 1 段，不受影响。
    - `skip_head` / `skip_tail` 跳过的帧照常按预测段测量（到达时无法确定），判定不取（D-SB-22）。
  - 示教件测量、验证样本、历史复测
    - 示教件测量：按示教件已确认的手动分段，每帧只用所在段的检测相机和走廊测量，不测其余相机。只统计检测相机在本段的测成率，低于 80% 在试测页提示，相机仍由人在分段标定工作台选。
    - 验证样本、历史复测（原图）：与生产同一套“预测段 + 收尾补测”，共用实现，结论口径一致。
    - 每帧记录增加所用走廊的段号；补测帧记补测结果，到达时被取代的结果不入判定（可留在帧明细供追溯）。用存储指标重判（`same_measurement_layout`）要求计划身份与各段走廊都不变，否则走原图复测。
  - 发布包与生产加载
    - 测量图从“每台相机一张”改为“每段 × 检测相机一张”（算法图 schema 升版），发布包冻结每张段示教帧；预热在每张示教帧上各测一次，没测成的（段, 相机）生产不测（D-SB-59）。
    - 发布检查“走廊示教”：每段每台检测相机都有走廊且落在示教帧内、相机有像素当量、各示教帧设备标签未变；各段 N_exp 见“段帧数”。
  - 不迁移（用户确认）：放弃相机走廊。读入旧数据时丢弃 `CameraInspect.corridor` 与相机级示教帧（`cameraTeaching` 里 `segment` 为空的记录），不复制到各段；缺段走廊的（段, 检测相机）即为待示教。配方 schema 不升版（读入时忽略旧字段）。旧发布包（每台相机一张测量图）不再加载，生产须用新候选重新示教并发布。
- 测量量估算（NEW-14，按已确认的 16 轮手动分段与 R01–R14 均值 N_exp = 4/10/9/6/8、各段检测相机 1/1/1/2/1、`boundary_guard` = 2 推算，未实测）：现行每件 3 × 36 ≈ 108 次测量；到达时按预测段测平均 42 次，收尾补测平均 20 次、最多 21 次（主要是过渡区需要另一侧走廊或相机的帧），合计约 62 次，减少约 43%。预测边界与比例边界最多差 2 帧。补测 20 帧按 7.1 的 4 线程吞吐（约 100 fps）约 0.2 s，计入收尾时间。
- 理由：
  - 走廊和段一一对应才与图像事实一致；去掉兜底后，“相机看不到胶条的段”不再被量成检测不完整，测量量随之下降。
  - 判定本来就在收尾后进行，补测只覆盖少量归属变动和过渡区的帧，比“边界附近全部双测”算得少，也不受预测偏差上限的约束。
  - 相机参数与示教帧解绑后，像素当量、检测参数只在一处改，不随换帧丢失。

### D-SB-46 发布不再要求独立样本验证（修订 D-SB-20；2026-10-26 用户要求，已实现）

- 问题：发布生产配方要先在验证与发布页选独立整圈样本、跑整套图像验证并通过（规格 §0/§1 独立验证，D-SB-20），发布时还要核对验证后相机、标定与生产版本没变。NEW-14 调试中样本轮次已被示教占用，验证成了发布的额外负担；用户要求简化发布逻辑，不再需要验证。
- 采用：
  - 发布前检查在发布时当场核对（`burst_release::publish_checks`）：相机配置、示教件、走廊示教、段帧数（各段 N_exp）、示教件采集参数、胶偏参考 x_ref（不阻断项照旧）、生产版本；全部满足即可发布，不再要求 `Workspace.validation` 通过，也不再比对验证时的环境标签。检查结果随待生效版本存档（`Release.validation`，样本为空）。
  - 新增只读命令 `workspace_publish_checks`，验证与发布页按候选修订当场展示；发布按钮只看这些检查与计划本身（各段 N_exp、三台相机）。
  - 独立样本验证保留为可选工具（`workspace_validate`，页面“独立样本验证（可选）”），结果照旧展示，不影响发布；进度里“验证”步骤标为可选，“发布”步骤只要求示教件、分段、走廊示教完成；单段配方需要示教件得出的胶偏参考时，“试测”步骤也是前提，其余情况试测可选。
  - 步骤条与菜单里“验证与发布”改名“发布”。
  - 不要求相机在线（用户要求，2026-10-26）：原“设备与采集”改为“相机配置”，只核对计划相机在相机组里有配置、来源一致、三台互不相同的单视角相机；相机是否连上、就绪不在发布时核对，接件时照旧检查。发布包记录的采集配置取相机组配置，不读在线设备。
- 理由：发布前检查已覆盖设备、示教件、走廊示教、段帧数与生产版本这些硬条件；样本验证的结论由操作员按需在发布前或上线后核对。

- 回退：`workspace_publish` 恢复要求当前修订的 `validation.passed` 并比对环境标签，进度把“验证”改回必经步骤。

### D-SB-47 逐帧定向测量（修订 D-SB-42、D-SB-45 的走廊选择，取代 D-SB-43；2026-10-27 已实现，按段开关，新建的段默认开启）

- 问题：
  - 现行走廊是示教中线两侧各 `searchMm` 的搜索带，中心偏移容差 = 搜索半宽 − 胶宽上限的一半。胶条横向小幅偏移在容差内能测到，但走廊方向固定。
  - 生产按帧号预测所属段、选该段走廊（D-SB-45）。比例边界与真实边界最多差 2 帧（D-SB-40，NEW-14）。直线段内帧前后偏移没有影响，胶条方向不变；到了段边界和弯道，胶条方向已变，所选走廊方向不对，帧走出走廊，记检测不完整。
  - 弯道靠贴近出胶点的短走廊减小旋转偏移（D-SB-42），可测长度因此很短，而且没有经过真实弯道图像验证（默认做法 4）。收尾补测与过渡区两侧走廊都是为弥补“按帧号选走廊”。
- 采用：
  - 示教兼容：不另起一套示教流程，以现有的按段走廊示教为基础（D-SB-42、D-SB-45）。逐帧定向是按段的开关，新建的段默认开启（段列表新增或重建的段、新建配方的第一段），已有的段不变；关闭的段照旧用示教走廊、按预测段选取，行为与 D-SB-45 完全相同。
    - 出胶点：按相机标定，在开启定向的段的示教帧上用“标出胶点”点胶嘴出胶处，这台相机各段共用，须在示教帧内。没有标定时取这台相机开启定向的各段走廊起点的中位数（D-SB-42 规定走廊从出胶点一侧起画；中位数不被个别画偏的起点拉走）。手画起点总有偏差，起点离推算点超过 1 mm 只提示偏得最远的那段，不阻断试测与发布。画面里胶条的起点不一定是出胶点（例如 NEW-14 空跑件胶条贯穿全画面），推算值只作兜底。
    - 示教页叠加：选中开启定向的段时，示教帧上叠加出胶点（标定的为绿色，推算的为橙色并标“推算”）、跳过段 [0, s₀]（灰色圆盘）、测量区间环带 [s₀, s₀ + L] 和搜索扇区（黄色扇形），扇形只画到扇形扫描实际看的范围（区间前 150 px），试测时另画实测方向；各部件带编号 1–5，与右栏“逐帧定向”面板的行和面板里的示意图一致，指着面板某一行时图上只突出这个部件。扇区由后端按已保存的出胶点算出，与测量图一致；扇区上的 4 号把手可拖动，转到哪个方向就把这台相机在本段的扇区中线存为那个方向，这台相机其他段不变。走廊有未保存的修改时只显示出胶点、环带和拖过的扇区。
    - 方向不按段示教：扇区默认取出胶点背离最近画面边的半圈（见“定向与测量”的扇区），不用示教方向，也没有方向范围和回退方向。自动的半圈不合适时（例如胶嘴斜着装、胶条贴着画面边走），在这一段的示教帧上拖动扇区转到合适的方向，存为这台相机在这一段的 `sectorDeg`，面板上可“恢复自动”。拖出的扇区按（相机, 段）存，不在相机的各段间共用：同一台相机直线段与弯道的胶条出去的方向不同，转了一段的扇区不能牵动其他段。段上的方向容差（`toleranceDeg`，默认 5°）只用于细化分段边界，界面上不显示。
    - 已示教的候选不用重新示教。开关全部关闭时，schema 5 发布包照常加载；打开后才写入新字段。计划身份是否随开关变化待定：开关影响测量，但不影响 PLC。
    - 某段定向不可靠时（例如胶嘴遮挡、反光），只关这一段，退回固定走廊。
  - 测量区间：按段设置，本段各检测相机共用，界面上填“跳过胶嘴附近前 s₀ mm”和“测到距出胶点 s₀ + L mm”，配方存起点 s₀ 和长度 L（`HeadingSettings.window`），按各相机的像素当量换算成像素。每帧只测沿胶条方向、距出胶点 s₀ 到 s₀ + L 的一段。
    - 按段而不按相机：不同笔的胶条长短差得多（1SS2_10R3 NEW-3 的短笔只有约 28 mm），相机级共用的区间在短笔上测不满、在长笔上又嫌短。区间是沿胶条的物理距离，与相机无关，所以同一段的各检测相机共用。
    - 新开启定向的段（新建的段、打开开关的段）写入默认 s₀ = 5 mm、测到 20 mm。
    - 兼容：以前按相机存的区间（`CameraInspect.window`）不迁移、原样保留，段没设区间时沿用这台相机的区间；两者都没有时列为定向前置问题（需设置）。旧配方与已发布包因此测量范围不变；界面不再编辑相机级区间，段上填了就以段为准，清空段上的值即回到沿用相机级区间。
    - 跳过 0 到 s₀，是为了避开胶嘴遮挡、反光和刚挤出、还没稳定的胶堆。
    - 不测 s₀ + L 以外，是因为弯道里胶条在画面上是弧线，摆直的窗口离出胶点越远偏得越多，远处还受透视和焦深影响。
    - 打开定向的段不再用示教走廊的形状，胶路由图像拟合得出（见“定向与测量”），只取弧长 [s₀, s₀ + L] 这一段测，宽度沿用检测参数的搜索半宽。
    - 这一截取与 D-SB-22 的段首、段尾跳过帧不同：D-SB-22 按时间跳过整帧，这里在一帧之内按距离截取。两者可以同时生效。
  - 定向与测量：测量图是模板 `graphs/heading.lyflow.json`，每（相机, 段）一组参数：`glue.response` 算一次响应图，`glue.fan_scan` 在扇区里取前三个峰、各接一个 `glue.track_path`（粗跟踪与拟合）与 `glue.lateral_runs`（横向卡尺）。
    - 参数：`nozzle` = 出胶点；`zone` = [s₀, s₀ + L] 换算成像素；极性、胶宽上限沿用这台相机的检测参数。响应图只算出胶点 ± 检测区外沿 + max(胶宽上限 + 8, 卡尺半长 + 5) 的一块。
    - 定向：扇形扫描在扇区 `sector` 里取前三个相距 > 15° 的峰，每个峰沿它的方向粗找胶点、拟合成一条光滑胶路，能跟随缓弯。粗找时卡尺按半高拆分暗段，较淡一段的峰值不低于较浓一段的 0.4 才合并（1.1 按连通段）：胶条旁有平行的阴影或凹槽时，连通段把两者连成一段、超出胶宽上限，胶条上只接上一半左右的点，覆盖率反而不如旁边的阴影（NEW-1 cam1 段 3：示教帧选中了胶条左侧的阴影，末帧胶条转到扇区边上后接不上、回退；改后本段 4 帧 120 站由 86 站有胶变为全部有胶）。合并比取 0.4 而不是 0，是因为胶条中间有反光时被切成两半，量出的边缘陡度偏低、会被当成不像胶（现场件 cam1 一帧陡度 0.39，低于 `pathSharpMin` 0.4）。GlueSight 选方向（`vision/judge/fit.rs`）：得分 = 覆盖率 ×（像胶 ? 1 : 0.1），射线响应不到最强峰四分之一的再打对折；先只在最强峰与扫描得分里是局部峰的候选中取最高的，它找不到胶时才在全部候选中取（与 1.1 不同：1.1 直接在全部候选中取，扇区边上得分一路升上去的方向起跑、接上同一条胶后覆盖率更高时会被选中）；覆盖率 ≥ `minCoverage`、边缘陡度 P25 ≥ `pathSharpMin`、胶点 ≥ 3 才算找到胶。θ 取拟合胶路在检测区里首尾连线的方向（度，图像坐标 0° 朝右、−90° 朝上），不取候选的起跑方向，同一条胶的读数因此不随起跑方向跳动。定向与测量共用 `zone`：内半径 s₀ 避开胶嘴附近，跳过距离 s₀ 不宜为 0——s₀ 为 0 时各方向射线的前一段都落在出胶点附近同一片暗区，扇形扫描分不出方向（seg-new14 cam2：起点 0 mm 时扇区内得分 190–200 连成一片，起点 5–10 mm 时只剩胶条方向一个峰）。
    - 扇区：以出胶点为圆心的半圈（180°，`heading::search_sector`），中线取这台相机在这一段拖出的方向 `sectorDeg`；没拖过时背离离出胶点最近的画面边。胶嘴装在画面边上，刚挤出的胶条从出胶点往画面里延伸，胶嘴本体在画面边那一侧；不取“朝画面中心”：出胶点偏离画面中线时半圈会斜过去，贴着画面边走的胶条落到扇区外（cam3 出胶点偏左 90 px，扇区转 14°，两件各有一帧往左走的胶条丢失）；弯道转多少度都在扇区里，不需要按段示教方向。扇区写进这一（相机, 段）测量图的参数，随发布包冻结；帧按预测段选测量图（D-SB-45），段边界上被预测到相邻段的帧用相邻段的扇区，两段都没拖过扇区时两者相同。按段示教的方向范围在弯道上框不住：NEW-1 cam1 段 3 四帧方向从 140° 转到 39°，允许偏离已到上限 45° 仍有末帧落在范围外。
    - 没找到胶条：灰度测量在方向不满足门限时按全段无胶处理；彩色 `extent` 只有在有效跟踪候选均证明没有胶且没有未知步时按全区无胶处理，其余为路径不可信，记录未知及检测不完整，不能误报断胶。不再按示教方向回退重测：扇区已覆盖胶条可能的方向，回退只会在同一片区域里换个窄范围重找。
    - 测量结果：测站与胶边取自选中那条的横向卡尺，每站按 1.1 拟合胶路的规则（D16）判有无胶。卡尺按半高拆分暗段（1.1 按连通段）：胶条旁有平行暗带、两者之间的响应谷底不够深时，连通段会把它们连成一段、超出胶宽上限，整站判无胶（NEW-1 cam2 段 2 示教帧 31 站丢 10 站）。代价是胶条中间有反光、截面呈双峰时会被切成两段、都窄于胶宽下限，离出胶点几毫米内最常见（NEW-14 cam1 段 3：跳过 5 mm 时 1995 站少 16 站，有胶 ≥ 80% 的帧数不变）；`AbsoluteX` 对拟合胶路没有意义，定向测量的段胶偏只能按 D-SB-48 的 ToEdge 判。每帧另记 θ 与是否没找到胶条（指标字段沿用旧名 `headingFallback`），没找到时记下原因（覆盖率不足或边缘太缓不像胶），本段试测与试测页的逐帧查看里显示。
    - 没拖过扇区时，搜索角度与扇区都不依赖帧属于哪一段，所以到达即可测。
  - 覆盖核对：按示教件测量逐段核对窗口能否接上相邻帧。
    - 胶条每帧在画面里后移 v / fps。用已有数据估算这一后移量：段长（`PathSegment.length_mm`）÷ 该段 N_exp。
    - 开启定向的段，它的检测相机窗口 L 小于后移量时，相邻帧窗口之间有一截胶测不到，断胶可能漏检。试测页逐段提示，发布前检查“段帧数”里列为不阻断提示。
    - 段长没填的段不核对，提示补填。
    - L 超过后移量 3 倍时提示：同一处胶会被测多次，测量量无谓增加。
  - 跟随核对：拟合的胶路能跟随缓弯，急弯跟不住。示教件测量按段统计定向测量的帧数与没找到胶条的帧数，超过 20% 时在试测页提示缩短 L 或减小 s₀。开启定向的段不再看 D-SB-42 弯道走廊固定的 8 mm 长度提示。
  - 分段（配方开关 `boundaryRefine`，默认关闭）：直线段的 θ 平稳、弯道连续变化。直线段开了定向的“直线—弯道”边界，在比例边界 ± (两段容差之和 + 1) 帧内对准直线段检测相机的 θ 开始偏离（或回到）该段方向的帧：每台相机的参考方向取它在直线段核心帧上的 θ 中位数，偏离阈值为方向容差，一帧多数相机偏离即算离开直线段；只用找到了胶条的帧，窗口内没有方向数据时保留比例边界，置信度不变。这一条取代 D-SB-43 的平移、旋转估计。
  - 与 D-SB-45 的关系：采用后，打开定向的段选窗口不再依赖帧属于哪一段，到达即可按 θ 测。收尾补测只剩“判定需要的检测相机到达时没测”这一种情形。允差、检测项仍按区域在判定时取，不需要补测。
- 理由：
  - 相机相对胶嘴固定。实际涂胶时，胶条从出胶点伸出，方向就是工件此刻相对胶嘴的运动方向。
  - 按图像逐帧定向，帧前后偏移和弯道转动就不再让胶条走出走廊。
  - 方向序列直接反映直线与弯道，比推算的比例边界更贴近每一件的实际情况。
- 前提与风险：
  - “胶条锚定在出胶点”只在实际涂胶时成立。NEW-14 是空跑已涂胶的工件，胶条随工件一起运动，只能验证方向搜索本身，不能验证锚定这一前提，必须用实际涂胶轮次复核。
  - 出胶点附近的遮挡、反光与胶堆可能干扰定向，s₀ 要按真实图像调整。
  - 相机斜着看，画面远近的像素当量不同，s₀、L 按单一当量换算会有误差，影响要用真实图像确认。
  - lyFlow 1.1 `bead_path` 的说明列出了这套自由搜索（1.2 拆成扇形扫描与粗跟踪，规则不变）的弱点：缺胶时会顺着旁边零件翻边的暗边走（断口位置报错，原则上还可能放行），胶团、急弯、起胶与收胶段跟不住。`zone` 避开出胶点、粗找按半高拆分与选方向的门限是针对这一点的措施，效果要靠离线评估确认。

- 实现（2026-10-27）：
  - 模型：`PathSegment.heading`（`{toleranceDeg, window?}`，None = 关闭；`toleranceDeg` 校验 0–45°，只用于细化分段边界；`window` 为本段测量区间 `{startMm, lengthMm}`，起点 ≥ 0、长度 > 0、终点 ≤ 500 mm）；`CameraInspect.window`（旧配方的相机级区间，校验同上，段没设时沿用，见 `heading::window`）；`CameraInspect.nozzle`（`[x, y]` 图像像素，0–100000 的有限数）；`SegmentCorridor.sectorDeg`（这台相机在这一段的扇区中线方向，度，±360° 内的有限数，None = 自动）；`RecipeDoc.boundaryRefine`。都按 serde 默认读旧文件、不升配方 schema，都不进计划身份。`heading`、`window`、`nozzle` 与 `sectorDeg` 进测量布局（`same_measurement_layout`）与示教件测量的走廊身份（`sectorDeg` 随段走廊项进身份，没拖过的段不写这一项，标签与之前相同），变了就不能用已存指标重判，示教件测量失效、x_ref 清空。

  - 分段：`segmentation::segment_part` 按 `boundaryRefine` 选比例分段或 `refine_by_heading`，生产节拍与历史重判、验证样本、原包重现共用；示教件测量写的 boundaries.json 仍按比例分段（只作追溯）。
  - 前端：走廊示教页右栏只有一个“逐帧定向”面板，顶部是编号示意图，每行参数带同样的编号：1 出胶点（看状态、清除标定，这台相机各段共用）；选段时另有本段开关、2 跳过胶嘴附近、3 测量到（本段各检测相机共用；没设时显示沿用的相机级区间，开了定向却都没有时标“需设置”；可“套用到其余开启定向的段”；段长与 N_exp 已知时就地提示短于每帧后移量或超过 3 倍）、4 搜索扇区（显示范围与是否拖过、含扇形扫描看的距离，拖过的可“恢复自动”；在示教帧上拖动 4 号把手转动）、5 方向读数；选相机时列出开了定向的段及各段的测量区间与来源。面板末尾“什么算找到胶”放专家参数里“定胶路”一组（覆盖率、最长断口、陡度等），其余专家参数仍在“专家参数”卡片；开启定向的段的示教帧上有“标出胶点”模式和定向叠加，示教帧下方“本段试测”可逐帧或全段只读试测示教轮次里本段的帧，看实测方向与没找到胶条的帧，几何取自 `CameraTeachingView.nozzle` 与 `SegmentTeachingView.heading`；段列表参数“按胶条方向细化边界”（有段开了定向时可用）；试测页逐段列出提示；逐帧查看显示方向与是否没找到胶条。

### D-SB-48 胶偏以工件边为参考（实现 ToEdge，修订 D-SB-15、D-SB-18 与默认做法 2；2026-10-27 已实现）

- 问题：相机相对胶嘴固定，`AbsoluteX` 是胶中心相对走廊、也就是相对胶嘴的偏移，主要反映出胶偏斜。工件位置轻微扰动时，胶相对工件偏了，但胶相对胶嘴不变，`AbsoluteX` 测不到。示教件得出的 x_ref 只能扣掉系统偏差。
- 采用：
  - 测量：参考相机的测量图（示教走廊与 D-SB-47 的定向测量都有）里，`glue.part_edges` 与横向卡尺同一条胶路、同样布站，输出每站两侧的全部零件边跳变；取边、选侧、剔野、算距离在 GlueSight（`vision/judge/edge.rs`，与 1.1 `glue.edge_distance` 同口径）。不依赖 D-SB-47 是否采用。
    - 做法：沿每个有胶测站的法向，从胶边外 3 px 起往外找零件边：第一个满足极性、两侧灰度差 ≥ `contrastMin`、远侧持续 ≥ `farRun` px 都暗下去的跳变；零件边在哪一侧按多数测站判（两侧站数相同时这一帧胶偏记未测）；逐站结果沿弧长做滑动中值剔野。
    - 工件边的检测区域就是这些测站法向上的搜索段：沿胶条方向的范围与胶宽测量相同（D-SB-47 采用后即 [s₀, s₀ + L]），法向范围 = `searchLength`。不另画多边形。
    - 胶偏 = 每帧各站胶中心（`reference = bead_center`）到零件边距离的均值，像素按相机当量换成 mm；与胶宽同帧、同测站。
    - 找不到边（各站 `status` 多为 none）时，该帧胶偏记未测，不判 NG。区域内可用帧不足时，标“胶偏未判”。
  - 参数：走廊示教页选段时“检测项”卡片里胶偏参考选“到边缘距离”时设零件边极性、搜索长度（mm）、对比度下限与可选的图纸胶边距，作用于胶偏参考相机（`offsetRef.camera`）。`glue.part_edges` 在 `packaging/runtime.json` 的 `requiredOperators` 里。
  - 判定：沿用 D-SB-15 的段级口径。直线核心区域去掉首尾各一帧，均值与参考值之差判整段偏移，最大偏差判局部跑偏。参考值填了图纸胶边距就用它（多段配方也能判），否则用测量示教件得出的胶边距均值（D-SB-18 的 x_ref 取 ToEdge 口径，与 AbsoluteX 一样只在单段配方里算）。
  - 模板匹配：不用于找胶条。胶条没有纹理，沿路径方向定不准，所以横向位置以边缘检测为主。模板匹配（lyFlow 有 `glue.locate`）只考虑用于两件事：一是工件扰动超过 `searchLength` 时，借角、孔等特征给找边做初定位；二是判断当前帧落在胶路哪一段（与 D-SB-44 的图像对齐同一思路），作为 D-SB-47 方向序列的补充。直线段的工件边同样没有纹理，只能给出法向偏移。找边稳定性有数据之前不做。
- 理由：工件扰动造成的胶偏才是要拦下的质量问题，参考必须取工件本身；胶边距不受胶嘴与相机安装偏差的影响。
- 前提与风险：
  - 每段要在参考相机画面里有稳定可见的工件边。没有的段继续用 `AbsoluteX`，或不判胶偏。
  - NEW-14 空跑数据里胶和工件一起运动，胶边距可以测，能验证找边是否稳定，但不代表实际涂胶时的胶偏分布。
  - 找边取远侧持续变暗的跳变（默认亮 → 暗），翻边上的划痕、反光不易抢走；但零件边的明暗关系因工件而异，极性要按真实图像设。耗时计入吞吐。
- 离线评估（2026-10-27，NEW-14 直线段的检测相机，`heading_eval`，示教走廊按真实段 + `edge_distance`，`searchLength` 200 px，`reference = bead_center`）：空跑数据里胶与工件一起运动，同一轮同一直线段内胶边距应近乎不变，轮内标准差可看作测量噪声。
  - 亮 → 暗：找到边（≥ 半数测站）s1 36/57、s3 128/144、s5 85/126，胶边距轮内标准差中位 1.0 / 2.9 / 2.8 mm。
  - 暗 → 亮：s1 19/57、s3 128/144、s5 85/126，轮内标准差中位 0.0（样本少）/ 1.5 / 0.23 mm。
  - 结论：极性因段而异，必须按段（参考相机）设置；s5 暗 → 亮的噪声 0.23 mm 可用于判 ±2 mm 的胶偏，s3 的 1.5 mm 偏大、s1 找边率低，需按真实图像调整 `contrastMin`、`farRun` 或换参考相机。
- 离线评估（2026-11-06，现场件 f2d30b6d 胶色段，NEW-1 第 2 段以 cam1 为参考相机，钣金边在胶的一侧、胶与边之间是拉丝金属面，亮 → 暗，搜索长度 18 mm）：
  - `contrastMin` 40 时拉丝纹理的暗谷（十几 px 宽、落差 100 以上）抢在钣金边前面：稳态 26 帧只有 12 帧有胶边距，值 6.3–8.5 mm 且跳动。
  - `contrastMin` 70 时 26/26 帧有值，中位 9.98 mm、逐帧标准差 0.29 mm；与独立参考（每站胶边外剖面上 30 px 窗口落差最大处）之差中位 −0.15 mm、最大 0.33 mm。

- 实现（2026-10-27）：

### D-SB-54 按 Line0 门控关闭提前收尾（2026-11-02 用户确认，已实现）

- 问题：PLC 报工件结束后固定等满收尾窗口（默认 1000 ms）才判定，每件白等近 1 s；想按相机信号判定“帧已收完”。现场 JHEM131GC-XS 没有 GenICam 事件（没有 `EventSelector`）、不支持 Chunk；PLC 侧不再加复杂度。
- 现场实测（`examples/camera_event_probe.rs`，2026-11-02，一次门控、三台各 22 帧）：
  - 状态寄存器 `LineStatusAll` 的 Line0 位空闲读 1、拍照时读 0（与触发的“高电平有效”相反，光耦反相），三台看到边沿的时刻相差 1–2 ms。
  - 门控开始后第一帧几乎立刻曝光；每帧从相机时间戳到 PC 收到约 39 ms，三台同时到达；门控结束时末帧已在约 60 ms 前到达。
  - 读一次电平平均 0.23–0.25 ms，个别一次读卡住 0.5 s；`Counter0` 设为统计 Line0 跳变后始终为 0，不可用。
- 采用：
  - 每台按 Line0 触发、已打开的海康相机一个线程，每 5 ms 读一次 `LineStatusAll` 第 0 位（`camera::watch_gate`）。空闲电平取“1 s 没来帧时读到的电平”，不按触发方式推断极性；没打开、已释放给 MVS、读失败或空闲电平还不知道时不报状态。各相机的读数汇总在相机组共用的 `gate::Gate`。
  - 收尾截止（`Part::burst_deadline`）：partEnd 后等满 `drain_ms`；或本件用到的相机里读数新鲜（50 ms 内）的都看到门控关着，且取其中最晚看到关闭的时刻，又过了 `gate_guard_ms`（默认 80 ms，盖住末帧约 39 ms 的在途时间），提前截止。截止后到的帧照旧不收，已接受的帧照旧测完、照旧收尾补测。
  - 不提前、照旧等满收尾窗口的情况：没有新鲜读数（读卡住、相机没开）、有相机看到门控开着、空闲电平还没学到、模拟与样本集相机、`gate_guard_ms = 0`。学错极性时 PLC 报结束时会读成“开着”，同样不提前，不会丢帧。
  - 设置页“门控关闭后收尾（ms）”：0 或 40 ms 到收尾等待之间。
- 待核：只测了一次门控、一件；多件、段间开关门控与长时间运行下末帧在途时间的分布，用探测程序或生产记录的收尾耗时（`drainMs`）继续观察。
- 回退：`gate_guard_ms` 设为 0。

  - 丢帧只能靠三台帧数对比推断（`loss_alarms`），说不出丢的是哪一帧。
  - 收尾（D-SB-54）只知道“门控关了”，不知道最后一帧是第几帧，只能再等一段余量。
  - 现场 JHEM131GC-XS 不支持 Chunk、没有事件，拿不到相机侧的帧计数或触发计数（`counter_after_open` 一直未知，靠首帧定基线）。
- 依据（`camera_event_probe` 现场实测，2026-11-02）：
  - 相机时间戳（`MV_FRAME_OUT_INFO_EX` 的 `nDevTimeStampHigh/Low`，`GevTimestampTickFrequency` = 1 GHz）在相机重开后连续：两次运行相隔约 23 分钟、中间重开过相机，cam1 的时间戳差约 1383 s，与墙钟一致；只有断电或 `DeviceReset`、`GevTimestampControlReset` 才会归零。
  - 门控内出帧严格等间隔：21 个间隔共 2100.028 ms，每帧 100.001 ms，累计偏差 < 0.03 ms。
  - 门控一开就曝光：首帧时间戳比看到门控开始时锁存的相机时钟早 1.5 ms（边沿到曝光只有去抖与检测延迟）。三台相机看到同一门控边沿的时刻相差 1–2 ms。
- 采用（待评审）：
  1. **帧身份 = (门控号 g, 门控内序号 i)**，只用每台相机自己的时间戳，不需要三台时钟同步：
     - 帧周期 T 取配置帧率（`configuredFrameRate` 回读），开流后再用门控内相邻帧间隔的中位数校准。
     - 同一台相机相邻两帧间隔 Δ：Δ ≈ k·T（与最近整数倍相差 < 10%）且其间没有门控边沿时，属同一门控，i 加 k（k ≥ 2 即这台相机丢了 k − 1 帧）；否则开新门控，i 从 0 起。
     - “其间有没有门控边沿”看 D-SB-54 的轮询：看到边沿时同时锁存这台相机的时钟，所以能判断边沿是否落在两帧的时间戳之间。轮询不可用时只按 Δ 判，Δ ≈ k·T（k ≥ 2）而另外两台都没有这些空位时，按新门控处理（三台丢同一批帧的可能可忽略）。
  2. **seq（帧组序号）在一件内跨门控连续**，与现在的帧组、N_exp、按比例分段口径一致：seq = 前面各门控的槽数之和 + i + 1。门控 g 的槽数 = 三台在该门控的最大 i + 1，与“门控关闭时锁存的时钟换算出的应有帧数”取大，这样即使一台丢了门控末帧，后面门控的 seq 也不会错位。三台的门控号按一件内的先后顺序对齐，并用各门控开始边沿换算到 PC 时间互相核对（差 > 半个帧周期时记告警，不改编号）。
  3. **件的边界**：接件时每台相机记下“上一件最后一帧的时间戳”作下限，时间戳不大于它的帧算上一件的迟到帧（对应现在的 Stale）。不再需要帧号基线与 `counter_after_open`。
  4. **相机重开不再判 ERR**：会话变了但时间戳连续（不回退、没有大跳），照常编号；只有时间戳回退（相机断电或被复位、时钟归零）才算这台相机断档，之后的帧本件不收，这台相机缺的帧组标检测不完整并告警，不改整件结论。整件 ERR 只保留三台相机一帧都没有（91）等现有情形。
  5. **收尾按应有帧数结束（取代 D-SB-54 的固定余量）**：门控关闭时锁存的时钟 C 给出这次门控应有的最后序号 L = max{i : t_开 + i·T < C}。三台都收到 L（或 L 之前确实丢了、超过余量）就算这次门控收完；PLC 报结束且最后一次门控收完即判定。C 与 t_开 + L·T 相差不到一次轮询间隔（边沿正好卡在曝光开始附近，第 L 帧可能有也可能没有）时，第 L 帧最多再等 `gate_guard_ms`。实测末帧在看到门控关闭前约 60 ms 就到了，多数件看到关闭即可判定。
  6. **门控就是现成的段间分隔**：一件内的门控序列即笔结构，分段边界按它对齐（D-SB-62）。
- 数据与接口：
  - `Frame` 增加相机时间戳（换算成纳秒，`Option<u64>`）；`FrameInfo` 已有 `dev_ts_high/low`，只是取图回调没带出来。打开相机时读一次 `GevTimestampTickFrequency`。
  - 模拟与样本集相机给合成时间戳：序号 × 帧周期，门控时间由输入图像来源提供。
  - 检测记录先不加列；帧录制的 `part.json` 每帧加相机时间戳，供离线复核与回放按同一规则重算。
- 迁移：用户要求不经并行比对，直接切换。生产配组只用时间戳编号；帧号只留作诊断、手动帧判断与下一件台账（不再决定 seq）；示教采集轮次仍按帧号。
- 实现：
  - `frame_clock::FrameClock`（编号器，纯逻辑）；`Frame.dev_ts`（海康按 `GevTimestampTickFrequency` 换算成 ns，模拟 / 样本集为帧计数 × 100 ms 的合成时钟）；`CameraSlot::clock_now`（接件时锁存相机时钟作下限）、`frame_period_ns`（打开时确认的帧率）。
  - `camera::watch_gate` 在门控边沿时锁存相机时钟交给 `gate::Gate`（`opens` 只在这台相机 30 ms 内读过电平时给出，否则编号退回按帧间隔判）。帧只归入锁存时钟不晚于其时间戳 15 ms（`EDGE_SLACK_NS`，轮询与锁存误差）的门控开始边沿，前一门控在途的末帧不会被算进刚开的门控；轮询中断漏记边沿、按边沿数得出的门控号小于已按帧间隔推断的门控号时，以帧间隔为准，并记下差额对齐之后的边沿；边沿晚于这台相机上一帧（超过 `EDGE_SLACK_NS`）即新门控，门控号至少比上一帧加一。门控起点取边沿加上相机的触发延时（`triggerDelayUs`）。门控号取相机组共同的门控开始序号（`Gate::edge`：不同相机看到的开始相差 100 ms 内算同一次，同一台相机又看到一次开始总是新的一次），从接件时相机组的门控开始次数起算，一台相机漏看一次门控也与其余相机对齐，接件时读不出相机时钟也不会把上一件的门控算进来。轮询学空闲电平要求没来帧且电平本身不变都满安静时长（不短于三个帧周期），空闲后门控刚开、第一帧还在路上时不会把拍照电平学成空闲。
  - `Part::receive_burst` 按 `FrameClock::stamp` 编号后交给 `Grouper`（基线恒为 0）；新增到达类型迟到帧（`Late`）、时钟回退（`ClockBack`）、没有时间戳（`NoClock`），都只丢帧并每件每台告警一次。`check_sessions` / `check_observed` 不再因会话变化报故障。
  - 收尾（`Part::burst_deadline`）：门控关闭、各计划相机最后一帧时间戳 L 都满足 L + 帧周期 > 关闭时锁存的时钟 C、且 L 属于这台相机最近一次门控（不早于最近一次开始边沿超过 `EDGE_SLACK_NS`）时立即截止；否则按 D-SB-54 等余量。
  - 帧录制 `part.json` 每帧带 `deviceTs`。
- 待核：现场多件、段间开关门控时的门控对齐与收尾耗时；只测过一次门控。
- 计划的测试（每条对应一条规则）：
  - 同一台相机门控内丢一帧：Δ = 2T 时 i 跳 2，这一帧组标缺帧，后面的 seq 不错位。
  - 门控关闭后很快又开（Δ < T 或 Δ 不是 T 的整数倍）：开新门控；有轮询边沿时以边沿为准。
  - 一台相机丢了门控末帧：门控槽数取三台最大，下一门控的 seq 三台一致。
  - 相机检测中重开（会话变、时间戳连续）：照常编号，不判 ERR；时间戳回退：这台相机之后的帧不收，标检测不完整。
  - 上一件的迟到帧（时间戳不大于下限）不计入本件。
  - 收尾：三台都收到应有的最后序号即完成；边沿卡在曝光开始附近时最多等余量。
  - 相关但不在本条：用 `UserSetSave` + `UserSetDefault` 把触发、帧率等配置存进相机，断电重启后自带正确配置（缓解“相机开关”的另一半问题），另行评估。
- 回退：没有配置开关，回退到上一个发布版本的软件。

  - 开启时：
    - 帧内只累计低于下限的站。超过允许超差长度判 NG_WIDTH，原因“胶宽偏窄”；不超过判 OK_WITH_EXCURSION。
    - 高于上限的站与超出溢胶上限的帧不判 NG，也不计入超差长度。区域记预警 `RegionResult.warnings`（`wide` / `overflow`），整件标 `flags.wide_warning` / `flags.overflow_warning`，原因末尾附“预警：区域：胶宽偏宽、溢胶”。
    - 整件结论与 PLC 结果码按其余项照常给出：只有偏宽时为 OK（1）。
  - 未分段区域合并检查项时，有一段开启即开启（预警是更宽的一档）。
  - 胶宽不均（D-SB-16 的极差上限）不受影响，照常判 NG_WIDTH。
  - 展示：标记与历史 CSV 写“胶宽偏宽”“溢胶预警”，运行日志各记一条；宽度曲线上偏宽与溢胶用预警色。
- 回退：把各段 `wideWarnOnly` 关闭。

### D-SB-62 一次门控即一笔：按笔对齐分段，每笔首尾跳过（修订 D-SB-40、D-SB-50，实现 D-SB-55 第 6 条；2026-11-07 用户确认，已实现）

- 问题：
  - 机械臂每次起涂打开、收胶关闭拍照信号，一件里多次开关。每笔刚开始时胶条还没铺满走廊，直接检测会判断胶，应从第 3、4 帧开始判。
  - 段跳过帧（`skip_head` / `skip_tail`）挂在段上，段边界按比例推算，有 ±2 帧误差，分段不可信时中间段的跳过不生效。示教建议也只给第 1 段段首和末段段尾。
  - 有些笔极短（只点一下或一小段线），跳过起涂后已经没有帧可判。
- 依据：1022 工位四件录制（2026-11-06），三台相机在相同帧组号后同时停顿。正常帧间隔 200 ms，停顿 640 ms 至 19 s。四件分别有 37、97、10、4 笔，其中很多笔只有 2–5 帧。相机开关与出胶几乎同步，收胶时最后一帧基本就是结尾。
- 采用：
  - **笔结构**：各笔的帧组数，seq 在一件内跨笔连续（D-SB-55）。
    - 生产取帧编号器的门控槽数（`FrameClock::gate_slots`），截到本件帧组数（`passes::from_slots`）。
    - 示教件与轮次样本按帧记录的时间戳重算（`passes::from_times`）：帧周期取同一台相机相邻 seq 间隔的中位数；相邻两个 seq 之间，两帧都在的相机里多数看到间隔超过 1.5 个帧周期，就在后一个 seq 开新笔。丢帧（seq 不相邻）不算停顿。
    - 本件的笔结构记进判定 `BurstJudgement.passes`。重判、复测、重现与历史样本都从记录里取；旧记录没有笔结构，按没有笔处理。
  - **示教件的笔结构**：选示教件时按轮次帧记录算出，记在候选的 `teachingPiece.passes`；旧候选在保存分段时补上。各段 N_exp 写入时（`calibrate_from_teaching`），帧组数与已确认分段一致的笔结构一并写进配方 `pass_frames`（`passFrames`）。和 N_exp 一样不能手填，保存时不采用传入值；不进计划身份。
  - **分段**：
    - 本件笔数与示教件相同、各段 N_exp 之和等于示教件的帧组数时，示教件的每个段边界逐个按笔换算（`passes::map_cuts`）。
      - 边界正好是示教件某笔的最后一帧时，取本件同一笔的最后一帧，即硬边界（`Boundary.hard`），不留过渡区，方向细化也不动它。
      - 边界落在笔中间时，按这一笔本件与示教件的帧组数比例换算，并留在本笔内。两侧照旧各留 `boundary_guard` 帧过渡区，方向细化（D-SB-47）只在本笔内移动。
    - 两边笔数不同时，比例边界一律置信度 0，整件按未分段判，记 `flags.pass_count_anomaly`（笔数异常，只告警）。`BurstJudgement.expected_passes` 记示教件笔数。
    - 配方没有笔结构时照旧按比例分段（D-SB-40）。
    - 到达时预测段：本件第 j 笔第 i 帧，换成示教件第 j 笔的第 i 帧（超出取该笔末帧）后，再按累计 N_exp 预测。笔数多时累计误差不再越滚越大，收尾补测随之减少。
  - **每笔首尾跳过**：
    - 配方 `pass_skip`（`passSkip.head` / `tail`，0–50，不进计划身份）给出每笔开头、结尾跳过的帧组数。新建配方开头取 2，结尾取 0；旧配方读作 0。
    - 只要知道本件的笔结构就生效，不论分段是否可信。跳过的帧划为 `RegionKind::Skipped`，区域与 `uninspected` 记第几笔（`pass`，从 1 起）。
    - 一笔的帧组数不超过首尾跳过之和时，整笔不检，标 `short`，结果写“第 j 笔（太短，不检）”。段跳过（`skip_head` / `skip_tail`、不检测的段）已覆盖的帧不重复标。
  - **示教建议**：试测页“每笔起涂”按 D-SB-50 的成形规则，在测量过的示教件上逐笔数起涂帧组数（帧所在段的检测项与检测相机），建议取各笔最大值。没有连续成形帧组的笔（点胶、很短的线）不参与，列出原因。操作员确认后写 `pass_skip`（`workspace_pass_skip_suggest` / `workspace_confirm_pass_skip`）。
  - **发布前检查**：“段帧数”按示教件的笔结构核对，去掉过渡区与跳过帧后示教件上没有可判帧的段，提示“生产整段不检”（不阻断）。
- 代价：
  - 每笔开头 N 帧里的真断胶会漏判。
  - 笔数与示教件不同的件整件按未分段判，不判胶偏。
  - 样本集、模拟相机没有门控停顿，一件就是一笔：新建配方的每笔开头跳过只作用于整件开头。
- 回退：把 `passSkip` 置 0。删掉配方的 `passFrames` 后，分段回到按比例。

- **走廊提取**：`workspace_extract_corridor` 按 `camera`（相机 id）找到 `plan.cameraTeaching` 里这台相机冻结的示教帧，`imageId` 必须等于该帧 id（不等报“图像已变化”）；按亮度找两侧胶边，胶比背景暗还是亮自动判断，这台相机的检测极性（没有时取配方默认）只决定两种都像时先试哪种（[r2-algorithm](r2-algorithm.md) RA-6）。示教帧是彩色时，示教页的刷选改调 `workspace_snap_corridor`：与示教 MCP `teach_corridor` 的 `color` 同一吸附（偏移上限为笔刷半径），沿吸附后的走廊取色，走廊与颜色模型一起写进候选、只推进一次修订；缺像素当量、吸附或取色不可用、走廊核对不过时候选不变，原因放在 `message`。框选和灰度帧仍用 `workspace_extract_corridor`。
- **读图命令的参数口径**：`camera` 在在线与历史命令里是计划相机下标（与 `FrameGroupView.cells`、`FrameRecord.camera` 一致）；示教轮次命令用 `cameraId`（与 `CaptureRound.cameras[].cameraId` 一致）。
- **前端调用**：上表命令前端直接调用（`desktopCall`），失败按普通错误显示。

## 六、口径

- **seq**：`frame_counter − 该相机基线`，从 1 起；frame_counter ≤ 基线为 Stale（上一件迟到帧，不计入本件）；同一相机重复的 seq 为 Duplicate，保留先到的那帧。
- **帧数 = 帧组数**：区域帧数 = `last_seq − first_seq + 1`；整件或整轮帧组数 = 各相机最大 seq 的最大值。示教件分段与运行同一口径。单台相机的帧数只用于丢帧告警：与另外每一台相机都相差 > 1（`frame_group::loss_alarms`；[10, 10, 8] 只有第 3 台告警，前两台彼此一致，不因第 3 台少帧被连带告警），每台相机至多一条。
- **每相机基线**：接件时取各相机本会话见到的最高 frame_counter 与上一件推算的下限中较大者；下一件基线 = max(原基线, 该相机本件见到的最高 frame_counter)（`Grouper::max_counter`，D-SB-7）。
- **帧数越界只告警**：区域帧组数 ∉ [N_exp − tol, N_exp + tol] 记 `frame_count_anomaly`，该区域照常检测，不改 OK/NG。运行时只有覆盖全部段的未分段区域，与 `expected_total ± tolerance_total` 比较。
- **short_part**：整件帧组数 < `expected_total − tolerance_total`（`expected_total` 为 null 时不判）。
- **expected_total**：各段 N_exp 都非空时为其和，否则为 null（`part_calib` 不再写入；已有配方文件里的值在缺 N_exp 时照常读取）。**tolerance_total** = Σ 各段 tolerance。
- **N_exp**：示教件已确认分段里这一段的帧组数（分段确认时自动写入，`calib` 记 1 件）；容差取段类型默认值 2 帧，操作员可逐段确认修改，不给建议值。

### 7.1 吞吐摸底（实测，2026-10-22）

**怎么跑**（探针是 `src-tauri/examples/throughput_probe.rs`，不是测试，不在 `cargo test` 里；写约 4 GB 临时文件、结束后自动删除，约 1 分钟；已发布的运行库即可；dev profile 构建，与下面记录的数值同一配置）：

```powershell
$env:LYFLOW_CORE_DLL = 'src-tauri\target\dependency-cache\lyflow\1.1.5\lyflow_core.dll'
cargo run --manifest-path src-tauri/Cargo.toml --example throughput_probe
```

**量的是什么**：1280×1024 灰度图、一条横穿的暗胶条；走廊 121 mm、121 个测点（间距 1 mm），只用中线测量的算子（glue.taught_path + glue.bead_width），与走廊测量是同一组算子。经生产加载路径（`release::publish` → `release::load` → `Prepared::load` → `warm`）后用 `Prepared::measure` 计时，包含 `Engine::run` 里的像素拷贝、lyFlow 运行与结果解析。每个并发度测 300 帧。写盘用生产录制的 `image_file::save_pgm`，每张 1,310,720 B 像素 + 17 B 头。

**环境**：Intel Core i5-1135G7 2.40 GHz（4 核 / 8 线程）、15.7 GB 内存、Windows 11 Pro 10.0.26200；lyFlow 1.1.5（`dependency-cache/lyflow/1.1.5`）；测试构建（gluesight 包 opt-level 2、其余依赖未优化，结果解析比发布构建慢一些，数值偏保守）；写盘目录是系统盘的 `%TEMP%`，没有排除杀毒软件的影响。共跑 3 轮，下表为各轮的范围。

**测量耗时**（每个线程数 300 帧）：

| 测量线程 | 轮数 | 单帧 p50（ms） | 单帧 p95（ms） | 单帧 max（ms） | 吞吐（fps） |
| --- | --- | --- | --- | --- | --- |
| 1（串行） | 3 | 15.9–18.1 | 26.4–30.3 | 30.5–34.5 | 51.5–56.8 |
| 2 | 3 | 25.3–25.9 | 34.0–37.2 | 43.7–160.0 | 74.0–78.3 |
| 3 | 1 | 28.7 | 46.6 | 85.6 | 99.0 |
| 4 | 3 | 32.6–36.7 | 56.0–63.3 | 118.2–163.7 | 101.1–112.4 |
| 6（逻辑核 − 2） | 3 | 41.1–51.6 | 68.3–93.1 | 140.5–201.7 | 109.3–134.7 |

线程数翻倍吞吐不翻倍（1 → 4 线程约 2 倍，4 → 6 线程增加有限）：这台只有 4 个物理核，逻辑核再多也不线性。

**写盘**（PGM，不压缩；需求 = 3 台 × 25 Hz × 1.31 MB ≈ 98 MB/s、75 张/s）：

| 方式 | 张数 | 速率（MB/s） | 张/s | 单张 p95（ms） | 单张 max（ms） |
| --- | --- | --- | --- | --- | --- |
| 串行 `save_pgm`（不 sync） | 3000 | 201–275 | 154–209 | 12.8–13.5 | 297–4724 |
| 3 路并行（每台相机一个目录，3 × 1000） | 3000 | 248–273 | 189–209 | 36.1–63.3 | 405–981 |
| 串行，每张 `sync_data`（不经系统缓存的盘速） | 300 | 157–231 | 120–176 | 10.8–27.6 | 45–161 |

平均速率是需求的 1.6–2.8 倍，但**单张写入偶发长停顿**（串行三轮里最长的一张分别是 3.1 s、0.3 s、4.7 s），停顿期间帧只能在队里等。原因没有查（系统缓存回写或杀毒扫描都有可能）。

**回填**：

- `MEASURE_WORKERS = 4`。公式 `ceil(75 fps × p95 / 0.7)`：串行 p95 取三轮最差的 30.3 ms 得 ceil(3.24) = 4（另两轮 26.5、26.4 ms 得 3）；上限 逻辑核 8 − 2 = 6，不起作用。核对：4 线程实测吞吐 101–112 fps，75 fps 占其 67–74%；3 线程（只测了一轮）99 fps，占 76%，高于 0.7 的目标，所以取 4 不取 3。4 线程下单帧 p95 56–63 ms，75 fps 下在途约 5 帧，可以忽略。
- 逻辑核少于 6 的机器上上限 `逻辑核 − 2` 会把线程数压到 4 以下（如 4 逻辑核只剩 2 线程，按本机 2 线程的实测约 74–78 fps，没有余量），这类机器直接走下面的降级方案。
- `IMAGE_BUDGET_PER_CAMERA` 保持 256 MiB。依据：实测最长写盘停顿 4.7 s，25 Hz 下每台相机积压 118 帧约 155 MB，占预算的 58%；测量积压可以忽略（上一条）。停顿超过 8.2 s 才会触发预算满，此时按 D-SB-32 丢该帧记缺帧、不判失败。真机压测里看到预算满再调，不预先放大。
- 其余队列条数（FRAME_QUEUE 等 1024、示教写盘 8192）不受 7.1 数据影响，保持表中初值。

**75 fps 不可达时的降级方案**（由用户决定，PC 不自行降频）：

- 触发条件（任一）：现场机探针的串行 p95 代入公式得到的线程数超过 `min(4, 逻辑核 − 2)`；吞吐压测出现预算满或测量队列满（记缺帧 / Unmeasured）。
- 第一步，在软件相机配置中降低固定帧率（重新选示教件、分段并发布）。可持续帧率 = 0.7 × 该机满线程实测吞吐，Hz = ⌊可持续帧率 / 3⌋。以本机串行 p95 30.3 ms 按公式推算（推算值，未逐档实测）：25 Hz（75 fps）需 4 线程，20 Hz（60 fps）需 3，15 Hz（45 fps）需 2，10 Hz（30 fps）需 2。本机 6 线程吞吐 109–135 fps 的 70% 是 76–94 fps，即 25 Hz 刚好踩在 0.7 的线上，没有富余。
- 降频的连带影响：每段 N_exp 随帧率变，必须按新帧率的示教件重新分段（按默认做法 6 换计划版本）；规格 §0 的 10～25 Hz 范围不变。
- 第二步才考虑缩短走廊（减少测点数）等需要改算法的做法。
- 在降级之前和之后，测量跟不上时都不会静默丢帧：该帧记缺帧或 Unmeasured，该组标 incomplete，整件 `flags.incomplete`，不改 OK/NG（D-SB-13）。

**局限**：

- 只在一台开发笔记本上测，现场工控机型号未知；本表不外推，现场机要重跑探针并把 p95 代入公式。
- 测量和写盘是分开测的，没有与 MVS 回调拷贝、界面、SQLite 同时跑；同时跑的余量由 3 × 25 Hz 吞吐门槛判定，目前没有通过的结论（见第九节第 17 条）。
- 只测了 1280×1024、121 个测点的合成图；更大的图、更长的走廊、真实胶条图像对耗时的影响没测。

#### 11. 生产节拍

- **接件**：`shot_router::arm_frames` 在接件登记时按 SDK 帧计数定基线（D-SB-7），本会话没见过帧时取开流后计数起点，仍未知时不阻止接件，取本件这台相机首帧计数 − 1（本件没收到帧的相机不记下一件下限）；`Policy::burst_production` 认 ChunkTrigger / ChunkFrame / SdkFrame，`Policy::burst_offline` 另认 Synthetic。会话或计数来源不可信记 98，测量池全部超时未返回、发布包核验超过 1 s 未完成（`INTAKE_CHECK_TIMEOUT`，存储卡住时不阻塞节拍）记 99：本件照常运动，PC 等 plcState=20 后回结果码 90 与该故障码（[core-flow.md](core-flow.md) D-CF-4）。
- **帧**：Grouper 的 seq 上限 = ΣN_exp + Σtol + 64，超出判 `Offer::OutOfRange`（不计入本件、不抬基线），丢弃并告警。重复帧号丢弃，每台相机每件告警一次；上一件迟到帧记游离帧；接件后的手动帧丢弃并告警（不判 ERR，告警写明该相机此后帧组可能错开一格）；检测中会话变化或计数来源变为不可信判 ERR 98。回调通道满、图像内存预算满的帧不交给节拍，即缺帧。
- **测量**：每帧经 `FramePool` 送测，结果经 `cycle::Input::FrameMeasured` 回节拍；QueueFull / Timeout 记 Unmeasured，Failed 记 Error；超过 T_proc 或到收尾截止仍没结果记 Unmeasured；测量输出的帧身份与送测帧不符或含非有限数改记 Error。都只记检测不完整，不判 99。
- **收尾与判定**：工件结束（plcState=20）后到收尾截止（等满收尾窗口，或按 D-SB-54 看到门控关闭满余量提前）、已接受的帧都测完，有收尾补测目标时再等补测完（D-SB-45）即判。故障（98、97）优先；否则 `Proportional`（D-SB-40）→ `resolve_regions` → `loss_alarms(各相机帧数)` → `burst_judge::judge`。丢帧、帧数异常、疑似提前终止写运行日志（warn），结论不变。
- **结果与记录**：`ResultView.burst` 带区域判定，`PartView.burst` 按 5.2 输出（帧格的 verdict 按 D-SB-56：判定后按所在区域，判定前按所测走廊的段）。`BurstRecord.frames` 在 1..=帧组数内每台相机每帧一条、缺帧也有，`rawFile` 入库时为空（录制结果事后补）；`frames_expected` = ΣN_exp，`frames_received` = 帧组数。接件时不能检测、在途中断、进程中断补记录的件也带 `BurstRecord`。诊断包按帧记录的 `rawFile` 打包原图。
- **在线读图**：`workspace_live_frame_image`（预览缓存 128 MB）；叠图读 `workspace_live_frame_view`，取生产测量时测到的胶边与胶路（不重测，同一帧收尾补测后以后测的为准），换件即清空。检测视图按历史详情的画法叠走廊、搜索带与逐站胶边。
- **胶偏未判**：直线区域去掉首尾各一帧后参考相机没有可用 x 时标 `OffsetUnjudged::NoFrames`（“胶偏未判：参考相机没有可用帧”）。
- **带宽估算**：`camera::aggregate_bandwidth` 计入 GigE 协议开销（不开巨帧约 1.05 倍），三台 130 万像素 25 Hz 约 826 Mbps，超过单口 80% 预算。

#### 12. 候选工作区（`workspace/burst.rs`）

- **`WorkspaceView.plan`**：productionPlc / candidatePlc / candidatePlcError / coverage 为 null、旧 progress 没有步骤。`plan.progress`（ProgressV2）按示教件 → 分段 → 走廊示教 → 试测 → 验证（可选）→ 发布给出：“示教件”以候选已设示教件为完成，未完成时下一步为“选示教件”；“分段”以示教件边界已确认为完成；走廊示教依赖分段完成；“试测”以示教件已按当前走廊身份测量为完成，可选，不是发布前提。`plan.pieces` 列出示教件（来源、复核状态、是否已按当前走廊测量、屏蔽数，[recipe-build-flow](recipe-build-flow.md)）。

- **走廊示教**（D-SB-45 起按段）：`workspace_teach_segment_corridor` 只冻结所选帧，走廊随候选整份保存，提取用 `workspace_extract_corridor`（5.4）；相机还没有当量时取这台相机的设备标定 `device/{device}`（模拟相机取模拟当量）。示教帧须来自本候选完整的轮次、这台相机有这一帧、采集后设备配置没变；多段配方还要求轮次已确认手动分段、帧组落在该段内。`cameraTeaching[].segments[].saved` = 走廊至少两点、不短于 1 px 且完整落在示教帧内。
- **N_exp**：候选每次改动后（`calibrate_from_teaching`），各段 N_exp 取示教件已确认分段的帧组数，`calib` 记 1 件，`partCalib` 清空；示教件分段未确认或已失效时清空。容差不写，由 `workspace_confirm_tolerance` 写入。
- **测量示教件**（`workspace_measure_teaching`）：要求示教件分段已确认、走廊示教完成；轮次须属于本候选、已完整完成、相机集合等于计划相机，各相机采集时的设备配置与当前设备相同；每段每台检测相机都有走廊且能建测量图。屏蔽的帧组不参与取样。每帧只由所在段的检测相机用该段走廊测（`calibration_corridors`，D-SB-45；缺帧记 missing、测量失败记 error），每帧特征与分段结果写在候选目录 `calibration/<轮次>/`（重新测量时整个替换）：`features.jsonl` 一行 `{camera: 相机编号, seq, metrics: FrameMetrics}`，1..=帧组数内每台相机每个 seq 一行；`boundaries.json` 为 SegOutcome。不写进采集轮次目录（特征依赖候选的走廊）。
- **x_ref**：只给单段计划的直线段，由测量示教件写入（`apply_reference`）：参考相机去掉首尾各一帧（再去掉示教件的起涂、收尾帧，D-SB-50）后测成帧的 x 均值，用 `calibration::x_ref` 得出（一件，spread 为 0），只用走廊身份与当前相同的测量。直线段启用了胶偏但没配 offsetRef 时按 AbsoluteX、计划第一台相机补上；ToEdge 取同口径的胶边距均值（`edgeMeans`，D-SB-48），没配找边参数时不写；多段计划不写。走廊身份变了测量即失效，x_ref 清空，要重新测量。
- **编辑约束**（`workspace_save_doc` 与 `workspace_update_segments` 共用 `update_doc`）：段的类型序列不变时 N_exp、calib、partCalib 不能改，x_ref 只能原样带过或清空，胶偏参考的测量量或相机变了 x_ref 清空；类型序列（段数、顺序、类型）变了清空全部 N_exp、calib 与 x_ref，待示教件按新段结构重新确认分段。工作台保存分段（`workspace_segment_template_save`）先按示教件帧范围对应新旧段、迁好段参数、走廊与示教帧（D-SB-52），再经同一 `update_doc` 保存，这时不按类型序列整体清空走廊。

#### 13. 候选验证、发布、进度与历史

- **发布前检查**（`burst_release::publish_checks`，发布时当场核对，D-SB-46）：相机配置（不要求在线）；示教件；走廊示教（恰好 3 台计划相机，每段每台检测相机都有示教帧、走廊完整落在帧内，每台相机有像素当量，且各示教帧采集后相机的设备标签没变）；段帧数（各段 N_exp 都已由示教件分段得出，附逐帧定向等不阻断提示）；示教件采集参数（测量示教件时的相机采集参数与当前一致）；胶偏参考 x_ref（只在有启用胶偏检查的直线段时列出参考值或不判的原因，不阻断：单段配方运行时整条胶路按未分段处理、不判胶偏；多段计划暂不计算 x_ref；ToEdge 填了图纸胶边距即按它判）；生产版本；示教帧试测（各段在示教帧上测没测成，部分没测成只提醒、一段都没测成拦发布，D-SB-59）。不含独立正常样本。
- **验证样本**（可选，D-SB-46）：`workspace_capture_sample` 把采集轮次记进样本库（`BankSample.captureId` = 轮次编号，帧留在采集轮次目录，验证时按 (相机, seq) 读；`geometryTag` = 产品代码 + 有序计划相机 + 各段 (序号, 类型)，不含 N_exp，示教件分段确认前采的样本之后仍可用）。样本轮次不能是示教件，相机集合等于计划相机，各相机采集时的设备配置与当前相同。原图齐全的生产历史也可作样本：段结构身份与候选相同（历史没有记相机配置，不比较）。样本与生产同一规则选走廊重测（D-SB-45；缺帧不读图，读图或测量失败只算检测不完整），按 D-SB-40 分段判定；丢帧告警对采集轮次按计划相机顺序重算，对历史沿用记录。帧组数超出 ΣN_exp ± Σtol 与检测不完整只写进样本原因，不改是否符合。不接受按拍照点导入的样本图片。
- **发布**：`workspace_publish` 调用 `burst_release::freeze_bundle` → `release::publish_burst`（schema 5）：每台计划相机一份标定 JSON（`mmPerPx` = 示教当量，`reference` = 标定引用或 `device/{device}`，`source` = 工位标定文件内容），它检测的每一段一张示教帧与走廊（D-SB-45）；测量图为 `production::burst_graphs`，`versions.graph` = `GRAPH_VERSION_BURST`。发布门槛 = 发布前检查当场通过（只提醒的项除外）+ `ready_burst`（D-SB-46）。计划版本由 `plan_version_for` 按 `same_plan` 分配，换示教件或改分段使 N_exp 变化即换新号。配方版本也在发布时由配方库当场分配（`RecipeStore::release_version`，与生效时 `save_published` 的核对同一口径），不沿用候选里记的版本：候选建好后，启动时会按历史记录里出现过的版本抬高版本下限，候选里的版本可能已过时。验证环境标签（`environment`）含各检测相机的工位标定（缺省为设备标定 `device/{device}`）。
- **进度**：发布步骤的阻塞项取未完成的必经步骤（示教件、分段、走廊示教；试测可选、不阻断），各自跳到该步骤的第一个阻塞目标：选示教件、在示教件上确认分段、第一个没示教好的（段, 相机）。设备与生产版本在发布时当场核对。
- **历史**：`workspace_record_frame_image(historyId, camera, seq)`（5.4）读历史一帧原图。生产记录读录制目录：路径在 `*_cycle_{cycleId}` 内、文件名为 `{相机}_s{seq:06}.pgm`，part.json 里这一帧的 cycleId、相机下标与编号、seq、帧号一致且已落盘，解码尺寸等于录制尺寸。`workspace_compare` 从原图用候选走廊逐帧复测（任意候选；相机按编号对应记录原图，至少一台相机有原图、至少一段能量，其余记未测，D-SB-57、D-SB-58），或按已存每帧指标与记录里的区域用候选规则重判（要求 `store::same_measurement_layout`，ERR 记录不重判）；`workspace_compare_original` 按原发布包（schema 5）的走廊逐帧重现。结果写进 `Comparison.burst`（5.1）。`workspace_record_frame_view(historyId, comparison, camera, seq)` 给历史详情叠图（只读）：用对照保存的候选配方、示教帧尺寸（`Comparison.burst.sizes`）与这一帧在对照里所用的走廊段从录制原图重测，返回走廊、搜索带、胶边与胶边距线（与试测页逐帧查看同一形状），不依赖候选现在的示教，候选换了示教件或已删除也能看；按原发布包重现的对照用那个发布包重测；没有保存尺寸的旧候选对照不支持。看原始记录时用 `workspace_history_frame_view(historyId, camera, seq)`：按记录的发布包与这一帧当时所用走廊段从录制原图重测（与在线检测同一入口 `Prepared::measure_frame`，生产预热里有这个包就复用，否则加载并只缓存一个），线不落盘，指标取记录里存的；没有发布包、原图或走廊段时写明原因。`workspace_history_compare_options(historyId, candidate)` 给历史详情三种复测各自能不能做与原因：`candidate` 为选来复测的本机候选（任意候选，缺省为记录所属配方的候选，不新建候选、不看工作台打开的配方），`choices` 列出可选的全部候选；检查与真正执行对照时同一处（按规则重判还要求记录的配方快照、段结构相同、原记录有区域判定；从原图复测按 D-SB-58，有不测部分时在 `raw.note` 里写明）。`workspace_history_candidates(id, all)` 的 `all` 为真时列本机全部真机录制件（试测用）。

#### 14. 生产模拟与吞吐验收

独立模拟器的 S7 与 TCP 相机输入走正常生产链路，测量由真实 lyFlow 执行，操作见[独立生产模拟器](../testing/production-simulator.md)。`examples/capture_fixture.rs` 保留为生成仿历史录制件的手工工具，供示教流程复现。

3 × 25 Hz 持续吞吐门槛仍未验证。应在现场工控机使用真实相机与正式配方记录持续帧率、测量队列、预算丢帧与未测帧，再决定降帧率或增加并发。独立模拟器的条图只检查连通性；真实原图及匹配正式配方才可核对检测结果。当前没有自动故障注入或吞吐达标判定脚本。

## D-SB-63 宽胶证据与完整性

彩色固定走廊与逐帧定向采用 `flow-3` 发布图和 `widthPolicy=extent`，测量证据版本为 1。超过预期宽度的完整胶继续量测；截断下界只在严格超过规格时证明偏宽，保留 `maxExcursionMm` 和 `wideWarnOnly`。部分截断/未知列入 `incompleteGroups`，不覆盖已经确认的缺陷；全无可用证据沿现有检测错误路径返回 PLC 90 / fault 91。生产跳过先排除，旧记录无证据字段按原语义读取。生产加载不按测量图版本或 lyFlow 版本拒绝已发布配方。完整数据与显示契约见[宽胶测量](../architecture/wide-bead-measurement-plan.md)。
