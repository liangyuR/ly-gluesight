# 彩色图像决策记录（color）

每条写明问题、可选项、采用的做法与理由、回退方式。

## CL-1 彩色帧链路：按相机选择、内存用 RGB、录制存原始 Bayer

- 问题：现场项目使用粉色胶，底材是发黑的铸件与镀铝 / 镀锌面。相机 JHEM131GC-XS 出 8 位 Bayer（BG），原来取图时就转成灰度，示教、检测、录制、显示都只有灰度，胶在两种底材上的明暗方向可能相反（[r2-records](r2-records.md) R-8）。离线去马赛克后，胶与金属、铸件的颜色区分明显，程序内部需要能直接用彩色图。
- 可选项：
  - 范围：A 按相机选择灰度或彩色；B 彩色相机一律彩色。
  - 帧在内存与录制里的形态：C 内存用 RGB、录制存原始 Bayer；D 全程 RGB、录制存 PNG；E 全程 Bayer、各处按需去马赛克。
- 采用：A + C。
  - 相机配置新增“图像模式”（`CameraConfig.imageMode`，`gray` / `color`，缺省 `gray`）。灰度模式的取图、录制、读图与显示完全不变。
  - 彩色模式下相机只设 8 位 Bayer 像素格式，相机不支持时报错、不回退到 Mono8；取图回调里按相位双线性去马赛克成 RGB（`FrameImage.channels = 3`），测量、预览、示教都用这份 RGB。三目拼接相机不支持彩色。
  - 录制：彩色模式的原图文件名不变（`{相机}_s{seq:06}.pgm`），内容是相机原始 8 位马赛克，PGM 头里带注释 `# bayer {相位}`（GenICam 命名，如 `BG`）；part.json 帧项记 `imageMode: "color"`。读图统一经 `image_file`：带该注释的 PGM 去马赛克成 RGB，普通 PGM 仍是灰度，所以历史读图、复测、示教件导入（硬链接）不用区分模式。
  - 需要灰度的地方（中线提取、帧对齐与分段缩略图等）对 RGB 帧按 BT.601 取亮度。测量仍用现有测量图：RGB 原样以 3 通道注入 lyFlow，glue 算子入口按 BT.601 转灰度。
  - 前端预览字节格式头部为 20 字节 `[预览宽, 预览高, 原图宽, 原图高, 通道数]`（u32 小端），之后为 `预览宽 × 预览高 × 通道数` 字节；分段缩略图条头部为 `[帧组数, 宽, 高, 通道数]`。前端按通道数解码，叠加线配色在粉色、黑色、灰色底上都能看清。
- 理由：
  - 双线性去马赛克单线程约 2 ms/帧（1280 × 1024，release 构建实测），CPU 可忽略；相机仍出 Bayer，网口带宽不变。
  - 内存用 RGB 让各消费方只认一种彩色形态，不必到处记得去马赛克（E 改动点分散）。代价是每帧 RGB 3.75 MB 加原始 Bayer 1.25 MB，在途预算（每台相机 256 MiB，原始 Bayer 另记在同额的独立池里）可积压的帧数约为灰度的三分之一（约 68 帧）。
  - 录制存原始 Bayer 无损，大小与灰度相同，每件 570 帧约 0.7 GB；存 RGB PNG 约 1.4 GB，编码每帧约 67 ms，三相机要多占约 2 个核（D 不取）。
  - 文件名与读图入口不变，旧录制、历史导入与诊断包都不用改路径约定。
- 边界：
  - 彩色模式下检测设置“同时保存原始 Bayer”不起作用，原图本身就是 Bayer。
  - 去马赛克算法固定为双线性；离线评估可换算法重新还原原始文件。
  - 示教帧与生产帧的通道数不一致时测量报错，换模式后需要重新示教。
  - 灰度公式：灰度模式的 Bayer 相机仍按 (R + 2G + B) / 4，彩色帧取亮度按 BT.601，两者数值不同。
- 回退：把相机图像模式改回灰度。完全撤回时回滚该提交；彩色模式录制的原图在旧版本里会被当作灰度读（马赛克纹理），需要用 `scripts/color-eval` 或去马赛克后再看。
