# 定稿：特征定位 + 示教胶路判胶偏

讨论 3 轮收敛（[第 1 轮](round-1.md) · [第 2 轮](round-2.md) · [第 3 轮](round-3.md)）。起草方与评审方对第 1–9 节无分歧；第 8 节第 1–6 项已由用户于 2026-10-20 拍板，第 9 节说明阶段 0 数据能证明什么、不能证明什么。第 10 节是阶段 0 之后的结论与两项决定（决定一、决定二，用户于 2026-10-21 按建议拍板，列在第 8 节第 7、8 项）。第 11、12 节是 G2、G3 的实施记录。

## 1. 方案

工件特征定位得到位姿 T，把示教胶中线（合格胶路 N）搬到当帧得到 N'；胶照旧在静态示教线走廊里检测；胶中心到 N' 的有向法向距离即胶偏，按 `limits.position` 判定。

胶检测走廊不随位姿，位置基准随工件。这一拆分不依赖任何关于“胶在画面里跟不跟工件走”的现场结论（MX11 数据已判定不可信，不作依据，见 §8）：

- d = B − T(N) 的定义就是“胶相对工件上合格位置偏了多少”。胶随工件动时，B 与 T(N) 一起动，d 不变；胶不随工件动时，d 如实给出胶相对工件的偏移。两种情形下 d 都正确。
- 走廊保持静态，沿用已验证的胶检测与解析契约（`glue.taught_path` / `glue.bead_width`、`parse_result` 的站数、弧长、法向校验），不引入“走廊随位姿重建”的新失效面。前提是胶落在静态走廊内，走廊宽度见 §5、§9。

## 2. 结构

```text
LyFlow 图（静态，发布包“图一致”校验不变）
  n_load → n_path(taught_path, 静态示教线) → n_width(bead_width) → stations、beadInfo
  n_load → n_locate(glue.locate 1.1.0, template = "template.pgm", templatePad = 4) → pose

GlueSight（Rust 纯函数）
  N' = T(N)
  每个有胶站 i：在 N' 上沿弧长离 N'_i 不超过 r_i = |B_i − N'_i| 的线段上就近投影，两侧各多一段
               （直线段上 B_i 的垂足离 N'_i 不会比 B_i 更远，位姿的平移与绕模板中心转动带来的切向搬移都在窗口内；
                 窗口只挡同一胶路弧长更远的部分，如 U 形的另一条腿）
               取 |距离| 最小、且线段法向与 n'_i 夹角 ≤ 45° 的线段（挡拐角；直角拐点上的站恰为 45°，算合格）
               投影参数不在 [0,1] 内 → 该线段不算；弯道外侧落在相邻两段之间楔形区、两段都合格 → 按共同顶点距离
               越出 N' 两端或窗口两端、找不到合格线段 → ST_NO_REF
  d_i = B_i 到所选线段的有向垂直距离 × mmPerPx，正向取 n'_i 一侧（原始几何距离，名义值在判定里扣）
        即 (B_i − P_i)·m_j，m_j 为线段法向；与 (B_i − P_i)·n'_i 只差两法向夹角的余弦（门限内 ≥ 0.71）
  pose.ok = false → 该视图所有有胶站 ST_NO_REF
```

窗口在 P0 评审时修订（2026-10-20）：第 2、3 轮的 k = ⌈searchRadiusPx / stationStepPx⌉ 只算了模板中心的平移，漏了方形搜索窗的对角（最多 √2 倍）和绕模板中心转动在杠杆臂 L 上的切向分量（约 L·2·sin(θ/2)，L = 900 px、θ = 3° 时 47 px）。locate 接受的位姿会让整段中间站都找不到线段而报 ERR 92；改为按每站实际的 |B_i − N'_i| 开窗。

## 3. 判定与状态

- 新测点状态 `ST_NO_REF`：有胶、无位置基准，胶宽有效。`PointState::Measured { d: Option<f32>, w }`。
- 位置统计只用有值的 d；`ST_NO_REF` 连续长度按 `MAX_INVALID_LEN`（2 mm）容忍；超过或整视图无基准 → 该段位置 ErrInspect，`SegmentResult.reference_invalid = true`。
- 合并：按现有全序取 max；若 ERR 只由基准无效引起、且存在任一段 NG，则取该 NG。`Verdict` 顺序不动。
- fault 92 由 judge 给出；删除 `Measured.located`、`FrameStatus::LocateFailed` 和 `cycle.rs` 整周期短路；帧增加 `referenceFailed`。
- 定位失败始终可见：帧记录与 UI 徽标；同一拍照点连续 N 件定位失败告警。
- 名义值：`limits.position.nominal`（默认 0）。验证阶段统计合格样本 d 的 μ/σ 只做诊断，不自动校正；`nominal ≠ 0` 时必须填写量具确认件编号 `gaugeRef`。改名义按相同测量定义重判历史；改 fixture 需原图重测。
- PLC 协议无改动，fault 92 只更新语义说明。

- **走廊**：`search_mm` 逐点按阶段 0 的 σ_B 取 `max(3σ_B, 胶宽上限/2 + 2 px)`；σ_B 超阈值的点关闭位置判定。
- **示教**：框选定位特征（叠加模板框、搜索范围、杠杆臂 L）；保存检查模板与走廊不重叠、纹理、`peakRatio`、L；优先与胶同面、刚性、不被喷嘴遮挡的孔或角点；在样本库其他图上做定位试测；试测标签与草稿比较纳入 fixture。
- **验证**：独立合格样本全部定位成功；位姿超出搜索范围 70% 告警；d 的 σ ≤ 位置公差 1/5；|μ − nominal| > 公差 1/3 告警。
- **存储/叠图**：位姿写入 `FrameView` JSON（各视图结果 `viewResults[].pose`，G3）；`POINTS_FORMAT` 3；audit `d_bits` 可空，旧格式 spool 按 D-0 拒绝并提示清理；示教、生产、历史叠图按位姿画 N' 与模板框。
- **版本与依赖**：`RELEASE_SCHEMA` 3、`GRAPH_VERSION` 新值；`requiredOperators` 加 `glue.locate`，以 `runtime.json` 为唯一来源（§8 第 3 项，Rust 编译期读取，不再需要一致性测试，见 §11）；打包自检加 locate 冒烟。

## 9. 数据与局限

阶段 0 只有 2026-10-17 样本集（1 件、单圈、未标定）。它能测的：

| 能测 | 方法 |
| --- | --- |
| 模板候选能否找到：纹理、与走廊不重叠、杠杆臂 L、自匹配分数 | 每张图按规则自动提议候选框，在同图上跑 `glue.locate` |
| 定位精度 | 整图刚体扰动（平移、旋转、缩放）单独及叠加成像扰动（噪声、亮度、模糊），真值由扰动定义给出 |
| 共同运动下 d 不变 | 同一刚体扰动下静态走廊测胶，再用位姿算 d，对比原图 |
| 只移胶的检出 | 评测已有的合成偏移缺陷（1/3/6 mm）：模板区不动，位姿应为恒等 |
| 定位耗时 | 单线程逐张计时 |
| 复拍对比（3 对） | S001/S034、S002/S035、S003/S036：用原图模板定位复拍图，比较静态 d 与定位后 d 的差 |

它测不了的：

| 测不了 | 原因与后续 |
| --- | --- |
| 件间胶位抖动 σ_B | 只有 1 件；3 对复拍不构成分布。§5 逐点 `search_mm` 暂不按 σ_B 设定，沿用默认值 |
| 已知物理偏移的线性度 | 没有 0.5/1/2 mm 实物偏移样本，只能用合成偏移代替 |
| 视差与高度：特征与胶不同面、工件倾斜 | 合成扰动都是整图平面变换，测不到 Z 向变化 |
| 真实 mm 刻度 | 未标定，mm 值来自模拟当量（A-3） |
| 模板框里是否有喷嘴或胶枪 | 随枪相机下喷嘴跟相机走，框进去会让位姿恒为恒等；工具判断不了，每个选中的框都要人工复核 |

后续采集至少需要：多件、同一件重复上下件 ≥ 10 次、已知偏移样本（0.5/1/2 mm）、标定后的当量。

阶段 0 评测结果见 [算法评测报告 §9](../../testing/algorithm-evaluation.md#9-特征定位评测fixture-阶段p0)。其中三条影响后续实施：

- **L1**：glue.locate 1.0.0 在有噪声的图上估出 0.3–0.7° 的假角度（φ = 0 不经插值、其他角度经双线性插值），三对复拍图的 d' 因此比静态 d 还抖；只找平移时 d' 重复性优于静态。locate 1.1.0 需让各角度走同一插值路径，并加对应用例（1.1.0 已做，见 §10）。整图过曝时有错锁仍报成功；§10 表明 `peakRatio` 与 `minScore` 都分不开这些错锁、`at_angle_edge` 只拦下一部分，所以 `maxPeakRatio` 默认保持 1，改由 G4 验证时的亮度 ±40 试定位把关。
- **G1**：共同运动带切向分量时，胶路两端约一个切向位移长度的站投影越出 N'（无基准），按 §3 的 2 mm 容忍会报 ERR（平移 2.9 mm 时 21/36 张）。§10 决定一：新增“超出检测范围”状态加护栏，示教余量 m 默认 0、G4 再定（2026-10-21 已拍板，G1 实现状态与判定，G2 计算两端搬移）。
- **G4**：自动提议的框会落在离焦前景件、镜面高光或喷嘴边上。亮像素比例只作示教保存时的预筛，必须过的检查是 G4 验证时每个框在亮度 ±40 下的离线试定位（§10）；另要求人工确认不含喷嘴。

## 10. 阶段 0 结论（2026-10-20；2026-10-21 按 L1 构建 dcc726b 重跑后更新数字）

依据是[算法评测报告](../../testing/algorithm-evaluation.md)的 §9.3（locate 1.0.0）和 §9.4（locate 1.1.0，L1 本地构建 dcc726b，未发布），数据都来自 2026-10-17 样本集。证据范围：只有 1 件；除复拍外都是同图内的合成扰动；跨图证据只有 3 对同点位复拍，真实转角未知。MX11 数据没有用。

**已验证（同图内）**

- **几何链路成立。** 原图上 d' − d 的 P95 为 0.003 mm（1.0.0；1.1.0 为 0.017–0.023 mm，见评测报告 §9.4 结论 1 的角度噪声）。工件共同平移 5–25 px 时 |Δd'| P95 ≤ 0.083 mm，静态 |Δd| 是 0.57–2.91 mm；+40 px 时两端的站占了上风（|Δd'| P95 6.8 mm，静态 4.66 mm，见决定一），中间段的 d' 仍是对的。合成只移胶 1 / 3 / 6 mm 全部按预期判定，位姿不漂。
- **locate 1.1.0 去掉了插值与亚像素相位造成的假角度。** 同一组框上只加噪声 σ=6 时角度误差 P95 从 0.75° 降到 0.046°；代价是整像素平移时多了约 0.03° 的角度噪声（1.0.0 在 0° 上不经插值，恰好偏向真值 0）。
- **复拍对分开看。** 同一组框（1.0.0 选的）上，S001/S034 从 0.53° / |Δd'| P95 0.204 mm 降到 −0.03° / 0.029 mm（静态 0.051 mm），这是相位修复的效果；S002/S035 仍报 0.11°、0.105 mm，与静态 0.102 mm 相当、比只找平移的 0.043 mm 差；S003/S036 判看不出角度、只补平移，0.050 mm。1.1.0 自动选的框上三对是 0.029 / 0.079 / 0.055 mm，都低于静态 0.051 / 0.102 / 0.061 mm，但 S002/S035 在自动选框上也报 0.13°、仍比只找平移（0.053 mm）差。S002/S035 的真实转角未知，只有这一对，算 n = 1 的证据。
- **贴边门有效。** 平移 +70 px（超出 searchRadius）36/36 判 `at_search_edge`，1.0.0 下则全部报成功、全部错锁。旋转 +4° 时两组框都是 36/36 判 `at_angle_edge`，看不出角度的分支也不再绕过它。
- **耗时够用。** 按评测 E5（单线程，每张图 5 次，含建图、调用、解析；96 / 128 px 模板、searchRadius 60 px、±3°）P50 约 21 ms、P95 ≤ 28 ms，不需要金字塔；只找平移时更快。LyFlow 记录里的内核单独计时没记构建配置、与 E5 对不上，不作依据。

**没通过、要改的**

- **错锁门拦不住大部分过曝错锁。** 亮度 +40 下有 10/36 次错锁，分数 ≥ 0.98，`peakRatio` 不高于锁对；`at_angle_edge` 拦下其中 1–4 次，`minScore` 从 0.6 扫到 0.9、`maxPeakRatio` 从 1.0 扫到 0.7 都多拦不下一次，反而先误拒锁对。错锁还会造成假 NG：S017 错锁 38.4 px，被判位置 NG。示教时的亮像素比例筛框只能减少、不能杜绝：自动选框时取比例 < 0.1 的框，亮度 ±40 下 0 次错锁、4/36 个拍照点选不出框；但固定 1.0.0 选的框时，S016 比例 0.099 仍错锁 19.8 px（1.0.0、1.1.0 下都是）。0.1 这个门限是在同一批 36 张、单一扰动上挑出来的。所以亮像素比例只作预筛，**每个框在 G4 验证时用亮度 ±40 离线试定位才是必须过的检查**。`maxPeakRatio` 默认保持 1。叠加了亮度 +40 的组合用例里，另有 9–19 次看不出角度、中心偏 2–10 px 的定位按“转角没补偿”计、没算进错锁（亮度 +40 单独就会在这个分支上错锁），实际的错锁可能更多（评测报告 §9.4 结论 5）。

- **缩放（工作距离变化）补不了。** 这条不变。
- **胶路两端。** 见下面的决定一。

**决定一：胶路两端在切向搬移下的处理（2026-10-21 用户按建议拍板，见 §8 第 7 项）**

已决定：两端被位姿搬出 N' 的站按下面第 1、2 条（新状态“超出检测范围” + 按 |Δ| 判的护栏）处理，第 3 条示教余量 m 默认 0、G4 按验证数据再定。代价：每帧两端约 |Δ| 长的站不判胶偏、不判断胶；m > 0 时两端各 m 长永远不判。

现象：位姿把胶路沿自身切向搬 Δ 时，前沿一端的胶落在 N' 端点之外，这些站没有基准；后沿一端的静态走廊里已经没有工件上的胶。按 §3，前者连续超过 2 mm 判 ERR 92，后者判断胶。d' 本身是对的：平移 +25 px（约 2.9 mm）时 |Δd'| P95 为 0.083 mm，但 36 张里有 22 张判 NG（21 张 ERR、1 张断胶）；平移 +40 px 时 25 张判 NG。正常件因此停线，原因只在两端。

建议：

1. **新增站状态“超出检测范围”，与 `ST_NO_REF` 分开。** 每个视图按位姿算两端的切向搬移：Δ_起 = (T(N_0) − N_0)·t_0，Δ_止 = (T(N_n) − N_n)·t_n，t 是端点处沿胶路方向的单位切向。离检测区起点（或终点）弧长不超过 max(0, |Δ| − m) 加 1 个站距的站（单端排除长度），记为超出检测范围；m 是下面第 3 条的示教余量。这些站不参与位置判定和断胶判定，也不计入 `ST_NO_REF` 的 2 mm 连续长度。帧里记下两端各排除了多长，叠图上标出。理由：这些站是几何上本来就测不了，不是检测失败。判 ERR 会让正常件停线，判断胶是误判。
2. **护栏。** 护栏按切向搬移本身判，不按排除长度判：任一端 |Δ| 超过配方上限 `maxEndShiftMm` 时，该段位置判 ERR 92（`reference_invalid`）。这样位姿搬得太远时，覆盖损失不会悄悄变大；按 |Δ| 判也与 m 无关（若按排除长度 max(0, |Δ| − m) + 1 站距判、门限又按 m = 0 的数据定，G4 取 m ≈ P99 之后要 |Δ| 到约 2·P99 + 1 mm 才触发，比设想宽一倍）。上限要高于正常运行时最大的切向搬移并留余量，否则护栏在正常件上就会触发：评测按 m = 0 算的单端排除长度（= |Δ| + 1 个站距，本样本集站距约 1 mm），平移 +25 px 时 P50 3.66、最大 3.92 mm，+40 px 时最大 5.67 mm（§9.4 结论 10）。默认值：G4 验证时两端 |Δ| 的 P99 再加 1 mm。G4 之前的临时默认取 locate 接受的位姿能产生的最大 |Δ|：搜索窗是方的（每个轴 ±searchRadius，峰离窗边 ≤ 1 px 判贴边），平移最多 √2·(searchRadius − 2) px；开转角时端点还绕模板中心切向移 L_端·2·sin(angleRange/2)（L_端 是模板中心到较远端点的距离）。即 `maxEndShiftMm` = √2·(searchRadius − 2)·mm/px + L_端·2·sin(angleRange/2)：本样本集 60 px、约 0.117 mm/px、只找平移时约 9.6 mm，±3°、L_端 87 mm 时再加约 4.6 mm。按构造，定位成功的位姿不会因两端判 ERR；代价是 G4 之前每端最多可排除约 |Δ| + 1 站距 ≈ 10.6 mm（只找平移）而不报 ERR。评测里没有接近搜索半径的对角平移（E3 只有 +10,+10 与 +70,0），这个上界没有实测，G1 实现后在 E3 加一例（如 +55,+55）复核；“超出检测范围”的判定本身也尚未在评测里模拟，G1 实现后要在 E3 上复核 +25 / +40 px 的 NG / ERR 数。
3. **示教余量。** `glue.taught_path` 的 `zone` 取 [m, L − m]，静态走廊和判定只覆盖 zone 以内；偏差投影要用整条示教线 N，不能只用 zone 内的站。这样 |Δ| ≤ m 时 zone 内的站都能投到 N' 上，静态走廊里也仍然有胶，不排除任何站。m 默认 0（与现在相同）；G4 验证时按两端切向搬移的 P99 加 1 个站距来取。代价是两端各长 m 的一段（起胶、收胶）永远不判，这需要用户确认能否接受。第 2 条的护栏按 |Δ| 判，取 m 之后门限不用跟着改。
4. 胶检测走廊仍然是静态的（§1），不引入“走廊随位姿重建”。

**决定二：v1 默认只找平移（`angleRange = 0`）（2026-10-21 用户按建议拍板，见 §8 第 8 项）**

已决定：v1 默认 `angleRange = 0`，开转角逐拍照点由 G4 验证决定（条件见下）。代价：真有转动时只补平移，合成 1° / 2° 下最远站误差 P95 约 1.3 / 2.7 mm。

证据：

- **不转动时，只找平移不比 ±3° 差，S002/S035 上两组框都更好。** 噪声 σ=6 下最远站误差 P95 为 0.023 mm（±3° 为 0.054 mm）。复拍 |Δd'| P95：自动选框 0.028 / 0.053 / 0.055 mm，±3° 为 0.029 / 0.079 / 0.055 mm；1.0.0 选的框上 0.029 / 0.043 / 0.050 mm，±3° 为 0.029 / 0.105 / 0.050 mm。
- **±3° 的补偿取决于“看不看得出角度”，逐帧不稳；看不出时平移也偏。**
- **代价：** 真有转动时，只找平移在 1° 下最远站误差 P95 为 1.3 mm，2° 下为 2.7 mm（合成，杠杆臂 35–87 mm）。纯转动时 |Δd'| 只比静态好约 12%（±1°：0.93 vs 1.06 mm）；带平移的转动好得多（平移 +20,−10 加 1.5°：1.38 vs 3.52 mm），因为平移被补掉了。样本集里没有真实转动的数据。

建议：

- v1 默认 `angleRange = 0`。
- 是否对某个拍照点开转角，由 G4 验证（多件实拍）决定，三个条件都要满足：
  - 用 ±3° 离线跑验证帧，L·|θ| 的 P95 超过位置公差的 1/5（公差 ±2 mm 时为 0.4 mm，L = 87 mm 时对应 0.26°）；
  - 这个转角要有独立于单个模板的证据，因为同一个估计器在同点位复拍上报过多半与真值无关的角度（S002/S035 在两组框上报 0.11–0.13°、真值未知，71503de 之前 S001/S034 报 0.48°），量级接近 0.26°。满足其一即可：同一视图两个不同的模板估出的 θ 一致；验证帧上 ±3° 的 |Δd'| 明显低于只找平移；多件采集时实物确认转过；
  - 选中的框在全部验证帧上（含亮度扰动）都是 `angleObservable = true`。
- 开了转角的拍照点，运行时遇到 `angleObservable = false`，按定位失败处理：该视图 `ST_NO_REF`，判 ERR 92，计入连续 3 次告警；不要悄悄降级成只补平移。
- 只找平移的拍照点没有角度门保护，所以验证阶段同样要用 ±3° 离线核对真实转角；超过上面的门限，就开转角或改夹具。

**其他**

- 模板带 4 px 外圈（lyFlow#32 a30885f，见 §5“模板”）去掉了框边 BORDER_REPLICATE 平滑偏置：两组框上纯平移的模板中心误差 P95 约减半（0.115 → 0.059、0.086 → 0.042 px），纯平移的最远站误差 P95 减 0.020–0.026 mm（模糊、亮度 −40 与带转动的用例减得更多），亮度 +40 的错锁不变（评测报告 §9.5）；两项转角问题留作已知问题（v1 只找平移）。
- L1 发布 1.1.0 后，用发布的运行库重跑 §9.4。
- G4 的示教保存检查加亮像素比例上限作预筛（建议 0.1），必须过的是验证时的亮度 ±40 试定位。
- σ_B、实物偏移线性度、视差、真实转动仍然等后续采集（§9）。

## 12. G3 实施记录（2026-10-21）

G3 的实现细节与上文不同或上文没写的部分，G4、G5 实施前先读。

- **模板身份 = 来源身份，不用内容哈希（D-0）。** `FixtureSpec.source` 记裁模板用的冻结示教原图编号，身份三元组是 (source, rect, `FIXTURE_TEMPLATE_PAD_PX`)，它在测量布局里（fixture 含 source；布局顶层另有 `"fixtureTemplate": {"pad": 4}`）。成立的前提，都写在代码注释里：

- **来源由后端掌管（`bind_fixture_sources`）。** 前端传来的 source 一律不用。只有“保存示教参数”强制把所选视图的框改绑到当前冻结图；草稿自动保存与整份保存（`workspace_save_doc`）只给新增或改动的框绑定当前冻结图，没动的沿用旧来源——否则重新冻结后任何一次自动保存都会把旧框悄悄绑到新图上。冻结、整圈采集（含继承示教）、恢复示教都不改写来源（恢复示教只回滚帧，不回滚配方）。使用时 `fixture_source` 要求来源就是该视图当前冻结图：试测、验证、候选试运行、发布前都经过它，过期的框报“定位框是在示教图 X 上保存的，当前示教图是 Y”，要在示教页确认框后重新保存示教参数。不在编辑态页面上的提示归 G4。
- **G2 时期的数据。** 配方校验要求 source 合法，`RECIPE_SCHEMA` 不升：G2 时期带 fixture 的工作区 `build()` 失败、打不开，要删除重建（D-0，不迁移）。配方快照经 `RecipeDoc::build` 反序列化，缺来源的快照解析即失败，`Recipe` 也没有别的构造途径，所以历史重判与候选比较只靠测量布局比较：来源在布局里，任一侧来源不同就拒绝复用（`DB_VERSION` 8 重建记录库后也不会再有 G2 时期的记录）。不另设“来源未知”守卫——那是生产里到不了的状态，删掉它行为不变。G2 的“含 fixture 一律拒绝复用”（`readings_depend_on_template`）已去掉：来源、框、外圈都没变时，§7 的“只改名义 → 历史可重判”对含 fixture 的配方成立。
- **走廊检查替代 `reject_fixture`（§11 跨阶段约束）。** `RecipeDoc::validate` 里，按 (Pose, 相机, 图) 分组：同一 Pose、同一相机、同一幅图的几个拍照点拍的是同一场景的不同帧（同一 Pose 可多次触发），组内每个启用的框（带外圈，按像素中心 [x − 4, x + w + 3] × [y − 4, y + h + 3]）到组内每条已示教中线及其两端切向延长线的精确距离（线段、射线到矩形）必须大于该线搜索半宽 + 4 px。两端各沿末段方向延到无穷远（对图内的框即延到图边，与图像尺寸无关）：枪上相机里同一条胶通常越过示教段两端继续留在画面里（各拍照点只测自己的检测区），只量示教段时端点处是半圆帽，框放在胶的直线延长上也能发布，模板里却有胶。代价是胶确实在示教段端点结束时，延长线上的框也被拒，要换位置。余量 4 px 的来由：P0 选框时要求内框离走廊大于 10 px，外圈在角上最多近 4√2 px，P0 选出的框到这里还剩约 10 − 4√2 ≈ 4.3 px（不计 P0 每 2 px 取点的采样误差）；P0 选框时的走廊不含切向延长，落在延长线上的 P0 框在这里会被拒。停用视图、不检拍照点的框与中线不参与。带外圈的框在图内（右、下边要看图像尺寸）由工作台保存示教、发布与加载时用 `check_image_size` 查。已知影响：校验也作用于草稿自动保存与配方页改 `search_mm`，压走廊的框会让这些保存失败，错误要能在前端显示；第一个带框的 UI 在 G4。剩余风险：几何检查只认同组示教中线及其直线延长。胶越过示教段两端后拐弯的部分、不同 Pose 或其他胶路的胶进到模板里，G3 拦不住，要靠 G4 的亮度与 `peakRatio` 检查；这项检查在 G4 要做成发布门，含特征定位的配方在它就位前不上现场（G3 还没有画框的 UI，示教页只原样带过已有的 fixture）。
- **发布包（`RELEASE_SCHEMA` 3）。** 启用 fixture 的视图在 `shots/kk/vN/` 下带 `template.pgm`（(w + 8) × (h + 8) 的 P5），清单每个视图记 `imageId`（有图则必有）与 `template`；发布时要求来源 = 发布原图编号、带外圈的框在图内；加载时按包内原图与配方重算模板比对（与中线、测点同一机制），fixture 视图必须引用模板、非 fixture 视图不得带模板，声明集合与引用集合一致。已知局限（与原图、中线相同）：按部件 `verify` 只核对大小，同尺寸替换要到下次 `load_directory` 才发现。
- **运行库能力。** `vision::require_locate(recipe, &engine.locate)`：运行库不支持带外圈模板时只挡含特征定位的配方，发布前（`freeze_bundle`）、生产加载与重现（`Prepared::load`）、候选试运行调用。按系列兼容运行时，本地构建发布的含 fixture 包放到已发布 1.1.4 上会在加载时被拒。
- **生产 base_dir。** `Prepared` 只给启用 fixture 的视图登记 base_dir = 发布包里该视图的目录（UTF-8 绝对路径），其他视图照旧给空串，与工作台、候选试运行一致；`measure`、`measure_views`、`warm` 与重现都经 `measure_view`。
- **预热的定位验收。** `warm()` 在发布包自己的示教原图上跑每个视图，fixture 视图位姿必须被采用，否则不布防并报出 locate 原因。这是生产接线验收，不是 G4 的质量门。
- **位姿存储。** `ViewResult.pose`（帧记录的各视图结果）保存 `PoseRecord`（含没被采用的）；`Measured.poses` 在单图与多图两条路径都填。G5 叠图时 T 由 `offset`、`angle` 与快照里 `rect` 的示教中心还原。`DB_VERSION` 8、spool `FORMAT` 3，旧库备份后重建、旧 spool 文件拒绝就绪（D-0），开发机上的历史记录会被清掉。
- **打包自检。** 应用自检的 `lyflow.locate` 只报告状态：运行库不支持带外圈模板 → `unsupported`（写明影响，不算失败）；支持 → 跑合成图冒烟（示教图位姿被采用且偏移 ≈ 0，整图平移 (+6, +4) 后偏移 ≈ (6, 4)、胶偏不变），失败即自检失败。放不放行由 `packaging/runtime.json` 的 `lyflow.locateSmoke` 决定（`optional` 警告、`required` 失败，只给打包脚本读）。当前为 `optional`：用已发布 1.1.4 打无特征定位的包照常通过；L1 发布、运行库升到 deps v4 的 PR 里改成 `required`，并用正式运行库重跑真引擎 E1–E6 与 §9.4（E7 届时要换一个不支持带外圈模板的旧运行库，或随 1.1.4 退出一起删除）。
- **测试。** 发布—加载—生产端到端：真引擎用例（`vision::taught::engine_tests`，E1–E4）在临时目录里 `release::publish` → `release::load` → `Prepared::load` → `warm` → `measure_views`，E4 把加载后的包内模板换成被抹平的同尺寸模板，下一帧位姿不再被采用；E5 把定位框逐像素挪向胶路，发布要在带外圈的框碰到漂到最远可测处的胶之前以走廊检查拒绝，最近一个能发布的框上胶漂过去时真实 glue.locate 的位姿不动、判 NG_POSITION（走廊余量改到约 −5 px 以下即失败）；E6（`packaging`）在支持带外圈模板的运行库上冒烟报 ok；E7 在已发布 1.1.4 上冒烟报 `unsupported`、不算失败。本地 lyFlow#32 构建上 E1–E6 通过，1.1.4 上 E7 通过，`Prepare-RuntimeDependencies.ps1`（1.1.4）的 `Test-PackagedRuntime.ps1` 按 `optional` 只警告。加载时模板被改的拒绝、发布时框压走廊的拒绝与引擎无关，由默认运行的 release / recipe 单测覆盖，不在真引擎用例里重复。
