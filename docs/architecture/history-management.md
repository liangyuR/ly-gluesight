# 历史件管理

历史页支持人工 Tag 和手动删除，适用于生产检测记录。历史按所属项目查询，见[历史范围](../decisions/history-scope.md)。

直接进入历史页默认选择最近 7 天，重置筛选也恢复到最近 7 天；从其他页面带筛选条件进入时沿用全部日期，便于查看该条件下的记录。

## 人工 Tag

- 常用 Tag 为“故障件”“待复核”“误判件”“参考件”，也可以输入自定义标签。一件最多 8 个，每个最多 24 个字符；保存时去掉首尾空白、空标签与重复项。
- 列表和详情显示已保存的标签。详情可编辑本件标签，列表可勾选多件后统一设置；批量设置会替换每件原有标签，空标签列表表示清空。
- 历史列表按单个 Tag 精确筛选，可与项目、来源、时间、SN、配方及检测结果条件组合。计数、导出及前后件导航使用同一筛选条件。
- Tag 是人工分类，不改变原始检测结论、PLC 结果或自动标记 `flags`；标记“故障件”不会把 OK 改成 NG。
- 标签随记录持久保存，旧记录读为无标签。升级在现有记录库原地补充字段，不重建数据库。CSV、历史件包和含检测记录的项目包携带标签；重复导入不会覆盖本机已有件的人工标签。

## 手动删除

历史列表可选择多件删除，详情可删除本件。确认后永久删除记录、逐帧数据与人工标签；删除不可撤销。列表刷新记录与统计，详情返回原入口。

删除仅清理能够核对归属、且未被其他历史件共用的关联录制原图。共享目录或路径无法安全确认时保留原图，并显示警告；实际文件清理失败也会返回警告，此时部分文件可能已清理。已导入的示教轮次原图和冻结发布资料不随历史记录删除。

生产有在途件或未结 PLC 事务、追溯仍在收尾或等待落库时不能删除；所选件的录制尚未结束或 PLC 交付未结（待提交、已提交、交付失败）时也会拒绝。删除整批校验后再提交，校验失败时不部分删除。

删除后原编号不会分配给新件，已有历史引用也不会指向其他工件。已开始但尚未保存的复测不能在删除后保存旧对照。删除不会清空 PLC 握手或运行日志，也不会改变已经交付的检测结果。

本机保留已删除件的编号与 cycleId，阻止旧审计或中断恢复自动补回。该删除标记不随记录包导出；显式重新导入已删除的工件时，可以作为新编号的历史件恢复，旧引用不会重新绑定。

## 接口

- `PartSummary.tags`：人工标签数组，旧记录为空数组。
- `HistoryQuery.tag`：可选的精确标签条件。
- `history_set_tags({ ids, tags })`：批量替换标签，返回规范化后的标签数组；标签或记录校验失败时整批拒绝。
- `history_delete({ ids })`：删除选中的记录，返回 `{ deleted, warnings }`；警告用于说明保留的原图或清理异常。

本机记录库 10 → 11 升级会清理旧离线与候选调试记录，保留生产记录。删除墓碑阻止旧审计回放恢复；关联原图仅在旧离线根下通过项目归属、非链接路径、cycleId 目录名和生产引用检查后清理，不合规路径保留并告警，文件清理失败下次重试。旧项目库与项目包导入也只接收生产记录。
