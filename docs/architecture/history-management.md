# 历史件管理

历史页支持人工 Tag 和手动删除，适用于生产检测记录。历史按所属项目查询，见[历史范围](../decisions/history-scope.md)。

直接进入历史页默认选择最近 7 天，重置筛选也恢复到最近 7 天；从其他页面带筛选条件进入时沿用全部日期，便于查看该条件下的记录。

“今天”、7 天和 30 天按本机日历日期计算筛选下界。页面跨过午夜时会刷新，切回前台时也会用当前日期核对下界。

SN 和 Tag 在停止输入后查询，按 Enter 可立即应用。中文输入法确认文字后才开始等待。点击列表标签、切换其它筛选或手动刷新会立即应用当前输入；等待新结果时，导出和批量操作暂不可用。

选择检测结果后，列表件数按所选结果统计。各结果芯片和良率仍覆盖当前项目、日期、SN、配方、模式和 Tag 条件下的所有结果，便于比较各类件数。

首页收到新件入库通知后会刷新。同一筛选、同一页后台刷新时，仍可勾选当前列表和翻页。查询期间收到多条更新或多次切换筛选时，当前查询结束后只补查一次最新筛选和页码。翻到后面的页时，新件入库不会移动正在浏览的记录。列表每次刷新以同一只读快照提供件数和记录，前后件导航也在只读快照中按时间和编号查找。记录已不存在时没有可导航的前后件。

常用的历史查询按来源或项目、时间使用覆盖结论的索引。入库关联复检时，使用非空 SN 和项目的索引定位按时间和编号排序的最新同号记录。已有记录库首次打开时原地替换旧索引，记录库格式仍为 11。

打开详情后，新件入库会刷新前后件。当前记录或相邻件变更时，按钮和快捷键会等到前后件重新确认后再启用。按 Tag 筛选时，标签修改也可能改变其它记录能否进入导航范围。

从列表打开工件后，点击“返回历史列表”会恢复打开工件时已显示的筛选和页码。同一查询和页码加载完成后，恢复仍在本页的勾选。原工件仍在该页时，会滚动到该行并恢复键盘焦点。自动刷新时，原先可见且仍有焦点的工件按钮会保持可见。前后件、复检链接和批量重判的工件入口沿用原列表筛选；从试测等页面进入的详情沿复检链接查看后，仍可返回原入口。删除导致原页码超出范围时，列表回到最后一页。

批量编辑 Tag 和删除以打开对话框时勾选的记录为准。列表自动刷新或回页时，对话框保留原操作范围和已输入的 Tag。要调整范围，关闭对话框后重新勾选。

CSV 导出按当前筛选从一次只读快照逐行写出全部匹配记录，按时间、编号倒序。导出期间新增、删除和更新不会改变本次文件内容。文件写完才显示为 `.csv`，包含 UTF-8 BOM，便于用 Excel 打开。

## 批量重判

批量重判使用发起时的历史筛选、配方选择和试算参数。同一窗口一次执行一项任务，收起弹窗或离开历史页后仍会执行。返回历史页可从工具栏查看进度、结果或错误，即使当前列表筛选已变化或为空。

进度显示本批处理件数和跳过件数，最多重判最近 5,000 件。收到取消请求后，任务在当前工件处理完成时停止。弹窗显示已取消状态，用户可重新发起重判。

任务复用一条独立的只读连接。先固定最近匹配的候选和进度总数，再分小批读取区域判定原文，按工件解码并读取原配方和逐帧指标。超限时只用第 5,001 件确认还有更多记录。取消时完成当前件，到下一件解码前停止。生产入库使用自己的连接，后续批次和逐件读取可看到其间提交的变更。

使用当前配方重判时，任务按项目和历史配方修订复用测量布局核对结果。每件仍按原顺序读取并校验逐帧指标。

区域的帧组起止序号颠倒时，批量重判将该件列入布局不一致的跳过记录，继续处理其他工件。查看该工件详情时会提示区域判定损坏。

跳过原因和判定变化记录各自按 25 件分页。每组最多列最近 300 件，超过时显示本组的总件数。判定矩阵统计本次成功重判的全部工件，跳过总数另列。

重判结果中的工件按原筛选打开详情和前后件导航。任务结束后可继续按原筛选重判。当前列表的筛选、件数或页码发生变化时，可在弹窗里选择“使用当前列表”。开始下一次重判时清除上一轮矩阵。

## 人工 Tag

- 常用 Tag 为“故障件”“待复核”“误判件”“参考件”，也可以输入自定义标签。一件最多 8 个，每个最多 24 个字符；保存时去掉首尾空白、空标签与重复项。
- 列表和详情显示已保存的标签。详情可编辑本件标签，列表可勾选多件后统一设置；批量设置会替换每件原有标签，空标签列表表示清空。
- 历史列表的 Tag 列预留固定内容宽度。长标签在本列折行，标签变动只影响对应记录的行高。
- 历史列表按单个 Tag 精确筛选，可与项目、来源、时间、SN、配方及检测结果条件组合。计数、导出及前后件导航使用同一筛选条件。
- Tag 是人工分类，不改变原始检测结论、PLC 结果或自动标记 `flags`；标记“故障件”不会把 OK 改成 NG。
- 标签随记录持久保存，旧记录读为无标签。升级在现有记录库原地补充字段，不重建数据库。CSV、历史件包和含检测记录的项目包携带标签；重复导入不会覆盖本机已有件的人工标签。
- 精确筛选使用从历史标签派生的日期索引，按筛选时段查找匹配标签。启动时为现有库补齐，标签保存、清空、导入及删除均与记录一同更新索引。索引会跳过坏标签 JSON，便于继续查看其它记录。

## 手动删除

历史列表可选择多件删除，详情可删除本件。确认后永久删除记录、逐帧数据与人工标签；删除不可撤销。列表刷新记录与统计，详情返回原入口。

删除仅清理能够核对归属、且未被其他历史件共用的关联录制原图。共享目录或路径无法安全确认时保留原图，并显示警告；实际文件清理失败也会返回警告，此时部分文件可能已清理。已导入的示教轮次原图和冻结发布资料不随历史记录删除。

生产有在途件、追溯仍在收尾或等待落库时不能删除；所选件的录制尚未结束或结果尚未回写 PLC（交付待提交）时也会拒绝。删除整批校验后再提交，校验失败时不部分删除。

删除后原编号不会分配给新件，已有历史引用也不会指向其他工件。已开始但尚未保存的复测不能在删除后保存旧对照。删除不会清空 PLC 握手日志或运行日志，也不会改变已经交付的检测结果。

本机保留已删除件的编号与 cycleId，阻止旧审计或中断恢复自动补回。该删除标记不随记录包导出；显式重新导入已删除的工件时，可以作为新编号的历史件恢复，旧引用不会重新绑定。

## 接口

- `PartSummary.tags`：人工标签数组，旧记录为空数组。
- `HistoryQuery.tag`：可选的精确标签条件。
- `history_query`：查询指定 `includeVerdictFacets: true` 且启用结果筛选时，在同一响应中附带 `verdictFacets`。该字段保留其余筛选条件下的各结果计数，`items`、`total` 与 `counts` 按全部条件计算。
- `history_set_tags({ ids, tags })`：批量替换标签，返回规范化后的标签数组；标签或记录校验失败时整批拒绝。
- `history_delete({ ids })`：删除选中的记录，返回 `{ deleted, warnings }`；警告用于说明保留的原图或清理异常。

本机记录库 10 → 11 升级会清理旧离线与候选调试记录，保留生产记录。删除墓碑阻止旧审计回放恢复；关联原图仅在旧离线根下通过项目归属、非链接路径、cycleId 目录名和生产引用检查后清理，不合规路径保留并告警，文件清理失败下次重试。旧项目库与项目包导入也只接收生产记录。
