# 运行日志与视觉证据存储

运行日志、PLC 通讯日志和历史原图集中存放在 `~/gs_logs`；配方、示教、标定、采集轮次、发布资源和历史数据库继续随 project 保存。`~` 由程序解析为首次初始化时运行账号的用户主目录。

## 目录与归属

```text
~/gs_logs/
├─ runtime/<环境>/<资料实例>/
│  ├─ gluesight-YYYY-MM-DD[.N].jsonl
│  └─ plc.db
└─ vision/<环境>/<资料实例>/<项目编号>/
   ├─ records/
```

环境为 `production`、`development` 或 `test`。资料实例是首次生成并持久保存的 16 位十六进制标识，不同资料目录即使使用相同项目编号，也不会混用外部原图。运行日志按环境和资料实例汇集，视觉证据再按项目隔离。

资料根目录仍为正式版 `%ProgramData%/ly/GlueSight` 或开发版 `%ProgramData%/ly/GlueSight-dev`。开发/测试显式指定 `GLUESIGHT_DATA_DIR` 时，日志根为该隔离目录下的 `gs_logs/`，不写入日常用户日志目录；安装版仍拒绝该覆盖变量。

首次初始化把绝对日志根、环境、资料实例标识与规范化资料根 `ownerData` 保存在资料根的 `config/log-storage.json`。以后沿用该绑定；换 Windows 账号不会自动改写日志根或另建一份历史原图。复制或搬迁整份资料目录后，不能直接沿用原绑定，避免两个副本共用并清理同一批原图。绑定目录不可用、权限不足、环境不符或命名空间已被占用时阻止业务启动，需修复原因后重试。运行实例持有该命名空间的独占锁，资料目录锁仍保留。

本次不提供界面修改日志根。调整目录需要同时迁移文件及受管引用，不能只编辑配置中的路径。

| 内容 | 位置 | 生命周期 |
| --- | --- | --- |
| 程序日志 | `runtime/<环境>/<实例>/gluesight-*.jsonl` | 按时间和容量滚动；事件带 `sessionId`，打开项目后带 `projectId`，旧日志仍可读 |
| PLC 日志 | 同一 runtime 目录下 `plc.db` | SQLite；运行时可有 WAL/SHM，保留天数来自当前 PLC 配置 |
| 真机历史原图 | `vision/<环境>/<实例>/<项目>/records/` | 当前项目按真机录制策略滚动保留；其他项目（含已删除项目）的随过期记录清理 |
| 历史数据库 | 资料根下 `history/inspection.db` | 本机一份，记录带所属项目，保留录制状态与外部原图引用；原图按记录的项目解析 |
| 整圈采集原图 | 项目内 `recipe-capture/<轮次>/` | 示教件与验证资产，不按历史原图策略清理；导出与复制默认不带 PGM 原图 |
| 冻结示教图与标定特征 | 项目内 `workspaces/<配方>/images/`、`calibration/<轮次>/` | 随候选和项目保存 |
| 棋盘格标定结果与原图 | 项目内 `calib/`、`calib/images/` | 成功标定写入原图及项目相对引用，随项目迁移 |
| 发布资源 | 项目内 `vision/releases/` | 不可变发布资源，包含冻结示教图和标定引用，不属于视觉日志 |
| 恢复状态及审计 | 本机 `state/`、`history/audit-spool/` | 维持现有恢复契约，不归入普通日志清理 |

录制原图内部结构保持日期目录、`*_cycle_<cycleId>/`、`{相机}_s{seq:06}.pgm` 和 `part.json`，不改变相机与帧组身份。

## 旧日志与原图

启动时只绑定日志根并取锁，不复制旧数据。早于外置日志根的版本留在资料根 `logs/` 和项目内 `records/`、`records-offline/` 的日志与原图不导入，历史读图只认当前录制根，读不到这些旧原图；软件也不自动删除它们。

## 历史读图、清理与磁盘空间

历史原图根据记录所属项目选择该项目的生产录制根，继续检查路径边界、`cycleId`、相机、帧组、帧号与 `part.json` 身份，不用任意同名文件代替。

运行日志保留 30 天、总量上限 1 GiB、单段上限 16 MiB，只清理 `gluesight-` 文件。历史数据库默认保留 180 天，由本机设置控制，覆盖本机全部项目，非当前项目的过期记录连同原图一起删除；生产原图默认 100 件/100 GB，由当前项目设置控制。原图清理保护最新一件、在用及待入库目录，并同步数据库引用；带 `maintenance-collect` 标记的维护采集原图仍跳过自动滚动清理。

磁盘空间守护同时检查项目目录和外部原图所在目录，空间低于现有下限时告警、新件不录原图，照常接件检测，提示包含对应目录；空间恢复后自动恢复录制。查询失败的处理沿用原有规则。示教、标定、采集轮次、样本和发布资源不进入原图滚动清理。

## 示教和标定图片

从历史选用一件用于示教或标定时，将原图物化到项目的 `recipe-capture/`：同卷优先硬链接，只有跨卷错误才改为复制并核验 SHA-256；权限等其他错误直接返回。失败撤回未完成轮次，不修改源录制。物化成功后，历史原图被清理也不影响项目轮次。

棋盘格标定成功时，原图保存到 `calib/images/<样本ID>.pgm`，标定 JSON 的 `samplePath` 为项目相对路径，另保留 `sampleId`、相机、视图，以及 `corners`（`image.board_calib` 找到的内角点像素坐标，按行排，首点为原点）。未显式冻结样本、直接使用最近帧时生成独立样本编号。先完成原图写入，再更新标定结果；图片写入失败时不发布新引用，已有图片不可被不同内容覆盖。同一冻结图像可复用原图后重新标定。

成功标定的样本图保留在项目内，本次不增加自动清理。标定页拍照或导入的冻结样本为内存对象，只持久化成功标定所用原图；进入标定页或切换相机、视图时，按当前标定的 `sampleId` 把该原图载入为冻结样本（`workspace_station_restore`，编号不变），原图不在时保持空态。

## 项目管理与导出

项目 ZIP 格式继续使用 `project/records/`。勾选包含历史记录时，导出从外部目录收集本项目的原图，从本机记录库导出本项目记录的子集，并把子集中的外部路径归一到包内项目根。导入时核验原图、重定位到新项目的外部目录，记录并入本机记录库；既有目标目录拒绝覆盖，操作失败撤回本次创建的外部资料与并入的记录。复制项目不带历史记录与原图。

导入的外部原图带项目提交标记。启动恢复时，项目目录尚未提交则清理未完成原图；项目已提交则保留原图并移除标记，避免中断留下孤儿目录或误删已导入图片。

不包含历史记录时，冻结示教图、标定图、采集轮次记录和发布资源仍随项目导出；采集轮次的 PGM 原图只在勾选“包含示教件原图”时带上。项目用量分别报告项目目录和外部视觉证据，合计为占用空间；保留的旧目录副本仍占实际磁盘空间。

删除项目只删项目目录，该项目的检测记录与外部视觉原图保留，过期后随记录清理。项目先进入 `.trash`，后台删除，中断后启动续清。`.trash` 里带外部原图清理标记的残留按标记清理：标记只记录项目编号，清理时核对编号与目录名，并通过受管配置推导外部路径，不信任任意文件路径，不清理其他项目或共用运行日志。

诊断包通过当前日志与记录所属项目的录制根解析文件，包内结构保持原契约。系统设置显示资料目录、日志根、运行日志及当前项目视觉目录，并提供对应的打开入口。

## 验证边界

定向回归覆盖资料实例隔离与锁、外部盘空间守护、历史件跨卷物化、棋盘格原图保存、项目导出导入复制及删除续清。测试使用临时目录，不触碰开发或正式现场资料。

目录调整不替代真实相机、PLC 和现场磁盘吞吐验收。部署后通过设置页核对资料目录与日志根，再检查项目资产。

- [`recipe_capture/burst/history.rs`](../../src-tauri/src/recipe_capture/burst/history.rs)、[`vision.rs`](../../src-tauri/src/vision.rs)：历史件物化及标定图保存。
