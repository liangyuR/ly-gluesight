# 运行日志与视觉证据存储

运行日志与 PLC 通讯日志存放在日志根 `~/gs_logs`；历史原图存放在有序的一块或多块录制盘上，默认只有日志根这一块。配方、示教、标定、采集轮次、发布资源和历史数据库继续随 project 保存。`~` 由程序解析为首次初始化时运行账号的用户主目录。

## 目录与归属

```text
~/gs_logs/                          日志根
├─ runtime/<环境>/<资料实例>/
│  ├─ gluesight-YYYY-MM-DD[.N].jsonl
│  └─ plc.db
└─ vision/…                         日志根也是录制盘时

<录制盘>/                            每块录制盘（C:\gs_logs、D:\gs_logs 等）
└─ vision/<环境>/<资料实例>/<项目编号>/
   └─ records/
```

环境为 `production`、`development` 或 `test`。资料实例是首次生成并持久保存的 16 位十六进制标识，不同资料目录即使使用相同项目编号，也不会混用外部原图。运行日志按环境和资料实例汇集，视觉证据在每块录制盘上再按项目隔离。

资料根目录仍为正式版 `%ProgramData%/ly/GlueSight` 或开发版 `%ProgramData%/ly/GlueSight-dev`。开发/测试显式指定 `GLUESIGHT_DATA_DIR` 时，日志根为该隔离目录下的 `gs_logs/`，不写入日常用户日志目录；安装版仍拒绝该覆盖变量。

首次初始化把绝对日志根、环境、资料实例标识与规范化资料根 `ownerData` 保存在资料根的 `config/log-storage.json`；录制盘列表存在同一文件的 `recordingRoots`（有序的绝对路径），没有这一项时只有日志根一块录制盘。以后沿用该绑定；换 Windows 账号不会自动改写日志根或另建一份历史原图。复制或搬迁整份资料目录后，不能直接沿用原绑定，避免两个副本共用并清理同一批原图。绑定目录不可用、权限不足、环境不符或命名空间已被占用时阻止业务启动，需修复原因后重试。运行实例持有该命名空间的独占锁，资料目录锁仍保留。

界面不提供修改日志根。调整日志根需要同时迁移文件及受管引用，不能只编辑配置中的路径。录制盘在设置页“录制盘”里增删、调整顺序，见下节。

| 内容 | 位置 | 生命周期 |
| --- | --- | --- |
| 程序日志 | `runtime/<环境>/<实例>/gluesight-*.jsonl` | 按时间和容量滚动；事件带 `sessionId`，打开项目后带 `projectId`，旧日志仍可读 |
| PLC 日志 | 同一 runtime 目录下 `plc.db` | SQLite；运行时可有 WAL/SHM，保留天数来自当前 PLC 配置 |
| 真机历史原图 | 各录制盘的 `vision/<环境>/<实例>/<项目>/records/` | 当前项目按真机录制策略跨所有录制盘滚动保留（默认不限）；其他项目（含已删除项目）的随过期记录清理；被示教件引用的不清理 |
| 历史数据库 | 资料根下 `history/inspection.db` | 本机一份，记录带所属项目，保留录制状态与每件的录制目录（绝对路径）；原图按记录的录制目录读 |
| 采集轮次 | 项目内 `recipe-capture/<轮次>/` | 新示教件只写轮次记录、引用历史原图；以前导入的轮次里的 PGM 原图可能是唯一一份，随项目导出与复制 |
| 冻结示教图与标定特征 | 项目内 `workspaces/<配方>/images/`、`calibration/<轮次>/` | 随候选和项目保存 |
| 棋盘格标定结果与原图 | 项目内 `calib/`、`calib/images/` | 成功标定写入原图及项目相对引用，随项目迁移 |
| 发布资源 | 项目内 `vision/releases/` | 不可变发布资源，包含冻结示教图和标定引用，不属于视觉日志 |
| 恢复状态及审计 | 本机 `state/`、`history/audit-spool/` | 维持现有恢复契约，不归入普通日志清理 |

录制原图内部结构保持日期目录、`*_cycle_<cycleId>/`、`{相机}_s{seq:06}.pgm` 和 `part.json`，不改变相机与帧组身份。

## 录制盘

- **写哪块盘**：每件开录时按列表顺序选第一块剩余空间不少于 5 GB 的盘，本件的 `_pending/` 临时目录与收尾目录都在这块盘的录制根下，一件不跨盘；写满一块自动换下一块。5 GB 余量是固定常量，不可配置。剩余空间查询失败的盘照常使用；目录不在且建不起来（盘离线、拔出）的盘跳过。
- **全部不足**：所有录制盘都低于余量或不可用时，在线检测报警栏与就绪检查“审计与录制”项告警，列出每块盘的剩余空间或“不可用”；新件按录制关闭处理，照常接件、检测、回写 PLC 与入历史。要测图的件（收尾补测读原图）仍写临时录制，写到在线录制盘里剩余最多的一块，收尾一律删除；写盘失败时那些帧补测不了，按检测不完整报，不影响下一件。空间恢复后自动恢复录制。
- **改列表**：设置页“录制盘”列出每块盘的路径、剩余空间、是否可写与新件当前写哪块；可添加、移除、上移下移。保存时逐块建目录并试写，不可写、重复或互相包含（同一目录换大小写、末尾分隔符或子目录也算）的拒绝保存；至少保留一块。保存后下一件按新列表选盘，已录的件不搬。
- **读**：每件按记录里的录制目录读，目录必须在某块已配置录制盘的本项目录制根下。那块盘离线或已从列表移除时报“原图所在盘不可用”，加回或接上后可读。

## 旧日志与原图

启动时只绑定日志根并取锁，不复制旧数据。早于外置日志根的版本留在资料根 `logs/` 和项目内 `records/`、`records-offline/` 的日志与原图不导入，历史读图只认已配置的录制盘，读不到这些旧原图；软件也不自动删除它们。

## 历史读图、清理与磁盘空间

历史原图按记录的录制目录找到它所在的录制盘（读图、复测、诊断包、历史件导出、从历史选示教件都一样），继续检查路径边界、`cycleId`、相机、帧组、帧号与 `part.json` 身份，不用任意同名文件代替。

运行日志保留 30 天、总量上限 1 GiB、单段上限 16 MiB，只清理 `gluesight-` 文件。历史数据库默认保留 180 天，由本机设置控制，覆盖本机全部项目，非当前项目的过期记录连同原图一起删除；生产原图的保留件数与总大小由当前项目设置控制，新项目默认不限（已有项目 `cycle.json` 里存的值不变）。原图滚动清理跨所有在线录制盘，按件的时间（录制目录名的时间戳）从新到旧累计，超出件数或总大小上限的旧件删除，离线的盘不扫；清理保护最新一件、在用及待入库目录，并同步数据库引用；带 `maintenance-collect` 标记的维护采集原图仍跳过自动滚动清理；被本机任一项目的示教件、标定件引用的历史件，记录与原图都不参与滚动清理和按天清理。

磁盘空间守护每 5 s 复查一次：录制盘按上节选盘与告警；资料目录所在盘低于 2 GB 时另告警（检测记录与追溯可能写不进去），不再因此停录，原图照常写到有余量的录制盘。示教、标定、采集轮次、样本和发布资源不进入原图滚动清理。

## 示教和标定图片

从历史选用一件用于示教或标定时，项目的 `recipe-capture/` 只写轮次记录，帧原图按记录的 `cycleId` 在检测记录库查到录制目录再读（可在任意盘），不复制也不链接；被引用的录制受清理保护，录制已不在时示教件提示原图不可用（[在线投运 5.2](online-commissioning.md#52-导入为采集轮次引用录制)）。

棋盘格标定成功时，原图保存到 `calib/images/<样本ID>.pgm`，标定 JSON 的 `samplePath` 为项目相对路径，另保留 `sampleId`、相机、视图，以及 `corners`（`image.board_calib` 找到的内角点像素坐标，按行排，首点为原点）。未显式冻结样本、直接使用最近帧时生成独立样本编号。先完成原图写入，再更新标定结果；图片写入失败时不发布新引用，已有图片不可被不同内容覆盖。同一冻结图像可复用原图后重新标定。

成功标定的样本图保留在项目内，本次不增加自动清理。标定页拍照或导入的冻结样本为内存对象，只持久化成功标定所用原图；进入标定页或切换相机、视图时，按当前标定的 `sampleId` 把该原图载入为冻结样本（`workspace_station_restore`，编号不变），原图不在时保持空态。

## 项目管理与导出

项目 ZIP 格式继续使用 `project/records/`。勾选包含历史记录时，导出从每块录制盘收集本项目的原图合进包里同一个 `records/`（录制目录名带时间戳与 `cycleId`，不重名），从本机记录库导出本项目记录的子集，并把子集中各录制盘的路径归一到包内项目根。导入时核验原图、整体装到第一块剩余不少于余量的录制盘（都不足时装第一块），重定位记录；任一录制盘上已有该项目编号的原图目录时拒绝覆盖，记录并入本机记录库；既有目标目录拒绝覆盖，操作失败撤回本次创建的外部资料与并入的记录。复制项目不带历史记录与原图。

导入的外部原图带项目提交标记。启动恢复时逐块录制盘核对，项目目录尚未提交则清理未完成原图；项目已提交则保留原图并移除标记，避免中断留下孤儿目录或误删已导入图片。

冻结示教图、标定图、采集轮次记录和发布资源随项目导出；新示教件的原图引用录制，只随历史记录带出；以前导入的轮次目录里的 PGM 原图照带。项目用量分别报告项目目录和各录制盘上的外部视觉证据之和，合计为占用空间；保留的旧目录副本仍占实际磁盘空间。

删除项目只删项目目录，该项目的检测记录与外部视觉原图保留，过期后随记录清理。项目先进入 `.trash`，后台删除，中断后启动续清。`.trash` 里带外部原图清理标记的残留按标记清理：标记只记录项目编号，清理时核对编号与目录名，并通过受管配置推导每块录制盘上的外部路径，不信任任意文件路径，不清理其他项目或共用运行日志；离线盘上的残留这次清不到，同编号新建项目时提示先处理。

诊断包通过当前日志与每件记录的录制目录所在录制盘解析文件，包内结构保持原契约；原图所在盘不可用的件在包的说明里注明未打包。系统设置显示资料目录、日志根、运行日志及当前项目在第一块录制盘上的视觉目录，并提供对应的打开入口；录制盘列表单列。

历史页“导入历史件”的原图装到第一块剩余不少于余量的录制盘的 `imported/`；启动时逐块录制盘清理中断导入的暂存。

## 验证边界

定向回归覆盖资料实例隔离与锁、录制盘选盘（第一块不足时写第二块、全部不足时不录原图）、录制盘重复或互相包含拒绝保存、按记录目录跨盘读图与根外拒绝、跨盘按时间清理、历史件导入只引用录制原图与被引用录制免清理、棋盘格原图保存、项目导出导入复制及删除续清。测试使用临时目录，不触碰开发或正式现场资料。

目录调整不替代真实相机、PLC 和现场磁盘吞吐验收；多块物理盘、盘离线与热插拔只在现场验证。部署后通过设置页核对资料目录与日志根，再检查项目资产。

## 代码入口

- [`log_storage.rs`](../../src-tauri/src/log_storage.rs)：根绑定、录制盘列表、环境及实例隔离与锁。
- [`storage.rs`](../../src-tauri/src/storage.rs)、[`cycle.rs`](../../src-tauri/src/cycle.rs)：资料状态、目录入口、录制盘设置及录制根接线。
- [`project/records.rs`](../../src-tauri/src/project/records.rs)：项目在各录制盘上的录制根，按记录的录制目录找所在盘。
- [`applog.rs`](../../src-tauri/src/applog.rs)、[`plc.rs`](../../src-tauri/src/plc.rs)：运行日志与 PLC 日志。
- [`recorder.rs`](../../src-tauri/src/recorder.rs)、[`disk_guard.rs`](../../src-tauri/src/disk_guard.rs)：跨盘清理与保护、选盘及资料盘/录制盘空间。
- [`recipe_capture/burst/history.rs`](../../src-tauri/src/recipe_capture/burst/history.rs)、[`vision.rs`](../../src-tauri/src/vision.rs)：历史件导入（引用录制原图）及标定图保存。
- [`project/transfer.rs`](../../src-tauri/src/project/transfer.rs)、[`project/manage.rs`](../../src-tauri/src/project/manage.rs)：项目打包、复制、统计与删除。
