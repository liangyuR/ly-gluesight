# 配方创建与示教

配方都是**段配方**（分段连拍飞拍）：固定胶枪，机器人抓工件从胶嘴下走过，三台独立相机共用 Line0 高电平门控，按软件设定的固定帧率（默认 10 fps）沿胶路连续采集。本文写段配方的业务行为，规则取舍与实现细节见 [分段连拍决策记录](../decisions/segment-burst.md)。生产现场的相机交付格式、门控时序和毫米精度仍须现场验收。

## 段配方流程

### 业务结构

```text
候选配方（segments 非空）
  ├─ 段列表：沿胶路的直线段 / 弯道段，各段预期帧数 N_exp、帧数容差、检测区间、检测项与允差
  ├─ 三台计划相机（共用 Line0 门控，各按设定帧率出帧，按 SDK 帧号配成帧组）
  │    └─ 各自一条检测走廊（按直线段几何示教）、像素当量、检测参数
  ├─ 整圈采集轮次（多轮，含标准件轮次）→ 多轮标定 → ΣN_exp、各段 N_exp 与建议容差、标准件 x_ref
  ├─ 默认检测参数与按段类型的默认检测项
  ├─ 独立整圈验证样本与验证记录
  └─ 待生效的不可变发布版本（发布包格式 schema 4）
```

- 每个帧周期三台相机各出 1 帧，不是一帧里三个视角。帧序号取相机 SDK 帧号，不按到达顺序；同一序号的三帧配成一个帧组，某台缺帧只标“检测不完整”，不改变 OK/NG。三台相机必须互不相同、都是单视角设备。
- 配方里没有“拍照点”，计划是段列表。预期帧数 N_exp 不能手填，只能由多轮采集得出；新建时各段“待标定”，整件预期总数 ΣN_exp 有值之后才能发布。
- 配方结构版本为 8，7 及更早的文件拒绝读取、不迁移，需要重建。发布包结构版本为 4；业务身份用明确的 ID、版本、修订号、帧号与帧组序号，不计算业务内容哈希。

### 页面主线

进度总览把步骤排成 `capture → segments → corridor → calibration → validation → publish`，每步给出完成条件与阻塞原因。

| 步骤与页面 | 行为与完成条件 |
|---|---|
| 配方库 | 新建配方取相机组的前三台相机（不足三台也能建，但不能发布）和一个直线段，各段“待标定”，帧数容差默认 ±1。卡片标明阶段（草稿 = 只有候选、没发布过；采集版；正式版）和 PLC 要配的型号 |
| 整圈采集 | 确认计划相机就绪、设好曝光与增益，核对现场轨迹，点“开始整圈采集”；PC 准备接收和保存后请求 PLC，PLC 接受并启动运动，Line0 高电平期间相机按设定帧率采集。每轮是一件工件的一次完整行程，轮次可标为标准件 |
| 段列表（`/recipe/segments`） | 沿胶路添加直线段与弯道段：类型、长度、帧数容差、检测区间 [a, b]、检测项（胶宽、断胶、溢胶；直线段另有胶偏）。预期帧数 N_exp 与标定统计只读；改段序列或类型会清空全部 N_exp、统计与 x_ref |
| 配方默认参数 | 默认检测参数、标定轮数和按段类型（直线 / 弯道）的默认检测项，新建段与走廊示教时取用 |
| 相机走廊示教（`/recipe/teach`） | 每台相机从一轮完整采集里选一帧冻结，在这一帧上提取并保存一条走廊，设像素当量与检测参数；三台相机都保存后完成 |
| 多轮标定（`/recipe/calibration`） | 把完整采集轮次加入标定（至少 `calibrationRounds` 轮，默认 10，可配 10–100；标准件轮次不计入），点“应用标定”得出 ΣN_exp，再逐段确认容差 |
| 验证与发布（`/recipe/validation`） | 发布前检查、独立正常样本验证、发布；发布在工件边界生效。另有“发布采集版”（见下文） |

### 整圈采集

本地图片状态为 `waitingStart → receiving → draining → complete/failed`；PC 发请求前已进入可接收状态，避免遗漏 PLC 接受后的首帧。握手按 [示教接口 V1](../integration/teaching-capture-sequence.md) 的 DB6 / DB12 执行，不走生产握手。一轮帧数由实际接收决定，不设上限。图片完成或取消后仍保持资源锁定，直到 PLC 确认并释放；异常未结事务需人工处置并复位。每台相机的每一帧存成无压缩 PGM，帧元数据追加写入 `frames.jsonl`，重启后据此恢复统计。

- 完成条件：收到 PLC 采集结束（示教 PLC 状态 20）、收尾窗口（200–30000 ms）到期、已入队的帧全部写完；三项齐备即完成，不用计数判完整。
- 缺帧（丢包、写盘队列满、图像内存预算满）记缺帧并告警，不判轮次失败；采集结果页显示帧组数、各相机帧数、不完整帧组与丢帧告警（只告警）。
- 相机断连或会话变化、写盘超时、操作员中止、手动帧、计数来源变化等使整轮失败；失败的轮次保留供追溯，需要整圈重采。采集失败时 PC 按示教接口报失败（PC 状态 30 与原因码）。
- 开始接收前把候选里每台相机的曝光与增益下发到相机。

### 轮次分段复核与帧组屏蔽

采集完成后，在采集页整理本轮帧组。段类型及顺序来自段列表；有 K 段时设置 K−1 个边界，每个边界表示上一段的最后一个原始帧组，下一段从该序号加一开始。边界必须严格递增，不能产生空段或超出本轮范围。保存草稿后，通过边界附近的原图复核并确认；三台相机共用同一套边界。

已确认轮次可以设为当前配方的分段模板。其他轮次可显式按原帧号或总帧组数比例套用，结果始终是待确认草稿；套用保留目标轮次自己的屏蔽记录，不复制模板的异常帧组。比例只提供初始位置，不能证明弯道减速时的边界准确。段结构变化后旧确认失效；模板还校验采集配置，不能跨不匹配的采集条件直接套用。

帧组可按连续区间屏蔽或恢复，屏蔽需填写原因。屏蔽仅表示该组图像不参与标定测量取样，原图和原始序号仍保留，`groupCount`、各相机原始采集计数及缺帧告警均不变。例如 90 组屏蔽第 40–42 组后仍是 90 组，第 43 组不改号；页面另列屏蔽 3 组、未屏蔽 87 组，未屏蔽不等于测量成功。运动暂停、程序错误等异常轮次应整轮移出标定，不通过屏蔽压缩正常帧数。

已被走廊示教引用的帧组不能直接屏蔽，需先更换示教帧；已屏蔽的帧组不能新选作示教帧。已加入标定轮次的边界或屏蔽发生变化时，该轮移出标定并清除派生标定结果；整理完成后重新加入、应用标定并验证。手动移出标定同样清除派生结果，其余轮次保留，重新应用标定时仍需满足轮数要求。屏蔽恢复同样需要重新计算，不沿用旧结果。

已确认的手动边界用于多轮标定的逐段标定（见“多轮标定”）；草稿或模板套用后未确认的边界不参与。手动边界不接入生产 `Segmenter`，生产与独立样本验证仍按未分段检测，不能通过屏蔽隐藏验证缺陷。不提供永久删除原图或单相机局部屏蔽。

### 相机走廊示教

每台计划相机示教一条走廊：在这台相机的示教帧上沿胶路提取（刷选后“自动提取走廊”，或“笔划直接生成走廊”），可编辑点、调整点间距。三台相机各一条、所有帧共用；走廊只决定每帧的检测范围与测站，没有逐点的示教中线比对。示教帧必须来自本候选的一轮完整采集，采集后相机的设备配置不能变；走廊至少两点、不短于 1 px 且完整落在示教帧内才算保存。每台相机各设一个像素当量（由设备菜单的“标定”得出，没有视角）和可选的检测参数，检测项与允差按段配置。

选帧期间采集轮次列表自动刷新，正在采集或收尾的轮次完成后即可选择；未完成及失败轮次不作为示教来源。从采集结果点击“用于走廊示教”会直接打开本轮选帧，即使相机已有示教帧，也先预览本轮候选帧；确认“用此帧示教”后才更换已保存的示教帧并返回走廊编辑。

弯道帧里胶条走出走廊时，这一帧记“检测不完整”，不判 NG。这个走廊模型还没有用真实弯道图验证（决策记录 D-SB-17）。

### 多轮标定

同一工件程序连续采集多轮，在“多轮标定”页把完整轮次加入标定；标记为标准件的轮次另用于胶偏参考 x_ref，不计入轮数。点“应用标定”：每轮取整件帧组数，均值四舍五入作 ΣN_exp，记录各轮 min / max / mean，并给出建议容差 = max(默认容差, N − min, max − N)；容差由操作员逐段确认后才写入。

- 单段配方同时写该段 N_exp 与统计。多段配方只有在每个标定轮次（不含标准件）都在采集页确认了手动分段时才逐段标定：按边界得出每轮各段帧组数，各段分别取均值四舍五入作 N_exp、记录 min / max / mean 并给出建议容差，ΣN_exp 取各段之和（取整可能与整件均值差一两帧，ΣN_exp 只用于帧数告警）；有轮次未确认分段时各段保持“待标定”并列出这些轮次，ΣN_exp 取整件均值，凭它即可发布。多段配方的 x_ref 仍不计算。运行时整条胶路按一个未分段区域判，只核对整件帧组数 ∈ ΣN_exp ± Σtol。
- x_ref 只用于直线段，由标准件轮次去掉首尾各一帧后取均值得出，不能手填；只有单段、`AbsoluteX` 的配方会算，`ToEdge` 的测量量没有实现，该段胶偏不判。
- 重新标定使 ΣN_exp 变化时，发布会分配新的计划版本；PLC 只发型号，不需要同步帧数。

### 判定

三台相机取最差：任一相机任一帧 NG，所在区域即 NG，整件取最严重结论。每帧独立检测胶宽、断胶和溢胶（某帧最大胶宽超过溢胶上限判 NG，PLC 结果码沿用 NG_WIDTH，原因写“溢胶”）；气泡、拉丝不检，结果标“未检项”。整条胶路按一个未分段区域判：只跑每帧独立检测，不判胶偏；帧组数不在 ΣN_exp ± Σtol 内只记“帧数异常”告警；缺帧只标“检测不完整”；都不改变 OK/NG，整件没有一帧测成才判 ERR（91）。PLC 提前报运动结束时用已收到的帧照常判，帧组数小于 ΣN_exp − Σtol 时加 `short_part` 标记。起头、收尾不在检测范围内，结果写明各段检测区间 [a, b] 与“未检区域”。

### 验证与发布

发布前检查：设备与采集；走廊示教（恰好三台计划相机，每台都有示教帧、走廊完整落在帧内、有像素当量，且示教后相机的设备标签没变）；段标定（有 ΣN_exp 即通过，逐段列出 N_exp、“待分段算法”或“待标定”）；标准件 x_ref（只在有启用胶偏检查的直线段时列出；多段配方与 `ToEdge` 运行时不判胶偏，列出原因、不阻断）；独立正常样本；生产版本。

独立样本取自新的实拍整圈（不能是走廊示教或多轮标定用过的轮次）或原图齐全、段结构相同的生产历史，用候选的走廊逐帧重测；缺帧只算检测不完整，帧组数超出 ΣN_exp ± Σtol 只写进样本原因，不改变是否符合。验证运行期间或之后设备、标定、引擎、候选修订或生产基础版本变化，需要重新验证。

通过后发布成 schema 4 发布包：先生成不可变包并保存待生效版本，冻结该候选；当前工件继续持有原配方快照，在完整工件与 PLC 事务边界切换。失败保留原因和同一个待生效包，人工重试切换，不重复生成版本；也可放弃待生效版本。

### 采集版（在线投运）

新产线正常生产、还没有可用配方时，先把未完成的候选发布成**采集版**（配方 `stage = collect`），维护模式按它的型号、三台计划相机与曝光增益跟着生产采图；攒够历史件后再示教、标定、验证，发布**正式版**（`stage = formal`，即上一节的完整发布）。在线投运的整体方案见 [在线投运](online-commissioning.md)。

- 发布前检查只有：恰好三台互不相同的计划相机；都在当前相机组里且是单视角独立相机；三台的曝光与增益齐全有效；型号不与其他生产配方冲突；至少一段（可以是一个直线段占位）；生产版本（候选基于当前生产版本，且还没有正式版）。不要求走廊示教、ΣN_exp 标定与独立验证，不生成发布包。
- 版本号照常递增，计划版本照常由配方库分配（PLC 只发型号），同样在工件边界生效；验证与发布页的确认框逐条列出未满足的项，全部满足才能确认。
- 采集版之后照常继续示教、标定、验证，发布正式版即替换；正式版不能降级：已有正式版时拒绝发布采集版（检查项与配方库写入两处都拒绝）。
- 正常模式的生产准入遇到采集版一律拒收（“配方只有采集版，仅维护模式可用”，回 90/95）；只有维护模式按采集版采图，不判定。

### 维护模式（在线投运）

在线检测页开启维护模式（须填原因），从下一件起 PC 置 pcMode=1、每件照常布防采图，回 PLC 结果码 0（按未检放行），不输出 NG：

- 采集版配方：只录图不判定，不论录制设置都录全部帧；录制目录带保留标记，不被自动清理。
- 正式版配方：照常测量判定（试判），结论入历史但不进当日合格率，也不输出给 PLC。
- 找不到配方或配方、设备有问题：不拒收，照常布防放行，原因记进本件记录（不录图）。

在线检测页按配方显示“已录 N 件，其中完整可用 M 件”（完整可用：录制完整、各计划相机帧数一致且非零），标定至少需要 10 件，验证另需若干。退出维护模式前列出仍只有采集版的配方：退出后这些型号回 90/95。实现取舍见 [维护模式决策](../decisions/maintenance-mode.md)。

## 候选配方离线试运行

在线检测页的“候选配方离线试运行”只在离线样本集模式提供，选择已保存候选和样本件后单圈运行；验证与发布页提供入口。每次运行冻结候选修订、测量图、图像尺寸与引擎，继续走整圈采集、测量、判定和离线 S7 握手，不发布候选、不写入生产配方。样本帧按 [离线样本集格式](../integration/sample-set-format.md) 的段配方解释取：每台计划相机按清单顺序的第 seq 帧。

运行中及结果显示候选编号和修订，并标注调试。历史记录单列“候选调试”，不计入真机或普通离线统计；调试通过不代表标定、独立样本验收或生产发布通过。候选须满足发布就绪（三台计划相机都有走廊与像素当量、ΣN_exp 有值），各计划相机的示教帧采集后设备配置没变，按示教帧尺寸建走廊测量图；同时保留结构、尺寸、计数和会话校验。

飞拍可行性计算器允许手填像素当量；修改其他来源参数时保留手填值，仅在明确恢复来源值时替换。此值用于当前页估算，不写入示教标定或替代标定验证。

离线样本模式的主设备状态不使用生产发布条件判定候选调试；已发布配方回放有独立入口与检查范围。候选启动仍由后端核对示教、样本、设备及周期状态。历史按记录自身来源展示，不能随当前站点模式改变身份。进入或退出离线后清除上一次当前工件、结果与实时图像显示，统计恢复当前站点范围；历史数据库与候选示教保持不变。

## 验收分层

段配方的全流程（合成图三相机从建站到投产）由软件回归覆盖，测试入口见 [测试记录](../testing/TESTING.md)。软件流程测试不代表实体相机、PLC 接线或算法质量已经验证；真实样本集 gs-20261017 是停稳拍数据，只作冒烟。

3 × 25 Hz 吞吐门槛口径不改，尚未达标也没有被直接验证：须在现场工控机上用真实相机来源跑 `pnpm test:soak:throughput`，再决定降低相机帧率还是加测量并发。

现场仍需确认：拿到按量产曝光与速度拍的含弯道三相机图像，验证分段算法与“每台相机一条直线走廊”的模型（D-SB-17）；核对三台相机共用门控的接线、SDK 帧号来源与三路带宽（约 826 Mbps 的估算超过单个千兆口 80% 预算）；用真实良品、断胶、偏位、宽度异常样本验证检测质量，并检查实际采集速度下的带宽、写盘和连续运行表现。
