# 配方创建与多图示教

段配方的流程见下面“段配方流程”一节；旧拍照点配方的页面流程与状态设计以 2026-10-11 确认的为准（标“旧拍照点模型，保留、停用”的各节），替代此前“每个拍照点只能选择一幅图”的设计。生产现场的相机交付格式、硬触发时序和毫米精度仍须单独验收。

当前完成程度、已取得的测试结果和后续步骤见 [当前进度与后续计划](recipe-creation-progress.md)；本文说明业务行为，不代表全部验收已经通过。

2026-10-11 软件交付范围：负责人明确无需现场验收、忽略算法。本轮完成工作流、状态约束和软件回归，现场与算法质量不作为送审门槛，也不声明已经通过。

## 段配方流程（分段连拍飞拍，现行）

2026-10-22 起新建的配方都是**段配方**：固定胶枪，机器人抓工件从胶嘴下走过，三台独立相机共用一个触发，沿胶路连续拍照。本节是段配方的业务行为，规则取舍与实现细节见 [分段连拍决策记录](../decisions/segment-burst.md)，实施进度见 [当前进度与后续计划](recipe-creation-progress.md)。没有段列表（`segments` 为空）的**旧拍照点配方**从未部署，已停用：配方工作台不再提供它的示教、试测、特征定位等入口，后端遗留代码不再维护；后面标“旧拍照点模型”的各节只作历史记录。

### 业务结构

```text
候选配方（segments 非空）
  ├─ 段列表：沿胶路的直线段 / 弯道段，各段预期帧数 N_exp、帧数容差、段首 / 段尾跳过帧数、检测相机、检测项与允差
  ├─ 三台计划相机（共用一个触发，各出 1 帧，按 SDK 帧号配成帧组）
  │    └─ 各自一条检测走廊（按直线段几何示教）、像素当量、检测参数
  ├─ 整圈采集轮次（多轮，含标准件轮次）→ 多轮标定 → ΣN_exp、各段 N_exp 与建议容差、标准件 x_ref
  ├─ 默认检测参数与按段类型的默认检测项
  ├─ 独立整圈验证样本与验证记录
  └─ 待生效的不可变发布版本（发布包格式 schema 4）
```

- 一次触发是三台相机各出 1 帧，不是一帧里三个视角。帧序号取相机 SDK 帧号，不按到达顺序；同一序号的三帧配成一个帧组，某台缺帧只标“检测不完整”，不改变 OK/NG。三台相机必须互不相同、都是单视角设备。
- 配方里没有“拍照点”，计划是段列表。预期帧数 N_exp 不能手填，只能由多轮采集得出；新建时各段“待标定”，整件预期总数 ΣN_exp 有值之后才能发布。
- 配方结构版本为 8（旧拍照点配方与段配方共用，7 及更早的文件按 D-0 拒绝读取，需要重建）。段配方的发布包结构版本为 4，旧拍照点配方仍为 3；业务身份仍用明确的 ID、版本、修订号、帧号与帧组序号，不计算业务内容哈希。

### 页面主线

进度总览把步骤排成 `capture → segments → corridor → calibration → validation → publish`，每步给出完成条件与阻塞原因。

| 步骤与页面 | 行为与完成条件 |
|---|---|
| 配方库 | 新建配方取相机组的前三台相机（不足三台也能建，但不能发布）和一个直线段，各段“待标定”，帧数容差默认 ±1。卡片标明阶段（草稿 = 只有候选、没发布过；采集版；正式版）和 PLC 要配的型号 |
| 整圈采集 | 确认计划相机就绪、设好曝光与增益，核对现场轨迹，点“开始整圈采集”；PC 准备接收和保存后请求 PLC，PLC 接受并启动运动，Line0 高电平期间相机按设定帧率采集。每轮是一件工件的一次完整行程，轮次可标为标准件 |
| 段列表（`/recipe/segments`） | 顶部“分段标定”工作台：选一轮完整采集作模板轮，在三台相机缩略图的帧组时间轴上点帧间竖缝插入或删除边界、点段名切换直线 / 弯道、点缩略图并排预览三台相机原图，在段下方点选该段的检测相机（D-SB-41，没选中的相机判定时不用），保存时一次写入段列表、确认本轮边界并设为分段模板（D-SB-44）。下方按选项卡逐段编辑长度、帧数容差、段首 / 段尾跳过帧数、检测项（胶宽、断胶、溢胶；直线段另有胶偏）。预期帧数 N_exp 与标定统计只读；改段序列或类型会清空全部 N_exp、统计与 x_ref，其余已整理轮次的边界变为需复核，保存前提示 |
| 配方默认参数 | 默认检测参数、标定轮数和按段类型（直线 / 弯道）的默认检测项，新建段与走廊示教时取用 |
| 相机走廊示教（`/recipe/teach`） | 每台相机从一轮完整采集里选一帧冻结，在这一帧上提取并保存一条走廊，设像素当量与检测参数；三台相机都保存后完成 |
| 多轮标定（`/recipe/calibration`） | 把完整采集轮次加入标定（至少 `calibrationRounds` 轮，默认 10，可配 10–100；标准件轮次不计入），点“应用标定”得出 ΣN_exp，再逐段确认容差 |
| 验证与发布（`/recipe/validation`） | 发布前检查、独立正常样本验证、发布；发布在工件边界生效。另有“发布采集版”（见下节） |

### 整圈采集（段配方）

本地图片状态为 `waitingStart → receiving → draining → complete/failed`；PC 发请求前已进入可接收状态，避免遗漏 PLC 接受后的首帧。握手另按 [示教接口 V1](../integration/teaching-capture-sequence.md) 的 DB6 / DB12 执行，不使用生产 `shotCount`/`deviceShots` 或 `partStart`。一轮帧数由实际接收决定，不设 1–64 上限。图片完成或取消后仍保持资源锁定，直到 PLC 确认并释放；异常未结事务需人工处置并复位。每台相机的每一帧存成无压缩 PGM，帧元数据追加写入 `frames.jsonl`，重启后据此恢复统计。

- 完成条件：收到 PLC partEnd、收尾窗口（200–30000 ms）到期、已入队的帧全部写完；三项齐备即完成，不再用计数判完整。
- 缺帧（丢包、写盘队列满、图像内存预算满）记缺帧并告警，不判轮次失败；采集结果页显示帧组数、各相机帧数、不完整帧组与丢帧告警（只告警）。
- 相机断连或会话变化、写盘超时、操作员中止、手动帧、计数来源变化等使整轮失败；失败的轮次保留供追溯，需要整圈重采。采集失败在握手仍可报告时回写 90 配 98/99。
- 开始接收前把候选里每台相机的曝光与增益下发到相机，规则同旧拍照点配方。

### 轮次分段复核与帧组屏蔽

段结构与模板轮边界优先在段列表页的分段标定工作台里按图像一次定好（见“页面主线”的段列表一行）；其余轮次在工作台下方“其余轮次复核”里确认：软件按图像把模板边界对齐到所选轮次，逐个边界并排对照模板与本轮两侧的帧，← → 微调、Enter 确认，全部确认后一次保存（D-SB-44）。采集页的轮次整理仍可按数字边界、按比例或原帧号套用模板并确认，屏蔽与恢复只在采集页。段类型及顺序来自段列表；有 K 段时设置 K−1 个边界，每个边界表示上一段的最后一个原始帧组，下一段从该序号加一开始。边界必须严格递增，不能产生空段或超出本轮范围。保存草稿后，通过边界附近的原图复核并确认；三台相机共用同一套边界。

已确认轮次可以设为当前配方的分段模板。其他轮次可显式按原帧号或总帧组数比例套用，结果始终是待确认草稿；套用保留目标轮次自己的屏蔽记录，不复制模板的异常帧组。比例只提供初始位置，不能证明弯道减速时的边界准确。段结构变化后旧确认失效；模板还校验采集配置，不能跨不匹配的采集条件直接套用。

帧组可按连续区间屏蔽或恢复，屏蔽需填写原因。屏蔽仅表示该组图像不参与标定测量取样，原图和原始序号仍保留，`groupCount`、各相机原始采集计数及缺帧告警均不变。例如 90 组屏蔽第 40–42 组后仍是 90 组，第 43 组不改号；页面另列屏蔽 3 组、未屏蔽 87 组，未屏蔽不等于测量成功。运动暂停、程序错误等异常轮次应整轮移出标定，不通过屏蔽压缩正常帧数。

已被走廊示教引用的帧组不能直接屏蔽，需先更换示教帧；已屏蔽的帧组不能新选作示教帧。已加入标定轮次的边界或屏蔽发生变化时，该轮移出标定并清除派生标定结果；整理完成后重新加入、应用标定并验证。手动移出标定同样清除派生结果，其余轮次保留，重新应用标定时仍需满足轮数要求。屏蔽恢复同样需要重新计算，不沿用旧结果。

已确认的手动边界用于多轮标定的逐段标定（见“多轮标定”）；草稿或模板套用后未确认的边界不参与。手动边界本身不接入生产 `Segmenter`：生产与独立样本验证按逐段标定得出的各段 N_exp 比例推算每件的边界（D-SB-40，见“判定”），不能通过屏蔽隐藏验证缺陷。暂不提供永久删除原图或单相机局部屏蔽。

### 相机走廊示教

每台计划相机示教一条走廊：在这台相机的示教帧上沿胶路提取（刷选后“自动提取走廊”，或“笔划直接生成走廊”），可编辑点、调整点间距。三台相机各一条、所有帧共用；走廊只决定每帧的检测范围与测站，没有逐拍照点的示教中线比对。示教帧必须来自本候选的一轮完整采集，采集后相机的设备配置不能变；走廊至少两点、不短于 1 px 且完整落在示教帧内才算保存。每台相机各设一个像素当量（由设备菜单的“标定”得出，没有视角）和可选的检测参数，检测项与允差按段配置。

选帧期间采集轮次列表自动刷新，正在采集或收尾的轮次完成后即可选择；未完成及失败轮次不作为示教来源。从采集结果点击“用于走廊示教”会直接打开本轮选帧，即使相机已有示教帧，也先预览本轮候选帧；确认“用此帧示教”后才更换已保存的示教帧并返回走廊编辑。

弯道帧里胶条走出走廊时，这一帧记“检测不完整”，不判 NG。这个走廊模型还没有用真实弯道图验证（决策记录 D-SB-17）。

### 多轮标定

同一工件程序连续采集多轮，在“多轮标定”页把完整轮次加入标定；标记为标准件的轮次另用于胶偏参考 x_ref，不计入轮数。点“应用标定”：每轮取整件帧组数，均值四舍五入作 ΣN_exp，记录各轮 min / max / mean，并给出建议容差 = max(默认容差, N − min, max − N)；容差由操作员逐段确认后才写入。

- 单段配方同时写该段 N_exp 与统计。多段配方只有在每个标定轮次（不含标准件）都在采集页确认了手动分段时才逐段标定：按边界得出每轮各段帧组数，各段分别取均值四舍五入作 N_exp、记录 min / max / mean 并给出建议容差，ΣN_exp 取各段之和（取整可能与整件均值差一两帧，ΣN_exp 只用于帧数告警）；有轮次未确认分段时各段保持“待标定”并列出这些轮次，ΣN_exp 取整件均值，凭它即可发布。多段配方的 x_ref 仍不计算。各段都标定后运行时按比例分段（见“判定”），否则整条胶路按一个未分段区域判；帧数都只核对整件帧组数 ∈ ΣN_exp ± Σtol。
- x_ref 只用于直线段，由标准件轮次去掉首尾各一帧后取均值得出，不能手填；本轮只有单段、`AbsoluteX` 的配方会算，`ToEdge` 的测量量没有实现，该段胶偏不判。
- 重新标定使 ΣN_exp 变化时，发布会分配新的计划版本，界面提示 PLC 同步 `shotCount`/`deviceShots`。

### 判定（段配方）

三台相机取最差：任一相机任一帧 NG，所在区域即 NG，整件取最严重结论。每帧独立检测胶宽、断胶和溢胶（某帧最大胶宽超过溢胶上限判 NG，PLC 结果码沿用 NG_WIDTH，原因写“溢胶”）；气泡、拉丝本轮不检，结果标“未检项”。分段按 D-SB-40：多段配方各段都已逐段标定时，本件收尾后按各段 N_exp 的比例与本件帧组数推算边界；帧组数在 ΣN_exp ± Σtol 内时边界可信，每个边界两侧各 `boundaryGuard` 帧（配方默认参数页“边界过渡帧数”，默认 2、可配 0–5）为过渡区，只按两侧较宽的允差判每帧胶宽、断胶、溢胶，不判胶偏；其余帧按所属直线 / 弯道段判，直线段核心区域去首尾各一帧判胶偏（多段配方没有 x_ref 时标“胶偏未判”）。单段配方、有段待标定或帧组数越界时整条胶路按一个未分段区域判：只跑每帧独立检测，不判胶偏。帧组数不在 ΣN_exp ± Σtol 内只记“帧数异常”告警，不逐段核对帧数；缺帧只标“检测不完整”；都不改变 OK/NG，整件没有一帧测成才判 ERR（91）。PLC 提前 partEnd 时用已收到的帧照常判，帧组数小于 ΣN_exp − Σtol 时加 `short_part` 标记。各段段首 / 段尾跳过的帧不判定、不计检测不完整，结果按帧组号列为“未检区域”；分段生效前只有整件起头（第 1 段段首）与收尾（末段段尾）能定位（D-SB-22 修订）。原按毫米的检测区间已停用。

### 验证与发布（段配方）

发布前检查：设备与采集；走廊示教（恰好三台计划相机，每台都有示教帧、走廊完整落在帧内、有像素当量，且示教后相机的设备标签没变）；段标定（有 ΣN_exp 即通过，逐段列出 N_exp、“待逐段标定”或“待标定”；多段配方里 N_exp 短于 2 × 过渡帧数 + 1 的直线段提示两侧过渡区取空后不判胶偏，不阻断）；标准件 x_ref（只在有启用胶偏检查的直线段时列出；多段配方暂不计算 x_ref、`ToEdge` 测量量未实现，列出原因、不阻断）；独立正常样本；生产版本。

独立样本取自新的实拍整圈（不能是走廊示教或多轮标定用过的轮次）或原图齐全、段结构相同的生产历史，用候选的走廊逐帧重测；缺帧只算检测不完整，帧组数超出 ΣN_exp ± Σtol 只写进样本原因，不改变是否符合。通过后发布成 schema 4 发布包，在工件边界生效，机制同旧拍照点配方；发布日志写明 PLC 要同步的 `shotCount`/`deviceShots`（等于 ΣN_exp）。

### 采集版（在线投运）

新产线正常生产、还没有可用配方时，先把未完成的候选发布成**采集版**（配方 `stage = collect`），维护模式按它的型号、三台计划相机与曝光增益跟着生产采图；攒够历史件后再示教、标定、验证，发布**正式版**（`stage = formal`，即上一节的完整发布）。

- 发布前检查只有：恰好三台互不相同的计划相机；都在当前相机组里且是单视角独立相机；三台的曝光与增益齐全有效；型号不与其他生产配方冲突；至少一段（可以是一个直线段占位）；生产版本（候选基于当前生产版本，且还没有正式版）。不要求走廊示教、ΣN_exp 标定与独立验证，不生成发布包。
- 版本号照常递增，计划版本照常由配方库分配（协议 7 下 PLC 只发型号），同样在工件边界生效；验证与发布页的确认框逐条列出未满足的项，全部满足才能确认。
- 采集版之后照常继续示教、标定、验证，发布正式版即替换；正式版不能降级：已有正式版时拒绝发布采集版（检查项与配方库写入两处都拒绝）。
- 正常模式的生产准入遇到采集版一律拒收（“配方只有采集版，仅维护模式可用”，回 90/95）；只有维护模式按采集版采图，不判定。

### 维护模式（在线投运）

在线检测页开启维护模式（须填原因），从下一件起 PC 置 pcMode=1、每件照常布防采图，回 PLC 结果码 0（按未检放行），不输出 NG：

- 采集版配方：只录图不判定，不论录制设置都录全部帧；录制目录带保留标记，不被自动清理。
- 正式版配方：照常测量判定（试判），结论入历史但不进当日合格率，也不输出给 PLC。
- 找不到配方或配方、设备有问题：不拒收，照常布防放行，原因记进本件记录（一期不录图）。

在线检测页按配方显示“已录 N 件，其中完整可用 M 件”（完整可用：录制完整、各计划相机帧数一致且非零），标定至少需要 10 件，验证另需若干。退出维护模式前列出仍只有采集版的配方：退出后这些型号回 90/95。实现取舍见 [维护模式决策](../decisions/maintenance-mode.md)。

### 旧拍照点模型（保留、停用）

新建配方（`recipe_template`）都是段配方；旧拍照点模型从未部署、已停用，下面只作历史记录；当时的行为是：示教按拍照点、Pose 与视角，停稳拍（`trigger_mode = Stop`）、组选图、特征定位、示教中线逐点比对、三目拼接拆分和发布包 schema 3 都仍然可用（保留清单见决策记录第八节）。下面标“旧拍照点模型”的各节是它们的业务行为，不适用于段配方。

## 业务结构（旧拍照点模型，保留、停用）

一个 SDK device 的一次硬触发交付一张拼接图。软件保留完整拼接原图，并依据设备配置拆出图 1、图 2、图 3。一张拼接图生成一个拍照点，三幅图不重复计数。

```text
候选配方
  ├─ 采用的采集轮次 captureId
  │    └─ 拍照点 k / shotId
  │         ├─ 图 1：选用、标定引用、中线、参数、试测、完成状态
  │         ├─ 图 2：选用、标定引用、中线、参数、试测、完成状态
  │         └─ 图 3：选用、标定引用、中线、参数、试测、完成状态
  ├─ 默认检测参数与判定参数
  ├─ 独立整圈验证样本与验证记录
  └─ 待生效的不可变发布版本
```

旧拍照点配方的发布包结构版本为 3，配方结构版本现为 8（见上，7 及更早的旧文件按 D-0 拒绝读取，保留原文件供备份后重建）。业务身份使用明确的轮次 ID、图像 ID、配方版本、候选修订、设备会话、帧号、触发计数及图编号；不计算业务内容哈希。

`ShotSpec.views` 保存每图配置。`ShotSpec.view` 及顶层示教字段是当前编辑图的投影，切换编辑图不改变采集来源。运行时只检测启用的图。发布包按 `(k, view)` 存原图（清单记示教图编号 `imageId`）和标定资源，用特征定位的视图另带定位模板 `template.pgm`，不能按发布清单的数组下标推断拍照点数量。

## 整圈采集（旧拍照点模型，保留、停用）

状态依次为 `waitingStart → receiving → draining → complete/failed`。`draining` 表示 PLC 已结束，正在等待在途图像。PLC 开始时自动提供计划数量（1–64），开始前显示待收到；等待在途图像时间是 200–30000 ms。

- 界面不填写计划触发次数；PLC 开始时锁定本轮数量，实时统计收图。PLC 结束和实际触发计数参与完整性校验，收到计划数量不能提前结束。
- 检查设备会话、图像尺寸、计数来源、连续帧号以及可用的触发计数；无法确认来源时失败，不自动补位。
- 19/21 张对应计划 20 张、重复或跳帧、掉线、写盘失败、队列溢出和超时均保留异常轮次，要求整圈重采。
- 不检测点仍须正常收图。所有图像属于明确轮次，异步写盘队列不能将旧轮次帧加入新轮次。
- 退出时尚未完成的轮次在恢复时标为异常。重新采集不覆盖旧轮次。设备会话每次启动重新建立，上次进程的异常轮次不封锁本次启动的会话，重启后可直接重采。
- 失败轮次不封锁设备会话，可直接重采：新一轮的基线取开始时本会话见到的最高帧计数，计数不大于它的迟到帧不计入；PLC 开始前到达的帧让新一轮判失败。
- 真实 MVS 设备须显式配置横向三等分、纵向三等分或三个不重叠裁切区域。裁切尺寸和范围必须有效。
- 开始接收前把候选里该 device 的曝光与增益下发到相机，并记入本轮；采用后各图记下采集时的值。之后改配方的曝光与增益不作废已采图像与示教，单帧示教页只提示两者不同。生产布防前按配方逐台下发（PLC 换型同样），下发失败拒绝布防。

S7 教学采集复用现有握手的一个设备槽。开始时只根据本轮数量建立临时计划，核对该槽数量等于总数、其他槽为零，并记录 PLC 计划版本。采集事务有独立 `captureId`，不生成生产工件记录，不计入生产 OK/NG。采集结束后仍完成结果序号、ACK 和输入释放握手，设备才回到空闲。

采用图像或加入验证样本要求当前工件与 PLC 事务结束。重新实拍独占设备；使用已保存图像编辑候选和离线试测不占用采集设备。

## 示教与标定（旧拍照点模型，保留、停用）

单图状态为未配置、编辑草稿、待试测、有效试测完成、示教完成。算法正常执行并形成 NG 也是有效试测；全段缺胶不能仅因没有有效宽度测点而被归为执行失败。真正的算法异常或无法判定不能完成示教。

自动中线提取默认使用刷选：按住左键从胶路起点沿中心刷到终点，每一笔替换当前选区。笔刷宽度可设为 6–300 原图像素，覆盖胶路及两侧少量背景；中键拖动和 Ctrl＋滚轮仍用于平移、缩放。矩形框选保留为辅助方式，包含相邻阴影时应改用刷选。

刷选路线只提供搜索范围、方向和起止位置，不直接替换已保存中线。GlueSight 沿笔划法向寻找完整双侧胶边，并按靠近笔划、位置与宽度连续性选取路线。无完整边缘、无法连续连接、笔划折返或等价路线有歧义时返回具体原因与原图位置，图中标出失败点并保留笔划和原中线；不跨过缺失胶边补线。矩形方式仍采用区域分割与细化，不具备笔划方向先验。

“笔划直接生成中线”将当前笔划整理为可编辑草稿，保留端点和转角，不依赖自动边缘提取，也不表示胶路存在或检测通过。生成后仍须人工检查并运行算法，旧试测结果不能用于保存示教。

中线编辑点间距可设为 4–80 原图像素，默认 20。新提取与“应用到当前中线”均按间距整理点列并保留端点、转角；为保持形状，转角附近可能比设定间距更密。该设置不修改全配方的检测站距（mm）。修改中线后需重新试测；提取结果需要人工检查，不自动完成示教。

默认标定引用为 `device-v1`、`device-v2`、`device-v3`。毫米误差目标暂定 ±0.1 mm，与胶宽公差分别配置。标定检查记录标准尺寸、实测尺寸、误差及适用的设备、标定和比例状态；设备、标定或比例改变后不能沿用原通过记录。现场必须使用实际参考件测量，界面填写通过记录本身不构成精度证明。

代表性拍照点验证通过后，操作员可明确确认复用范围；仅对设备、图编号、标定、设备配置和比例均匹配的已采图复用，并保留验证 ID、来源点和来源原图。

### 定位特征（特征定位，可选；只服务旧拍照点模型）

需要按工件特征判胶偏的图，在示教页右栏“定位特征”里用画布的“定位框”模式在冻结示教图上拖出定位框（取整到像素）。松手后先做只读检查：带 4 px 外圈的模板框要在图内、不能压同一场景任何胶检测走廊（含示教中线两端的切向延长），没过的框标红、列出原因、不写进草稿。图上叠加带外圈的模板框、搜索范围（框四周各扩搜索半径）和杠杆臂 L（框中心到最远站）。可改框、搜索半径、最低分数和次峰比上限；v1 只找平移，示教余量 m 与两端搬移上限只能由验证建议写入。

试测时同时做示教图检查：纹理（框内灰度标准差 ≥ 12）、亮像素比例 < 0.1、示教图上定位被采用且位姿恒等（偏移 ≤ 0.5 px），杠杆臂过长只告警。任一阻断项没过，试测就无效，即使胶路另判 NG。保存示教要人工确认框里没有胶（含越过示教段后拐弯、其他 Pose 或其他胶路的胶），也没有喷嘴、胶枪等随相机不动的结构；框里有胶没有自动检查能拦住，只靠这条确认。“定位试测”在样本库里同一拍照点、同一幅图的原图上试定位并显示位姿与 d′，只作诊断、不保存。定位框是在别的示教图上保存的（重新冻结、整圈重采、继承示教之后）时，页面提示来源过期，确认框位置后运行试测会把框改绑到当前示教图。

开转角是高级设置：要有同一修订的验证统计且转角证据满足前两个条件（±3° 下 L·|θ| 的 P95 超过公差/5、全部帧含亮度 ±40 都看得出角度），再选一种独立证据并写说明，确认记进应用日志；草稿自动保存和整份保存不能把转角调大。

## 判定（旧拍照点模型，保留、停用）

| 层级 | 汇总规则 |
|---|---|
| 同一拍照点 | 任一选中图 OK 则点 OK；没有 OK 且有异常则点异常；全部 NG 则点 NG |
| 整件 | 任一检测点异常则整件异常；无异常但有 NG 则整件 NG；全部检测点 OK 才是整件 OK |

已有“允许短段超差”的 OK 子类型归于合格。各图的独立结果与异常原因保留在实时帧及历史明细中，即使另一图使该点汇总为 OK。缺帧、设备故障等采集级异常独立阻止正常判定。全不检配方禁止发布。

## 修改与恢复（旧拍照点模型，保留、停用）

| 操作 | 结果 |
|---|---|
| 修改单图中线或参数 | 保留原图，仅该图重新试测；整套验证失效 |
| 修改定位框、门限，或采用两端参数建议 | 同上：特征定位是测量定义，该图重新试测、重新保存示教，整套重新验证 |
| 修改默认参数 | 实际使用该默认值的图重新试测，覆盖值未变的图保留完成状态；整套验证失效 |
| 取消并重新勾选 | 保留原示教；图像、标定、引擎和生效参数仍相同才恢复完成状态 |
| 标记不检测 | 保留该点图像和示教；更新检测范围、撤销整套验证 |
| 整圈重采 | 只有数量相同且人工确认轨迹及触发顺序对应时才带入旧中线参数，全部作为待确认草稿 |
| 单帧恢复旧原图 | 已采用整圈采集时拒绝，避免旧轮次图像混入当前轮次 |
| 退出并恢复 | 以已成功保存的草稿恢复；未保存成功不能显示已保存 |

## 验证与发布（旧拍照点模型，保留、停用）

所有选中图完成示教和适用的标定验证后，至少用一套独立于示教采集的正常整圈样本重新执行当前候选检测。支持重新实拍及结构、轨迹顺序、成像条件适用且原图完整的历史工件。图像加载校验各点、各图和尺寸，不复用旧测量结果充当验证。样本来源由操作员确认，后端继续校验轮次、计划版本、结构和设备状态。

所选正常样本须符合预期。缺陷样本为可选验证项，其结果如实保存，不作为本版必选发布门槛。验证运行期间或验证之后设备、标定、引擎、候选修订或生产基础版本变化，需要重新验证。

用了特征定位的图，验证时在每件独立正常样本上另跑整图亮度 ±40 和 ±3° 的离线试定位，形成发布前检查“特征定位”：每件都要定位成功、d′ 的 σ ≤ 位置公差/5、亮度 ±40 下没有错锁、每次 ±40 都跑出结果且至少有一次锁在原位姿，开了转角的图每帧都要看得出角度；位姿用到搜索半径 70% 以上、|μ − 名义值| 超过公差/3（不自动校正）、部分 ±40 被拒、只找平移却测到明显转角、两端参数还没采用建议、样本不足 10 件只告警。验证页给出两端参数建议（护栏 = 两端 |Δ| 的 P99 + 1 mm，示教余量 m = P99 + 1 个站距），确认后由后端写进配方（这是两端参数唯一的写入口）；写入改的是测量定义，该图要重新试测、整套重新验证。发布要求每个特征定位图都有同一修订、通过的统计。

发布先生成不可变包并保存待生效版本，冻结该候选。当前工件继续持有原配方快照，在完整工件与 PLC 事务边界切换。失败保留原因和同一个待生效包，人工重试切换，不重复生成版本。生产生效状态无法可靠保存时阻止下一件开始，恢复可靠状态后再继续。

## 候选配方离线试运行

（两类配方都适用：段配方按脉冲串节拍运行，旧拍照点配方按触发次数与拍照点取图。）

在线检测页的“候选配方离线试运行”只在离线样本集模式提供，选择已保存候选和样本件后单圈运行；验证与发布页提供入口。每次运行冻结候选修订、测量图、图像尺寸与引擎，继续走整圈采集、测量、判定和离线 S7 握手，不发布候选、不写入生产配方。

运行中及结果显示候选编号和修订，并标注调试。历史记录单列“候选调试”，不计入真机或普通离线统计；调试通过不代表标定、独立样本验收或生产发布通过。旧拍照点配方的试运行仍要求组选图完成、所选检测图的示教与当前图像、设备及引擎相符；段配方须满足发布就绪（三台相机走廊与当量、ΣN_exp 有值），各计划相机的示教帧采集后设备配置没变，按示教帧尺寸建走廊测量图。两类都保留结构、尺寸、计数和会话校验。

飞拍可行性计算器允许手填像素当量；修改其他来源参数时保留手填值，仅在明确恢复来源值时替换。此值用于当前页估算，不写入示教标定或替代标定验证。

## 验收分层

（两类配方都适用。段配方的全流程验收，即合成图三相机的建站到投产，已做；3 × 25 Hz 压测门槛没有达标、也没有被直接验证，已定（2026-10-23）：门槛口径不改，等现场工控机用真实相机来源跑 `pnpm test:soak:throughput` 后再决定降 PLC 频率还是加测量并发，合并前须完成该复测，见 [测试记录](../testing/TESTING.md)；真实样本集 gs-20261017 是停稳拍数据，只作冒烟。）

软件回归应覆盖采集数量和顺序异常、多图 OR、整件异常优先、有效 NG 示教、修改失效、草稿恢复、标定状态、样本来源以及发布边界。当前 S7 回环测试验证协议交互；原生 DLL 专项已于 2026-10-12 删除。软件流程测试不代表实体相机、PLC 接线或算法质量已经验证。已执行结果以进度文档和对应测试报告为准。

现场仍需确认：段配方要拿到按量产曝光与速度拍的含弯道三相机图像，验证分段算法与“每台相机一条直线走廊”的模型（D-SB-17），核对三台相机共用触发的接线、SDK 帧号来源与三路带宽（约 826 Mbps 的估算超过单个千兆口 80% 预算），并在现场工控机上复测吞吐；旧拍照点配方仍需确认 SDK 确实以一个 device 交付拼接图、实际拼接区域、硬触发计数、机械臂轨迹对应关系，以及不同代表性 Pose 下的 ±0.1 mm 误差。两类配方都要用真实良品、断胶、偏位、宽度异常样本验证检测质量，并检查实际采集速度下的带宽、写盘和连续运行表现。

离线样本模式的主设备状态不使用生产发布条件判定候选调试；已发布配方回放有独立入口与检查范围。候选启动仍由后端核对示教、样本、设备及周期状态。历史按记录自身来源展示，不能随当前站点模式改变身份。进入或退出离线后清除上一次当前工件、结果与实时图像显示，统计恢复当前站点范围；历史数据库与候选示教保持不变。
