# 历史件导出包

在历史页选一件或多件检测记录，打成一个自包含的 ZIP 包，再导入本机或另一台机器当前项目的历史，用于复测、示教或对比。典型场景是把现场的维护采集件带回开发机示教。取舍理由见 [HS-7](../decisions/history-scope.md#hs-7-历史件导出包导入件归当前项目)。

实现在 `src-tauri/src/history_package.rs`（打包、校验、装原图、启动恢复）和 `src-tauri/src/store/package.rs`（按件导出记录库子集、按件并入），前端在 `src/features/history/components/PackageDialogs.tsx`。与项目导出包、配方回传包共用 `project/transfer.rs` 的 ZIP 读写与清单核对。

## 能导出什么

- 一次 1–20 件（每件约四千个帧文件，清单要在 64 MB 的读取上限以内），同属一个项目，都是带 cycleId 的真机段配方记录。历史列表可勾选记录进行 [Tag 或删除操作](history-management.md)；选中无 cycleId 或旧拍照点记录时不能导出历史件包。
- “包含原图”默认勾选。勾选后，只有录制完整、目录在该项目某块录制盘的真机录制根下、目录名与 cycleId 一致、有 `part.json` 的件才带原图；其他件只带记录与每帧指标，结果里逐件列出原因。不带原图的件导入后只能按已存指标重判，不能原图复测，也不能选作示教件。
- 原图量大，彩色现场每件约 0.7–5 GB。

## 包格式（`kind: "history"`，格式 1）

| 包内路径 | 内容 |
| --- | --- |
| `manifest.json` | `kind`、`format`、来源项目编号与名称、导出时间、来源软件版本、各件身份（`cycleId`、SN、时间、原图目录名或 null）、`notes`，以及每个文件的字节数与 SHA-256 |
| `records.db` | 记录库子集（版本 11）：所选记录、帧记录、记录所用的配方快照；指向子集外的复测引用置空 |
| `parts/<录制目录名>/` | 带原图的件的录制目录原样拷贝（`part.json` 与 `{相机}_s{seq:06}.pgm` 等） |

包里不含本机绝对路径。`records.db` 里带原图的件，录制目录记为 `parts/<目录名>`，帧原图记为 `<目录名>/<文件>`。不带原图的件没有录制目录和帧原图引用，`recording_available = 0`，录制错误里注明“导出包未带原图”。

## 导入

1. **读清单**：选包后先只读清单，预览来源项目、导出时间、软件版本、件数、带原图件数，以及本机已有、会跳过的件数。
2. **拒绝不能用的包**：以下情况整包拒绝，并给出原因：
   - `kind` 不是 `history`。
   - 格式版本不认识，提示升级软件。
   - 清单里的 cycleId 或目录名无效、重复，目录名与 cycleId 不一致。
   - 有清单外条目、重复条目，或路径不在 `records.db`、`parts/<清单列出的目录>/...` 之内。
3. **去重**：本机记录库里已有同一 cycleId 的件，不论属于哪个项目，都跳过，原图也不解出，结果里列出跳过的 SN 与时间。全部重复时不改动任何东西，提示没有新件。
4. **解包核对**：其余文件解到当前项目在第一块剩余不少于 5 GB 的录制盘（都不足时第一块）上真机录制根下的 `imported/.staging-<毫秒>-<n>/`，逐个核对字节数与 SHA-256。再核对 `records.db`：
   - 库版本为 10 或 11，且记录来源只能是生产。
   - 记录正好是清单里的各件，都是真机段配方记录。
   - 原图引用都是包内相对路径。
   - 新件的 `part.json` 属于本件。

   任一项不符，整包拒绝，并删掉暂存目录。
5. **写入**：先把暂存库里的引用改到当前项目：录制目录改为 `<录制根>/imported/<目录名>`，帧原图改为 `imported/<目录名>/<文件>`。然后在一个记录库事务里完成：
   - 并入记录：归当前项目，重新编号，按 cycleId 再查一次重复。
   - 带入配方快照：快照按（当前项目, 修订号）保存，本机已有同修订号但内容不同时整包拒绝。
   - 提交前，把新件的原图目录从暂存移到 `imported/<目录名>/`；目标已存在则拒绝覆盖。

   提交失败时，移入的目录随即删除。
6. **完成**：去掉各目录里的未提交标记 `.history-import-pending`，删除暂存目录。

导入的件和本机记录不作区分：照常出现在历史列表、各项统计、历史件选择器和试测里。

## 进度与取消

导出与导入都是 Operation 长任务，界面显示进度条，可以取消：

- 打包和解包阶段按文件计数，可以取消。导出取消后删除未完成的包，包写完、替换目标文件前进入写入阶段（`saving`），之后不能取消；导入取消后删除暂存目录。
- 导入进入写入阶段（`saving`）后不能取消。

## 中断与清理

- **启动恢复**：启动打开记录库后，扫描当前项目的 `imported/`：
  - 删掉残留的 `.staging-*`。
  - 带未提交标记的目录：记录库里有记录引用它，就去掉标记；没有，就删除该目录。
- **滚动清理**：录制的滚动清理（件数、容量）只扫日期目录，不动 `imported/`。
- **保留天数清理**：导入件和其他记录一样，按记录时间与本机保留天数清理。被清理时，导入件的原图目录连同记录一起删除（`Store::purge_before` 把当前项目的导入件原图目录也交给清理）。早于保留期的件导入后，结果里会提示它们会在下次清理时删除。

## 已知限制

- 配方修订号只在项目内唯一。不同项目各自发布的同号版本内容不同，所以带这些件的包导不进当前项目，会提示是哪个修订号冲突。从同一个项目复制或导出导入而来的项目，修订号对应同一内容，可以正常导入。
- 包里不带发布包。导入件的“按原发布包重现”与辅助线不可用，按原配方重判、按候选复测和原图复测不受影响。

## 测试

定向回归在 `src-tauri/src/history_package/tests.rs`：

- 往返一致：原图引用为包内相对路径；导入后记录、每帧指标、原图字节与配方快照一致，原图位于导入目录。
- 重复导入：只导新件，已有件跳过，不新增记录或目录。
- 损坏、版本不支持、配方快照冲突：整包拒绝，不留记录与原图。
- 中断恢复：已提交的原图保留，未提交的删除。
- 过期清理：导入件的原图交给清理，本机录制仍归录制滚动清理。
