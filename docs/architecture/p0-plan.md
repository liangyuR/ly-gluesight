## 1.1 现场相机（W0 已知）

- 型号：海康 MV-CU013-80GC（负责人提供，按数据手册传感器 SC130GS 对应；以相机标签为准）。1280 × 1024，4.0 µm 像素，全局快门，满分辨率最高 89.9 fps；GigE；Line0 光耦输入（硬触发）、Line1 光耦输出（频闪）、Line2 双向 IO，与现有 `Line0` 触发、`Line1` 频闪配置一致。
- 像素格式只有 Bayer BG 8/10/10Packed/12/12Packed，**没有 Mono8**：现有代码设 Mono8 失败只记警告，取图回调只收 Mono8，因此真机上没有预览、测量拿不到图且原因不明确。由步 0b 解决。
- 数据手册未写明 Chunk 内容（帧计数、触发计数、时间戳是否可选）。需在 MVS 特性树里确认 `ChunkSelector` 的可选项，结论决定步 2 的计数来源。
- 单帧 8 位约 1.31 MB；三台同时触发经同一千兆上行口约需 33 ms 传完。需确认工控机是每台相机一个网口，还是交换机共享上行；并在台架上确认无丢包。（按 1.2 节，现场是一台三目设备，这一条改为按每次触发三幅图的数据量核算。）

## 1.2 三目相机（2026-10-10，W0 已知与待确认）

**已知（负责人告知）**

- 三目相机在 SDK 枚举时只出现为**一个 Device**，不是三台独立相机。
- **一次取图得到三幅图像**（三个视角）；每个拍照点由人工示教从中**选一幅**来检测。

**旁证**

- 早期的海康三目演示数据每帧是 `FrameN_1/2/3.jpg` 三个文件，回放相机已经按“通道”读取（`replay.rs`、`CameraConfig.replay_channel`）。

**待现场确认（决定步 T 的取图实现）**

1. 三幅图怎么交付：一帧里拼接（上下或左右，各占多大）、按颜色通道打包、SDK 的多部分（multi-part）缓冲，还是同一触发的三次回调？
2. 每幅图的分辨率与像素格式：是否仍是 1280 × 1024、Bayer BG8；1.1 节的 MV-CU013-80GC 是否就是其中的传感器。若三幅按颜色通道打包，步 0b 的 Bayer 转灰度不适用，要改为按通道拆包。
3. 三幅图是否同一时刻曝光；触发输入几路（整个设备一路，还是每个视角一路）；Chunk 的帧计数 / 触发计数是设备级一份，还是每个视角一份。
4. 设备最高帧率与每次触发的数据量（若每幅 1.31 MB，一次约 3.9 MB）；设备到工控机的链路与丢包。
5. 能否只输出选中的视角；不能时生产也要收三幅。录制与历史是三幅都存，还是只存选中的一幅。
6. 现场一共几台三目设备（一台，还是每把胶枪一台）。

**对已完成各步的影响**
