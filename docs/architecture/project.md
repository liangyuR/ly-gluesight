# 项目（Project）设计

## 一、目标

把“一套可上线的检测方案”收拢成一个**项目**：相机组参数、PLC 配置、节拍设置、工位标定、配方（候选、示教资料、采集轮次、示教件测量、发布包）都归属于某个项目。这套方案产生的检测记录存在本机一份记录库里，每条记录带所属项目；历史原图按项目存放。软件启动时打开当前项目，操作员可以切换、新建、删除项目。

典型用途：同一台工控机在换线、换夹具或换相机布置后切到另一套方案；调试新方案时不影响已上线的方案。

不在本设计范围：PLC 不感知项目；不支持两个项目同时运行；不做按项目的操作权限。

## 二、概念与边界

- **项目** = 一个工位的完整检测方案。一个项目内可以有多个配方，PLC 仍以 `productCode` 在**当前项目**的配方中选取；当前项目没有对应配方时，本件照常运动，工件结束后回“配方不可用”（90/95）。
- **本机资料**指与项目无关、属于这台工控机或整个资料目录的内容：PLC 握手事务、检测记录库与审计 spool、历史保留天数、日志、界面偏好等。
- 任一时刻只有一个**当前项目**；项目资料通过当前项目根目录访问，新检测记录归当前项目。历史原图按记录所属项目，由受管日志绑定解析到该项目的外部目录。项目管理页可以读取其他项目的统计信息和删除其他项目。

### 归属划分

| 资料 | 现位置 | 归属 | 说明 |
| --- | --- | --- | --- |
| 相机组 | `config/cameras.json` | 项目 | 相机编号、序列号、触发、帧率；项目之间可用不同的相机组 |
| PLC 配置 | `config/plc.json` | 项目 | 地址、点表；切换后按新配置重连 |
| 节拍设置 | `config/cycle.json` | 项目 | 不含历史保留天数 |
| 飞拍估算参数 | `config/feasibility.json` | 项目 | |
| 工位标定 | `calib/` | 项目 | 含 `calib/device/` |
| 生产配方 | `recipes/` | 项目 | |
| 候选与示教资料 | `workspaces/` | 项目 | 含 `comparisons/` |
| 发布包 | `vision/releases/` | 项目 | |
| 采集轮次 | `recipe-capture/` | 项目 | |
| 检测记录库 | 资料目录 `history/inspection.db` | 本机 | 一份，版本 11；记录带所属项目（`parts.project_id`），配方快照与候选实例按项目区分（第五节） |
| 历史保留天数 | 资料目录 `config/history.json` | 本机 | 所有项目共用，清理覆盖本机全部项目 |
| 历史原图 | 外部 `~/gs_logs/vision/<环境>/<实例>/<项目>/records/`、`records-offline/` | 按项目存放 | 按记录所属项目解析；导出项目时按选项带上本项目的；删除项目时保留 |
| 审计 spool | 资料目录 `history/audit-spool/` | 本机 | 待入库的件证据；切换前必须写完 |
| PLC 握手事务 | `state/` | 本机 | 绑定物理 PLC，与项目无关，见第四节 |
| 握手审计、日志 | `state/plc-handshake*`；运行日志和 PLC 日志在 `~/gs_logs/runtime/<环境>/<实例>/` | 本机 | 握手恢复状态不外置；新运行日志条目带项目及会话标识 |
| 界面偏好 | `config/preferences-<SID>.json` | 本机（按账号） | 不记上次打开的配方：配方页按地址打开（[ui-recipe D12](../decisions/ui-recipe.md)） |
| 缓存、WebView、导出、迁移 | `cache/` 等 | 本机 | |

## 三、目录结构

```text
%ProgramData%\ly\GlueSight[-dev]\
  config/
    current-project.json        { "schema": 1, "current": "<projectId>" }
    log-storage.json            日志根、环境、资料实例及所属资料目录绑定
    history.json                { "historyDays": 180 } 历史保留天数
    preferences-<SID>.json
  history/
    inspection.db               本机检测记录库，记录带所属项目
    audit-spool/                待入库的件证据
  projects/
    <projectId>/
      project.json              项目身份与描述
      config/                   cameras.json  plc.json  cycle.json  feasibility.json
      calib/
      recipes/
      workspaces/
      vision/releases/
      recipe-capture/
    .trash/                     删除中的项目，启动时清理
  state/  cache/  webview/  exports/  migration/
```

`project.json`：

```json
{
  "schema": 1,
  "id": "p-20261024-01",
  "name": "京航 A 线",
  "description": "",
  "createdAt": 1793030400000,
  "createdBy": "<软件版本>",
  "copiedFrom": null
}
```

- `id` 创建时分配、之后不变，只含 `[A-Za-z0-9_-]`，同时是目录名；`name` 可改，在本机内不重名。
- 项目内路径引用的写法不变（`workspace.json` 的 `calibTag.path` 等仍为绝对路径）；以后复制、导出项目时用 `storage/relocate.rs` 重写。

## 四、启动与切换

### 启动

1. 资料目录就绪检查照旧（`storage_startup`）；准备日志绑定及独占锁，失败时阻止业务启动。
2. 恢复未完成的项目原图导入，清理 `projects/.trash/` 下的残留；读 `config/current-project.json`，校验 `projects/<id>/project.json` 存在且格式可读。
3. 把当前项目根目录放进托管状态 `ActiveProject`。打开本机记录库 `history/inspection.db`，新记录归当前项目，并把各项目遗留的旧记录库并入（第五节“旧记录库合并”）；之后 `CameraRig`、`PlcHost`、`CycleHost`、`WorkspaceHost` 等按项目根取路径初始化。
4. 本机还没有任何项目时，自动新建空的“默认项目”（编号 `default`）并设为当前项目。
5. 已有项目但当前项目无效（指针缺失、目录被删、`project.json` 损坏）时**不自动挑一个项目**：资料准备窗口进入“选择 / 新建项目”状态，检测服务、相机、PLC 均不启动，选定后写指针并重启。只有一个可用项目时也要求确认一次。

启动画面：每次启动先显示资料准备窗口（`storage-startup`，560×340 无边框），播放一次三叶光圈归位动画（Iris latch），系统开启“减少动态效果”时直接显示定格画面。下方以英文显示后端当前阶段、步数和软件版本。启动依次经过六个阶段（准备资料目录、打开项目、初始化相机与检测、加载配方工作台、初始化 PLC、加载界面）；上述初始化在后台线程执行，阶段由 `storage_startup::stage` 更新、窗口每 500 ms 查询。主窗口建好后先隐藏，前端首屏渲染完调 `startup_ready` 才显示并关闭启动画面；15 s 内没等到就照样显示。启动失败或需要选项目时，窗口放大到 720×480 并恢复系统标题栏，显示错误或项目选择。已初始化的资料目录下，启动画面与主窗口共用 WebView 配置。

### 切换

切换采用**写指针后重启进程**：各宿主都在启动时一次性按路径初始化，开发机实测重启式切换约 1.1 秒，换线场景可以接受。不做不重启的热切换。

1. 操作员在侧栏的项目菜单或项目管理页选目标项目，确认框显示目标项目名称、编号、配方数与检测记录数，并提示“将重启软件”；候选配置有未保存编辑或保存失败时不能切换。
2. 后端 `project_switch(id)` 检查前置条件，任一不满足即拒绝并给出原因：
   - 没有在途工件，没有未结 PLC 事务（由 `project::check_project_switch` 检查）；
   - 录制队列与审计 spool 已写完；
   - 前端没有未保存的候选编辑（前端自查后才发请求）。
3. 原子写 `current-project.json`，写一条 info 日志（旧项目 → 新项目）。正式版调用 `app.restart()`；`tauri dev` 返回 `restartRequired=true`、`currentProject` 和 `nextProject`，不自行重启可执行文件。界面保留等待状态，明确当前项目尚未切换；停止原开发命令后，用原来的 `pnpm dev` 或 `pnpm dev:joint` 参数重新启动。
4. 重启后按“启动”流程打开新项目。

### PLC 握手与项目无关

PLC 握手只关心工件，不记录、不核对项目，握手状态与协议都不改。正常切换要求没有未结事务，所以事务不会跨项目。唯一例外：软件异常退出时 PLC 还有未结事务，下次启动又因当前项目无效、在选择页换了项目，这时“中断工件”按现有逻辑补记到新打开的项目。这是已接受的取舍。

## 五、跨项目约束

- **本机一份记录库，记录带所属项目**：资料目录 `history/inspection.db`（版本 11）保存本机全部项目的检测记录，`parts.project_id` 记所属项目，新记录归当前项目；记录编号本机唯一。配方修订号 `<配方>-v<版本>` 只在项目内唯一（复制项目沿用修订号），所以配方快照 `recipe_snapshots` 按（项目, 修订号）保存，候选实例 `workspace_instances` 按（项目, 实例号）分配；按 SN 关联的复测（`retest_of`）只在同一项目内找。取舍见 [history-scope](../decisions/history-scope.md)。
- **历史原图按项目存放**：原图仍位于绑定日志根的 `vision/<环境>/<实例>/<项目>/records/`、`records-offline/`，不随记录库搬动，读图、诊断包按记录所属项目解析。
- **历史页**：默认看本机全部项目，可切到只看当前项目；列表有“项目”列与项目筛选，按（时间, 记录编号）倒序，详情的前一件 / 后一件同序。当日统计、试判统计、维护采集进度与配方版本下限只算当前项目。
- **其他项目的记录**：查看、读图、按规则重判（用原配方）都可用，配方快照取记录所属项目的；按原发布包重现与辅助线用所属项目 `vision/releases/` 下的发布包，项目已删除时不可用，界面写明原因（发布包随项目删除）。按当前配方重判跳过其他项目的记录（配方编号只在项目内唯一）；按候选对照（规则复测、原图复测）对所有记录开放，可选当前项目的任意候选（[D-SB-58](../decisions/segment-burst.md)），对照文件存在当前项目的 `workspaces/comparisons/<记录编号>/`。诊断包按（项目, 修订号）带配方快照 `recipes/<项目>/<修订号>.json`。
- **本机库升级与旧记录清理**：10 版记录库原地升级到 11，保留生产记录，删除旧离线与候选调试记录及其关联帧、测量数据，并保存删除墓碑，防止审计回放恢复这些件。启动也清理旧离线审计写入。被删除记录引用的原图进入清理队列：只清理能确认属于项目旧 `records-offline/` 根、路径不经过链接、目录名匹配该 cycleId 且未被生产记录引用的目录；不合规路径保留并告警，文件清理失败下次重试。
- **旧记录库合并**：启动时把各项目目录里遗留的旧记录库 `projects/<编号>/inspection.db`（版本 9）中的生产记录并入本机库，一个项目一个事务。当前项目先并，尽量沿用原编号；其余项目重新编号；本机已有同一 cycleId 的件不重复保存，映射到已有记录。之后按编号对照改写项目文件里的记录引用（编号没变的项目也做，清掉指向已清理记录的引用）：候选 `workspace.json` 与示教帧元数据里的 `historyId`、候选的 `teachingPiece.recordId`、采集轮次 `round.json` 的 `origin.recordId`、复测对照目录 `workspaces/comparisons/<编号>/`（目录名、文件名与内容）；旧库里已清理的记录的引用改为 0，对应对照目录删除。冻结的配方文档（候选的 `doc` 与待生效版本 `pending`）、发布包与导航辅助快照里的示教件 recordId 不改。并完的旧库连同 `-wal`、`-shm` 改名为 `inspection.db.merged-<毫秒>.bak`，不删；`project_merges` 记已并入的项目，再启动不重复合并。编号对照与改写完成标记随合并写进本机库，改写先暂存再按清单 `.record-remap.json` 换上，中断后下次启动接着做、不会映射两次，改写完成前旧库不改名（HS-4）。合并失败时该项目旧库保留、写错误日志，下次启动重试。项目目录里遗留的审计 spool：当前项目的移入本机 spool（本机 spool 也有未入库证据时两边都保留，写日志待人工核对）；其他项目还有证据时保留，切到该项目后启动时处理。
- **历史清理**：保留天数是本机设置（资料目录 `config/history.json`，设置页修改），首次启动用当前项目 `cycle.json` 里原有的值建立，`cycle.json` 不再写这一项。清理覆盖本机全部项目的过期记录；非当前项目（含已删除项目）的过期记录连同录制目录一起删除，当前项目的原图仍由录制按件数与容量滚动清理。失效的复测对照只清当前项目的 `workspaces/comparisons/`。
- **审计与诊断**：`applog` 字段增加 `projectId`；诊断包导出当前项目的 `config/` 与 `project.json`。
- **相机与 PLC 物理独占**：不同项目可以引用同一台相机或同一个 PLC 地址，因为同时只运行一个项目，不做跨项目冲突检查。

## 六、项目管理页

入口：侧栏项目卡片菜单的“管理项目…”与导航里的“项目”页（`/projects`）。页面列出本机全部项目，提供新建、重命名、切换、复制、导出、导入、删除。

### 列表

每个项目一行：名称、编号、“当前”标记、描述、创建时间、配方数、检测记录数与时间范围（本机记录库里归该项目的记录）、占用空间（项目目录与外部视觉证据分别显示，合计为总量）。占用空间与记录数可能较慢，单独异步计算，算完前显示“计算中”。`project.json` 损坏的目录也列出，标“不可用”并显示原因，只允许删除。

### 新建

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，本机内不重名 |
| 编号 | 默认按日期生成 `p-YYYYMMDD-NN`，可改；只含 `[A-Za-z0-9_-]`，不与已有目录（含 `.trash`）、仍存在的外部原图目录重名，也不与本机检测历史里出现过的项目编号重复（已删除项目的记录仍在本机，复用编号会把它们算到新项目名下），创建后不可改 |
| 描述 | 可选 |
| 初始内容 | “空项目”或“复制当前项目的硬件配置”（`config/` 与 `calib/`：相机组、PLC、节拍、飞拍估算参数、标定）；不复制配方、候选、采集轮次与记录 |
| 创建后切换 | 默认不勾；勾选时按切换流程检查并重启 |

### 重命名

只改 `project.json` 的名称和描述，不影响编号与目录。

### 删除

- 当前项目不能删除，按钮置灰并提示“先切换到其他项目”。
- 删除只删项目资产（项目目录：配置、标定、配方、候选、采集轮次、发布包等），检测历史与外部历史原图保留：历史页仍能查看、读图、按原配方重判这些记录，按原发布包重现与辅助线随发布包一起不可用，界面写明原因；过期后按本机保留天数连同原图清理。确认框列出将被永久删除的内容（配方数、候选数、采集轮次数、项目目录占用空间），并说明检测记录与历史原图保留，要求输入项目名称后才能确认。
- 删除先把目录原子改名到 `projects/.trash/<id>.<毫秒时间戳>`，列表立即不再出现该项目，再在后台删除。中途退出时下次启动继续清理；`.trash` 里带外部原图清理标记的残留照标记清理其外部原图。删除失败（文件被占用等）写日志，残留留在 `.trash` 等下次启动清理。
- 已删除项目在本机检测历史里还有记录（或并入过旧记录库）时，它的编号不能再用于新建、导入或复制的项目。

### 导出与导入

- **导出**：任一可用项目都能导出为 ZIP（`project/transfer.rs`，格式版本 2）。包内是 `project/` 下的 `project.json`、`config/`、`calib/`、`recipes/`（含修订来源记录）、`workspaces/`（含候选导航图）、`vision/`、`recipe-capture/`（新示教件轮次只有 `round.json` 与 `frames.jsonl`，原图引用检测记录的录制，只随检测记录带出；以前导入的轮次目录里的 PGM 原图可能是唯一一份，照带）、`recipe-support/`（正式导航辅助快照，临时与未生效目录排除）；勾选“包含检测记录与历史原图”时另含 `inspection.db` 与从外部目录收集的本项目 `records/`，默认不含。包里的 `inspection.db` 是本机记录库按项目导出的子集（版本 11，只有本项目的记录、帧记录、配方快照与候选实例；指向其他项目记录的复测引用置空），原图引用归一到包内项目根。本项目示教件、标定件引用的别的项目的历史件（复制出的项目最常见）也一并导出、改归本项目，录制放在包里的 `records/imported/<录制目录名>/`（与历史件导出包导入的件同处：滚动清理不扫，不再被引用、记录过期时随记录删除），记录的录制目录与帧原图引用改到那里；它的配方快照与本项目同修订号的内容不同时拒绝导出。本机审计 spool 不导出。`manifest.json` 记格式版本、来源项目、来源项目目录、导出时间、来源软件版本、是否含记录及每个文件的字节数与 SHA-256。导出当前项目前按切换的条件检查：没有在途件与未结事务、没有在采集、录制与追溯已写完。导出框按是否包含检测记录显示压缩前的导出大小（`project_transfer_size`），不显示项目占用空间。
- **导入**：先完整解到 `cache/project-import-*` 暂存目录，格式版本不认识、路径不在白名单结构内（含 `..`）、清单外条目、重复条目、字节数或校验和不符都整包拒绝，暂存目录用后删除，不留下半个项目。导入为新项目，编号与名称按新建项目的规则校验；`project.json` 的 `copiedFrom` 记来源项目编号。格式 1 的包（带项目自己的 9 版记录库）以及带 10 版记录库的项目包可导入，但只接收生产记录，丢弃旧离线及候选调试记录。
- **检测记录**：包里的记录库并入本机记录库，归新项目：记录全部重新编号，并按新编号改写候选、采集轮次与复测对照目录里的记录引用（范围同第五节“旧记录库合并”，冻结的配方文档、发布包与导航辅助快照不改）；本机已有同一 cycleId 的件（例如同一台机器导出再导入）沿用已有记录、不重复保存，这些件仍归原来的项目。配方快照与候选实例按新项目保存。并入失败时撤回这次并入的记录与已装入的外部原图，整包导入失败。记录并入后、项目目录装上前进程退出时，这次并入记为未装好（`project_merges.installed = 0`）：下次启动时项目目录在就记为装好，不在就撤回这次并入的记录（外部原图暂存同时清掉），同一编号可以重新导入。
- **路径**：`storage/relocate.rs` 把 `workspace.json`、采集轮次 `round.json` 中的项目资产引用改写到新项目目录。导出快照的原图引用先归一到包内项目根，导入和复制时再改为新项目的外部录制根，核对没有残留的来源路径；外部目录已有内容时拒绝覆盖。
- **生产配方**：保持可生产，发布包一起导入，修订号不变；发布包与发布归档按修订号与生产配方对应。
- **候选**：回到草稿，清掉待生效版本。候选的示教件与派生内容（分段、走廊、测量结果）保留；示教件原图按示教件那一件的 cycleId 读本机录制（[在线投运 5.2](online-commissioning.md#52-导入为采集轮次引用录制)）。导入没带检测记录时，导入结果列出有示教件的候选：已发布配方照常检测，本机没有那件的记录与录制时示教件页提示原图不可用，看示教图、示教走廊、测量示教件与试测需重新选用示教件；复制出的项目沿用来源项目的记录与录制，照常可用。导航图与已生效辅助快照保留，辅助资料身份和资源校验异常列为提示，不阻止生产配方导入；归档按配方编号、配方修订和发布 ID 关联。
- 导入完成后提示核对相机组、PLC 配置与标定；切换到该项目仍按切换流程重启。
- 只搬一个示教好的配方时，用配方库的“导出 / 导入工件配方”（回传包，[RB-10](../decisions/recipe-build-flow.md#rb-10-配方回传包)）：带候选与示教件帧记录（不带原图），导入到当前项目替换同编号候选；示教件原图读目标机器上那一件的录制，没有时示教件页提示原图不可用。
- 只搬几件历史件（例如把现场的维护采集件带回开发机示教）时，用历史页的[历史件导出包](history-package.md)：导入到当前项目；带原图的件和本机录制件一样按选用条件核对（相机设备配置须与当前一致等），通过后可以选作示教件；回传包的示教件是这一件时，导入后即可读到原图。

### 复制

- 入口：列表中任一可用项目一行的“复制”。填新项目名称（默认“<原名>（副本）”）、编号、描述。
- 不带检测记录与历史原图：记录本机共用，仍归来源项目，新项目候选里的记录引用（示教件记录与示教件原图）照常指向原记录。历史件选择器列本机全部项目的记录。
- 其余内容与导出相同；文件先拷进 `cache/project-copy-*` 暂存目录，再按导入的规则落成新项目：路径改写到新项目目录、候选回到草稿，最后原子移入 `projects/<新编号>/`。来源项目不改动；`copiedFrom` 记来源编号。
- 复制当前项目前按导出的条件检查。复制后不自动切换，完成框里可直接进入切换流程。

## 七、旧资料不迁移

旧资料全部抛弃、不迁移：新版本不读取根目录下的 `config/cameras.json`、`plc.json`、`cycle.json`、`feasibility.json`、`calib/`、`recipes/`、`workspaces/`、`vision/releases/`、`recipe-capture/`、`inspection.db`、`records/`、`audit-spool/`，首次启动新建空的默认项目。软件不自动删除这些旧文件，启动时检测到它们就写一条提示日志，由人工清理。

## 九、已确认

1. 切换采用写指针后重启软件，不做热切换。
2. 不做按项目的操作权限控制。
4. 旧资料不迁移，全部抛弃（第七节）。
