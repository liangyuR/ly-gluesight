现有队列基线 · 校核三机节拍

相机 → 节拍：64 帧

节拍 → 测量：32 个任务

测量返回 → 节拍

运行契约：先关联，再测量，再结算

  1. 布防：核对现场计划版本及各槽计数、三机必要参数与资源，冻结本件设置和相机会话；建立旧帧隔离边界后确认 armed。
  2. 关联：原始帧保留 cameraId、设备会话、原始计数及来源、设备/接收时刻与有效性；ShotRouter 验证后才产生绑定。
  3. 调度：BoundFrame(cycleId, shotId, cameraId, bundleId) → 现有 Job / lyFlow 工作池；结果必须回带全部身份。
  4. 收尾：partEnd 不是“图都到了”。等待唯一必需 shot 到齐并完成，或截止形成 ERR，再输出一次整件结论。
  5. 交付：PLC 结果包成功写入并确认，历史同时记录交付状态；匹配 ACK 且释放成功后才能开始下件。

在回调时给帧贴上“当前 SN”不能识别上一件的迟到图。身份必须来自经过验证的触发/会话边界；无法确定时不得猜配。

一期继续收敛：三台相机、每 shot 一台相机、同台可多 shot、单件在途、整件结果。随动退出一期入口与维护主线；三维重建、多件并行、在线机器人轨迹规划不作为一期默认承诺。

现场需要补的参数与测量

需要确定的量怎样验证当前证据边界
每 Pose 几何与精度三台实机逐点原图、已知尺度/量具真值、胶段可见性、重复性；验证平面、视角与参考边。已有单应标定与示教能力；多 Pose 几何适用性尚未证明。
相对速度、曝光与清晰度模糊 px ≈ v(mm/s) × t(μs) × 10⁻⁶ / s(mm/px)，仅作平移近似；旋转/透视看实际像素位移。现计算器用≤0.5 px 作初筛，不是实物检测准确性保证。光照、反光和胶形仍需样本验证。
逐相机触发间隔与身份分别取同一相机相邻 shot 的最短间隔；用 PLC/示波器、Chunk 和真实出图交叉核对。1/fps 仅初筛；型号、曝光和读出模式影响结果。帧计数与触发计数不能无条件互换。
共享链路和磁盘负载 = Σ(帧 payload × 触发频率)，按各物理链路分别算，再测同时触发与录制的突发/重传。无本次实测图像尺寸、频率、链路或磁盘数据，因此不填虚构带宽和吞吐量。
测量与整件结果期限分别记录入队等待、引擎耗时、最后触发→done、partEnd→done、队列高水位和超时恢复。现 Measured.ms 不含排队；T_proc 从提交时开始。须冻结现场 deadline 与验收的最坏值。
实物误差、漏检与误报在测试前约定指标和样本量，含三机全部 Pose、边界缺陷、光照变化和独立保留验收样本。现有合成图结果只证明链路；现场指标未知时不能宣布准确率达标。

最终验收看这些结果

正常闭环

cam1→cam2→cam3→cam1 的计划能承受跨机交错到达；每点用正确标定与模板，只有一个整件结论。每件的计划、物理触发、合法帧和完成 shot 可核对。

证据：原图、绑定日志、点表、PLC 结果与配方/资源版本。

异常不会放行

缺首/中/尾帧、漏触发、重复、计数重置、重连、同 SN 旧结果、队列满、测量挂起、写拒绝、ACK 异常和磁盘错误均有预期处理及恢复；无法证明完整的检测不得输出 OK。

各 Pose 的尺度和重复性、良品和边界缺陷满足约定指标；最坏节拍与生产录制下结果按 deadline 到达，内存与队列无持续增长。
