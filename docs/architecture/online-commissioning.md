# 在线投运方案

维护模式、采集版配方与历史件示教。前提是 [生产通讯协议 8](../integration/plc-communication-protocol.md) 的模式字 `pcMode`（维护时结果码为 0，PLC 按未检放行）。

现状：一期（维护模式采集、采集版配方、录制元数据）、二期（历史件导入为采集轮次）与三期（试判统计与复核）已实施，实现取舍与已知限制见 [维护模式决策](../decisions/maintenance-mode.md)。

## 一、要解决的问题

新产线已经在正常生产（机械臂照常涂胶），相机刚装好，还没有可用配方。原有流程建不出配方：

1. **不能停线专门采图**：现场只能跟着生产件采图，不能为建配方停线、让机械臂跑专门的采集轨迹。
2. **没有配方时生产不留图**：PLC 发来的型号在配方库里找不到时，本件照常运动、相机照常出帧，但 PC 不知道该用哪几台相机，不录图，工件结束后回 90/95。
3. **未完成的配方不能生产**：正常模式接件要求配方已示教走廊、有 ΣN_exp（示教件分段得出）、有发布包，否则工件结束后回 90 与故障码。

目标：**不影响生产节拍、不导致停线**的前提下，跟着在线生产采集原图，攒够件数后用这些历史件完成示教、试测、验证并发布，再切到正式检测。

## 二、方案概览

| 环节 | 做法 | 作用 |
| --- | --- | --- |
| **维护模式** | 项目级开关。开启后 PC 置 `pcMode=1`，对每一件都接件、采图、录制，结果码写 0、PLC 按未检放行，永不输出 NG，也不因配方问题回检测错误 | 不影响生产的前提下采图 |
| **采集版配方** | 只定义型号、三台计划相机；发布后只能在维护模式下运行，“只采集不判定” | 让维护模式知道这个型号用哪几台相机 |
| **历史件导入为采集轮次** | 把维护模式录下的完整件登记成候选的采集轮次，轮次只引用这件的录制原图、不复制，分段、走廊示教、测量示教件全部沿用现有流程 | 不停线完成示教与试测 |
| **试判** | 正式版发布后先留在维护模式里运行一段时间，正常测量和判定、记录结论，结果码仍为 0；看过误判率再退出维护模式 | 正式输出 NG 前把关 |

### 端到端流程

```text
装相机、配相机组，在相机页保存各相机曝光与增益
  → 新建配方（型号、相机）→ 发布“采集版”
  → PLC 只需配好型号 → 开启维护模式
  → 生产照常：每件接件、采图、录制，PLC 按未检放行             ← 采集阶段
  → 有完整可用件 → 候选里选一件设为示教件（导入为采集轮次）
  → 分段 → 走廊示教 → 测量示教件，用其他历史件试测 → 发布“正式版”
  → 维护模式下试判 M 件，复核误判                             ← 试判阶段
  → 退出维护模式 → 正式检测，输出 NG
```

## 三、维护模式

相机配置的保存与设备应用分别反馈：`camera_save_config` 成功返回 `saved: true`、`applied`、`warnings` 和 `applyError`。设备离线时，配置仍可落盘，界面显示“配置已保存，设备应用失败”；连接设备后需重新连接并核对实际参数，不能把保存成功当作设备就绪。落盘失败仍报错并保留未保存状态，错误说明是否已应用到设备。

### 3.1 行为

维护模式是**项目级**运行状态，保存在当前项目的 `cycle.json`，重启后保持；进入、退出都写日志，并要求在确认框里说明原因。

开启后，接件流程按配方阶段分两种行为：

| 配方阶段 | 接件登记 | 采图与录制 | 测量与判定 | 回 PLC |
| --- | --- | --- | --- | --- |
| 采集版 | 是 | 录制全部帧（不受录制模式设置影响） | 不做 | 结果码 0，PLC 按未检放行 |
| 正式版（试判） | 是 | 按录制模式设置 | 正常测量、判定，结论记为“试判”，不进合格率统计 | 结果码 0，PLC 按未检放行 |
| 找不到配方 | 是 | 不录（一期限制，见维护模式决策） | 不做 | 结果码 0，PLC 按未检放行 |

**维护模式下 PC 不回检测错误。** 正常模式下工件结束后会回 90 与故障码的情况（型号找不到、配方只有采集版、发布包有问题回 95，相机没就绪回 98 等），在维护模式下都回结果码 0、按未检放行，只把原因记进这件的记录。PC 只因协议故障置 90。

退出维护模式时，列出当前只有采集版、还没有正式版的型号，提示“退出后这些型号的工件会回检测错误（90/95）”，要求确认。

### 3.2 回给 PLC 的结果

按协议 8 第八、九节：维护模式下 PC 置 `pcMode=1`，结果码固定写 0（`faultCode=0`）；PLC 看到 `pcMode=1` 即按未检放行，不看结果码。切换从下一件生效，在途件按接件时锁存的模式完成。

### 3.3 不拖慢节拍

- 采集版不测量，收尾只等收尾窗口和录制队列入队，比正式检测更快。
- 录制队列满时丢帧（记 `rawDropped`），这一件标“原图不完整”，**不能用作示教**，但照常放行。
- **不设采集配额**：维护模式下每件都录制，不设磁盘上限、不自动停录，磁盘由现场负责清理。三台相机按 10 fps 全帧录 PGM，单件约 1～2 GB（取决于分辨率和节拍时长）。录制盘可配多块，按顺序写到第一块剩余不少于 5 GB 的盘；所有录制盘都不足时沿用现有保护：告警，新件（含维护件）不录原图，照常接件并回写 PLC；空间恢复后自动恢复录制（[soak S-7](../decisions/soak.md)）。

## 四、采集版配方

### 4.1 配方阶段

| 阶段 | 含义 | 能否生产 |
| --- | --- | --- |
| 草稿 | 候选，未发布 | 否 |
| **采集版** | 已发布，只有型号、三台计划相机、至少一段（可先放一个直线段占位） | 只在维护模式下，只采集 |
| 正式版 | 完整发布：走廊、ΣN_exp、发布包 | 正常检测；维护模式下为试判 |

### 4.2 发布采集版

- 发布前检查：恰好三台互不相同的计划相机、至少一段、还没有正式版。相机组与型号冲突在接件和写入配方库时照常核对。不要求走廊、ΣN_exp、验证。
- 不生成发布包，只在 `recipes/<编号>.json` 里写 `stage: collect`，版本号照常递增。
- 已有正式版时不能再发布采集版（正式版不降级）。
- 配方卡片显示阶段标记。
- 正常模式下生产遇到采集版配方，本件照常运动，工件结束后回 90/95，原因写“配方只有采集版，仅维护模式可用”。
- 新型号必须先发布采集版再开始攒件：维护模式下找不到配方的件不录图（见 3.1）。

## 五、历史件作为示教数据（二期，已实施）

### 5.1 录制的元数据（一期已实施）

录制时在 `part.json` 里写：

- `partMode`：`maintenanceCollect` / `maintenanceShadow` / `production`（已有的 `mode` 是录制方式，不复用）；
- `devices[]`（已有的 `cameras` 是计划相机编号，不复用）：每台计划相机的 `cameraId`、`cameraConfig`（完整设备配置，与采集轮次的 `round.json` 同一份序列化）、`imaging`（本次打开实际写入相机的曝光增益，没有则取相机保存值）、`deviceSession`；
- `plc`：这件的 `requestSeq`、`productCode`。

没有这些字段的旧历史件不能导入为采集轮次。

### 5.2 导入为采集轮次（引用录制）

候选的示教件页用历史件选择器：列出本机全部真机录制件（不限项目、配方，最新在前，每页 50 件），可按项目、配方、SN、记录日期与判定筛选；每行有时间、SN、模式、判定、所属项目与配方、帧组数、各相机帧数、时长 / 实测帧率（设定）、原图是否完整、不可用原因与提示，可在导入前按相机、帧组预览原图；单选“设为示教件”，选用即导入，生成一个采集轮次（界面不显示轮次，见 [示教件决策](../decisions/recipe-build-flow.md)）。导入时按记录编号重新核对所选的件，不受列表分页影响。试测页的历史件试测默认列当前项目本配方的历史件（可切到本机全部），直接用录制原图复测，不导入。

- **可用条件**：维护模式或生产录制的真实件（不含离线）；原图完整（录制已核验落盘，无缺帧、无 `rawDropped`，每帧都已落盘）；三台计划相机齐全，有曝光增益与设备会话记录；没有提前结束运动（`plc.earlyEnd`）；属于本候选的型号（`plc.productCode`）；帧号与帧组序号一致、没有手动触发帧；本候选还没有选用这一件（已用作示教件的标“已使用”）。不满足时列出全部原因，不能勾选。录制时 `cameraConfig` 与本机当前相机配置不同只提示、不拦：项目与示教件常导到别的机器上示教，取示教帧、测量示教件同样不比较。
- **提示（不阻断导入）**：时长与实测帧率取录制帧的时间戳，设定帧率取 `devices[].cameraConfig`；实测帧率偏离设定超过 10% 时标黄。本批可比较的件（可导入或已导入为本候选轮次）不少于 3 件时，帧组数 N 小于其中位数 M 的 0.9 倍的件提示“帧组数 N，明显少于本批中位数 M（疑似提前结束）”：采集版录制没有 ΣN_exp，提前结束只能从帧组数看出。
- **引用方式**：项目的 `recipe-capture/<新轮次>/` 下只写 `round.json`（格式版本 4，`origin: {kind: "history", cycleId, recordId}`，状态直接为完成；`origin.standard` 恒为 false，只为读入旧轮次保留）与 `frames.jsonl`（每帧的 `path` 是录制目录里的文件名 `{相机}_s{seq:06}.pgm`），不复制也不链接原图。读帧时按 `origin.cycleId` 在本机检测记录库查这件的录制目录（记录里的绝对路径，可在任意盘；录制被迁移或随记录导入时记录库里的目录随之改写，轮次不用改），只接受该目录里的文件。导入时核对每帧原图是普通文件、尺寸与录制一致，且按 cycleId 查到的录制目录就是这些原图所在的目录。
- **保护被引用的录制**：本机任一项目的采集轮次引用的历史件（按 `origin.cycleId`），记录与录制都不参与录制滚动清理与按天清理，也不能在历史页手动删除；换示教件或删除候选会删掉轮次，保护随之解除。清理时现查引用（扫描各项目 `recipe-capture/*/round.json`），查不了就本次不清理。
- **原图不可用**：录制已不在（被手动删除、来自别的机器）或本机没有这件的检测记录时，示教件页提示“原图不可用”和原因；分段、走廊与测量结果不变，已发布的配方照常检测，要看图、示教走廊、测量示教件或试测需重新选用示教件。
- **旧轮次**：格式 3 的轮次原图在本轮目录（以前的硬链接或复制），照常读取，不迁移；本轮目录缺图（导出或复制项目时没带）时按同一查法读来源历史件的录制原图。
- **不停线**：导入只写轮次记录，不占用相机与 PLC，生产进行中也能导入（只等配置门）。导入前在配置门内重新核对所选的每一件，任一件不可用就一件也不导。
- **下游**：示教件用于分段、走廊示教与测量示教件（各段 N_exp、x_ref），兼作标准件，规则见 [配方创建流程](recipe-creation-workflow.md)。
- **标准件**：不另选标准件，示教件兼作标准件：单段配方的 x_ref 由测量示教件得出；选示教件时应挑一件胶偏正常的件。

读帧都经轮次的帧索引（`BurstFrameIndex`）解析，分段、走廊示教、试测、示教件测量、发布打包等下游读图路径不变。

### 5.3 结果核对

候选没有验证样本。检测结果在历史页核对：用任意候选从原图复测或按规则重判任意历史记录（[segment-burst](../decisions/segment-burst.md) D-SB-46、D-SB-57）。

## 六、试判（三期）

正式版发布后，维护模式下的这个型号进入试判：

- 正常测量、判定、录制，记录的结论标为“试判”，不进合格率统计；历史页可按检测模式筛选（正式检测 / 维护试判 / 维护采集）。
- 在线检测页的“维护试判”面板按配方统计**最新正式版本**的试判件数，以及 OK、局部超差、NG、ERR 各多少，NG 再按结论细分（胶宽超差、断胶、位置超差、超绝对限）；重新发布后从零算起。
- 面板上的“复核”跳到历史页，预设这个配方、维护试判、NG 与 ERR、不限日期，操作员逐件看是否误判；误判就回候选调整后重新发布、继续试判。
- 不设自动退出条件，由工程师看过统计后手动退出维护模式。

## 十、已定事项（2026-10-25）

1. 维护模式用 `pcMode=1`、结果码 0，PLC 按未检放行；任何结果都不停线；PC 不在线时机械臂照常工作。
2. 采集版配方只能在维护模式下运行。
3. 不设采集配额与目标件数；界面只显示已录件数与完整可用件数。
4. 包含试判阶段，作为正式检测前的把关。
5. 不另标记标准件，示教件兼作标准件；单段配方没测量示教件时 x_ref 为空，不影响发布（单段配方运行时不判胶偏）。
