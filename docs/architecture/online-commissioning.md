# 在线投运方案

维护模式、采集版配方与历史件示教。前提是 [生产通讯协议 7](../integration/plc-communication-protocol.md) 的模式字 `pcMode`（维护时结果码为 0，PLC 按未检放行）。

现状：一期（维护模式采集、采集版配方、录制元数据）、二期（历史件导入为采集轮次、验证样本去重）与三期（试判统计与复核）已实施，实现取舍与已知限制见 [维护模式决策](../decisions/maintenance-mode.md)。

## 一、要解决的问题

新产线已经在正常生产（机器人照常涂胶），相机刚装好，还没有可用配方。原有流程建不出配方：

1. **示教采集要停线**：整圈采集走独立的示教握手（DB6 / DB12），需要现场 `TeachMode` 许可、机器人跑专门的示教轨迹，和生产握手互斥（[示教接口 V1](../integration/teaching-capture-sequence.md)）。正常生产时做不了。
2. **没有配方时生产不采图**：PLC 发来的型号在配方库里找不到时，PC 回 90/95，不布防，PLC 不运动，这一件不会采图。
3. **未完成的配方不能生产**：生产布防要求配方已示教走廊、已标定 ΣN_exp、有发布包。

目标：**不影响生产节拍、不导致停线**的前提下，跟着在线生产采集原图，攒够件数后用这些历史件完成示教、标定、验证并发布，再切到正式检测。

## 二、方案概览

| 环节 | 做法 | 作用 |
| --- | --- | --- |
| **维护模式** | 项目级开关。开启后 PC 置 `pcMode=1`，对每一件都布防、采图、录制，结果码写 0、PLC 按未检放行，永不输出 NG，也不因配方问题拒收 | 不影响生产的前提下采图 |
| **采集版配方** | 只定义型号、三台计划相机、各相机曝光增益；发布后只能在维护模式下运行，“只采集不判定” | 让维护模式知道这个型号用哪几台相机、什么成像参数 |
| **历史件导入为采集轮次** | 把维护模式录下的完整件，以硬链接方式物化成候选的采集轮次，走廊示教、多轮标定、分段复核全部沿用现有流程 | 不停线完成示教与标定 |
| **试判** | 正式版发布后先留在维护模式里运行一段时间，正常测量和判定、记录结论，结果码仍为 0；看过误判率再退出维护模式 | 正式输出 NG 前把关 |

### 端到端流程

```text
装相机、配相机组
  → 新建配方（型号、相机、曝光增益）→ 发布“采集版”
  → PLC 只需配好型号 → 开启维护模式
  → 生产照常：每件布防、采图、录制，PLC 按未检放行             ← 采集阶段
  → 完整可用件够标定（≥10）并留出验证件 → 候选里“从历史选用”导入为采集轮次
  → 走廊示教 → 多轮标定（≥10 轮）→ 用其他历史件做独立验证 → 发布“正式版”
  → 维护模式下试判 M 件，复核误判                             ← 试判阶段
  → 退出维护模式 → 正式检测，输出 NG
```

## 三、维护模式

### 3.1 行为

维护模式是**项目级**运行状态，保存在当前项目的 `cycle.json`，重启后保持；进入、退出都写日志，并要求在确认框里说明原因。

开启后，接件流程按配方阶段分两种行为：

| 配方阶段 | 布防 | 采图与录制 | 测量与判定 | 回 PLC |
| --- | --- | --- | --- | --- |
| 采集版 | 是，曝光增益取采集版配方 | 录制全部帧（不受录制模式设置影响） | 不做 | 结果码 0，PLC 按未检放行 |
| 正式版（试判） | 是 | 按录制模式设置 | 正常测量、判定，结论记为“试判”，不进合格率统计 | 结果码 0，PLC 按未检放行 |
| 找不到配方 | 是 | 不录（一期限制，见维护模式决策） | 不做 | 结果码 0，PLC 按未检放行 |

**维护模式下 PC 不拒收。** 正常模式下会回 90/95 的情况（型号找不到、配方只有采集版、发布包有问题）、相机没就绪、曝光下发失败、布防预算超时，在维护模式下都照常布防放行，只把原因记进这件的记录。目的只有一个：PC 不成为停线的原因。

退出维护模式时，列出当前只有采集版、还没有正式版的型号，提示“退出后这些型号会被拒收（90/95）”，要求确认。

### 3.2 回给 PLC 的结果

按协议 7 第七、八节：维护模式下 PC 置 `pcMode=1`，结果码固定写 0（`faultCode=0`）；PLC 看到 `pcMode=1` 即按未检放行，不看结果码。切换从下一件生效，在途件按接件时锁存的模式完成。

### 3.3 不拖慢节拍

- 采集版不测量，收尾只等收尾窗口和录制队列入队，比正式检测更快。
- 录制队列满时丢帧（记 `rawDropped`），这一件标“原图不完整”，**不能用作示教**，但照常放行。
- **不设采集配额**：维护模式下每件都录制，不设磁盘上限、不自动停录，磁盘由现场负责清理。三台相机按 10 fps 全帧录 PGM，单件约 1～2 GB（取决于分辨率和节拍时长）。资料盘剩余空间不足时沿用现有保护：PC 撤下就绪（pcState=0），PLC 按 PC 不在线处理、本件记未检，不停线。

## 四、采集版配方

### 4.1 配方阶段

| 阶段 | 含义 | 能否生产 |
| --- | --- | --- |
| 草稿 | 候选，未发布 | 否 |
| **采集版** | 已发布，只有型号、三台计划相机、各相机曝光增益、至少一段（可先放一个直线段占位） | 只在维护模式下，只采集 |
| 正式版 | 完整发布：走廊、ΣN_exp、发布包、独立验证 | 正常检测；维护模式下为试判 |

### 4.2 发布采集版

- 发布前检查：恰好三台互不相同的单视角计划相机、都在当前相机组里、曝光增益齐全、型号不与其他配方冲突。不要求走廊、标定、验证。
- 不生成发布包，只在 `recipes/<编号>.json` 里写 `stage: collect`，版本号照常递增。
- 已有正式版时不能再发布采集版（正式版不降级）。
- 配方卡片显示阶段标记。
- 正常模式下生产遇到采集版配方，回 90/95，原因写“配方只有采集版，仅维护模式可用”。

## 五、历史件作为示教数据（二期，已实施）

### 5.1 录制的元数据（一期已实施）

录制时在 `part.json` 里写：

- `partMode`：`maintenanceCollect` / `maintenanceShadow` / `production`（已有的 `mode` 是录制方式，不复用）；
- `devices[]`（已有的 `cameras` 是计划相机编号，不复用）：每台计划相机的 `cameraId`、`cameraConfig`（完整设备配置，与采集轮次的 `round.json` 同一份序列化）、`imaging`（实际下发的曝光增益）、`deviceSession`；
- `plc`：这件的 `requestSeq`、`productCode`。

没有这些字段的旧历史件不能导入为采集轮次（只能做验证样本）。

### 5.2 导入为采集轮次（物化）

候选的整圈采集页有“从历史选用”页签：列出本配方最近 200 件真机录制件（时间、SN、模式、帧组数、各相机帧数、原图是否完整、不可用原因），勾选后批量导入，每件生成一个采集轮次，导入后选中第一个新轮次。

- **可用条件**：维护模式或生产录制的真实件（不含离线）；原图完整（录制已核验落盘，无缺帧、无 `rawDropped`，每帧都已落盘）；三台计划相机齐全，`cameraConfig` 与候选当前相机配置一致，有曝光增益与设备会话记录；没有提前结束运动（整件标记“疑似提前终止”或 `plc.earlyEnd`）；属于本候选的型号（`plc.productCode`）；帧号与帧组序号一致、没有手动触发帧；还没有导入为本候选的轮次。不满足时列出全部原因，不能勾选。
- **物化方式**：在 `recipe-capture/<新轮次>/` 下为每帧建**硬链接**指向历史原图（同一项目目录，同一卷，不占额外空间），按 `{相机}/{seq:06}.pgm` 排好；生成 `frames.jsonl` 与 `round.json`（格式版本 3，`origin: {kind: "history", cycleId, recordId, standard}` 代替示教握手编号，状态直接为完成）。之后历史记录被保留策略清理，轮次里的硬链接仍然有效。建不了硬链接（录制目录与采集目录不在同一卷）时报错，不退回复制。
- **不停线**：导入只建链接与轮次记录，不占用相机与 PLC，生产进行中也能导入（只等配置门）。导入前在配置门内重新核对所选的每一件，任一件不可用就一件也不导。
- **下游不改**：走廊示教、多轮标定、轮次分段复核与帧组屏蔽都按普通采集轮次处理。
- **标准件**：生产件不能默认当标准件。操作员确认某件是标准件后（例如按 SN 对照），可在导入时勾选“标准件”（写进 `origin.standard`），这一轮加入标定时按标准件轮次（不计轮数，用于 x_ref）；否则 x_ref 留空，按现有规则“胶偏未判”，不阻断发布。也可以在停线窗口用示教采集补拍标准件。

不采用“适配器”（不复制，直接让示教和标定读历史目录）：那样要改走廊示教、标定、分段复核的读图路径，还要在保留策略里保护被引用的历史件，改动面更大。

### 5.3 独立验证

“用历史件做独立验证样本”保留，补一条检查：**不能用已经导入为示教或标定轮次的历史件**（导入为本候选的轮次、且该轮被走廊示教或多轮标定引用；只导入未用的件仍可验证）。验证样本也要求 `cameraConfig` 与候选一致（录制有设备记录的件才比较）。两条都在运行验证时核对，不满足的样本记“不符合”并写明原因。

## 六、试判（三期）

正式版发布后，维护模式下的这个型号进入试判：

- 正常测量、判定、录制，记录的结论标为“试判”，不进合格率统计；历史页可按检测模式筛选（正式检测 / 维护试判 / 维护采集）。
- 在线检测页的“维护试判”面板按配方统计**最新正式版本**的试判件数，以及 OK、局部超差、NG、ERR 各多少，NG 再按结论细分（胶宽超差、断胶、位置超差、超绝对限）；重新发布后从零算起。
- 面板上的“复核”跳到历史页，预设这个配方、维护试判、NG 与 ERR、不限日期，操作员逐件看是否误判；误判就回候选调整后重新发布、继续试判。
- 不设自动退出条件，由工程师看过统计后手动退出维护模式。

## 九、二期、三期测试计划

| 用例 | 防住的问题 |
| --- | --- |
| 历史件缺帧、`cameraConfig` 不一致、提前结束 → 不能导入（参数化） | 用不完整或相机不同的图示教 |
| 历史件导入后，原历史记录被保留策略删除 → 轮次原图仍可读，示教帧不失效 | 清理历史时破坏示教数据 |
| 已导入为示教或标定的历史件 → 不能选作独立验证样本 | 用训练数据自证，验证失去意义 |
| 维护模式下正式版配方判出 NG → 回 PLC 的仍是结果码 0，记录结论为试判 NG | 维护期间向线体输出 NG |
| 隔离实例：离线产线开启维护模式跑 30 件 → 导入为轮次 → 示教、标定、验证、发布 → 试判 → 退出维护模式后能判出 NG | 端到端链路 |

前三条由 `workspace/history_import_tests.rs` 覆盖，另有采集页“从历史选用”的界面流程测试。第四条的 PLC 侧由 `plc_session` 的维护件测试覆盖（锁存 pcMode=1 的事务只接受结果码 0）。三期另有：试判统计只算真机试判件、按配方取最新版本、NG 按结论细分（`store` 测试）；试判面板的“复核”把历史页筛到该配方试判件的 NG 与 ERR（前端测试）。运行方法见 [测试说明](../testing/TESTING.md)。隔离实例端到端未做。

## 十、已定事项（2026-10-25）

1. 维护模式用 `pcMode=1`、结果码 0，PLC 按未检放行；任何结果都不停线；PC 不在线时机器人照常工作。
2. 采集版配方只能在维护模式下运行。
3. 不设采集配额与目标件数；界面只显示已录件数、完整可用件数与标定最少件数。
4. 包含试判阶段，作为正式检测前的把关。
5. 标准件在导入历史件时由操作员标记；未标记时 x_ref 留空、胶偏未判，不阻断发布。
