# 长件浏览与复算

在线检测、历史详情、示教选帧和试测按原始帧组序号浏览。窗口化、分页和缓存只改变读取与显示方式，不压缩缺帧、屏蔽帧或跳过帧的序号，不改变检测规则。

## 页面读取与显示

- 历史页面用 `history_overview` 读取整件摘要、区域判定、逐帧状态及标量指标；概览保留完整逐帧判定，但不传每帧的逐站胶宽 `widths`。选中帧后通过 `history_frame_detail` 读取该帧完整指标。每次请求从独立只读快照取得摘要、配方、帧和复检编号，再解码帧指标并生成所需的结论。单帧接口不重新生成整件逐帧判定，格子颜色始终取概览的结论。
- 历史逐站指标有独立的单一执行槽。切换帧时取消还在等待的旧请求，已发出的查询可以完成，其结果只在对应帧仍选中时显示。
- 原图和叠图按相机、帧组查询，单帧读图不再重读整件帧指标。帧指标和判定在读取事务结束后解析，图像文件读取、解码和预览生成在后台线程执行。
- 原始历史叠图使用与帧指标在同一只读事务中取得的原配方快照，按记录所属项目和修订号核对身份。
- 候选对照的单帧叠图在同一个只读事务里按记录所属项目核对原配方，由相机编号定位记录下标并读取目标帧。测量图按对照保存的配方和示教尺寸，只为目标相机与段构建。
- 已保存对照的详情和叠图共享最近一条文件不超过 32 MiB 的解析结果。每次读取都核对历史工件身份和实际文件字节，内容一致才复用。
- 标定逐帧查看时，单段配方直接使用唯一的段，多段配方用该轮次确认的分段边界和原始帧组号确定所在段，再判断选中相机是否参与检测。
- 示教整轮测量按相机和段确定检测范围，再将段号映射到每个原始帧组。缺帧和跳过的帧组保留原始位置。
- 标定逐帧查看、示教单帧与区间试测、流程调试只构建选中相机与段的测量图，尺寸和通道取冻结的示教帧。
- 从在线证据进入历史详情或从示教页返回时，使用地址中的相机、帧组与复测候选发起首次加载。地址指定已保存的对照时，先按编号读取对照，再加载用于切换的对照列表。判定和对应原图在对照读取结果确定后即可显示。无法读取指定对照时，回到该帧的原始记录。
- 历史详情读取中或读取失败时可携带原上下文返回。读取失败提供原地重试，继续按当前地址读取同一件记录。
- 历史、示教、试测帧条只挂载可视列及缓冲列。方向键、Home/End 和外部选帧使用全局帧组序号，跨窗口时保持焦点和选中帧可见。逐帧追溯默认每页 50 行，可切换为 100 行；筛选与外部选帧会重新定位页码。
- 在线与历史帧组条按原始帧号定位选中项。生产跳过按实际存在的帧组计数，重叠区域合并计算；选帧或滚动时复用该统计。
- 在线采集详情使用当前工件的最终跳过区域。跳过帧显示不参与判定，缺帧和预量结果仅供诊断，设备帧计数仍可查看。
- 历史原图区使用左右方向键按实际存在的帧组顺序翻帧，遇到帧号空洞时直接定位相邻帧组，首尾停在当前帧。
- 逐帧追溯显示原始记录。选中追溯行时查看该相机和帧组的原始结果，并保留已打开的对照。切换显示结果时按相机编号保留当前相机，目标结果没有该相机时选择第一台。
- 点击追溯表原图列的“查看”会在历史内容区滚动到对应相机和帧组的原图，并将键盘焦点移到那里。原图正在读取时也可以定位，选择普通追溯行时可留在表格中继续操作。
- 原图中的“返回逐帧追溯”回到打开原图的行，即使图像浏览期间选中了另一页的帧。原行被筛选隐藏时，保留筛选条件并聚焦追溯筛选区。
- 逐帧追溯的异常筛选包括单帧 NG、检测错误、允许范围内的局部超差，以及缺帧、测量异常和混胶告警。同一帧只计一次。区域整体结论在区域结果中查看，生产跳过帧上的测量与混胶问题供诊断复查。
- 在线检测与历史详情的区域结果默认摘要不完整帧组的数量和连续范围，可直接定位首个帧组。展开后按原始序号每页显示最多 32 组。切换工件或历史对照时收起列表。
- 在线单件证据仅查询后端列出的不完整帧组，NG 证据只在所属区域的帧号区间内查找。存在同结论的实测帧时定位该帧，否则定位区域内可供复核的帧组。
- 从在线检测的异常明细或区域结果定位后，换件仍会恢复跟随新工件。右栏在本次应用会话中保留上次定位的 SN、帧组和已知相机，可按工件 `cycleId` 打开对应的原始历史记录。从历史返回时继续跟随当前工件，仍可再次打开原来的回查位置；历史记录暂不可用时可重试，也可清除回查位置。
- 已保存对照先通过 `workspace_comparison_summaries` 读取摘要，选中后用 `workspace_comparison_get` 按 ID 读取完整结果。前端只保留当前选中对照的完整指标；后端摘要缓存最多 1024 项，按文件大小、创建时间和修改时间失效，目标明细读取及删除仍核验文件身份。
- 静态预览沿用二进制像素并直接绘制到 Canvas，不在前端编码 PNG。历史图块读到原图后才排该相机的叠图重算。原图、叠图与单帧试测请求共享两个执行槽；切换帧会淘汰尚未执行的旧请求，已执行的原生请求完成后丢弃过期展示。原图缓存最多 24 张且总像素预算为 24 MiB，30 秒失效。

原有 `history_detail` 和完整对照列表接口保留，供需要全量数据的既有调用方使用。

## 分段时间轴按需加载决策

分段工作台以 `plan.pieces` 中示教件的 `groupCount`、已保存边界和笔结构初始化。段落、帧号和编辑操作不依赖缩略图返回；从历史件跳转时直接按全局帧号定位。

- 缩略图接口 `recipe_capture_round_thumbs` 必填 `startSeq`（从 1 起）与 `count`（1–32），只解码指定范围，缩略图最大 160×128 像素；末页返回实际帧数，二进制条带头部的数量表示本页数量。不存在整件读取回退。
- 时间轴按可见范围及两侧缓冲列渲染，保留完整滚动宽度。段色带、相机选择与边界位置使用原始帧号，跳段、键盘选帧和边界编辑不随窗口改变。
- 前端以 32 帧组分页，先请求可见页，再预取相邻一页，不自动遍历整件。缩略图请求最多两个并发，离页或滚动后淘汰过期排队任务；已发出的原生请求允许完成，但不更新旧页面。
- 缩略图使用有界 LRU 缓存，像素预算 32 MiB。加载中、整页请求失败和缺图分别显示，未加载不能当成缺图；单帧文件缺失或解码失败沿用条带的缺图状态。原图预览继续按选中帧读取，使用独立的原图请求调度。

此决策同时限制磁盘解码、IPC 返回量、前端画布数量与跨件缓存。仅做虚拟列表仍会全件解码；仅做分页仍会创建全件节点，因此两端一起修改。不在采集关键路径生成缩略图，不改变录制格式、原始帧序号与分段保存契约。

验证保护的规则：首屏不等待整件图像且读图量有界；范围外原图不被解码；滚动与历史跳转定位保留全局帧号；切换工件不显示旧结果；缓存受预算限制。真实 3000 张原图的首屏耗时、滚动延迟与生产并行负载需现场测量。

## 复算任务与取消

以下命令接受可选的 `taskId`：

- `workspace_compare`：候选规则重判、候选原图复测。
- `workspace_compare_original`：按原发布包重现。
- `workspace_teach_preview_segment`：示教全段试测。
- `workspace_measure_teaching`：测量示教件。

未传 `taskId` 的既有 MCP 调用保持原返回契约。带任务编号的调用通过 `operation://progress` 发出进度：`taskId`、`stage`、`completed`、`total`、`failed`、`skipped`、`elapsedMs`。阶段为准备、测量、汇总、保存以及完成、取消、失败；进度按 150 ms 节流，开始、阶段变化及终态立即发送。计数单位为相机帧，跳过与失败也计入已处理数量。规则重判不执行图像测量，不伪造逐帧测量百分比。

前端先建立事件订阅再调用命令，仅接收当前任务的进度；命令结束后用 `operation_status` 获取精确终态，避免最后一次节流事件未到就显示不完整计数。后端仅保留最近 64 个终态。测量达到总数后，界面仍显示汇总或保存，成功提交后才显示 100%。

`operation_cancel` 在准备或测量等可取消阶段接受请求，在帧间生效；当前帧的 lyFlow 执行不会被强制终止。进入保存阶段后拒绝取消。取消错误以 `OPERATION_CANCELLED:` 标识，不能被逐帧错误处理吞掉后继续返回部分结果。页面退出时撤销尚未提交的任务，已注册任务请求取消；已进入保存的任务完成提交。

历史复算始终另存对照，不覆盖原始检测记录。原图复测在本次任务的前置检查中构建可用走廊的测量图，随后将图和未测原因交给测量器。示教测量先写暂存产物，提交前重新核对候选修订；取消不提交，保存失败恢复原产物。示教全段试测保持只读，运行期间继续检查生产是否空闲。

历史列表批量规则重判 `history_rejudge` 也可通过顶层 `taskId` 使用任务接口。进度阶段为准备、重判以及完成、取消、失败，计数单位为工件，跳过件计入已处理。省略 `taskId` 时直接返回重判结果。

历史复测选项读取帧状态和原图引用。详情或选项查询完成后，最多保留最近一件的 16 MiB 已校验指标文本。再次读取时逐项比较原文，内容一致才复用校验结果。文本变化或超出上限时按原格式解析，仍会报告损坏的指标。执行复测时按所选方式读取完整的测量数据或原图。

执行段配方历史复测时，记录和原配方来自同一次数据库读取。规则重判读取完整测量指标，原图复测和原包重现按帧元数据定位原图，并对仍未校验的指标文本做格式校验。逐帧结论由本次复测结果生成，原始帧格沿用历史详情的结论。

规则重判将本次读取的逐帧指标转入对照结果。帧的相机与序号取自历史帧行，无指标的帧按记录状态补入对照。

复测选项读取失败可在原处重试，也可切换已列出的候选。详情收到录制状态或原图覆盖变化后刷新选项。执行按钮使用当前选项的结果，已经开始的复测继续按发起时的配方和修订完成。

## 帧数据校验与复用

历史单帧读图每次读取当前 `part.json` 和原图，并按文件名定位唯一条目。最近一份不超过 8 MiB 的清单在当前路径、工件和文件字节一致时复用解析索引。批量原图复测在实际读图时建立读取上下文，按录制目录读取一次 `part.json` 并建立任务内索引。示教测量在任务内读取并校验 `round.json` 与 `frames.jsonl`，建立帧路径索引。

每次读取仍核对相机、帧组、帧号、原图路径及尺寸。图像源不存在时沿用逐帧失败处理；全部帧被规则跳过时不打开图像源。原图清理、错误身份、路径越界不能通过缓存绕过。

浏览器结构验证使用合成的 1000 帧组数据，验证窗口、分页和键盘导航。真实图像读取耗时、lyFlow 吞吐及现场生产并行影响需在现场数据上单独测量；软件回归不代表这些指标已验收。验证入口见[测试说明](../testing/TESTING.md)。
