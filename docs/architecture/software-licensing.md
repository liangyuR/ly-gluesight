# 软件授权设计

本文是待实现的授权设计与验收契约，不表示当前应用已启用授权限制。目标是 Windows、Linux；当前 GlueSight 的部署入口为 Windows，Linux 授权适配不代表整套相机、PLC、lyFlow 应用已完成 Linux 移植。

## 授权规则

采用联网激活、固定期限签名许可证、本地离线校验。一机一授权，正常运行不定期联网，不使用心跳或短期租约；首次激活、领取续期许可证及异常恢复才需要联网。

| 项目 | 规则 |
| --- | --- |
| 停用日期 | 管理员选择日期的北京时间 0 点，内部保存 UTC 时间戳 |
| 提醒 | 到期前 7 天开始，应用内常驻提示，每天首次打开再提醒一次 |
| 到期条件 | 当前有效时间大于或等于 expires_at |
| 到期行为 | 禁止开始新业务，已开始的有限任务收尾后锁定 |
| 锁定后可用 | 查看和导出已有数据、授权管理、续期 |
| 续期 | 后台延期，客户端主动联网领取新许可证 |

例如停用日期为 2026-12-01：11 月 24 日 00:00 开始提醒，12 月 1 日 00:00 失效，不额外增加宽限日。若允许使用完整个 12 月，应选择 2027-01-01。后台显示完整停用时间和时区；修改客户端时区不改变截止时刻。应用关闭时不运行后台提醒服务。

## 组件与信任边界

| 组件 | 职责与技术选择 |
| --- | --- |
| 授权服务 | Rust、Axum、PostgreSQL；激活、设备绑定、签发、续期与恢复 |
| 网页管理后台 | React、TypeScript、Vite，与当前项目保持技术栈一致；管理客户、许可证与设备 |
| 客户端授权模块 | 独立 Rust crate；验签、设备匹配、时间检查与业务准入 |
| Tauri 界面 | 激活码输入、有效期和状态展示、到期提醒、更新授权 |
| C++ 算子 | 通过 Rust 调度入口调用，第一版不修改算子内部 |

使用 ed25519-dalek 完成 Ed25519 签名与验签，在其上实现业务授权模块。私钥只存于授权服务，客户端内置公钥；许可证内容可读，签名防止篡改期限、设备和权限。前端状态、按钮是否禁用不能作为授权依据。

授权是本机应用级状态，不随项目切换，不放入配方、发布包、项目或历史导出包。C++ DLL 的独立调用不在第一版保护范围。

## 许可证与设备绑定

签名载荷包含：

| 字段 | 用途 |
| --- | --- |
| schema_version、key_id | 格式版本、签名公钥标识 |
| license_id、revision | 授权唯一标识、递增版本 |
| customer_id、customer_name | 客户标识和展示名称 |
| product_id | 限定产品 |
| device_fingerprint | 绑定设备 |
| issued_at、expires_at | 签发与失效时间 |
| features | 功能权限，第一版使用固定产品功能集 |

载荷原始字节与签名采用 Base64 信封保存。先验签再解析，拒绝未知格式、公钥及产品；不通过重新序列化 JSON 构建验签内容。公钥按 key_id 查找，保留仍有有效许可证的旧公钥。最高已接受 revision 持久化，拒绝旧版本覆盖；校验产品、设备与有效期不能仅依赖签名正确。

设备指纹由 Rust 采集，前端不得传入任意指纹作为本地校验依据：

- Windows：系统安装标识与有效 SMBIOS UUID。
- Linux：系统 machine-id 与有效 DMI UUID。
- 规范化标识，结合 product_id 计算哈希；不上传原始硬件标识。UUID 缺失或为占位值时只用系统安装标识；安装标识也不可获取时拒绝激活。
- 激活记录保存指纹算法版本及采用的标识组合；后续按同一组合重新采集，避免读取权限变化悄悄改变身份。
- 换网卡不影响授权；重装系统、更换主板或绑定标识不可读取时要求人工重新绑定，不自动降级为其他指纹。

服务端用事务保证首次绑定原子性。同一设备重试幂等成功，另一设备拒绝；同机不同系统用户分别建立本地状态，不重复占用设备名额。设备绑定不承诺抵抗镜像克隆或标识伪造。

## 联网接口与续期

所有接口使用 HTTPS，客户端与管理接口分离。

| 接口 | 行为 |
| --- | --- |
| POST /v1/activate | 提交激活码、产品、设备指纹和算法版本，绑定设备并领取许可证 |
| POST /v1/refresh | 同一设备领取最新许可证 |
| POST /v1/recover | 校验授权与服务器时间，恢复异常本地状态 |

请求携带随机 nonce。响应中的许可证摘要、产品、设备、服务器时间及 nonce 一起签名；客户端验证与当前请求相符，完成全部检查后原子保存许可证与本地状态。旧响应不能用于新的恢复请求。

激活码由至少 192 位密码学安全随机数生成，服务端仅保存哈希；客户端保护本地副本。接口限速，日志不记录完整激活码。管理接口可创建客户及授权、延长停用日期、查看设备、重置激活码和人工重新绑定，所有修改记录审计。管理员密码用 Argon2id 哈希，会话使用安全 Cookie 与 CSRF 防护。

流程：管理员创建授权并签发激活码 → 客户联网激活并下载覆盖完整期限的许可证 → 离线运行 → 管理员续约延期并递增 revision → 客户点击“更新授权”领取新许可证。

续期失败保留原许可证，仍按原截止时间判断。后台已续期但客户端未领取时仍会按旧许可证到期，界面需明确告知。到期或异常状态下，激活、更新授权和恢复入口始终可用。

## 本地业务准入与生产收尾

状态统一为：未激活、有效、即将到期、已到期、需要联网恢复、许可证无效。

启动时检查，运行期间每 30 秒刷新状态，截止时刻安排本地定时通知；每次开始受限业务前重新检查，以业务准入的时间为准，不依赖 UI 缓存。

全部受限 Tauri command、MCP/Agent 入口、后台调度与队列派发经过统一 Rust 准入检查。受限业务包括新工件检测、维护采集、标定采图、示教测量、历史复测和重新判定；查看或导出已有结果允许，不能借导出触发新计算。

到期后不接收或派发新业务，未执行队列暂停。已准入的有限任务收尾；生产任务边界是一件工件，包括采集、测量、结果回写和记录。到期前准入的工件，其后续帧和收尾计算继续；连续生产只完成当前件，不将整条生产会话视为一个永不结束的任务。续期后由用户主动恢复暂停任务，不自动开始生产。

接入点包括 cycle/admission、cycle/burst、plc_session，以及维护采集、标定、候选工作区与历史复测的共享业务入口；实施前必须搜索实际调用方，包括本机示教 MCP。

### PLC 协议约束

遵守[生产通讯协议 8](../integration/plc-communication-protocol.md)：PLC 不等 PC，PC 不得为授权限制立即退出进程、停止心跳、改成维护模式，或将到期当作握手故障。

已准入的在途件完成原有握手与收尾。到期后的 PLC 请求仍须做协议登记，但不启动受限检测；在 plcState=20 后按不能检测的工件返回检测错误，不得回 OK 或伪造历史结果。外部机械运动由 PLC 控制，软件锁定不等于停线。

实施生产锁定前须在同一实现 PR 中确定授权不可用的 faultCode 分配、更新协议及双方点表和回归用例；当前协议未定义授权专用错误码，本设计不擅自占用现有 91–100 码位。该协议对接是启用生产授权限制的前置条件。

## 时间与状态保护

持久化最近服务器可信时间、最近观测时间、最高许可证版本和已确认的到期状态。进程内结合系统 UTC 与单调计时；有效时间不得倒退。每 60 秒、关键状态变化及正常退出时保存。

- 系统时间相对持久化记录或进程内预期时间回拨超过 5 分钟，禁止新业务并要求联网恢复；容差内也不能降低已观测时间。
- 启动、休眠唤醒和恢复业务前重新校验系统时间，不假定 Rust Instant 在所有平台都计入休眠时长。
- 同一版本已记为到期后，修改时间不能自动重新启用。误调时间需联网校正并由服务器确认授权仍有效后重建记录。
- 本地状态缺失、损坏、无法读取或无法可靠写入时要求联网恢复；删除记录不能重置有效期。正在执行的任务遵守同样的收尾规则。

Windows 使用应用数据目录，激活码与完整性密钥由当前用户 DPAPI 保护。Linux 使用用户应用数据目录，目录权限 0700、文件 0600；随机密钥对状态做 HMAC，密钥文件同样限制权限。两个平台都使用原子保存与进程间锁，防止并发覆盖较新状态。

这些措施用于发现常见回拨、删除和意外损坏，不等同可信硬件。Linux 同一用户能读取密钥；整盘快照回滚、修改二进制、长期伪造时间均不能由纯软件离线机制彻底阻止。

## 运维与交付边界

授权服务部署于 Linux，经反向代理提供 HTTPS。数据库定期备份；私钥单独受限保存及加密备份，不进入仓库、镜像、数据库普通导出或客户端。服务离线只影响激活、续期和恢复，已有有效许可证继续离线可用。

禁止后续激活、缩短期限、重置激活码或人工换机，不会立即撤销已签发且离线的许可证。后台人工换机必须显示旧设备仍可能用到原截止日的提示。第一版以延期为主，不承诺在线即时吊销。

客户端授权路径仅在测试中注入时间和签名器，正式发行不得提供跳过校验的环境变量或 UI 开关。上线先用测试密钥和短期限走完生命周期，再使用正式私钥签发；依赖版本遵循项目工具链与锁文件。

## 验收计划

以下为实施阶段计划用例，本次设计文档不表示已实现或已验证。按业务公开接口测试，不测试第三方密码库本身。

| 场景 | 防止的回归 |
| --- | --- |
| 首次激活、同机重试、两机并发激活 | 重复占位或一份授权绑定两机 |
| 断网、重启、升级及项目切换 | 有效授权意外依赖网络或项目状态 |
| 提前 7 天、截止前一秒与截止时刻 | 提醒或停用日期偏移、边界放行 |
| 持续运行或休眠跨越到期时间 | 只启动检查导致长期开机绕过到期 |
| 在途工件收尾、新件及队列拒绝、MCP 调用 | 中断当前件或非 UI 入口绕过准入 |
| 到期后 PLC 请求走完错误结果握手 | 不响应 PLC、误报合格或错误进入维护模式 |
| 续期成功、失败、服务已延期但本机未更新 | 失败覆盖有效授权或凭后台状态假定本机已续期 |
| 修改载荷、错误产品或设备、回放旧版本 | 校验链缺失导致错误授予权限 |
| 回拨、删改记录、重放恢复响应 | 重置状态或旧响应延长有效期 |
| 调整时区、误调时间后联网恢复 | 时区改变期限或误锁后无法恢复 |
| Windows/Linux 权限、异常退出、多实例 | 状态损坏或较旧状态覆盖新版本 |

交付顺序：签发服务与管理后台 → Rust 授权模块及两平台适配 → Tauri 和全部业务入口接入、PLC 契约对齐 → 生命周期验收与正式签发。按[测试说明](../testing/TESTING.md)选择定向检查；不因文档变更运行全量构建。
