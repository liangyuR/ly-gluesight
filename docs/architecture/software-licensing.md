# 软件授权

GlueSight 在 Windows 客户端使用 Grantmint v2 单设备离线授权。首次激活、领取续期证书需要联网；正常生产没有心跳续租，不依赖授权服务在线。服务端和管理后台位于独立的 [Grantmint 仓库](https://github.com/liangyuR/grantmint)，客户端固定依赖已核验的 SDK 源码修订。

## 期限与业务准入

- 管理员选择停用日的北京时间 00:00，证书使用 UTC 秒；客户端改时区不改变期限。
- 到期前七天显示常驻提醒，每个北京时间自然日首次进入提醒状态再显示一次弹窗。应用关闭时不运行提醒服务。
- 当前可信时间达到截止时刻即禁止开始新业务，没有合同宽限期。前端每 30 秒、提醒/到期时刻及窗口恢复时刷新；每次业务准入由 Rust 重新校验，不能靠 UI 按钮状态放行。
- 到期前已准入的有限工件继续采集、计算、结果回写及记录；后续新工件不放行。不把整条生产会话当成一个无限期任务。
- 历史查看、导出、授权管理继续可用。涉及重新计算的采集、标定、试测、复测、重判和发布验证经共享 Rust 入口检查，MCP 同样受限。历史查看不能隐式触发新计算。
- 后台续约不等于本机续期。用户点击“更新授权”，验签并可靠保存后新期限才生效；失败保留原证书。过期客户端仍可领取新证书。

例如停用日 2026-12-01，从 11 月 24 日 00:00 提醒，12 月 1 日 00:00 禁止新业务。允许使用完整个 12 月时应签发到 2027-01-01。

## 设备与安全存储

`src-tauri/src/licensing` 持有设备私钥和授权状态，前端只得到状态、期限和指纹摘要，不得到设备私钥或签名私钥。

Windows 指纹来自 MachineGuid 和有效 SMBIOS UUID，结合应用 UUID 计算摘要。首次读取决定是否采用固件 UUID，后续固定组合；已采用的标识不可读或变化时不能静默降级为另一设备身份。网卡不参与指纹。原始硬件标识不提交给授权服务。

设备随机 Ed25519 种子、证书、版本高水位、可信时间和应急记录由当前 Windows 用户 DPAPI 保护，保存在系统 Known Folder 定位的 `%LOCALAPPDATA%/GlueSight/licensing`。目录独立于项目、配方及 `GLUESIGHT_DATA_DIR`，切换项目或测试资料目录不能重置授权。不同 Windows 账号不能解开本机状态；换运行账号须由维护人员处理。

存储使用独占进程锁、临时文件同步与 Windows 原子替换。发现损坏、缺失、设备不匹配或可靠写入失败时拒绝新业务，不自动创建新的可信证书状态。设备身份或可信时间锚丢失时不能凭激活码随意重置历史；应保留原 Windows 用户资料并联系维护人员。

当前生产安全存储仅支持 Windows DPAPI。非 Windows 版本不退化为明文文件放行，Linux 整机应用和安全存储适配尚未交付。

## 激活与续期协议

使用 Grantmint v2 设备挑战与证书，不使用旧 `/v1` 接口。

| 路径 | 用途 |
| --- | --- |
| `/v2/licenses/challenges` | 提交应用/授权 UUID、激活秘密、设备公钥与指纹摘要 |
| `/v2/licenses/activate` | 用设备私钥签署本次挑战，取得证书和签名时间回执 |
| `/v2/licenses/sync-challenges` | 创建独立 sync 或 ack 域的设备挑战 |
| `/v2/licenses/sync` | 领取本设备最新证书 |
| `/v2/licenses/acknowledgements` | 证书验证、保存后确认指定 serial |

所有请求由 Rust 发出，HTTPS、有限超时与响应大小，禁止重定向；仅调试构建允许回环 HTTP。激活秘密不会长期保存。SDK核验产品、授权、设备公钥、指纹、nonce、证书 serial、修订与签名时间回执，防止跨应用、跨操作或旧响应替换。

签名公钥与产品、服务地址在构建时固定，不接受页面或运行时环境变量替换。保留仍有有效证书的旧 key ID；切换公钥配置需要重新构建客户端。客户端不持有服务端签名私钥。

## 时间检查

进程内结合 UTC 与单调计时，不降低已经观测的可信时间；受保护时间锚与版本信息在状态检查及关键变化时可靠保存。回拨超过五分钟要求处理时钟异常；容差不延长合同期限。每次新业务重新检查，因此长期开机、窗口挂起或休眠恢复不靠旧 UI 状态继续接件。

完全离线的纯软件机制不能防御整盘快照回滚、管理员替换程序或伪造整机时间。撤销服务端授权只阻止后续联网激活/同步，不能即时停止客户已下载的离线证书。C++ DLL 被绕过 GlueSight 单独调用不在此版本保护范围。

## 现场应急解锁

软件授权页提供明确的维护入口，使用构建时配置的固定密码，不设隐藏通用默认密码。

- 密码正确且填写处理原因后，临时放行 **72 小时**；不修改正式许可证或合同期限。
- 当前应急窗口内不累加期限，到期后恢复正常授权判断；维护人员可再次验证密码处理新的故障。
- 界面持续显示应急状态和准确截止时刻。成功、错误密码与原因写入 DPAPI 保护的本机审计，密码本身不入日志、不进入浏览器存储。
- 密码以 Argon2id PHC 校验值内置，错误尝试有持久化节流。密码掌握者具有临时放行权限，应由维护人员保管；更换固定密码需重新构建客户端。
- 配置未就绪、设备身份/可信锚不可用或存储不能可靠保存时，不把密码视为无条件关闭安全检查的开关。应急仅处理可保留可信状态的授权故障。

生成和交付方法见[授权部署与现场操作](../operations/software-licensing.md)。

## PLC 协议 8

授权不可用使用 `faultCode=96`，结果 `90`。PLC 请求仍登记，工件结束 `plcState=20` 后才返回检测错误；不得提前伪造合格、不停心跳、不擅自切维护模式。现有在途件按原结果与握手收尾。详情见[PLC 通讯协议](../integration/plc-communication-protocol.md)。

软件锁定不会停止 PLC 控制的外部机械运动。上线需同步现场 PLC 对 96 的故障显示；原有结果/确认握手与协议版本不变。

## 验证边界

前端定向测试保护七天提醒、北京时间每日提醒、正式及应急截止刷新、错误密码不改变状态和续期失败保留原期限。Windows授权测试覆盖DPAPI、指纹、离线期限和应急时长；S7回环与工件测试保护当前件收尾和新件延后返回96。MCP共享入口通过调用链核对；测试不代替真实PLC、相机、现场长时间运行验收。
