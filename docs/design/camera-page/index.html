相机与采集页（/camera）· 静态效果图

GlueSight · 胶路智检 · 青钢风格。每张画面 1440×900，含侧栏外壳；共用 camera-design.css（token 与 src/styles.css 一致）和 shell.js（侧栏、图标、灰度工件缩略图）。同名 PNG 为 Chrome headless 截图，shoot.ps1 可重截。

画面

01 相机组总览 · 同步正常进入页面的默认视图。三张相机卡（cam1、cam2 正常出图，cam3 未绑定紧凑卡）+ 同步触发核对（全部 +1，cam3 已排除）。 02 相机组总览 · cam2 触发落后最近一次触发 cam2 触发计数 +0；卡片和核对表都标黄，右侧给出按顺序排查的提示（触发线、滤波、网线、触发源）并可直接进 cam2 触发接线。 03 相机详情 · cam1顶部面包屑 + 相机切换胶囊；左列基础信息、绑定设备、触发接线（含“应用到全部相机”）、折叠的高级参数；右列出图验证与参数生效情况；底部粘性保存栏，移除相机被阻止的原因就近换行显示。 04 相机详情 · 高级参数与批量结果内容区滚到底：展开“高级参数（调试）”（曝光 / 增益临时下发，不写配方），并显示一次“应用到全部相机”的逐相机结果（cam2 有 1 项未接受、cam3 跳过）。 05 生产运行中 · 只读总览照常实时刷新；添加 / 绑定 / 释放等控件禁用并带锁图标说明，顶部一条状态说明写明何时可改。 06 离线托管 · 样本集相机相机组按离线样本集临时生成（source=sampleSet）：基础信息只读、绑定与触发接线显示“不适用”及原因、没有保存栏；出图验证照常显示样本帧。 07 异常 · cam2 断连紫色系统故障：卡片显示 message（GigE 心跳超时）、最后一帧淡显、丢包与最近出图标紫、检查建议与“立即重新连接”；同步核对因参与相机不足而暂停并排除 cam2。 08 异常 · 2 项参数相机未接受保存返回 warnings：保存栏与右侧“参数生效情况”列出未接受项，对应字段（触发延时、Line1 输出）加黄色标注与说明；配置已保存但相机保持原值。

设计说明

  • 总览优先。进入 /camera 默认是相机组总览，一屏看全所有相机的缩略图、绑定状态、帧 / 触发计数、丢包、最近出图时间；不再有常驻左侧相机列表，一台相机也不会浪费一整块面板。详情通过点卡片进入，顶部“相机组总览”面包屑和相机切换胶囊负责回退和横向切换。
  • 紧凑的“没有图”。未绑定相机的卡片不画大块“暂无图像”，只写一行“未绑定设备 · 进入详情选择设备”；断连相机保留最后一帧淡显并叠故障说明，而不是空白。
  • 错误就近显示。页面顶部不再放通用“操作未完成”横幅。移除相机被阻止的原因（含旧配方格式版本 5 读取失败）放在“移除相机”按钮旁并允许换行；保存结果放在保存栏；软触发错误放在“取一帧”旁；设备枚举失败放在设备下拉下方。
  • “是否生效”只用 warnings 表达。后端没有逐字段回读，所以主表达是“已应用，N 项参数相机未接受 + 列表”（保存返回 / status.warnings）；能对应到字段的在字段旁加标注，但标注只是列表的索引，不假装显示设备当前值。
  • 曝光 / 增益归配方。相机页只在“高级参数（调试）”里提供临时下发，并明确写“不写进配方、开始采集或生产时会被配方覆盖”；因为读不回设备实际值，只显示“本次调试已下发 xx（hh:mm）”。
  • 颜色语义。绿 = 已连接 / 同步；黄 = 未绑定、触发落后、参数未接受、未保存（需要人处理但不是故障）；紫 = 断连、SDK 错误等系统故障，与工件 NG 的红色区分。每个状态都带图标和文字。
  • 同步触发核对是前端计算。基于 Frame 事件里的 triggerCounter：取最近一次触发前后各相机的值与差值（+1 / +0 落后），累计本页打开以来的触发次数与不同步次数；Chunk 关闭、未绑定、断连的相机分别标注原因并排除；参与相机不足 2 台时暂停。
  • 批量应用。触发接线区的“应用到全部相机”复制触发源、触发沿、滤波、延时、频闪、Chunk 到其他已绑定 MVS 相机并保存应用，结果按相机逐条显示成功 / 有参数未接受 / 跳过原因；开流前触发计数、视角数、绑定不复制。
  • 只读态。生产中（productionBusy）与离线托管（site.mode=offline）都用同一套禁用样式 + 一条说明；生产中说明何时可改，离线态说明由站点模式管理、退出后恢复。
  • 不属于本页的内容（标定、PLC、整圈采集、配方文件问题）只保留跳转链接：底部“保存后前往飞拍标定”、移除原因里的“在配方库处理”。

与真实数据的对应

  • 卡片与详情字段均来自 CameraConfig（id、name、source、viewCount、compositeLayout、serial、triggerSource、triggerActivation、triggerDelayUs、debouncerUs、strobe、chunk、counterAfterOpen）与 CameraStatus（ready、released、message、device、sdkVersion、frames、fps、maxFps、lostPackets、droppedFrames、warnings）。
  • “最近出图”“帧 / 触发计数”来自 Frame 事件（frameCounter、triggerCounter、lostPackets、ts），前端按 250 ms 合并刷新；“刚刚 / N 秒前”为前端相对时间。
  • “枚举到 N 台”来自 camera_list_devices；“已绑定 cam2”是前端用其他相机的 serial 标注。
  • “应用到全部相机”可由前端对每台相机依次调用 camera_save_config 实现，逐相机收集返回的 warnings。
  • “临时下发到设备”的曝光 / 增益需要一个新的后端命令（现有 API 没有），属于待实现项。

待用户确认的问题

1. 调试曝光 / 增益的生命周期

临时下发的值在离开页面、相机重新连接、释放给 MVS 后再重连时是否清除？界面目前只显示“本次调试已下发 xx（hh:mm）”，并在重连后清掉这条记录——是否符合预期？是否需要“恢复为配方值”按钮（需要知道当前配方是哪一个）？

2. “应用到全部相机”的范围

目前只复制触发源、触发沿、滤波、延时、频闪、Chunk，不包括视角数、拼接布局、开流前触发计数与绑定。是否要把视角数也纳入？遇到某台相机已释放给 MVS 或断连时，是跳过并说明，还是整批中止？

3. 同步核对的触发匹配窗口

前端把各相机“同一次触发”的帧按到达时间归组，草案窗口 500 ms；节拍快（>2 Hz）时需要更小的窗口或改用 Chunk 时间戳。希望确认现场最短触发间隔，以及是否接受窗口可配置（放系统设置而不是本页）。

4. 不同步时的提示强度

cam2 落后目前只在本页标黄并给排查提示，不弹窗、不影响生产状态。是否需要在在线检测页也提示？累计多少次不同步才算需要停线排查？

5. 断连相机的最后一帧

07 画面保留最后一帧淡显并叠故障说明（前端缓存的缩略图）。是否接受这种做法，还是断连后应直接清空图像避免误判为“还在出图”？

6. 卡片点击区域

整张相机卡可点进入详情；卡上的“立即重新连接”等按钮是否要直接在总览执行（不进详情）？目前设计：重新连接在总览可直接点，释放给 MVS 只在详情里。

7. 只读态中“释放给 MVS / 重新连接”

生产中禁止释放（会打断采集）没有异议；但相机已释放时的“重新连接”是否允许在生产中执行？现有代码允许，设计稿沿用。

8. 旧配方格式导致“引用未读取”

此时移除相机被阻止并指向配方库。是否还应允许修改绑定和触发接线（设计稿允许，只阻止移除）？

9. 三目相机在总览卡的缩略图

viewCount=3 时总览卡只显示视角 1 的缩略图并标“三目 · 视角 1/3”，详情里提供视角切换。是否需要在总览直接显示三幅小图？
