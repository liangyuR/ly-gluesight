## 2. 设计原则

1. **点表是唯一的汇合点。** 无论飞拍还是随动，最后都归结为"名义胶路上按弧长排列的测量点 → 每点的状态"。`judge`、`store`、历史、重判都只认点表，所以这部分不因工况变化。
2. **工况差异收在"帧 → 点"映射层。** 飞拍按帧计数对拍照点 k；随动按帧时间 / 路径进度对弧长 s，并按行进方向选相机。两者用配方里的枚举区分，不开两套状态机。
3. **测量后端可替换。** 模拟、文件回放、lyFlow 以及将来的其他引擎都实现同一个接口，只量不判。lyFlow 何时就绪不再阻塞其他工作。
4. **相机数量不写死。** 按"相机组"建模，三目只是 N=3 的一种配置；飞拍是 N=1。
5. **能离线复现。** 每种现场问题都应该能用"录下来的帧 + 配方快照"在办公室重放。文件回放相机是稳定性的基础设施，不是可选项。
6. **失败要显式。** 帧队列有界，满了就丢帧并记 ERR，不静默堆积内存；每个 ERR 都有 faultCode 和原因（沿用现有做法）。

## 3. 目标架构

```
PLC 边沿 ─┐
          ▼
 相机组 CameraRig ──帧(cam, seq, ts, image)──▶ 节拍状态机 cycle（不变的握手）
 ├ Sim / Replay / Mvs 驱动                       │
 └ 每台相机独立配置、状态、重连                  ▼
                                       帧→点映射 Sampler（按配方的 mode）
                                       ├ FlyShot：帧计数 → k → 该拍照点负责的点
                                       └ Follow：ts/进度 → s 区间 + 选相机
                                                 │ Job(cam, image, 点区间)
                                                 ▼
                                       测量后端 Measurer（有界队列、并发上限）
                                       ├ Sim  ├ lyFlow  └ （备选引擎）
                                                 │ Measured(idx, 位置, 宽度, 状态)
                                                 ▼
                                       点表 → judge → store / PLC 回写 / UI
```

### 3.1 关键类型的变化

- **`Frame`** 增加 `cam: u8`。图像改成 `Arc<FrameImage>` 从缓冲池取，不再每帧 `to_vec()` 分配新缓冲（三路 × 1.3 MP × 几十 fps 时，分配和拷贝都是负担）。
- **`Recipe`** 增加 `mode`：
  ```rust
  enum InspectMode {
      FlyShot { shots: Vec<[f32; 2]>, trigger: TriggerMode },
      Follow  { cameras: Vec<FollowCam>, sampling: Sampling },
  }
  ```
  `shots`、`trigger_mode` 从顶层移进 `FlyShot`。`PathPoints.k`（点归属哪个拍照点）改成由 Sampler 在运行时算，不存进配方。
- **`Measured` / 点表**：现在每点只有一个量 `d`（内边 → 胶中线的距离）。随动需要**胶宽**和**位置**两个量，改成 `d: Vec<f32>, w: Vec<f32>`，`PointState::Measured { d, w }`。`JudgeParams` 分成 `position` 和 `width` 两组限值；任何一组为空就不判这一项。`store` 的 `POINTS_FORMAT` 升到 2，读旧格式时 `w` 为空。
- **`CameraHost` → `CameraRig`**：`Vec<CameraSlot>`，每台相机有自己的 `CameraConfig`（带 `id`、`role`、`serial`）、`CameraStatus`、重连循环。配置文件从 `camera.json` 改为 `cameras.json`，首次启动时自动迁移旧文件。
- **`CameraDriver` trait**：`Sim`、`Replay`、`Mvs` 三种实现。`Replay` 从目录读 `FrameN_c.jpg`，也读后面要做的录像格式，按原始时间间隔或手动单步交付。

### 3.2 不变的部分

PLC 握手时序、faultCode 表（91–99）、`judge` 的断胶合并与局部超差算法、`store` 表结构（只升点表格式）、历史 / 重判页面。

## 4. 分期

每一期都能独立合入 main、应用能正常启动，不留半截功能。

### M0 稳定性基线（约 2 天）

- [ ] **Replay 相机**：读 `5_涂胶演示图-海康三目` 这样的目录，当成一台或三台相机按节拍交付。后面所有开发和回归都靠它。
- [ ] 测量队列、帧通道改成**有界**：满了丢帧，记 `faultCode 99`，并在 UI 报警（现在 `measure.rs`、`cycle.rs` 用的都是 `unbounded_channel`）。
- [ ] 帧录制：可选打开，把一件的所有帧和配方快照落盘（`records/<ts>_<sn>/`），供 Replay 重放和离线调试。
- [ ] lyflow-client 依赖从 `branch = "main"` 改成 `rev = "<commit>"`（现在靠 Cargo.lock 锁定，但改 lock 时容易被一起升级）。

### M1 相机组（约 4 天）

- [ ] `CameraRig` + `CameraDriver` trait，把现有 Sim / Mvs 代码搬进去。单相机配置自动迁移，flyshot 行为不变。
- [ ] 图像源页改为相机列表：每台相机单独配置、状态、空跑、缩略图；飞拍可行性核算按相机分别算。
- [ ] 三目的触发方式：**按固定频率连续采集**（Follow 模式不按 Line0 逐点触发），三台同源触发保证同一时刻各出一帧。这需要现场确认，见 Q2。
- [ ] 缓冲池 + `Arc<FrameImage>`，并量一下三路满帧率下的 CPU 和内存。

### M2 实时检测页：主视图 + 三路相机（约 3 天）

- [ ] 布局：左侧大图是**主视图**，复用 `TrajectoryMap`，画工件轮廓 + 名义胶路 + 按点着色的结果 + 当前胶嘴位置；右侧竖排 **N 个相机小窗**，显示最新帧、叠加测量结果、fps / 丢帧，当前负责测量的相机高亮；底部是展开曲线 + 事件日志。
- [ ] 飞拍配方下只有一个相机窗，主视图仍是轨迹图，现在的 `ShotStrip` 保留。
- [ ] 相机窗的图像走现在的 `camera_preview`（降采样），按相机 id 取；不要把整帧推到前端。

### M3 随动模式：帧 → 点映射（约 5 天，先用模拟和回放）

- [ ] `Sampler` 抽象：把现有 `on_frame` 里的 k 推算挪进 `FlyShotSampler`；新增 `FollowSampler`。
- [ ] `FollowSampler` 从帧时间戳推算弧长 s：配方给出名义路径和速度曲线，PLC 给出涂胶开始 / 结束边沿，还可以选用机器人发来的进度（Q1）。
- [ ] 选相机：按当前行进方向，选能看到胶嘴后方胶条的那台相机（配方里给每台相机一个方位角区间）。
- [ ] 抽帧：不是每帧都测。按相机视野里可用的胶条长度和重叠率，决定每隔几帧测一次；每个点至少被一帧覆盖，没覆盖到的点记 `Invalid`。
- [ ] 模拟相机在 Follow 模式下合成"胶嘴 + 拖出的胶条"图，场景包括断胶、胶宽超差、偏位，接上现有的 `Scenario`。

### M4 配方管理与示教（flyshot P3 收尾，约 6 天）

- [ ] 配方落盘：`recipes/<id>/recipe.json` + `vision/`，版本号、哈希沿用现有的 `content_hash`，删掉 `builtin()`（两个演示配方改为首次启动时写入的样例文件）。
- [ ] 配方页：列表、新建 / 复制 / 删除、分段限值编辑、模式切换，保存前校验；只要已入库的记录引用了旧版本就不覆盖，改为新版本。
- [ ] 胶路来源：先支持导入 CSV / DXF 点列，再按弧长重采样成 `PathPoints`；圆角矩形生成器保留作样例。
- [ ] 示教向导（真实相机）：取一帧 → 框选模板 → 自动布测量点 → 试测 → 保存 `vision.json`。飞拍逐个拍照点示教；随动按相机示教胶嘴位置和测量窗。
- [ ] 标定：沿用图像源页的工位标定，扩展成每台相机一份；随动额外需要相机 → 胶嘴外参（Q3）。

### M5 视觉算法接入（约 5 天 + 依赖 D1 / D2）

- [ ] `Measurer` trait，现有模拟和 lyFlow 分别实现。
- [ ] lyFlow 图像域合入 main 后：去掉 `IMAGE_INPUT_UNSUPPORTED`，恢复 `RunImageInput` 注入，跑一遍 P3 里记录的端到端场景（正常 6 件、局部超差、跨帧断胶、丢帧、定位失败、N 不符、配方 B）。
- [ ] 随动检测图：胶嘴定位 → 沿胶条法向卡尺，量宽度和中心 → 输出和飞拍同构的 `StationMeasure`（多一个宽度字段）。
- [ ] 用 Replay 跑 Glue1 / Glue2 的全部帧做回归，胶宽曲线要和目视一致。

### M6 现场联调（按现场排期）

- [ ] 补采真实三路图像：直线、圆角、波浪各一条，包含一次人为断胶。
- [ ] PLC 联调 Follow 模式的信号表（Q1、Q2）。
- [ ] 节拍与资源：连续 8 小时跑三路满帧率，内存不增长，丢帧率 < 0.1%。

## 6. 需要现场确认的问题

- **Q1** 随动时怎么知道胶嘴走到路径的哪里？机器人能否实时发出路径进度或当前段号？如果只有开始和结束信号，就只能按时间和名义速度推算，速度波动会直接变成位置误差。
- **Q2** 三台相机的触发：同一路硬触发同时出图，还是各自按频率自由采集？帧率要求是多少？
- **Q3** 三台相机相对胶嘴的安装方位（是否 120° 均布），有没有相机 → 胶嘴的标定方法？
- **Q4** 检测项：胶宽、偏位、断胶都要吗？"溢胶"指什么（宽度上超，还是胶条外有胶点）？旧版首页上有"溢胶数"。
- **Q5** 结果回写：整件一个结果，还是按段回写？NG 时是否需要实时停枪（随动模式能做到边涂边报）？

### 8.2 与计划的出入

- **配方的工况没做成带数据的枚举**，而是 `mode` + 可选的 `follow`：`Recipe` 同时是检测记录里的配方快照，旧快照必须能读回来。
- **飞拍的帧 → 拍照点逻辑留在 `cycle.rs`**，没有抽成与随动对称的 Sampler；随动的 `Tracker` 是独立模块。
- **视觉引擎按 D1 的备选②执行**：lyFlow main 仍没有图像域，随动用本程序卡尺；飞拍的图像测量仍然只能走 lyFlow。系统设置里按工况分别选"模拟 / 图像测量"，飞拍、随动配方可以同时存在。
- **计划外新增"胶嘴位置同步"**。按名义速度推算胶嘴位置，会因为机器人起步延迟、速度误差、拐角减速而偏几毫米；沿胶路的误差在拐角里会变成横向误差，直接判 NG。现在做了两步：
  1. 起点同步：胶条起点在图上时，沿胶路找它断开的位置，一次修正起步误差。
  2. 拐角同步：拐角里各点的横向读数里有一项 (n·t)·δ，用最小二乘解出沿程误差 δ，修正胶嘴位置并从读数里扣掉。
  PLC 进度模式同样受益：零点取布防时读到的寄存器值，没清零也能处理。进度按帧拍下的时刻取值：PLC 轮询到的每次变化都记下来（最近 3 s，值与第一次读到它的轮询时刻；往回跳的读数不记，开走前比零点小 1 mm 以上才当作 PLC 清零），帧落在两次变化之间就内插（间隔长时先停后追），在最近一次之后按估出的速度外推、最多推一个间隔，两个间隔不变就停在读到的值上；间隔按实测的轮询节奏自适应。起点同步只在图像测量且配方开了自动同步时做。另外起点区（默认 4 mm）内不判断胶。
- **相机按固定编号引用**（`cam1`、`cam2`…）：配方存编号，不存在相机组里的位置，增删相机不会让配方指到别的相机；删掉的编号不再分给新相机（`cameras.json` 里记着下一个编号）。旧配方里的序号 k 读成 `cam{k+1}`，旧 `cameras.json` 首次启动时补编号；工位标定文件、帧录制文件名、检测记录里的帧都按编号记（`cam1` 的工位标定沿用 `plane_calib.json`）。`cameras.json`、`cycle.json` 读不了时先备份成 `*.broken-时间.json` 再按默认运行（开工日志里写明）；配置、配方、示教清单带 BOM 的 UTF-8 都照常读，写入走临时文件改名、一次一个。序列号留空的海康相机第一次连上哪台就固定成哪台，图像源页随即取回固定后的序列号；想换一台时可以再选"第一台可用相机"重新固定。相机的增删、改配置与软触发只在空闲或故障时做。
- **开工与就绪检查**：配方的相机要在相机组里、采集方式与工况相符（飞拍触发采集、随动连续采集）、随动相机做过标定。海康相机要打开图像测量才能开工（PLC 用模拟器时不拦，可以拿真相机试触发）。人工选型号时选中配方不满足（或配方文件没能加载）就停在故障；PLC 下发型号时只报警列出开不了工的配方（原因变了报警跟着变），这些型号来了单件回 ERR，不拦别的型号，一个配方都开不了工才停在故障。在途的件只看它自己用的相机，等 PLC 确认结果时不因相机掉线打断握手。
- **折线胶路的每条边可以是圆弧**（bulge = tan(圆心角/4)，正值逆时针）。DXF 导入读 ENTITIES 段的 LWPOLYLINE / POLYLINE（圆弧与闭合标志）、CIRCLE，以及首尾相连的 LINE / ARC，有多条路径时取最长的；CSV 第 3 列起默认不认（常见的是高度 z），表头写明 bulge 的那一列才当圆弧参数；导入时首尾重合的点当作闭合。整圆（两个点、两段半圆）自动剖成四段。判定的滤波与连续超差沿整条胶路算，不在分段边界处断开（折线导入的胶路每条边一段）；一次超差只判一次，记在点最多的那一段、按它的允许长度判，原因里写出超差的弧长位置（其余段只记落在本段的那一截与它的位置）。
- **配方文件**：目录里已有、却没加载的同名文件不会被保存覆盖（启动时读坏的、之后手工放进来的都算）；检测中的配方（人工选中的、在途工件的，从 PLC 下发型号那一刻算起）不能删、不能改编号；示教资料跟着配方改名、删除（清单里的模板按清单所在目录找），换了飞拍相机要重新示教，旧的示教资料照常可用。
- **VM 模型未用**（D2 ①）。

### 8.3 验证

- 单元测试 16 个：判定（跨帧断胶、首尾相接、局部超差、胶宽）、配方几何（圆角矩形周长、折线倒圆）、胶路导入（首尾重合且带 z 列的 CSV、LINE 与 ARC 拼成的 DXF、整圆）、PLC 进度取值（走—停—走、慢轮询、晚到的帧）、投影、三相机全覆盖、卡尺亚像素、"合成图像 → 卡尺"往返、起点同步（超前 5 mm、滞后 3 mm）、回放文件名。
- 模拟节拍（三台模拟随动相机 + 本程序卡尺，名义速度模式；模拟机器人起步比视觉晚 60–90 ms、速度偏 ±1%、拐角慢 10%）：连续 30 件。
  - 结果：正常 14 件中 11 件 OK；断胶 4/4 `NG_GAP`（定位在短边 B，3.0–3.5 mm）；胶宽不足 4/4 `NG_WIDTH`；偏位 4 件中 3 件 `NG_POSITION`；间歇丢帧 4/4 OK。
  - 另外 4 件判 ERR 93（胶条连续 2.5–54 mm 没测到）：那几段时间里三台模拟相机同时有 0.3–0.7 s 一帧都没出，帧通道没有丢帧，是模拟出图被 CPU 挤停了。
  - 30 件里没有误判：没有把缺陷件判成 OK，也没有把正常件判成 NG。起点同步每件都成功，修正量约 −6 mm（相当于起步延时 +75 ms）。三路连续运行 40 多件后进程内存约 135 MB，没有上涨。
- PLC 进度模式（模拟 PLC 每 10 ms 写一次进度）：改成按帧时刻取值之后正常件 10/10 OK，偏位、胶宽不足、断胶（定位在短边 B）、丢帧都判对。之前的外推在机器负载高、帧晚 0.4–1.1 s 才处理时会超前几十毫米，造成大段未测与断胶定位错。进度改成每 40 ms 写一次：正常件 26 件里 23 件 OK、3 件 ERR 93（未测成，没有误判），失败的那几件出现在机器负载高的时段。
- 相机编号：旧配置迁移成 cam1–cam4，随动配方 `[1,2,3]` 读成 cam2–cam4。删掉 cam1 后随动配方照常检测，报警栏列出两个飞拍配方开不了工；新加的相机拿到 cam5；人工选中飞拍配方时停在故障、原因写明缺哪台相机。随动件检测中把另一个配方用的相机改坏（回放目录不存在），这一件照常判 OK，回到空闲后才进故障。
- 帧录制回放：把一件"胶宽不足"的三路录制接到三台回放相机上重跑两次，都复现 `NG_WIDTH`，胶宽 0.88–2.09 mm、连续 9.0 mm，与录制时一致。
- 飞拍回归：正常 OK、跨帧断胶 `NG_GAP`、丢帧 ERR 91，与改动前一致。
- 第 4 轮评审修复后复跑：名义速度模式正常 OK、偏位 `NG_POSITION`（原因带 s=421.5–425.0）、断胶 `NG_GAP`；PLC 进度模式正常 2/2 OK、断胶 `NG_GAP`。之后机器整体 CPU 占到 96–98%、主频只有额定的 39%，三路模拟相机每路每秒只出 2–3 帧，后续各件都是 ERR 93（未测成），不是误判。检测中软触发被拒、空闲时照常；没有工件时主视图也画出名义胶路。
- 第 5 轮评审修复后复跑（机器负载恢复正常）：名义速度模式正常 2/2 OK、偏位 `NG_POSITION`、断胶 1 件 ERR 93 后复跑 `NG_GAP`；PLC 进度模式正常 2/2 OK、偏位 `NG_POSITION`、断胶 `NG_GAP`；飞拍跨帧断胶 `NG_GAP`。PLC 下发型号时把飞拍相机改坏：只报警、照常空闲；再把一台随动相机改坏：停在故障"没有一个配方开得了工"；修好一台就回到空闲。运行中往配方目录放一个坏文件，同名保存被拒；移走后不用重启就能保存。
- 第 6 轮评审修复后复跑：带 BOM 的配方文件启动时照常加载；名义速度模式正常 2/2 OK、偏位 `NG_POSITION`（s=421.0–425.0）、断胶 `NG_GAP`；飞拍局部超差 `OK_WITH_EXCURSION`。中途有一段 LyFlow 基准测试把 CPU 占满，那几件随动出帧不足判 ERR 93，测试结束后复跑正常。PLC 下发型号时飞拍相机先后报两种不同的原因，报警文字一秒内跟着变。
- 海康演示图（真实图像，像素当量未知，按 0.02 mm/px 假设；胶嘴设在 (690, 620) px）：逐帧自动找方向试测。
  - Glue1 共 80 帧。第 12 帧起方向稳定在 280°–293°（图像里朝上），每帧 13/13 点测到，帧内胶宽标准差大多在 0.01–0.2 mm。胶宽随帧在 0.50–1.35 mm 之间变化，与目视一致（第 46 帧细，约 30 px；第 78 帧粗，约 65 px）。前 11 帧是起胶前的空走，方向与胶宽都不可信。
  - Glue2 共 71 帧。方向稳定在约 310°，每帧 13/13 点测到。波浪胶不沿直线走，帧内标准差 0.1–0.34 mm，符合预期。

### 8.4 已知限制与 M6 待办

- 三路真实数据仍然没有：演示图三个通道是同一张图。相机方位、胶嘴位置、像素当量都要现场标定，随动标定面板提供了这些工具。
- 海康相机的连续采集（`TriggerMode=Off` + `AcquisitionFrameRate`）还没在真机上验证。
- 名义速度模式靠图像同步兜底。推荐 PLC 给进度（Q1），`pathProgress` 刷新得越勤越好：外推误差到拐角会变成横向误差（模拟 PLC 从每 40 ms 改成每 10 ms 写一次后才稳定）。
- 可测窗口实际比配置的短：胶嘴遮挡半径加搜索余量那一段测不了。帧率 × 步长要保证相邻两帧间胶嘴走的距离小于实际窗口长度。
- 模拟节拍三路同时合成很吃 CPU：每幅渲染限到 1/3 的核；帧录制"全部"约 50 MB/s 写盘，一件随动约 0.5 GB。
- lyFlow 图像域合入后要恢复飞拍图像测量：去掉 `vision.rs` 的 `IMAGE_INPUT_UNSUPPORTED`，恢复 `RunImageInput` 注图，重跑 P3 的端到端场景。
