# Agent 示教执行问题与改进项

本文说明示教执行中容易混淆的证据、当前接口提供的保护，以及仍需图像和工艺验证的部分。工具字段以 [Agent 示教接口](agent-teaching.md) 为准，生产判定以 [段配方决策](../decisions/segment-burst.md) 为准。原图、现场身份、本机配置和逐段日志不进入本文。

配置检查、测量保存、生产判定和独立验收分别说明不同结果。走廊全部保存、测量命令成功，甚至复测判定与来源标签一致，都不能替代逐帧证据与产品质量验收；同一示教件自测不能替代独立好件和缺陷件验收。

## 当前接口与保存保护

| 问题 | 当前行为 | 使用时仍需核对 |
|---|---|---|
| M1：定向前置配置分散 | `teach_status` 返回各段测量区间及来源（本段覆盖、相机或默认）、出胶点及来源、逐帧定向前置问题，以及引擎状态、版本和运行库来源 | 开始多段示教前先解决公共前置问题；应用可以启动不表示 lyFlow 已就绪 |
| M2：模型存在被当作可用 | 状态区分模型存在、模型可用、质量数据和问题原因；配置检查与量测证据分开 | `saved` 只说明示教资料已保存；模型可用也不证明走廊落在新胶上 |
| M3：产出结果被当成完整测量 | 试测区分 `measuredFrames` 与 `completeFrames`，保留应测未测、截断/未知、无可用证据帧；整件复测返回汇总、`flags` 与完整相机/段量测证据 | `error`、`outOfCorridor`、缺帧和计划跳过分别看，不能只看 `errors=[]`、measured 数量或区域 `OK` |
| M4：走廊写入分阶段生效 | `teach_corridor` 在内存准备帧、测量方式、搜索扇区、路径和颜色模型，校验最终坐标、测站数及颜色可用性，再以同一修订提交 | 新段可以明确选灰度后一次提交；失败不能留下模式或方向变化，不通过静默裁剪修复越界 |
| M5：变更影响和身份不清 | 状态返回项目编号与名称；调用支持 `expectedProject`、`expectedInstanceId`，写操作另核对 `expectedRevision`，长操作标明是否过时 | 同名配方不代表同一项目或候选实例；冲突后重新读并应用补丁，不能给旧文档配最新修订号 |
| M6：窄范围仍测整段 | `teach_trial.from/to` 限定实际读图和量测范围，同时保留整段边界、相机归属、定向参数和原始帧号 | 局部通过只说明该区间；生产检测范围和整件判定不因这次试测改变 |
| M7：大量状态淹没待办 | `teach_status.summary` 返回计数、含未确认沿用或来源未知资料的待办、推荐帧和零覆盖原因；完整模式保留逐段冻结来源、配置与证据 | 迁移后的轮次不证明原图来自新件，核对 `frameSource` / `teachingSource`；推荐帧只作看图起点，整段计划不检时没有推荐帧 |
| M8：测量需绕到开发者控制台 | `teach_measure` 复用正式示教件测量流程，保存后返回提交身份、量测完整性和起涂建议 | 只保存当前候选的测量，不自动发布或采用 skip 建议；测量结果须与当前快照对应 |

`teach_corridor` 的准备、提取、最终几何校验、取色或修订检查失败均不替换旧候选和旧示教图，包括原测量方式、扇区和模型。提交使用独占创建的新图；候选落盘失败只清理本次拥有的新图，清理失败会明确报告。提交后视图刷新失败会报告已保存修订，不能按未保存直接重试。

独立取色工具保留重新取色入口，可返回不可用模型的诊断；它与 `teach_corridor` 的整体提交契约不同。工具成功返回、模型可用和物理跟踪正确是不同结论。

MCP 仍只负责候选示教。建项目、选示教件、确认分段、设置像素当量、每笔跳过、发布、项目切换和硬件操作使用正式界面，按用户已有授权处理。不经开发者控制台保存整份候选，不直接写记录库；缺少产品入口时说明缺口，而不是把临时任务脚本当接口。

实现依据：[MCP 工具](../../src-tauri/src/workspace/agent.rs)、[示教准备与提交](../../src-tauri/src/workspace/burst.rs)、[候选修订](../../src-tauri/src/workspace.rs)。

## 分段与检测覆盖

### A1：短检测段被边界保护覆盖

边界可信时，`skip` 段向两侧各扩展 `boundaryGuard` 帧，夹在两个不检测段之间的短检测段可能完全没有检测帧。更换示教件后，某笔少一帧也可能落入既有“首尾跳过之和”，从有检测帧变成整笔不检。单段试测能量到胶宽，不能证明整件生产仍覆盖该段。

分段确认预览与 `teach_status` 共用实际分段规则，报告 guard、过渡区、起止跳过后的检测范围、各相机应测帧数、示教可用帧数、零覆盖段和胶偏可判窗口。屏蔽帧组只减少示教可用帧，不冒充生产 skip；边界不可信时明确报告未知，不把预测数字当作可信覆盖。开启边界细化时，比例预览也不冒充最终图像细化结果。

`boundaryGuard=0` 可以恢复部分短段的检测范围，但取消了边界保护，不能作为通用默认修复。仍需用多件录制核对帧数波动与比例切点稳定性。胶偏的去首尾规则不变，1–2 帧短段可能没有可判胶偏的帧。

零覆盖须保留段号、笔范围与原因，区分已约定的计划不检和意外失去覆盖。前者可排除后单独验收其余范围，后者须先处理；二者都不能在交付时统称“全部已检”。

实现依据：[分段与覆盖](../../src-tauri/src/segmentation.rs)、[胶偏窗口](../../src-tauri/src/burst_judge.rs)、[分段保存预览](../../src-tauri/src/workspace/capture_review.rs)。

## 仍需图像与工艺验证的问题

### A2：起涂、短点胶与固定测量窗口

起胶增长阶段尚未填满固定窗口或静态走廊，容易出现长断口、存在率不足；短点胶有时只有末帧稳定。局部区间的中位数只能用于有限的标称统计，不能替代原完整区间的失败。物理段长未填写时，也无法核对窗口是否覆盖每帧后移量。

需要先明确哪些起胶形态正常、短胶需要什么长度或缺胶判定，以及运动与帧率能否形成可测区间，再设计和验证判定。本次接口改进不通过增加 skip、缩短走廊或降低存在率门限隐藏失败。

### A3：模型可用不保证跟踪新胶

过曝白底可造成背景样本不足、`usable=false`，后续量测报 `n_map（bad_param）`。重复取色不能恢复丢失的图像信息，也不能借用另一段的模型伪造有效结果。优先选择同段中曝光和覆盖合适的帧；已有自主调整示教方式的授权、全段图像证据充分且胶边清楚时，可以明确选择灰度重新示教并重新试测，不重复索取同一授权。取色失败本身不是授权或充分依据，授权不足时先询问，接口也不会静默降级。灰度提取在胶嘴遮挡、宽度突变处仍可能不连续，只有核对真实两侧胶边后才用手工中心线。

质量数值可用的模型也可能跟踪旧胶、相邻同色胶或错误分叉；没有 fallback 不证明路径正确。仍需准备曝光与视野合适的录制，并标注新胶、旧胶和分叉轨迹。未经标注样本验证，不能把模型质量当成物理路径验收。

### A4：ToEdge 稳定数值可能来自假边

相邻胶边或反光渐变可能给出稳定边距。接口提供有效率、缺失帧和胶偏未判原因，便于找出证据不足的区间；它不能确认边属于零件。降低找边对比度门限后数值变多也不等于参考正确。

标称边距须同时核对有效帧、分布和叠图中所选边；找不到可靠实体边时说明未判原因，不自行关闭检查掩盖失败。弯道不启用 ToEdge，短段没有有效判定帧时不声称具备胶偏检测能力。

### A5：胶宽标称与溢胶规则冲突

胶宽标称或公差上限超过独立溢胶上限时，MCP 给出参数冲突提示。胶宽在公差内仍可能被溢胶规则判为 `NG_WIDTH`；逐帧 `widthOutside` 为空不代表生产胶宽判定通过。门限须依据图纸或工艺确认，不把示教件中位数自动当作图纸规格；现有 OK/NG 规则保持不变。

### A6：选中帧改善不等于整段转向可测

搜索半圈方向不符时，可能在有胶帧上没有可用证据。`teach_corridor.sectorDeg` 可以改变本段本相机方向，但转弯过程中覆盖的方向会变化；一帧测成也可能以其他帧失效为代价。保留变更前后的完整段结果，无改善时撤回方向调整。扇区不能修复不准的出胶点、超出视野的胶条、固定参考落到裸金属，或缺失的图像信息。

断胶提示需要看测站落点：裸金属上的 absent、胶头/尾尚未形成完整参考形状、主体中间实际断开是不同证据。不能仅由小存在率或最终 NG 给出制造缺陷归因。

## 录制身份与更换示教件

[标准历史件包](../architecture/history-package.md) 包含清单、记录库与可选原图；只有 `part.json` 和原图的录制 ZIP 不具备完整检测指标。两者不能交换扩展名或拼造内容后混用。`capture_fixture` 的样本模式会重建身份、时序和配置，只能作为手动配置数据，不能冒充原件或保留原笔结构的导入。

更换件前核对当前项目编号、名称和录制归属，再核对相机、逐笔图像对应与迁移后的分段。录制内的配方 `passFrames` 是模板，不是该件实际门控笔结构；按时间戳推算与生产门控来源不同时，要保留这种差异。`passes.inRecipe` 只核对配方与示教件逐笔及总数，`passes.history` 另核对历史来源；后者不一致不能靠重保存分段修复。笔数异常应先查来源和导入链路，再判断工艺是否改变。文件名、来源 NG 标签和同件自测一致均不是独立真值。

## 开发环境与回传工作流

| 情况 | 当前入口与恢复方法 |
|---|---|
| 新 worktree 缺 lyFlow 运行库 | `pnpm dev` 不恢复运行库；先按 [lyFlow 依赖说明](../architecture/lyflow-dependency.md) 准备，或用 `pnpm dev:joint -LyFlowRuntime <目录>` 指定本次进程目录，再看示教预检 |
| 开发版切换项目 | 保存下次启动项目，返回 `restartRequired=true` 和当前/目标项目；界面等待手动重启。停止原开发命令后用相同入口与参数重开，再核对当前项目。正式版仍自动重启 |
| 相机离线时保存 | 成功结果分别返回 `saved`、`applied`、`warnings`、`applyError`；文件已保存而设备应用失败时明确提示，连接设备后重连核对。落盘失败仍报错 |
| 外部导入后版本快照冲突 | 配方版本下限在检测宿主初始化时读取。原样导入后重启，再建候选/发布；受控在线导入及下限刷新仍需另行实现 |
| 回传包找不到原图 | 示教件原图按 cycleId 读本机录制，不能用重建身份的样本件代替现场件。本机 recordId 可以不同；需在错开编号的模拟库验证改基、冻结图与示教件读图 |

本机没有示教件那一件的记录或录制时，示教件原图不可用。更换示教件会迁移分段并使原测量失效，需要核对逐笔对照与沿用资料，不能作为无损恢复。模拟现场验证应先发布采集版，再导入工件配方（回传包）检查改基。发布后等 `pending` 为空且 `publish.state=active`，读取实际发布版本，不能用下一候选版本冒充生产版本。详见 [配方创建与回传](../architecture/recipe-creation-workflow.md)、[项目切换](../architecture/project.md)、[相机保存](../architecture/online-commissioning.md)。

## 验收边界

软件回归保护的是：未测成帧不被摘要漏报、不可用模型不被当作可用、最终几何失败不替换旧示教、过期修订不能覆盖更新、失败清理不删除他人图像、区间量测不访问范围外帧，以及短段被 guard 吞没时预览能明确提示。它们不验证真实新胶路径、真假零件边或现场误判率。

逐帧诊断当前内联返回；大录制的分页或独立诊断导出尚未提供，需按记录保存完整响应并防止客户端显示截断。

每个配方交付仍需分别保留配置检查、选定范围试测、整件覆盖、逐帧完整性、整件生产判定和回传完整性证据。下一步算法验收使用已标注的起涂、短胶、过曝、多胶分叉和假边样本，按路径与产品判定逐项核对。
