# Agent 示教执行问题与改进项

本文整理一次四配方离线示教中暴露的接口、工作流和量测问题，供后续改进示教自动化时使用。MCP 契约以 [Agent 示教接口](agent-teaching.md) 为准，判定规则以 [段配方决策](../decisions/segment-burst.md) 为准；本文不重新定义发布条件或生产判定。

代码核对基线为 `ff3476c5`。原样录制导入和无对话框回传包导出在 [PR #240](https://github.com/liangyuR/ly-gluesight/pull/240) 的 `8d58b6a` 上验证，尚未合并，不能当作 main 已有入口。下文“建议”均未在本次工作中实现。原图、现场身份、本机配置和逐段日志不进入本文。

## 结论与边界

四个配方完成了分段、走廊示教尝试、回传包导出和模拟现场补图验证，但示教件整件自复测均为 `NG_GAP`。发布配置检查通过、候选可以发布、回传包能够补回原图，均不能代替实际量测和质量验收。

需要分别处理三类问题：

| 类别 | 本次主要表现 | 处理边界 |
|---|---|---|
| MCP 可观测性与接口一致性 | 模型存在不等于可用；整件复测摘要缺测量完整性；多阶段写操作可能部分生效 | 适合改进工具返回值、前置检查和保存一致性 |
| 开发环境与自动化工作流 | 新 worktree 缺运行库、开发版重启、离线配置、导入版本顺序、审批提示 | 需改启动/配置流程；不能归因为视觉算法或 MCP 传输失败 |
| 图像与量测行为 | 过曝背景、旧胶与分叉误跟踪、短胶起涂、假零件边、宽度规则冲突 | 需看图和工艺证据；不能靠重复调用工具或放宽门限得到验收通过 |

当前 MCP 有意只提供候选示教工具，未提供建项目、选示教件、确认分段、设置像素当量、发布或项目切换。端到端自动化因此需要界面或应用 IPC 配合。这是现行边界，不应把缺少这些工具统一列为 MCP bug；是否扩展须另行确定授权和操作范围。

## MCP 接口与自动化卡点

### M1：开始示教前，关键相机参数仍需切换到其他入口

开启逐帧定向的检测段要求相机已有 `window`；未显式标定 `nozzle` 时，系统用该相机各定向段的走廊起点推导出胶点，并检查起点到平均点的毫米距离。各段单独画线后，自动吸附的起点可能偏移，导致后续整段试测报缺少测量区间或出胶点不一致。

`teach_segment` 仅接受 `checks`、`offsetRef`，不能设置 `heading`、`window` 或 `nozzle`。`teach_status` 能返回出胶点，但没有返回 `window`，无法仅凭一次状态读取核对定向前置配置。本次需要额外通过应用 IPC 读取和保存这些参数。

现有处理是先在受支持的配置入口核定相机级测量区间和出胶点，再开始多段示教；需要调用 `workspace_save_doc` 时，用本次读取的候选修订号保存。短点胶是否关闭 `heading` 应依据可见胶路和实际运动，不能因段帧数少就一律关闭；连续长胶在相机切换后也可能只有少数帧。

建议先补齐只读状态中的 `window`、出胶点来源和定向前置错误。相机级参数写工具是否加入 MCP，应在明确范围后设计；不必为改善诊断而直接开放发布、PLC 或项目切换。依据：[定向几何与前置检查](../../src-tauri/src/heading.rs)、[工具 schema 和 status](../../src-tauri/src/workspace/agent.rs)。

### M2：`saved`、`colorModel`、`blockers` 容易被组合成错误的“已就绪”结论

`teach_status.cameras[].segments[].colorModel` 只检查颜色模型字段是否存在，没有解析 `quality.usable`。`saved` 检查走廊与冻结示教帧是否可用，不保证走廊位于新胶上；`blockers` 来自发布配置检查，也不代表逐帧量测已经通过。本次存在模型 `usable=false` 的白底段，也存在模型 `usable=true`、但示教线落在非胶纹理上的情况。

现有验收必须联合查看取色返回的 `quality`、示教叠图、`teach_trial.states` 和失败帧，再看整件结果。只检查 `saved && colorModel && blockers.length == 0` 会漏掉这些问题。

建议区分 `modelPresent` 与 `modelUsable`，返回 `glueCount`、`bgCount`、`centerShift`、分离度和不可用原因；对“配置已齐”“最近试测通过”“实际测量覆盖完整”分别报告，不增加一个含义不明的总布尔值。依据：[status、color_summary](../../src-tauri/src/workspace/agent.rs)、[发布检查](../../src-tauri/src/workspace/burst_release.rs)。

### M3：整件复测摘要缺少检测完整性，区域 `OK` 不足以验收

`teach_replay` 当前返回整件及区域的判定、原因、范围、宽度与胶偏，没有透出完整判定的 `flags`，也没有逐帧状态计数。生产规则把部分缺帧或测量不完整记在 `flags`，不直接改变 OK/NG；因此某区域返回 `OK`，不能证明它的目标相机帧都测成了。

本次一件示教录制经额外读取整件 features，才能完整识别 **25 个 `error` 和 1 个 `outOfCorridor`**。这不是 MCP 制造了量测错误，而是 MCP 的摘要不足以表达已有错误。`teach_trial` 也有相似的诊断缺口：数值分布和 `worst` 只从 `measured` 帧生成，`errors` 只列 `FrameState::Error`；`outOfCorridor` 可在 `states` 中出现，却没有对应的失败帧明细列表。

当前需把“应检测帧”“实际进入测量的帧”“成功测量的帧”分别核对；`error`、`outOfCorridor` 不能计入成功测量，计划内 `notInspected` 也不能计为检测通过。不能只看 `errors` 为空或 `worst` 列表为空。

建议 `teach_replay` 返回 `flags`、按相机/段汇总的帧状态、应测/实测数量和胶偏未判原因；`teach_trial` 为所有非 `measured` 状态提供帧号和原因。失败帧较多时提供分页或独立诊断结果，避免在简略文本中截断。此改进只补足可观测性，不自动改变现行 OK/NG 策略。依据：[trial 与 replay 返回值](../../src-tauri/src/workspace/agent.rs)、[Flags 与判定策略](../../src-tauri/src/burst_judge.rs)。

### M4：走廊工具不是一次全部成功或全部失败的事务

`teach_corridor` 先冻结所选帧，再提取、保存走廊，最后重新取色。提取失败时，示教帧可能已换成新的 `seq`；取色失败时，已保存的走廊不会撤回，错误放在返回的 `colorModel.error` 中。只依据顶层调用成功/失败重试，会误判候选状态。

本次还遇到合法输入笔划经彩色吸附和平滑后产生轻微图外坐标，后续试测才暴露走廊不可用。当前代码检查输入 `stroke` 是否落在 `[0, width-1] × [0, height-1]` 内，但在吸附结果写入前没有同等的最终图内检查。调用成功不能替代保存后 `saved` 和图内范围核对。

现有处理是失败后重新读取状态和修订号；查看输出走廊而不只看输入点。确需修正边界时，保证物理胶路范围不被悄悄缩短，再通过 `teach_corridor` 重新冻结/保存/取色，而不是仅在整份文档里裁点。直接修改走廊坐标不会自动重新训练颜色模型。

建议优先在提取完成后验证最终坐标和最少测站数，再提交冻结帧、走廊与颜色模型；不能原子提交的阶段需明确返回 `frameUpdated`、`corridorSaved`、`colorFitted`、当前 `revision` 和恢复动作。不得通过静默裁剪掩盖真正越出画面的胶路。依据：[corridor、snap_path](../../src-tauri/src/workspace/agent.rs)、[segment_corridor_saved](../../src-tauri/src/workspace/burst.rs)。

### M5：修改段结构、检测相机和整份候选时，关联数据影响不直观

更改段类型序列可能清空走廊；移除某段的检测相机会移除不再适用的走廊和示教帧。尚未选定示教帧时，预先给新相机塞入空走廊会被拒绝。普通检测项补丁不等同于这些结构性变更，不能把“任何参数修改都会失效”当作规则。

多 agent 修改同一候选时，整份文档保存还有覆盖风险：不能先读取旧文档，再取最新 `revision` 来保存旧内容。这会绕过修订号本来要防止的丢更新。应在一次读取的快照上应用最小补丁，以同一修订号提交；遇冲突重新读取并重新应用补丁。本次按段分工，同时把共享相机参数、整件测量和项目切换交给单一执行者。

建议为结构修改提供影响预览，列出将被清除或迁移的走廊/帧；写工具可接受调用方期望修订号，读/测量结果统一返回项目、候选修订和所用参数身份。当前 `teach_trial`、`teach_replay` 结果没有这一完整身份，长任务归档需额外保存快照。依据：[候选修订与 replace_doc](../../src-tauri/src/workspace.rs)、[guard_segment_corridors](../../src-tauri/src/workspace/burst.rs)。

### M6：窄范围试测没有相应减少量测工作量

`teach_trial.from/to` 是**统计范围**：工具先调用整段量测，再截取统计窗口。反复试一个终帧仍会重测整段。加上单段/单相机接口、图片和 JSON 分开归档，多配方多段执行需要较多调用和额外证据整理。

当前可先分离结构错误与算法失败，修复公共前置错误后再做有效试测；不同相机的原图分析可并行，同一候选的写入和共享配置应协调顺序。不能把缩小 `from/to` 理解为降低了生产检测范围。

建议按明确的候选修订提供真正的区间量测，或复用同修订的量测结果；批量接口应保留每项的参数、修订号、失败和图片引用，避免整批只有一个成功标志。依据：[trial 的调用与统计顺序](../../src-tauri/src/workspace/agent.rs)。

## 分段、图像与量测问题

### A1：短检测段会被相邻不检测段的边界保护覆盖

`boundaryGuard` 不只产生“过渡区”：在边界可信时，`skip` 段还会向两侧各延伸 guard 帧。夹在不检测段之间的一两帧短胶，可能被整个划入 `skipped`。单段 `teach_trial` 能测出结果，不能证明生产按比例分段时仍会检测它。

本次把候选的 `boundaryGuard` 设为 0 后，用整件复测逐区核对切点，确认短检测段重新进入检测；同时核对 `skipHead/skipTail` 和指定相机的逐帧状态。这个处理取消了边界保护，不是适用于所有项目的默认修复；还需要多件验证帧数变化和比例切点的稳定性。

建议分段预览直接显示 guard 展开后的有效检测范围，并提示被全部覆盖、没有有效胶偏判定帧的检测段；在自动化验收中独立输出覆盖检查。依据：[resolve_regions](../../src-tauri/src/segmentation.rs)。

### A2：起涂、短点胶与固定测量窗口不匹配

起胶增长阶段尚未填满固定窗口或静态走廊，容易出现长断口、存在率不足；短点胶有时只有最后一帧可稳定量测。把稳态窗口缩到终帧后得到合理胶宽，只能用作有限的标称统计或诊断，不能替代原完整区间的失败。

本次保留完整有胶帧和失败证据，没有通过增加 skip、缩短走廊或降低存在率门槛隐藏问题。单帧胶点没有独立稳态分布；整段只有 1–2 帧的直线段，去首尾各一帧后没有胶偏判定帧，过渡区和 skip 还可能进一步缩小有效范围。物理段长未填写时，系统还无法核对测量区间是否覆盖每帧后移量。

下一步应明确工艺期望：哪些起胶形态应判正常、短胶需要何种长度/缺胶判定、运动与帧率是否足以形成可测区间。确认后再设计相应判定，不能把一次末帧通过作为工艺结论。依据：[段帧数与覆盖提示](../../src-tauri/src/workspace/burst.rs)、[区域判定](../../src-tauri/src/burst_judge.rs)。

### A3：颜色模型可用，不保证跟踪的是新胶

过曝白底使背景取色不足时，模型可出现 `bgCount=0`、`usable=false`，量测报 `n_map（bad_param）`。这是输入图像/模型条件问题；同一帧重复取色不能生成已丢失的背景信息，也不能复制另一段的模型伪造有效结果。

另一类情况是模型质量数值尚可，但动态路径跳到旧胶、相邻同色胶或分叉；`fallbackFrames` 为空也不能排除走错分支。静态短线可能吸到高光边，甚至非胶区域形成可用模型。本次依靠代表帧、最差帧和相邻相机原图识别这些问题，无法可靠判断新胶时保留失败和未确认标称。

建议在错误中报告背景样本不足等可解释前置原因；为路径分叉提供轨迹/候选分支诊断。采集侧需准备曝光与视野合适的新录制，算法侧需用已标注的新胶/旧胶场景验证。单纯把 `usable=true` 或“未 fallback”作为自动验收条件不成立。依据：[取色结果与试测摘要](../../src-tauri/src/workspace/agent.rs)、[逐帧定向调用](../../src-tauri/src/vision/heading.rs)。

### A4：稳定的 ToEdge 数值也可能来自错误物体

多条平行胶或强反光区域中，绿线可能稳定吸到相邻胶的边缘、反光渐变，而非零件边；降低 `contrastMin` 后有数值的帧变多，也不证明边参考正确。另一种情况是真零件边只在部分帧被找到，或者零件轮廓变化本身使边距显著变化。

现有处理需要同时检查有效边距帧数、分布和绿线落点；找不到可靠实体边就关闭该段胶偏并说明原因，不能仅凭中位数写标称。弯道不启用 ToEdge。短段缺少有效判定帧时也不应声称具备胶偏检测能力。

建议返回边距有效率、缺失帧号和所选边的可视化证据；不能只用数值稳定性给出自动“边参考通过”。依据：[ToEdge 契约](agent-teaching.md#teach_segment)、[胶偏判定](../../src-tauri/src/burst_judge.rs)。

### A5：胶宽标称与独立溢胶规则可能互相冲突

本次部分实测宽胶的中位数高于保留的溢胶上限。即使“标称 ± 公差”覆盖了这些值，独立溢胶检查仍会判 `NG_WIDTH`；局部 `widthOutside` 为空也不能证明生产胶宽判定会通过。MCP 的逐帧提示并没有替代跨帧、局部最大宽度和其他规则。

当前应同时列出标称、公差和溢胶门限，核对图纸或工艺要求；未知规格不能由示教件中位数自动变成图纸值。建议增加相互矛盾的参数提示，保留现有检测规则直到业务要求明确。依据：[trial 的 against_checks](../../src-tauri/src/workspace/agent.rs)、[生产宽度判定](../../src-tauri/src/burst_judge.rs)。

## 开发环境与回传工作流

| 卡点 | 本次确认的原因与现有处理 | 仍需改进的方向 |
|---|---|---|
| 应用能启动但示教全报引擎错误 | `pnpm dev` 不恢复运行库；新 worktree/target 需要按 [lyFlow 依赖说明](../architecture/lyflow-dependency.md) 准备运行库，或用 `pnpm dev:joint -LyFlowRuntime <目录>` 指定本次进程目录 | 示教预检直接报告引擎版本、运行库来源和缺少的算子，先于逐段调用失败 |
| 开发模式切项目后启动异常 | `project_switch` 调用应用重启，不能把生产可执行文件的重启等同于 `tauri dev` 的启动器、前端服务与 CDP 生命周期；本次由统一启动器停机、切指针、重新启动并核对当前项目 | 提供明确的开发项目切换流程，或在开发模式报告需要重新运行开发入口；不据此认定正式版切换失效 |
| 离线相机保存返回失败 | 配置保存和即时应用到设备是两步；当前实现先保存再 `apply_config`，离线打开失败不等于配置没有写入。本次新项目在停机状态按录制配置准备相机组后重启核对 | 分别返回“配置已保存”和“设备应用失败”，支持明确的离线配置准备方式 |
| 导入录制后版本快照冲突 | 配方版本下限在 `CycleHost` 初始化时从记录库读取；外部导入后不重启就建候选/发布，可能沿用旧下限 | 原样导入后重启，再建候选；未来可提供受控导入入口并刷新下限，避免操作顺序成为隐含契约 |
| 回传包在另一库找不到原图 | 补图依赖 cycleId、相机配置和帧记录一致，不能用重新生成身份的样本件替代原现场件；本机 recordId 本来就可能不同 | 使用保留身份的导入路径；在记录号错开的模拟库中验证改基、冻结图和全轮原图补回 |
| 回传包导出依赖文件对话框 | main 的交互导出入口不适合长脚本；PR #240 新增 `export_recipe_package --project <项目目录> --recipe <编号> --out <包文件>`，本次已验证，但仍属未合并实现 | 合并后维护可复用的命令说明与自动化契约，不把临时任务脚本当成正式产品接口 |
| 执行器反复要求批准 | 提示来自宿主终端执行审批，不能据此认定 GlueSight MCP 鉴权失败；本次用户重启并调整权限后，执行环境为 `danger-full-access` / `never`，后续不再请求批准 | 只能记录观察结果；现有证据不足以判定此前反复审批由某一个设置引起，不把宿主权限教程写进示教接口 |

PR #240 的原样导入还解决了失败后遗留半件记录的问题：先准备文件，再把记录、帧引用和 Complete 证据放在同一事务中，目录落盘/提交失败清理本次拥有的数据。该实现及定向回归、CI 已验证，但其合并和现场升级需与本次示教效果结论分开。

本次在空模拟库验证 recordId 不同的场景：先写一件独立无关记录以错开编号，再停机原样导入录制、重启刷新版本下限，随后发布采集版，最后导入回传包验证改基。写入无关记录是这个验证场景的安排，不是现场导入的产品前提。补图候选来自同配方最近 200 件录制，原件已清理或不在范围内都可能无法补回；重新选示教件会清空示教，不能视为无损恢复方式。发布后应等待 `pending` 为空和 `publish.state=active`，并读取实际发布版本，不能用已经递增的下一候选版本冒充生产版本。流程依据见 [配方创建与回传](../architecture/recipe-creation-workflow.md)。

## 建议的改进顺序与验收方式

以下优先级针对误判验收和重复作业风险，不表示已经批准改变生产 OK/NG 策略。

| 优先级 | 建议范围 | 可验证的完成条件 |
|---|---|---|
| P0 | M2/M3：补齐模型可用性、量测状态与 flags | 不额外读取内部 features，MCP 使用者也能定位所有未测成帧；存在不可用模型或测量不完整时，不会被摘要误认为已验收 |
| P0 | A1：显示 guard 后的真实覆盖 | 夹在 skip 之间的短检测段在预览中明确显示其有效帧；被全部覆盖时有可追踪的提示 |
| P1 | M4：最终走廊校验与部分生效结果 | 合法输入吸附后越界能在保存前发现；失败返回能准确说明示教帧、走廊和色模分别是否改变 |
| P1 | M1/M5：前置配置与变更影响 | 单次状态读取能核对定向前提；结构修改前列出失效项，过期修订不能覆盖别人的更新 |
| P1 | A2–A5：针对真实失效场景的量测验证 | 用已标注的起涂、短胶、过曝、多胶分叉和假边样本，分别确认路径、有效率与产品判定；不能只验证某个中位数 |
| P2 | M6 与环境准备：减少重复量测和人工接续 | 区间调用或缓存不改变统计/生产语义，批量结果可逐项追溯；启动预检和离线配置错误有明确恢复入口 |

在接口改进落地前，每个配方的交付应同时保留：配置检查、选定范围试测、整件覆盖、逐帧测量完整性、整件生产判定和回传完整性。它们回答不同问题，不能相互替代。来自同一示教件的自测也不能替代独立好件与缺陷件验收。
