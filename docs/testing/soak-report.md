# 长稳与故障注入报告

日期：2026-10-19。范围：离线模式下进程内虚拟 S7 产线 + 实拍样本集回放 + 本机 lyFlow 1.1.0，连续生产与故障注入。决策见 [soak 决策](../decisions/soak.md)。

## 结论

- **长稳**：修复后连续生产 1000 件（58 分钟），进程内存、句柄、线程无持续增长；离线原图稳定在约 9.3 GiB（上限 10 GB）；记录库约 29 KB / 件。故障注入 21 类场景都没有出现“错误的 OK”；追溯目录不可写按设计需重启，事务中重启遇到下述死锁，其余场景复位后都能恢复生产。
- **发现并修复 3 个问题**（各自单独 PR）：
  1. 布防阶段追溯健康检查只要超出 200 ms 布防预算，就被当成需要重启才能恢复的追溯故障，产线停到重启（首轮第 485 件触发）。
  2. 追溯故障期间每 20 ms 写一行故障日志，13 分钟 45,838 行，会把有用日志挤出 512 MB 日志上限。
  3. 原图滚动清理后历史记录仍显示“完整落盘 · 已核验落盘”。
- **新增**：资料盘剩余空间低于 2 GB 时暂停接件、空间恢复后自动就绪（避免磁盘写满时进入只能重启的故障）。
- **最大剩余风险**：`arm_ms` 默认 200 ms 偏紧。修复后长稳 1000 件里 124 件因布防预算超时判 ERR（94 件需要 PLC 复位），本机同时有其他工作线编译，CPU 负载平均 75%、过半采样 ≥ 90%。需 plc-table / core-flow 决定默认值（见 S-12）。
- **未修复、交给相关工作线**：离线事务中途崩溃后无法回到离线（死锁）；PC 置故障输出时遇到断线会主动断开且不再自动重连，离线期间 PLC 页只读无法手工重连。

## 长稳数据

### 首轮（修复前，main + 注入钩子）

- 485 件后停产：第 485 件布防时 `audit-health` 阶段累计 212 ms，被标为追溯故障；虚拟 PLC 连续 21 次 faultReset 都无法复位，只能重启。
- 停产前 ERR 14 件：12 件 `plc-arm-confirmed` 超出布防预算（203–307 ms），1 件测量超时，1 件即上述 `audit-health`。
- 停产后 13 分钟写了 45,838 行“故障：持久追溯故障…”，日志 12.3 MB 中大半是这一行。

注入节拍 400 ms。“恢复”指注入结束后由虚拟 PLC faultReset 再投产，直到合格（最多 3 件）；断线类场景首轮脚本在重连完成前就发起了一次投产（被拒“离线 S7 服务尚未连接”），脚本已改为先等重连。所有场景都没有错误的 OK。

## 剩余风险

1. **离线未结事务导致重启后死锁**（交 core-flow / plc-table）：离线事务进行中崩溃，或在途件进入故障后重启（编排脚本在“追溯目录不可写”后重启时复现），重启总回到真机模式，握手日志仍保留离线虚拟 PLC 的未结事务；真机 PLC 不在线时无法复位，又因“检测仍有在途事务”进不了离线。只能人工移走 `state/plc-handshake.json`。建议握手日志记下事务来自离线会话，离线事务允许进入离线由虚拟 PLC 复位。
2. **PC 主动断开后不自动重连**（交 plc-table）：置故障输出时恰逢断线、无法确认撤销布防，PC 按设计断开以停止心跳，之后不再重连；离线期间 PLC 页整体只读，有未结事务时又退不出离线，只能经接口或重启恢复。建议在 PLC 心跳失活阈值（3 s）后自动重连并要求明确复位。
3. **`arm_ms` 200 ms 偏紧**（交 plc-table / core-flow）：成功布防的 p99 已到 197 ms，负载下 12% 的件超预算。现场需按实测把 `arm_ms` 与 PLC 布防等待一起放宽，或缩短 S7 轮询。PR #89 把 PDU 降到 240 字节后单次轮询更慢，需要复测。
4. **原图目录写失败只记日志**：产线继续、判定正确，但在线检测页没有报警，操作员可能长时间不知道原图没存（交 core-flow / ui-shell）。
5. **中断件不进历史**：事务中崩溃的那一件只在握手审计里，历史记录查不到。
6. **记录库只按天清理**：高节拍下 180 天约 50 GB，没有件数或容量上限。
7. **调试构建**：耗时分布来自调试构建且与其他工作线争用 CPU，只作相对比较，不代表发布版现场节拍。
8. **真实磁盘写满未实测**：用拒写 ACL 与调高下限模拟，ERROR_DISK_FULL 的错误文本未见过。
