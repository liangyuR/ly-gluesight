# 前端主业务测试（2026-10-11）

默认前端回归只保留创建配方、示教到验证发布，以及少量关键失败保护。工件启动到落盘由独立桌面集成测试验证。前端精简时未改生产代码和后端测试；不设置覆盖率门槛。后续后端收缩范围见[后端轻量测试](backend-lightweight-tests.md)。

## 三条主流程

| 流程 | 实现与边界 |
| --- | --- |
| 创建配方 | `tests/recipe-create-flow.test.tsx`：真实配方库创建空候选，经真实 WorkspaceProvider 选中新候选，进入进度及采集页面；模拟 Tauri 接口 |
| 示教、验证与提交发布 | `tests/teaching-flow.test.tsx`：从两个已采集拍照点开始，逐帧点中线、保存、试测、完成示教；进入真实总览页面调整并保存，再经真实采集页重采独立正常样本，返回验证页面验证并确认发布；末态为等待工件边界。使用真实页面和 Provider，只在接口边界提供分阶段数据 |
| 工件启动到落盘 | `tests/native/production-flow-ui.mjs`：自动构建启动隔离桌面实例，UI 配置模拟 PLC、相机、测量和录制，运行一件至握手结束；独立只读 SQLite 连接核对本件、修订、逐点测量及逐拍记录，读取真实 PGM 和录制元数据，在历史页面读回原图；最后关闭本次测试进程 |

前两条验证前端业务接线，图片为内存占位，采集/试测/验证结果来自接口模拟，不证明像素解码、算法或后端发布生效。第三条使用运行时生成的模拟图像、真实后端和磁盘。三条流程均不依赖本机预备图片，也不替代真实 PLC、SDK、LyFlow 引擎或现场验收。

## 运行与换机

使用 Node 24.15+、pnpm 11.1.3。桌面流程还需 Windows、PowerShell 7、Rust MSVC、Visual Studio C++ 构建工具和 WebView2；首次 Cargo 构建需要读取 `Cargo.toml` 中的私有 Git 依赖。Playwright Core 1.64.0 已作为项目依赖锁定，连接应用 WebView2，无需本机模块绝对路径、外部测量 DLL 或 Playwright 浏览器下载。

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm test:ui:all
```

`pnpm test` 运行全部 40 项前端测试；`pnpm test:ui:all` 顺序运行两个前端主流程及真实桌面生产落盘流程。单跑主流程可用 `pnpm test:ui` 或 `pnpm test:ui:production`。生产测试自动构建、启动和关闭隔离实例；已构建时可用 `pnpm test:ui:production -SkipBuild`，端口冲突可传 `-DebugPort 9349`。

`pnpm typecheck` 检查应用与测试类型；`pnpm build` 检查生产前端构建；`pnpm test:coverage` 生成整个 `src` 的覆盖率报告，仅供排查，没有全局或单文件门槛。

桌面数据位于独立 `com.xyzrobotics.tujiaovision.flow-tests` 应用目录，通过运行中的后端取得实际路径。该 profile 只供这套模拟流程使用，不导入实体设备或生产配置。SQLite、原图和截图保留供复核；产物不提交。旧 P0 的真实引擎与回放专项仍须另备 DLL、图片和相应环境。
