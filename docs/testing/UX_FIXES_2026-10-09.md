## 本轮修复的 9 项问题

| 编号 | 操作场景与原问题 | 修复后的行为 | 负责分工与验证 |
| --- | --- | --- | --- |
| UX-01 | 勾选并标注第一组验证样本后，再导入第二组，第一组的选择与人工期望被覆盖 | 同一候选内保留本地选择和期望；删除的原图样本会剔除；切换候选时加载目标候选自己的选择。修改后仍需重新验证才可发布 | validation_selection；新增 5 项回归，含连续导入、手动取消、改期望及切换候选 |
| UX-02 | PLC 配置已保存或快速重连，但连接状态仍为“已连接”，内置模拟节拍继续使用旧协议判断 | 保存成功发送配置事件；界面按配置事件和连接代次刷新，确认完成前禁用操作，旧请求不能覆盖新状态 | simulation_config_refresh；前端保存、重连与请求乱序回归 |
| UX-03 | 内置模拟节拍点击“本件后停止”后缺乏反馈，可以重复点击 | 收到请求后显示“已请求停止，等待本件完成…”，禁用重复停止；本件完成后恢复正常状态 | simulation_config_refresh；前端停止反馈与后端事件检查 |
| UX-04 | 内置连续模拟在两件间隔中收到停止请求，仍可能启动下一件 | 间隔结束后再次检查停止请求；连续状态在启动时同步初始化，结束时清理 | simulation_config_refresh；Rust 停止时序回归 |
| UX-05 | Robot 联调台点击停止后仍像在正常连续运行，用户不确定是否收到请求 | 明确显示“停止请求已收到”和等待收尾；重复停止无额外副作用；空闲停止不会显示虚假的待停止状态 | robot_console_ux；HTTP 回归与真实桌面连续运行实测，仅完成当前 1 件 |
| UX-06 | Robot 服务离线时，网页仍保留上次可操作按钮与旧信号值 | 禁用失去依据的操作，未知信号显示“—”，说明当前状态无法确认 | robot_console_ux；网页状态测试与独立服务断线实测 |
| UX-07 | 仅视觉就绪为真就允许开始，armed / busy / done 或输入握手仍未释放时容易卡住 | 网页与服务端同时检查完整就绪条件；开始前说明阻塞原因，不提前写入工件信号 | robot_console_ux；握手残留、未就绪及不产生副作用的回归 |
| UX-08 | Robot 故障复位后仍停留在旧错误，或把请求成功误当作设备已经恢复 | 显示“复位已请求”，清楚区分请求已发送与实际可启动；继续按真实握手状态决定是否开放运行 | robot_console_ux；复位请求及启动条件回归 |
| UX-09 | 飞拍拍照点输入有四行坐标，界面却只显示不到两行；折线坐标也受同一单行高度限制 | 配方编辑器内的多行输入按声明行数显示，增加可读行距并允许纵向拖动调整 | validation_selection；真实桌面核对四点坐标完整显示 |

## 前序调试中已处理的相关问题

以下四项来自本次完整试用的前序调试，未计入上表的 9 项：

| 场景 | 处理 |
| --- | --- |
| 快速重新连接 PLC 后，“已连接”但视觉就绪没有重新置位 | 检测连接代次变化，刷新就绪输出 |
| 开始拖定位模板时图像布局变化，导致框选起点跳动 | 稳定模板拖动期间的显示布局 |
| 删除数值输入内容后立刻变成 0，难以重新输入 | 空值保留为待输入状态，由校验阻止无效保存 |
| Robot 释放握手过快，视觉轮询错过低电平，下一件没有新的上升沿 | 释放保持时间改为配置项，示例为 200 ms，并验证每件结束后的信号释放 |

## 集成验证

- 前端：39 个测试文件，942 项通过；类型检查通过。
- 模拟服务：22 项 Python 回归、5 项 Node 网页状态回归通过。协议测试在隔离端口运行，不依赖已配置的桌面或 DLL。
- Rust：37 项通过，3 项需专用 DLL 的测试按默认配置跳过；实际 DLL 处理另由下述桌面五工况及原图复测验证。
- 桌面：重新构建专用实例，通过真实 Modbus TCP、模拟相机触发桥和实际 lyFlow 图像测量完成以下五项。

| 工况 | 工件 SN | 结果码 | 异常码 | 结果 |
| --- | --- | --- | --- | --- |
| 正常 | 915171862 | 1 | 0 | 通过 |
| 跨帧断胶 | 915171863 | 13 | 0 | 通过 |
| 末帧丢失 | 915171864 | 90 | 91 | 通过 |
| 定位失败 | 915171865 | 90 | 92 | 通过 |
| 拍照数不符 | 915171866 | 90 | 94 | 通过 |

五项均核对返回 SN 与输入一致、开始 / 结束 / 确认和 armed / busy / done 已释放。随后以 SN 915171867 验证连续运行收到停止请求后只完成当前一件。原图复测 SN 915171863 仍检出跨 k2 / k3 的 3.0 mm 断胶，原生产记录保留。

集成过程中同步补齐在线检测测试的 PLC 订阅替身，并修正几何页面测试等待曝光值同步的竞态；没有放宽断言或改变生产行为。

当时使用模拟协议及五工况桌面联调验证；五工况自动入口已于 2026-10-12 删除，旧报告仅供历史追溯。Robot/Modbus 模拟服务与内置模拟节拍已删除，由站点模式的离线产线取代。
